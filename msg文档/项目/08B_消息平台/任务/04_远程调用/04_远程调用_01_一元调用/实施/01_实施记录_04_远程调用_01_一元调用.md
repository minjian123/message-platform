## 6. 问题与处置 <a id="issues"></a>

### 6.1 路径参数的 `pattern` / `minLength` 被依赖挤掉

**现象**：首次重导后 `/rpc/{service}/{method}` 的两个 path 参数 schema 只有 `{"title", "type"}`，`pattern` 与长度约束消失（既有 `/api/v1/msg/admin/groups/...` 的同类参数是带的）。

**根因**：帧闸门最初把 `service` / `method` 声明成自己的依赖参数（`service: str`）。FastAPI 对同一路径参数取「先遇到的 dependant」的参数定义，裸 `str` 覆盖了端点的 `Annotated[str, Path(pattern=...)]`，生成的 OpenAPI 就少了约束。

**处置**：闸门改为从 `request.path_params` 取值，不再声明这两个参数；端点保持 `Path(...)` 声明。重导后约束回到契约（`maxLength` / `minLength` / `pattern` 齐备）。§13.2 已把这条写成「依赖先于端点校验」的注意事项。

### 6.2 `ParamError` 的 HTTP 状态不是 400

**现象**：用例断言 `service` 形态非法时 `status_code == 400`，实际 200 + `code=10001`。

**处置**：按仓内既有口径改断言——契约层错误的 HTTP 状态由基座统一错误响应决定，用例只判 `code`（与 `test_data_messages.py` 一致）。不把状态码口径写成第二份事实。

### 6.3 客户端缺租户头 → 全部 350012

**现象**：`RpcClient` 真实往返全部失败，服务端日志 `msg_error_code_mapped source=80001 target=350012`。

**根因**：设计只写了「租户沿数据面口径」，没写客户端**怎么把租户带过去**；而远程调用与 `/msg/*` 共用同一基座中间件，没有 `X-Tenant-ID` / 子域名就解析不到租户。

**处置**：`RpcClient` 增 `tenant`（构造缺省 + `call()` 覆盖），请求时写 `X-Tenant-ID`；头名收进 `core/config.py`（`RPC_TENANT_HEADER` / `RPC_CALLER_HEADER` / `RPC_TRACE_HEADER`），服务端 `api/rpc/caller.py` 复用同一常量。设计 §10.3 已回写。

### 6.4 覆盖率数据跨会话被覆盖

**现象**：分两次跑采集（先 142 条、再 6 条）后判定，缺口反而从 5 行涨到 168 行。

**根因**：`MSG_COVERAGE_DATA` 指向同一路径时，后一次 pytest 会话**覆盖**该数据文件，不是累加；`engkit coverage` 的「合并」只针对同一次会话的并行分片。

**处置**：所有目标用例放**一次** pytest 会话采集（330 条 / 27 秒），再判定。

### 6.5 补掉两处 03-2 / 03-3 的存量缺口

| 缺口 | 影响 | 处置 |
| --- | --- | --- |
| 帧形态 `nack` 无用例 → `api/frame/gate.py::_invoke` 的 NACK 分支未执行 | 模块级覆盖率不可能 100% | `test_frame_data_plane.py` 补 `test_frame_nack_roundtrip` |
| `test_frame_contract_snapshot.py` 仍断言旧键 `content_type`（03-3 已改名 `frame_media_type`） | 该文件一直是红的（`tests/ops/` 只在推送环跑，本地未暴露） | 改为 `frame_media_type`，并在注释里记明是存量笔误 |

### 6.6 测试里的依赖覆盖对远程调用端点不生效

**现象**：`msg_app.dependency_overrides[get_rate_limiter] = lambda: limiter` 对 `/rpc/...` 无效（对 `/api/v1/msg/publish` 有效）。

**处置**：改用「直接替换进程级单例」`msg_app.state.rate_limiter = limiter`——与生产装配同一入口，不依赖 `override` 的匹配细节。已在用例里注释原因。

## 7. 偏差与遗留 <a id="leftovers"></a>

### 7.1 偏差

| # | 偏差 | 说明 |
| --- | --- | --- |
| 1 | 帧类型取 **48** 而非任务 §2.4 字面的「7~15」 | `reserved_types` 已把 `7-15` 登记为数据面预留、`48-63` 登记为 rpc；取 48 不侵占数据面扩展位，且响应沿用仓内唯一的「同 type + response 位」。任务 §2.4 已回写 |
