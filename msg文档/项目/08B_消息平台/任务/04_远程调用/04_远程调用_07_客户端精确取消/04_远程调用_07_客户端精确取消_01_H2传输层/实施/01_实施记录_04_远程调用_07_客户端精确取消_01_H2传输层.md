## 3. 关键决策落地 <a id="decisions"></a>

| 设计决策 | 落地 |
| --- | --- |
| 路线：h2 自持连接 | `h2.connection.H2Connection` + `asyncio.open_connection`，无第三方 HTTP 客户端参与 |
| 测试注入面：`RpcTransport` 协议 | 生产 `H2Transport`、测试 `AsgiRpcTransport` / `ScriptedRpcTransport`；`RpcClient` 无测试专用分支 |
| 池：按 origin 分连接 + 冷启动去重 | `_connections[origin]` + `_connecting[origin]` 建立中 future 表 |
| 流中止只影响本流 | `abort_stream()` 只 `reset_stream(本流)`；用例断言同连接第二条流照常 200 |
| 删 `timeout_ms` | 构造与调用两处签名删除；用例断言传它即 `TypeError` |
| TLS + ALPN | `https` 走 `open_connection(ssl=…)`，`selected_alpn_protocol() != "h2"` → `RpcTransportProtocolError` |
| 依赖 | `h2>=4.1` 直接依赖；本服务不再声明 `httpx[http2]`（httpx 仍随 `bms-core` 进环境，测试用其 `ASGITransport`） |

## 6. 问题与处置 <a id="issues"></a>

### 6.1 写锁会与读取任务互锁（设计回写）

设计原定「所有写走同一把 `asyncio.Lock`」。实现时发现死锁路径：发送方持锁等 `WINDOW_UPDATE`，而窗口更新只能由读取任务从 socket 读出后置位；读取任务如果也要拿写锁来 flush（例如回 PING ACK），就永远拿不到 → 连接卡死。

**处置**：不用锁，改为**同步段原子**——每次都是「同步 mutate h2 状态机 + 同步 `writer.write()`」，两步之间不 `await`，其它协程无法插入；`drain()` 单独 await（只做背压）。已回写设计 §5.4。

### 6.2 `SettingsAcknowledged` 不带 `stream_id`，`else` 兜底会炸整条连接

事件分派最初写成「四类流事件 `elif`，其余进 `else` 当流事件处理」。`SettingsAcknowledged` 落进 `else` 后取 `stream_id` → `AttributeError` → 读取任务把它当连接故障 → **所有用例同时红**（`h2 连接异常：'SettingsAcknowledged' object has no attribute 'stream_id'`）。

**处置**：`_dispatch` 显式列出四类流事件，其余（`SettingsAcknowledged` / `PingAcknowledged`）不处理。已回写设计 §5.3。

### 6.3 「迟到的响应」实测不会产生事件（`pragma: no cover` 的依据）

客户端 reset 某流后，服务端可能还没收到 RST、继续往那条流写。为确认「收到这种帧会怎样」，用裸 `h2` 状态机做了最小实验：客户端 `reset_stream(1)` 后再 `receive_data(服务端的 HEADERS/DATA/END)` → **返回空事件列表**（h2 静默丢弃）。

所以 `_on_stream_event` 里「流不在表里」的判断是**防御性分支**，实测不可达，按规范加 `# pragma: no cover - 实测（h2 4.4）对已 reset 流的迟到帧静默丢弃、不产出事件`。

### 6.4 测试传输的 `receive()` 不能立刻回 `http.disconnect`

`AsgiRpcTransport` 首版在请求体给完后直接返回 `{"type": "http.disconnect"}`，结果服务端 04-2 的断开探测（50ms 轮询 `request.is_disconnected()`）把**每个** handler 都判成「客户端跑了」：`test_downstream_stops_at_its_own_budget` 里下游 350004 变成 `outcome=cancelled`。

**处置**：请求体之后**挂住**（等响应写完再回 disconnect），与真服务端行为一致。

### 6.5 服务端夹具两处坑

| 现象 | 根因 | 处置 |
| --- | --- | --- |
| 第二条请求永远不回、用例挂死 | `/gated` 在读取循环里 `await release`，把整条连接的读取卡住 | 路由改到独立任务里跑 |
| 200 KB 响应报 `FlowControlError` | 服务端对每个流也有 64 KiB 出窗口 | `respond()` 按 `local_flow_control_window` 分片、等 `WINDOW_UPDATE` |
| `/boom` 用例超时而不是协议错 | 纯文本字节的长度前缀让 h2 进「等更多数据」；未知帧类型 h2 直接忽略 | 改发「`SETTINGS` 带非零 `stream_id`」的帧头，h2 立刻 `ProtocolError` |

### 6.6 覆盖率第一次判定被路径前缀误导

在 `backend/` 下跑 `engkit coverage` 时报告 `files=1 percent=37.50`：`coverage` 写出的 JSON 路径不带前缀（`bms_msg/client/transport/pool.py`），而 `engkit` 的包匹配用的是 `/{suffix}/`（要求前导 `/`）。改到仓根跑即正常（`files=6`）。另：采集时**必须同时给** `MSG_COVERAGE_DATA` 与 `MSG_COVERAGE_SOURCE`，只给前者会连源文件都不采（只剩测试文件）。

### 6.7 Windows 上「连接被拒」要 2 秒

`127.0.0.1` 已关闭端口在 Windows 会重试约 2.0s 才回 `ConnectionRefused`。用例初始给 1s 超时，先命中了外层 `asyncio.timeout` 变成超时错误。**处置**：该用例超时给 5s（用例注释写明原因）。

## 7. 偏差与遗留 <a id="leftovers"></a>

### 7.1 偏差

| # | 偏差 | 说明 |
| --- | --- | --- |
| 1 | 写路径不用锁，改同步段原子 | 持锁跨越等窗口会与读取任务互锁（§6.1）；设计 §5.4 已回写 |
| 2 | 超时只在 `H2Transport.send()` 一处判 | 原设计的「传输层分层超时 + 流级超时」会两处同时到点、排障分不清谁先放弃；设计 §5.8 已补 |
| 3 | 事件分派显式枚举四类流事件 | `SettingsAcknowledged` 等不带 `stream_id`（§6.2）；设计 §5.3 已回写 |
| 4 | `httpx` 未真正移出运行时 | 基座 `bms-core` 自身依赖 httpx；本服务只是不再声明 `httpx[http2]`。设计 §11.1 决策 14 已回写 |
| 5 | 并发流上限用「在途数 + 事件」而非信号量 | 远端可中途调小上限，信号量减容要在读取任务里 await（§5.4）；设计 §5.7 表格已注明 |
