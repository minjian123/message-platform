## 2. 任务内容 <a id="content"></a>

1. **`InstanceProvider` 端口**：msg 侧定义 `InstanceProvider` 抽象与选择 / 摘除逻辑；首期由 **bms 客户端提供者**读 bms 服务目录（`service_endpoints` / 能力寻址的 `CapabilityTarget.base_url`），该提供者随 bms 适配任务交付并注入；单实例也走同一接口，地址不写死在代码里；DNS / 静态列表实现后置，接口先留位。
2. **不引外部注册中心**：不接 Consul / etcd；bms 服务目录是首期唯一来源；部署变更只改 bms 登记 / 配置，不改客户端代码。
3. **选实例**：默认**轮询**（确定性、易断言）；可选「最少在途」；按目标服务维护游标 / 在途计数；策略可配置；单实例时退化为直连。
4. **失败换实例**：连接错误 / 可重试错误换实例；重试预算与 04-4 共用；**不重放已提交的请求 / 批次**，非幂等无键调用不换实例重试；同一请求不得在两个实例同时执行（幂等调用除外）。
5. **摘除与恢复**：连续失败达到阈值即摘除；被动探活（成功调用恢复）/ 主动探活（可选，详细设计定）二选一或组合；摘除状态带 TTL / 半开探测；日志与指标出口由 06-3 接。
6. **与事件共用寻址**：事件总线与远程调用共用 bms 服务目录 / 同一 broker 集群，不另造地址簿；多副本时事件按分区 leader 路由（8B_05），远程调用可路由到任意健康实例。
7. **配置与失败语义**：实例来源、刷新间隔、轮询策略、失败阈值可配；不硬编码 IP / 端口；bms 服务目录不可用时按 04-4 快速失败，**不得静默回退到写死地址**。
8. **测试**：停一个实例后有限次数内切到健康实例且不产生重复提交；地址变更只改配置；轮询 / 最少在途；摘除 / 恢复；单实例；服务目录不可用。
9. **边界**：DNS / 静态列表实现后置（接口保留）；不做分区 leader 路由（8B_05）；不做外部注册中心；不做网关负载均衡；不做 bms 迁移（8B_08）。

## 3. 完成标准 <a id="accept"></a>

- 停掉一个实例后，客户端在有限次数内切到健康实例，且不产生重复提交。
- 地址变更只改配置 / bms 服务目录，不改客户端代码；单实例走同一 `InstanceProvider` 抽象。
- 连续失败可摘除，探活通过后恢复；服务目录不可用时快速失败而非静默写死地址。
- 变更模块行 + 分支覆盖率 100%，静态检查全绿。

## 6. 收口（2026-11-06） <a id="close"></a>

**结论**：本任务交付「实例来源与选择」抽象、目录来源、换实例判定、半开摘除与流式接入；核心代码落 **bms 仓 `bms_core/msgclient`**（04-5 已把整条协议链上移，msg 仓再持客户端会形成仓级循环依赖），msg 仓保留任务文档与**跨仓契约用例**（`services/msg/tests/client/test_instance_failover_contract.py`，真 msg 应用 + 按 origin 路由的传输替身）。

| 交付面 | 结果 |
| --- | --- |
| 来源 / 选择分离 | `InstanceProvider`（只回答「有哪些实例」）+ `InstanceSelector`（轮询 / 最少在途、在途计数、连续失败摘除、TTL 半开）；单实例走同一抽象并退化为直连 |
| 换实例判定 | 只对「确定未执行」换（连接建立 `phase=connect`、发送 `phase=send`、`429` / `350005`、服务端 `transient` 且 `retryable`）；超时 / `350004` / `unknown` / 协议错同实例重试；非幂等无键仍由 04-4 `RpcRetryBlockedError` 阻止 |
| 摘除与恢复 | 连续失败 3 次摘除、TTL 30s、半开最多 1 个探测；探测成功恢复、失败 / 中性续摘；全部摘除且到期放一个探测，否则 `InstanceUnavailableError`（`RpcCallError` 子类，**不新增产品码**） |
| 目录与配置 | `[service_client].instances.<service>` > `endpoints.<service>` > `base_url_template`；映射精确 → `*` → 缺省 `msg`；快照 TTL 30s、地址变化 `revision` 递增；非法地址 / 显式空列表 `ConfigError` 拒启 |
| 装配 | `MsgServiceClientFactory` 改用 `ServiceCatalogInstanceProvider` + `selector_for`；启动期 `resolve` 一次做配置校验；事件发布只共用地址来源（多实例取首个） |
| 流式 | `RpcStream` 持 selector + `request_factory`，打开时才选实例；打开成功 / 失败反馈健康，流中错误不摘除；租约覆盖整条流，`aclose` / 正常结束释放；流式不进重试层 |
| 观测 | `msg_rpc_instance_selected` / `removed` / `recovered` / `unavailable` 四个结构化日志事件（指标出口归 06-3） |

**验收**：bms 侧 360 例、msg 跨仓 191 例全绿；13 个变更模块行 + 分支 100%（`missing_lines=0` / `partial_branches=0`，推送环口径）；文档三项（`links` / `docs-scope` / `eol`）通过。

**偏差**：实例语义按「msg 平台节点」落（`service` 只是逻辑路由键）；「可重试错误换实例」细化为「确定未执行才换」；目录提供者由本任务实现（`06_01` 只用了静态来源）；摘除取「被动 + TTL 半开」、不做主动探活；`RpcClient` 构造破坏性改为 `selector`。**过程偏差**：全量预检首次暴露 `msgclient` 23 处基类继承违规（17 处为 `06_01` 存量），按铁律全量归位基座体系（另一次 `fix(bms-core)` 提交，Kiwi 2444）。
