## 3. 实施过程 <a id="process"></a>

1. 按现场现象复现：最小应用 + 真实守卫 + 共享业务会话，内存库。空集 200；1 条主题列表 500（序列化处 `MissingGreenlet`）；3 条列表 500（第二轮 `topic.namespace` 处）；详情 500。
2. 定位根因：`release=uow.rollback`（05-3 引入）→ `rollback` 过期请求会话内全部 ORM 实例 → 判权后读行即同步懒加载。用 `git log -S` 确认引入提交为 05-3 的 `001f6c8`。
3. 清点同源破面：逐端点核对「先查行 / 后判权 / 再读行」的顺序，列出 11 处（主题 4、位点 1、死信 5、重放 2、ACL 收回 1，其中死信列表即计划 §6.1 #15）。
4. 实施根治：新增 `get_topic_acl_session`（未声明扩展点时不建会话），守卫绑定该会话、不再传 `release`；`snapshot()` 补 `ConfigError` 装配守卫。
5. 写回归用例 6 组 10 例；先做负向对照（临时恢复旧接线）确认 5 例能复现缺陷，再恢复修复。
6. 提交环：改动行覆盖率通过；pyright 首次以 `async for` 转发基座生成器，产生结构性 partial branch（`887->-866`），改用 `aclosing` + `anext` 后消除。
7. 真容器复跑：隔离演练集群换新镜像，验证主题列表 / 详情与同源 smoke。

## 4. 关键实现 <a id="impl"></a>

- **会话**：`get_topic_acl_session` 用 `get_platform_write_db`（平台库主库，与平台库读写口径同源）；未声明 `resource_acl` 时产 `None`。用 `aclosing` 手工驱动基座生成器并在请求结束时关闭——语义等价于 `async for` 转发，但避开「循环正常耗尽」这条请求期不可达的分支边。
- **守卫**：`TopicAclService` 的 `rules` / `scopes` 改为可空；`acl_provider` 为 None 时照旧短路（不碰仓储）；仓储缺失而走到 `snapshot()` 抛 `ConfigError`（装配缺陷，不静默放行、不伪装 503）。
- **release**：保留参数但生产装配不传；直连仓储的单测仍可用它控制事务边界，测试形态不被迫改写。
- **顺序不变**：端点侧「先查行 → 再判权」的代码一行未动——会话隔离后订单已安全，不必逐处投影。
- **口径**：列表 `total` 仍是 ACL 过滤前命中数（与 05-3 遗留 #7、06-6-1 一致），本次不改语义。
