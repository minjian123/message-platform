## 3. 实施过程 <a id="process"></a>

1. 按详细设计先建两份表文件并回写数据库设计总览，再写 ORM 与仓储（幂等建表，无迁移脚本）。
2. 实现授权快照缓存、纯判定、基座 `resource_acl` 端口实现与异步守卫；判定顺序固定角色权限 → 主题授权 → 归属。
3. 接入真实角色权限：msg 侧远程权限数据源、`prepare_settings` 置 provider、`msg-permissions` 种子写平台权限字典。
4. 接线数据面（publish / consume / ack / nack / join / subscribe）与管理面（topics / groups / delayed / replay / acls）；帧闸门透传授权守卫，补 `BizError` error 帧。
5. 复用 05-4 `emit_acl_change` 写 grant / update / revoke 强审计；授权管理路径加入审计中间件排除清单。
6. bms 侧补 `role_ids` 快照字段与 `current_roles()`，`AclContext.roles` 填角色主键；回写 07D `02-5` 文档与记录。
7. 补测试至 53 例（msg 新增）+ bms 3 例；跑选测、静态、类型、契约与覆盖率。

## 4. 关键实现 <a id="impl"></a>

- **表**：`msg_topic_acl` 唯一键 `(tenant_id, namespace, topic, principal_type, principal_key, action)`，不带 `deleted_at`；`msg_topic_acl_scope` 唯一键 `(tenant_id, namespace)` + `scope_version`。
- **判定**：无匹配默认允许；显式 deny 优先；`manage` 不隐含其他动作；user / role 主体；服务身份不匹配 user 规则（本期不受授权限制）。
- **缓存**：每判定读 `scope_version`，变化即重载；两个缓存实例共享版本源；读取异常 `10007 / 503` fail-closed；缓存上限 4096，超限清空。
- **事务**：授权守卫读取后**不再释放请求会话**——守卫绑定独立平台库会话（`get_topic_acl_session`），读完随请求结束关闭；管理面写前仍显式 rollback，版本冲突整批重试一次。~~旧口径 `release=uow.rollback`~~ 已在 05-3-1 移除（`rollback` 会过期业务 ORM 实例，见 §5 问题 1 复盘）。
- **管理面**：`GET` 列表（`msg:manage`）、`PUT` 批量授予/更新、`DELETE` 收回；写操作要求目标主题 `manage` 授权；收回软停用。
- **帧路径**：`build_frame_gate` / `_invoke` / `_handle_frame` 透传授权守卫；`_handle_frame` 增 `BizError` 分支，授权拒绝返回 error 帧（82013），不落到 JSON 4xx。
- **真实角色权限**：`prepare_settings` 置 `permission=rbac` / `resource_acl=msg.topic`；数据源不可达 fail-closed；`msg-permissions` 种子 5 个权限码。
- **bms**：`PermissionSnapshot.role_ids` 随缓存载荷往返；`current_roles()` 升序十进制字符串；`AclContext.roles` 由它填充。
