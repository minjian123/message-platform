## 1. 任务边界与已确认口径 <a id="scope"></a>

**本任务做什么**

1. **配额模型**：新建 `msg_quota`（只存限额，不存用量），六维 `topic_count` / `group_count` / `produce_rate` / `storage_bytes` / `unacked_count` / `connection_count`。
2. **用量统计**：统一 `usage_snapshot()`，为 05-1 的四列补真实值，并供配额判定与平台投影同源使用。
3. **执行点**：创建主题 / 首次 `join` / `publish`（JSON + 帧、立即 + 延迟）/ `consume` 未确认 / 连接守卫；软限告警、硬限拒绝。
4. **查询与调整**：`GET/PUT /api/v1/msg/admin/quotas`（批量），调整即时生效并写审计链。
5. **平台只读回显**：保留 `/api/v1/msg/tenant-usage/quota*` 三条投影（按单位拆分），按 07D `02-3` 契约返回。
6. **bms 通用记录页插槽**：`DictRecordLayout` 内置模块区域（默认 `sys.record.detail.tabs` + 页面 `moduleArea` 覆盖），用户 / 角色 / 租户统一走该机制。
7. **msg 前端只读插件**：msg 仓新建最小前端模块，注册「消息配额」只读页签，直连 msg 端点。
8. **原型**：补「配额管理」可交互原型，作为前端验收基准。

**不做什么**：不写 `sys_tenant_quota`；不做平台统一执行 / 跨产品汇总 / 计费；不做数据范围过滤；不做跨租户调整；不做配额调整历史表；不做组级未确认配额（按租户聚合，登记开放项）；不推送远程。

## 4. 数据模型（`msg_quota`） <a id="model"></a>

表结构以 [`msg_quota.md`](../../../../../../设计/数据库设计/数据表设计/msg_quota.md) 为唯一事实源，本节只写模型与查询口径。

- 唯一键 `uq_msg_quota_scope` = `(tenant_id, namespace, quota_key)`；**不带 `deleted_at`**（元数据表不做软删除，与 `msg_topic` 同口径）。
- `namespace` 空串表示**租户级**；命名空间级行只作覆盖，不预置。
- `limit_value`：硬限（`0` = 不限）；`soft_limit`：`0` = 未显式设置（读时按硬限 × 80% 派生）。
- `unit` / `period`：由 `quota_key` 派生后落库（客户端不可自报），用于投影与展示。
- `origin`：`default`（懒初始化写入的缺省行）/ `configured`（管理面调整写入）。
- 用量**不入库**；`updated_at` 来自基类审计字段。

仓储 `QuotaRepository`（`BaseDbRepository[MsgQuota]`）：
- `list_for_tenant(tenant_id)`：列出全部行（含命名空间级），按 `quota_key, namespace` 排序。
- `get(tenant_id, namespace, quota_key)`：单行。
- `upsert(...)`：按唯一键判存，存在则更新，返回行与「是否新建」。
- `delete_for_tenant(tenant_id)`：到期清理用。

## 5. 配额服务 <a id="service"></a>

`QuotaService`（`bms_msg/quota/service.py`）职责：合并缺省 / 覆盖、判定状态、缓存、懒初始化、审计辅助。

### 5.1 维度定义

`bms_msg/quota/keys.py` 定义唯一事实源：

```python
@dataclass(frozen=True)
class QuotaDefinition:
    key: str
    label: str
    unit: str          # count / bytes / qps
    period: str        # none
    scope: str         # tenant / namespace / tenant+namespace
    default_env: str
    default_value: int

QUOTA_DEFINITIONS = (
    QuotaDefinition("topic_count", "主题数", "count", "none", "namespace", "MSG_QUOTA_DEFAULT_TOPIC_COUNT", 100),
    QuotaDefinition("group_count", "消费组数", "count", "none", "tenant", "MSG_QUOTA_DEFAULT_GROUP_COUNT", 100),
    QuotaDefinition("produce_rate", "生产速率", "qps", "none", "namespace", "MSG_QUOTA_DEFAULT_PRODUCE_RATE", 1000),
    QuotaDefinition("storage_bytes", "消息存储", "bytes", "none", "tenant", "MSG_QUOTA_DEFAULT_STORAGE_BYTES", 10 GiB),
    QuotaDefinition("unacked_count", "未确认数", "count", "none", "tenant", "MSG_QUOTA_DEFAULT_UNACKED_COUNT", 10_000),
    QuotaDefinition("connection_count", "连接数", "count", "none", "tenant", "MSG_QUOTA_DEFAULT_CONNECTION_COUNT", 1_000),
)
```

`scope` 决定查找顺序：`namespace` / `tenant+namespace` 先查命名空间级行，再查租户级行；`tenant` 只查租户级行。

### 5.2 合并与状态

```python
@dataclass(frozen=True)
class QuotaLimit:
    key: str
    namespace: str        # 生效作用域（"" = 租户级）
    limit: int            # 0 = 不限
    soft_limit: int       # 0 = 未设置
    unit: str
    period: str
    origin: str           # default / configured
    updated_at: datetime | None
```

- `effective_soft(limit, soft)`：`soft > 0` 取 `soft`；否则 `limit > 0` 取 `limit * 80 // 100`；否则 `0`。
- `judge(usage, limit, soft)`：
  - `usage is None` → `unavailable`；
  - `limit > 0 and usage >= limit` → `hard_exceeded`；
  - `soft > 0 and usage >= soft` → `soft_exceeded`；
  - 否则 `ok`；
  - 未配置行（`origin=default` 且无显式行）→ 额外标记 `unconfigured=true`（管理面展示用），平台投影仍按生效限额判定。

### 5.3 缓存与失效

`QuotaCache`（进程级，`app.state.quota_cache`）：
- 键 `tenant_id`，值 `{namespace: [QuotaLimit...]}` + `loaded_at`。
- TTL `QUOTA_CACHE_TTL_MS = 60_000`；过期重载。
- `invalidate(tenant_id)`：管理面调整后调用；速率桶不预先同步——生产入口每次按缓存里的生效速率调用
  `RateLimiter.check_quota(...)`，速率变化时桶自动重建，调整后下一次请求即时生效。
- 多实例一致性登记 8B_05；直改库最多滞后 TTL。

### 5.4 懒初始化

`ensure_initialized(tenant_id)`：
- 缓存标记已初始化则直接返回。
- 查租户级行（`namespace=""`）是否齐全；缺哪维补哪维（`origin=default`、缺省值、`unit/period` 派生）。
- 唯一约束兜底并发：`IntegrityError` → 重查，不报错。
- 由首次 `publish` 路径调用（`publish` 入口、延迟发布分支之前）；失败只记日志、不阻断发布（缺省值仍可读）。

## 6. 用量统计 <a id="usage"></a>

`usage/snapshot.py::UsageSnapshotService`：

| 维度 | 取数 | 口径 / 失败 |
| --- | --- | --- |
| `topic_count` | `COUNT(*) FROM msg_topic WHERE tenant_id=?` | 实时；DB 失败 → 整次快照抛错（管理面 500，商业面不阻塞） |
| `partition_count` | `COUNT(*) FROM msg_partition JOIN msg_topic ON ... WHERE tenant_id=?` | 同上 |
| `storage_bytes` | 扫 `data_root()/data/{tenant_id}/**` 文件大小求和（含 `.delay`） | TTL 30s 缓存；扫描失败 → `None`（投影判 `unavailable`，配额不拒绝） |
| `delivered_today` | 进程内 `DeliveryCounter`（UTC 日切） | 重启清零；多实例不一致归 8B_05 |
| `group_count` | `GroupStore.list_for_tenant(tenant_id)` 长度 | 含空组（组记录存在即计） |
| `unacked_count` | 该租户全部组记录的分区 `DeliveryState.usage` 求和 | 组 / 投递状态进程内 |
| `connection_count` | `ConnectionRegistry.count_for_tenant(tenant_id)` | 按 `tenant_id` 归集，不含匿名连接 |

- 计数口径：主题含 `active` + `disabled`（停用仍占元数据）；组含空组；连接按 `tenant_id`。
- `storage_bytes` 采样器 `StorageUsageSampler`：进程级、TTL、异常返回 `None` 并记 `msg_quota_storage_sample_failed`。
- `delivered_today` 在 `DeliveryService._deliver` 每投出一条 +1；`acks=0` 与重放同样计。

## 7. 执行点与失败分支 <a id="enforce"></a>

| # | 维度 | 执行点 | 判定 | 超限行为 |
| --- | --- | --- | --- | --- |
| 1 | `topic_count` | `TopicService.create_topic`（事务前） | 当前租户 / 命名空间主题数 + 1 > 硬限 | `350025` / 429；`data` 带 `quota_key/limit/usage` |
| 2 | `group_count` | `GroupCoordinator.join`（新建组前） | 当前租户组数 + 1 > 硬限 | `350026` / 429 |
| 3 | `produce_rate` | `publish` 入口（JSON / 帧 / 延迟） | 静态两级桶 + `RateLimiter.check_quota`（按生效速率建桶） | `350005` / 429 + `Retry-After` |
| 4 | `storage_bytes` | `publish`（立即 + 延迟，`StorageGate` 之前） | 当前用量 + 本次字节 > 硬限 | `350022` / 507（`data.reason="tenant_quota"`） |
| 5 | `unacked_count` | `consume`（成员校验后、拉取前） | 该组当前未确认数 >= 硬限 | 返空批 + `paused=true`（不报错） |
| 6 | `connection_count` | 连接守卫（数据面 / 心跳 / 自报） | 该租户有效连接数 + 1 > 硬限（仅新连接） | `350020` / 429 |

**软限**：六维均只记日志 `msg_quota_soft_exceeded` + 指标计数，不改变响应。

**失败分支**

| 场景 | 行为 |
| --- | --- |
| 用量取数失败（storage） | 不拒绝；日志 + 指标；投影 `unavailable` |
| 配额行缺失 | 用缺省值（懒初始化补齐）；不拒绝 |
| 配额调整并发 | 唯一键 + 事务；后写覆盖前写，审计各记一条 |
| 调整值非法（负数 / 未知键 / 软限 > 硬限） | `ParamError`（10001） |
| 跨租户调整 | 请求体不接受 `tenant_id`；只调当前租户 |
| 未确认硬限 | 空批 + `paused=true`，不返回 350005 |
| 连接配额与副本全局上限同时触发 | 先判配额（按租户），再判全局（按副本）；两个码同 350020 |

## 8. 管理面端点 <a id="api"></a>

| 路由 | 权限 | 形状 |
| --- | --- | --- |
| `GET /api/v1/msg/admin/quotas` | `msg:query` | `ApiResponse[QuotaView]`，`items` 六维（可按 `namespace` 过滤） |
| `PUT /api/v1/msg/admin/quotas` | `msg:manage` | 请求 `{items:[{quota_key, namespace?, limit, soft_limit?}]}`；返回调整后的视图 |

`QuotaView` 条目：

```json
{
  "quota_key": "topic_count",
  "namespace": "",
  "limit": 100,
  "soft_limit": 80,
  "hard_limit": 100,
  "unit": "count",
  "period": "none",
  "usage": 12,
  "state": "ok",
  "source": "default",
  "updated_at": "2026-11-08T10:00:00Z"
}
```

- `limit` / `hard_limit` 同值（`0` → `null` 表示不限）；`soft_limit` 为 `0` → `null`。
- `state`：`unconfigured` / `ok` / `soft_exceeded` / `hard_exceeded` / `unavailable`。
- `source`：`default` / `configured`。
- 调整校验：`quota_key` 已知；`namespace` 为空或 `CurrentTenant.ensure_namespace` 通过；`limit >= 0`；`soft_limit` 为空或 `0 <= soft <= limit`（`limit=0` 时软限必须为 0）。
- 调整后：写库（`origin=configured`）→ 失效缓存 → 同步 `RateLimiter` → 写审计（`required=False`）。
- 审计：`build_operation_event(module="msg", action="msg:quota.update", method="PUT", path="/api/v1/msg/admin/quotas", params=<JSON>, status=200)`；失败只记日志，不阻断调整（普通审计）。
- 端点声明 `x-error-codes`：`350010` / `350011` / `350012` / `10001`。

## 9. 平台只读投影 <a id="projection"></a>

`deploy/registry/msg.toml` 三条声明（替换现有单条）：

| data_source_key | path | quota_dimensions | quota_unit | quota_period |
| --- | --- | --- | --- | --- |
| `msg_quota_count` | `/api/v1/msg/tenant-usage/quota` | `topic_count` / `group_count` / `unacked_count` / `connection_count` | `count` | `none` |
| `msg_quota_bytes` | `/api/v1/msg/tenant-usage/quota/bytes` | `storage_bytes` | `bytes` | `none` |
| `msg_quota_rate` | `/api/v1/msg/tenant-usage/quota/rate` | `produce_rate` | `qps` | `none` |

- 三条端点共用 `quota_projection_payload(tenant_id, unit)`，内部调 `usage_snapshot` + `QuotaService`。
- 返回 `{"items":[{quota_key, usage, limit, soft_limit, hard_limit, updated_at}]}`；`limit=NULL` 表示不限，`usage=NULL` 表示不可用。
- 平台 `QuotaProjectionReader` 按声明逐源取数；`module_key` 取 `data_source` 首段（`msg`），`source=msg.<data_source_key>`。
- 保留 07D `02-3` 契约与平台 `/api/v1/tenant-quotas/projections`；**租户页不再调用它**，改走 msg 前端插件（§12）。
- 失败口径：单源不可达 → 平台整源 `unavailable`（基座已有）；msg 内部单维不可用 → `usage=NULL`，不写 0。

## 10. 租户生命周期与懒初始化 <a id="lifecycle"></a>

- 首次 `publish`：`QuotaService.ensure_initialized(tenant_id)` 写 6 条租户级缺省行（`origin=default`）；命名空间级覆盖按管理面显式写入。
- 停用：不动配额行（恢复后沿用）。
- 删除：保留期内保留；`TenantPurgeService` 到期物理清理时调用 `QuotaRepository.delete_for_tenant`，并清缓存。

## 11. bms 通用记录页 Tab 插槽 <a id="bms-slot"></a>

### 11.1 机制

- `ModuleAreaOutlet` 增 `variant="panes"`：在 `el-tabs` 内渲染 `<el-tab-pane>`（每个区域项一个页签），保留 `inline` / `tabs` 两形态。
- `DictRecordLayout` 增：
  - `moduleArea?: string`（缺省 `sys.record.detail.tabs`）；
  - `moduleContext?: Record<string, unknown>`（缺省由 `info.formKey` / `info.id` 派生 `{formKey, recordId}`）；
  - `moduleTabs?: boolean`（缺省 `true`）。
- 渲染位置：`extra-tabs` 之后、系统信息之前，`<module-area-outlet variant="panes" :area="moduleArea" :context="moduleContext" ...>`；区域为空即不渲染（降级）。
- 权限：区域项声明 `perm`，插槽按会话权限过滤；后端仍鉴权。

### 11.2 存量页签

| 页面 | 现状 | 调整 |
| --- | --- | --- |
| 租户记录页 | 只有宿主 `extra-tabs` | 用默认 `sys.record.detail.tabs`；msg 插件按 `formKey === 'tenant'` 显示 |
| 用户记录页 | 手写 `ModuleAreaOutlet`（`sys.user.detail.tabs`） | 保留页面级区域（`moduleArea="sys.user.detail.tabs"`），改由布局统一渲染；移除手写 outlet |
| 角色记录页 | `RoleAssignTab` 内手写 `ModuleAreaOutlet`（`sys.role.detail.assign`） | 保留页面级区域（子页签位置不变），组件统一走 `ModuleAreaOutlet`；不改为顶层页签（避免 mdm 插件位置回归） |

> 口径：**通用默认 + 页面可覆盖**。租户页用默认；用户 / 角色用页面级区域覆盖，避免改变既有插件位置。
