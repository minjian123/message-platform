## 2. 任务内容 <a id="content"></a>

1. **配额模型**：在 msg 自维护配额表（`msg_quota`，表名以库设计为准）落维度——主题数、消费组数、生产速率、消息存储、未确认数、连接数；每个维度带限额、单位、周期、软硬限、更新时间。**不写 bms `sys_tenant_quota`**，不跨服务直写平台表。
2. **执行点前置**：在接收请求时判定，不在事后补算；软限只告警（日志 + 指标），硬限拒绝；既有语义复用 `350005`（生产限流）/ `350022`（存储）/ `350020`（连接），主题数与组数新增 `350025` / `350026`（产品自持 `[[errcodes]]` 声明 + 装载校验，07C 只登记段位）。
3. **软硬限与状态**：三态可区分——未配置（用缺省）、未超限、超限（软 / 硬）；状态判定与用量统计同源，避免两个口径打架。
4. **查询与调整**：提供配额查询与调整入口（管理面）；调整须留痕（接本域 `05-4` 审计留痕），并即时生效；调整不回溯历史用量。
5. **平台只读回显**：按 bms 07D `02-3` 的投影契约输出维度、限额、用量、单位、周期、软硬限、更新时间、来源；与 `05-1` 的 `/tenant-usage` 端点共用同一统计函数与字段常量，**不做双写**。
6. **边界**：配额值是 msg 单一事实源，平台只读；本任务不做平台统一执行、不做跨产品配额汇总、不做计费。
7. **测试**：软限告警 / 硬限拒绝、调整即时生效与留痕、三态区分、与平台投影字段一致、超限不产生双写、变更模块行 + 分支覆盖率 100%。

## 3. 完成标准 <a id="accept"></a>

- 六个维度可配置、可查询，值为 msg 单一事实源；
- 软限只告警、硬限拒绝，拒绝码在已登记段位内；
- 配额调整即时生效且可在审计链查到；
- 平台只读可见的用量与 msg 侧一致，字段符合 07D `02-3` 投影契约；
- 无双写、无跨服务直写平台配额表；
- 未配置维度的缺省行为明确且可测；
- 变更模块行 + 分支覆盖率 100%，静态检查全绿。
