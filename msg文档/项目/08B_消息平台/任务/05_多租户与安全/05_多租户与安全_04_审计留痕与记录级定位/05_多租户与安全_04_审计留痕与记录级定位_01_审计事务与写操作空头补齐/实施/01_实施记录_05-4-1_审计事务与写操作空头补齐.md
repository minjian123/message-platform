## 2. 实施过程 <a id="process"></a>

1. **审计同事务**：bms `AuditEventEmitter` 新增 `emit_in_session(session, event, required)`（复用发件箱 `enqueue`，不自开事务）；msg `audit/trail.py` 的 helper 增加可选 `session`，有 `emit_in_session` 即优先同事务、否则回落短事务。建主题 / 改保留期 / 扩分区 / 删主题 / 停用启用 / 删消息 / 延迟丢弃全部传 `uow.session`；删主题的 `cleanup.kick()` 移入 `finally`。
2. **删消息（墓碑）**：`RecordHeader` 增 `delete_target`（缺省不写、旧记录字节不变）；`MessageStore` 增 `delete()`；文件实现追加墓碑并维护进程内删除集合，启动按段重建（损坏段容错跳过）；`fetch` / `scan_headers` / `read_bytes` / `find_by_log_id` 过滤；内存实现用删除集合实现同语义；复制 / 唤醒包装层原样委托。
3. **删消息端点**：单条 `POST /admin/messages/{log_id}/delete` 与批量 `POST /admin/messages/delete`（≤100）；`confirm` 缺失 / 超限 10001；逐条返回 `deleted` / `not_found`；每次成功删除写一条 `msg:message.delete` 强审计（`record_ref`）。
4. **查询留痕**：消息检索、死信详情、重放详情各写一条普通审计（`msg:message.search` / `msg:dlq.detail` / `msg:replay.detail`），失败只告警。
5. **停用 / 启用**：新增 `POST /admin/topics/{id}/disable|enable`；`TopicService.set_status` 幂等、`deleting` 拒绝（350028）；`_ensure_writable_state` 改为只拒 `deleting`（停用不影响管理面写操作）；强审计含前后状态。
6. **语义修复**：
   - 死信重放：`mark_replaying` 冲突时取消刚建任务再抛 350030（消除孤儿）；
   - 并发建主题：`IntegrityError` 兜底为 350008；
   - 死信忽略 / 归档：仓储新增 `update_status` 条件更新（CAS），冲突 350030；
   - `cleanup_policy`：契约改 `Literal["delete"]`，服务只传 `CLEANUP_DELETE`；
   - 清理完成：`_complete` 先核对主题行已删，未删则保持 `running` 并记 `topic_row_still_present`；
   - 延迟丢弃：端点 `POST /admin/delayed/{log_id}/discard`（`confirm` + 原因 + 强审计）。
7. **前端接线**：主题详情加「停用 / 启用」按钮（按状态二选一、二次确认）；消息查询行加「删除」入口（`msg:manage`、二次确认、失败按错误码提示）。
8. **契约**：`contract_snapshot export` 重导；`api-types` 重新生成。

## 3. 问题与处置 <a id="issues"></a>

| # | 问题 | 处置 |
| --- | --- | --- |
| 1 | 删消息后 `find_by_log_id` 已返回 None，二次删除无法区分 `already_deleted` | 统一按 `not_found` 返回，删除枚举收敛为 `deleted` / `not_found` |
| 2 | 文件实现追加墓碑使 LEO +1，与设计「LEO 不变」不符 | 设计改为「既有 offset 与位点不变；文件实现 LEO +1」，内存实现 LEO 不变 |
| 3 | 启动重建删除集合直接扫段，损坏段会抛 `CorruptedRecordError` | 按段 try/except 跳过并告警（恢复流程已隔离 / 取证） |
| 4 | `set_status` 在提交后访问 `task.id` 触发 `MissingGreenlet`（同族坑） | 提前取 `replay_task_id` 并全程复用 |
| 5 | `_ensure_writable_state` 原拒绝 `disabled`，与「仅停数据面」口径冲突 | 改为只拒 `deleting`，既有用例同步调整 |
| 6 | `from_statuses: tuple[str, ...]` 触发集合声明护栏 | 改 `ConcurrentStableFrozenList[str]` |
