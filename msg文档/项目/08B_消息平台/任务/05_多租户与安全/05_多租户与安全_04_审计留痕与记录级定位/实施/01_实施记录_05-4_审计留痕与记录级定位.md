## 3. 实施过程 <a id="process"></a>

1. **Kiwi 先登记**：`ssh` 容器内 Django shell 登记一条用例，回读确认编号 **2455**（当前最大号 2454 顺延）；新用例统一标注 `@pytest.mark.kiwi_id(2455)`，未复用 2451~2454。
2. **审计基础设施**：新增 `audit/trail.py`，集中 `ACTION_CLASSES`（动作 → 类别 / 强审计 / 记录级）与 `emit_sensitive` / `emit_record_operation` / `emit_acl_change` / `emit_access_denied`。`ApplicationFactory.audit_classes()` 返回同一映射，helper 与装配声明同源。
3. **配置变更**：建主题在提交后写 `msg:topic.create` 强审计（作用域 + 主题元数据）；配额调整从普通审计改为 `msg:quota.update` 强审计；两条路径加入 `exclude_paths`，消除中间件重复记录。
4. **延迟转投异常处置**：新增 `DelayDisposalService.discard()`，先移除延迟区与时间轮，再写 `msg:delay.discard` 强审计（`record_ref{msg.message, log_id}`）；审计失败恢复记录并上抛。`DelayWheel.forget()` 同时清桶与 `_overdue`。
5. **访问异常**：新增 `AccessAnomalyAuditMiddleware`，只对基座未记录的 401 / 403 / 429 补 `msg:access.denied`；按 `(tenant, 路径, 状态)` 60 秒窗口节流；auth / 探针 / 文档跳过；写失败不影响原响应。中间件在 `configure_service()` 最后注册，位于最外层。
6. **删消息 / ACL 契约**：`msg:message.delete` 使用 `emit_record_operation` 契约用例覆盖；`msg:acl.grant/revoke/update` 使用 `emit_acl_change` 契约用例覆盖；均不建业务端点。
7. **排除清单**：补齐 `/api/v1/msg/subscribe`、`/api/v1/msg/connection/heartbeat`、`/rpc`，以及配置 / 延迟 / 位点显式审计路径；保留 4 条 auth 默认项。
8. **测试与覆盖率**：新增 37 例；定向回归 126 例全绿；7 个变更模块行 + 分支 100%（`missing_lines=0 partial_branches=0`）。

## 4. 关键决策落地 <a id="decisions"></a>

| # | 设计口径 | 落地 |
| --- | --- | --- |
| 1 | 删消息只出契约 | 新增动作常量 + `record_operation` 类别 + `emit_record_operation`；无端点、无存储删除 |
| 2 | 延迟处置服务原语 | `DelayDisposalService.discard()` + `DelayWheel.forget()`；端点归 06-2 |
| 3 | ACL 只出契约 | `emit_acl_change()` + `sensitive` 类别；实际调用归 05-3 |
| 4 | 配置变更显式审计 | 建主题 / 配额均显式强审计，路径排除 |
| 5 | 访问异常中间件 | 401 / 403 / 429 补记；窗口节流；失败不影响响应 |
| 6 | 强审计范围 | 配置 / 权限 / 记录级 `required=True`；访问异常 `required=False` |
| 7 | 重放 / 位点保持现状 | 未改 `ReplayAuditor` / `OffsetStore`；只补类别映射与文档口径 |
| 8 | 洪泛排除 | `config.toml` 全量清单 + 配置断言 |
| 9 | 组件级事件断言 | 全部用审计替身断言 `sys.operation.logged` 载荷与 `required` |
