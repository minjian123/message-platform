## 2. 任务内容 <a id="content"></a>

1. **留痕类别**：按需求固定四类——配置变更（主题 / 配额 / ACL 等）、数据操作（重放 / 删除消息 / 位点重置）、权限变更、访问异常（含停用租户访问）；逐类列出触发点，不漏操作、不重复记。
2. **字段口径**：谁（操作人 / 服务身份）、何时、对什么（`tenant_id` / `module_key` / `resource_key` / `topic` / `group`）、做了什么、结果、来源 IP / `trace_id`；涉及具体记录时另带 `record_ref`（记录类型 + 主键，基座强审计扩展位）。
3. **写入路径**：一律写基座审计链（`sys.operation.logged` 既有通道），不自建审计表、不绕过基座写入、不允许删除审计记录；审计失败处置按 07D `02-4` 口径——强审计操作失败即失败，其余记指标与告警。
4. **记录级定位**：重放、删消息、位点重置、延迟转投异常处置必须带 `record_ref`；**重放与位点重置两类已由 07D `03` 交付**（重放定位任务、位点定位位点），本任务只补**延迟转投异常处置**（`msg.message` + `log_id`）与**删消息契约**（实际触发归 06-2）。普通读写不逐条留痕，只做指标。
5. **与现有实现对齐**：`01_消息保留与重放` 已接入审计（含发件箱与高频路径排除），07D `03` 已把重放（建任务 / 终态）与位点重置两处迁到 `record_ref` 并启用强审计；本任务核对这两类字段口径、补齐延迟处置与删消息契约，不重写既有写入；ACL 留痕契约归 05-3 实现。
6. **边界**：不改哈希链构造与归档口径；不为审计新增第二套事件总线；不把审计当业务日志用；不建删消息端点、不改追加日志单条删除语义。
7. **测试**：四类各至少一条事件断言、`record_ref` 定位可用（重放 / 位点重置回归 + 延迟处置新增 + 删消息契约）、普通读写不产生洪泛、审计失败处置符合口径、停用租户访问可追溯；变更模块行 + 分支覆盖率 100%。

## 3. 完成标准 <a id="accept"></a>

- 四类操作逐类有触发点与事件断言，无漏记；权限变更本期以 ACL 契约用例覆盖，实际变更随 05-3；
- 审计条目含作用域字段与 `trace_id`，记录级操作含 `record_ref`；
- 写基座审计链，未自建审计表、未绕过写入；
- 普通读写不产生逐条审计（有断言）；
- 审计失败处置符合 07D `02-4` 口径，不静默丢弃；
- 从 `record_ref` 可一次定位到操作对象：延迟处置 / 删消息为 `msg.message` + `log_id`，重放为任务、位点为位点；重放 / 位点重置沿用 07D `03` 已交付实现并回归通过；
- 删消息本期交付契约与 helper，实际端点与存储删除语义归 06-2；
- 变更模块行 + 分支覆盖率 100%，静态检查全绿。
