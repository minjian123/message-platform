## 1. 测试范围 <a id="scope"></a>

依据「详细设计 + 实施记录」，覆盖五类事件动作、业务级幂等、停用即时拒绝与恢复、两步删除（`deleted` 只停写 / `purged` 才删）、激活竞态、跨仓契约快照、失败重试 / 死信、审计强弱、路径安全与装配。测试分层：

| 层 | 文件 | 重点 |
| --- | --- | --- |
| 账本 | `tests/tenant/test_tenant_lifecycle_ledger.py` | 版本幂等、删除计划、取消清理、失败计数、文件兼容读 |
| 动作 | `tests/tenant/test_tenant_lifecycle_actions.py` | created / suspended / activated / deleted、断连、易失清理、强审计失败 |
| 两步删除 | `tests/tenant/test_tenant_purged.py` | `deleted` 不删数据 / `purged` 才删、重复幂等、激活竞态、孤立 purged、晚到 deleted、跨仓契约快照 |
| 记录 | `tests/tenant/test_tenant_lifecycle_records.py` | 五事件声明、工厂实例事件类型、零参兼容入口 |
| 运行时 | `tests/tenant/test_tenant_runtime.py` | 租户可用性适配、审计强弱、进程级运行时、会话入口 |
| 清扫 | `tests/tenant/test_tenant_purge.py` | dry-run、逐主题到期、孤儿目录、活跃重放延后、失败重试、路径安全 |
| 既有原语 | `tests/broker/` 相关 8 份 | 连接 / 流 / 组 / 死信 / 投递 / 唤醒 / 延迟 / 消息 / 位点清理原语 |
| 回归 | `tests/api/test_tenant_status.py` 等 | 停用即时拒绝、长驻流、连接上限、数据面入口 |
| 只读窗口 | `tests/api/test_tenant_readonly.py` | 配置真值两条前缀、停用 / 注销 `GET` 放行、写方法仍拒、数据面仍拒、空白名单 fail-closed |

## 5. 问题与处置 <a id="issues"></a>

| # | 问题 | 处置 |
| --- | --- | --- |
| 1 | 初始清扫计划按 `purge_after` 判到期，与逐主题 `retention_ms` 口径不一致 | 计划改为按 `deleted_event_at + retention_ms` 判到期；`purge_after` 只作调度索引 |
| 2 | `FileMessageStore.close_tenant` / `FileOffsetStore.purge_topic` 依赖 `PartitionDirectory` 定位 | 目录登记保留到删位点之后；清扫顺序固定为「关句柄 → 删位点 → 删目录 → 删行 → 移除登记」 |
| 3 | 删除延迟区后时间轮仍持有旧记录 | 增加 `DelayWheel.forget_tenant`，与 `FileDelayStore.drop_tenant` 同事务路径清理 |
| 4 | 停用后延迟转投仍会写日志 | `DelayScheduler` 注入基座租户守卫适配器；停用期间保留记录、不转投 |
| 5 | 05-1 租户目录路径与实际存储布局不一致 | 修正为 `data_root/data/{tenant_id}`；注入 root 的用例不变 |
| 6 | 强审计失败与数据删除的先后 | 先删除、后强审计；失败不标记 `purged_at`，下轮计划为空仍补审计 |
| 7 | 全量测试守卫拒绝目录级 pytest | 改为显式文件列表；全量测试留给 CI |
| 8 | 两步口径下线后 `lifecycle.py` 导入期契约断言直接失败（bms 已登记第五类事件） | 消费声明补 `tenant.purged`（4 → 5 条）并新增 `on_purged`；这是 fail-closed 的预期表现，不是回归 |
| 9 | bms `TenantLookup` 新增 `readonly` 形参、`TenantMiddleware` 读 `[tenant_guard]` | 租户源测试替身补形参与调用记录；生产解析链不变 |
| 10 | 全量序下 330 个用例因 `settings` 替身缺 `tenant_guard` 而 `AttributeError`（中间件直接读属性，非 `getattr`） | 13 处最小应用（含共享 `tests_support/frame_app.py`）补 `tenant_guard.readonly_routes`（空 = 原口径全拒）；真实白名单由 `test_tenant_readonly.py` 单独验 |
| 11 | `test_actions_require_runtime` 在全量序下「DID NOT RAISE」 | 骨架用例 `ApplicationFactory().create()` 会登记进程级生命周期运行时；`tests/tenant/conftest.py` 的 autouse 复位夹具补 `reset_tenant_lifecycle_runtime()` |
