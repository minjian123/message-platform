## 2. 任务内容 <a id="content"></a>

1. **消费四类事件**：`tenant.created`（已由 05-1 第 7 条承接，本任务只做对齐与回归）、`tenant.disabled`、`tenant.enabled`、`tenant.deleted`；事件带 `tenant_id` / `module_key` / 变更前后状态 / 版本戳。
2. **状态动作**：`disabled` → 拒绝生产与消费（复用基座版本戳，不自建 TTL 缓存）；`enabled` → 恢复受理；`deleted` → 断开该租户连接、清理延迟区、按保留策略处理主题与位点（保留期内只读、到期物理删除）。
3. **幂等**：按「`tenant_id` + 事件类型 + 版本戳」幂等；重复投递不重复执行；清理动作可重入。
4. **失败与死信**：清理失败不阻塞基座已提交的删除事务；进事件重试，耗尽后进死信，输出日志与指标，提供可运维处置入口，**不得静默丢弃**。
5. **保留期**：与配额 / 主题登记中的保留期口径一致；删除后保留期内只读，到期物理删除；审计记录不随资源删除（接 05-4）。
6. **边界**：不自建租户状态表 / 状态机、不轮询基座租户表、不在删除处理器里反向调用基座改租户状态；不把清理做成一次性脚本。
7. **测试**：四类事件动作、重复投递幂等、停用即时拒绝与恢复、删除后清理可核对、失败重试与死信、保留期边界；变更模块行 + 分支覆盖率 100%。

## 3. 完成标准 <a id="accept"></a>

- 四类生命周期事件可消费，状态动作逐条可验证；
- 停用后生产与消费即时被拒，恢复后即时受理，不依赖产品自建缓存；
- 删除后连接断开、延迟区清理、主题与位点按保留期处理，结果可核对；
- 重复投递不产生重复副作用（幂等键可断言）；
- 清理失败可重试、可观测、有死信出口，不阻塞基座删除；
- 审计记录不随资源删除，可从审计追到清理动作；
- 无自建租户状态表 / 状态机 / 轮询实现；
- 变更模块行 + 分支覆盖率 100%，静态检查全绿。
