## 2. 任务内容 <a id="content"></a>

1. **消费五类事件**：`tenant.created`（已由 05-1 第 7 条承接，本任务只做对齐与回归）、`tenant.suspended`、`tenant.activated`、`tenant.deleted`、`tenant.purged`；事件带 `tenant_id` / `db_key` / 状态 / 版本戳（需求文本的 `disabled` / `enabled` 即契约的 `suspended` / `activated`，不新增同义事件）。
2. **状态动作**：`suspended` → 拒绝生产与消费（复用基座版本戳，不自建 TTL 缓存），并取消已建立连接与长驻流；`activated` → 恢复受理，若删除清理待执行则取消；`deleted` → 断开该租户连接、清理延迟区与易失资源，**只停写、不删数据**（保留期与清理时点归平台）；`purged` → 平台已物理清理，一次性删除该租户消息数据 / 位点 / 元数据。
3. **幂等**：按「`tenant_id` + 动作 + 版本戳」幂等，账本落 `msg_tenant_lifecycle` 表；重复投递不重复执行；清理动作可重入。
4. **失败与死信**：清理失败不阻塞基座已提交的删除事务；事件动作进重试，耗尽后进死信；到期清扫失败在账本记 `failure_count` / `last_error` 并下轮重试；输出日志与指标，提供可运维处置入口，**不得静默丢弃**。
5. **保留期（两步删除）**：保留期与到期时点由平台算并落 `tenant.deleted.purge_at`，平台届时发 `tenant.purged` 授权删除；本仓不自算保留期，`msg_topic.retention_ms` 只作既有数据保留口径与 05-5 存量行收敛用；审计记录不随资源删除（接 05-4）。
6. **边界**：不自建租户状态表 / 状态机、不轮询基座租户表、不在删除处理器里反向调用基座改租户状态；不把清理做成一次性脚本；不修改 `msg_topic.status` 表达租户停用。
7. **测试**：五类事件动作、重复投递幂等、停用即时拒绝与恢复、`deleted` 不删数据与 `purged` 才删、激活与 `purged` 竞态、跨仓契约快照、失败重试与死信、存量行收敛边界；变更模块行 + 分支覆盖率 100%。

## 3. 完成标准 <a id="accept"></a>

- 五类生命周期事件可消费，状态动作逐条可验证；
- 停用后生产与消费即时被拒，恢复后即时受理，不依赖产品自建缓存；
- 注销后连接断开、延迟区清理、数据保留；收到 `tenant.purged` 后数据 / 位点 / 元数据物理删除，结果可核对；
- 重复投递不产生重复副作用（幂等键可断言）；
- 清理失败可重试、可观测、有死信出口，不阻塞基座删除；
- 审计记录不随资源删除，可从审计追到清理动作；
- 无自建租户状态表 / 状态机 / 轮询实现；
- 变更模块行 + 分支覆盖率 100%，静态检查全绿。
