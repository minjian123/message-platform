## 2. 任务内容 <a id="content"></a>

> **归属（2026-11-04 拍板）**：本任务**全部在 msg 仓**交付，bms 侧不立项。产品自持链路 = 数据源声明 → 表单/字段种子（写平台库）→ `form_key` 登记 → 取数端点 → 前端页面（前端已立项 06-8）。
>
> **口径校准（2026-11-07 确认，详见[详细设计](设计/01_详细设计_05_多租户与安全_01_租户用量板块与表单登记.md) §1）**：固定四列；usage / quota 拆两条端点共用一个取数函数；种子模块 `bms_msg.seeds.forms`、种子名 `msg-usage-forms`；`sys_business.form_key` 保持 `business`；`tenant.created` 只预创建租户目录 + 幂等账本；数据范围过滤与前端不纳入本期。

1. **数据源声明**（已有，补齐）：`deploy/registry/msg.toml` 的 `[[data_sources]]`（`msg_tenant_usage`，`origin=product`、`path=/tenant-usage`）补 `allowlist`（`topic_count` / `partition_count` / `storage_bytes` / `delivered_today`），与表单字段同名闭合。`msg_quota_projection`（`kind=quota`）路径改为 `/api/v1/msg/tenant-usage/quota`，与 form 声明并存、各司其职。
2. **表单与字段种子**：新增 `[[seeds]]` 声明（`name=msg-usage-forms`、`service=msg`、`db_key=platform_platform`、`module=bms_msg.seeds.forms`、`entry=seed_usage_forms`、`[seeds.tables]` 声明 `sys_business`=code / `sys_form`=business_id / `sys_field`=form_id,field_key），种子入口在平台编排气泡的 XA 分支内写：
   - `sys_business`：业务码 `msg_usage`（`form_key=business`，平台业务码字典约定；`msg_usage` 只作 `code`，名称「消息平台用量」）；
   - `sys_form`：与业务码 1:1（`component=null`）；
   - `sys_field`：四个字段（主题数 / 分区数 / 消息存储 / 今日投递量，`number` 类型、按 `sort` 排序）；
   - **幂等**：按自然键 upsert，存在且**全字段**同值跳过、异值抛 `ParamError`；不建 `sys_menu_form`、不建按钮、不建 `sys_permission`。
3. **`form_key` 登记**：新增 `backend/services/form_registry.py`（仿 mdm），`FormRecord(form_key="msg_usage", table="msg_usage", kind=form, data_source_key="msg_tenant_usage")`；`main.py` 覆写 `form_records()` 返回该清单，使 **msg 应用级视图** `app.state.form_registry` 含 `msg_usage`。平台 `/api/v1/form-keys` 要聚合产品表单需 bms 侧「产品清单下发 / 聚合」通道（mdm 已登记同项），本任务回 bms 登记缺口，不在 msg 挂平台路由。
4. **取数端点**：固定四列 + 空数据，拆两条物理端点、共用一个取数函数：
   - `GET /api/v1/msg/tenant-usage`（前端 / `kind=form`）→ `{columns:[{key,label}], items:[], total:0}`；
   - `GET /api/v1/msg/tenant-usage/quota`（平台 / `kind=quota`）→ `{items:[]}`（本期空，真实条目随 05-2）。
   - 列与 `sys_field` 同源（同一常量派生）；平台只读 quota，前端只读 form，**不双写、不重复取数**。限额 / 状态 / 预警口径归 05-2，不在本期端点出现。
5. **数据范围过滤（不纳入本期，2026-11-07 确认）**：平台侧尚无产品数据源标准下推参数契约，本期无数据可过滤；登记 05-2 / 后续，不在 msg 自造过滤语法。
6. **前端（不纳入本期，2026-11-07 确认；已立项 06-8）**：msg 管理模块「租户用量」页与 bms 租户管理页内嵌板块由 06-8 交付；本期只保证后端数据与元数据就绪。
7. **非库类资源初始化（附带项，原 bms `04_04`；需求 `05-6` 归口，本任务附带实施）**：在产品工厂 `event_consumer_records()` 声明 `tenant.created` 消费组，**只预创建 `data/{tenant_id}/` 并写幂等账本 `.lifecycle.json`**；不建命名空间、不建默认配额（命名空间按架构 07 §5.1 首次发布懒创建，配额归 05-2）。实现用基座 `BaseTenantResourceHandler` + `TenantLifecycleDispatcher`，按 `tenant_id + 动作 + 版本戳` 幂等；失败**不阻塞租户开通**（事件重试 + 死信 + 日志 / 计数可观测）。**不新建基座机制**：事件契约、消费组声明、生命周期分发器均为既有能力。
8. **测试**：种子幂等与 XA 语义、`sys_business`/`sys_form`/`sys_field` 落库结果、`form_key` 清单含 `msg_usage`、双端点契约与列 / `sys_field` 一致性、`tenant.created` 消费幂等与失败不阻塞开通；变更模块行 + 分支覆盖率 100%。数据范围参数解析不在本期。

## 3. 完成标准 <a id="accept"></a>

- `msg.toml` 声明通过平台装载期校验（种子入口可导入、`[seeds.tables]` 自然键合法、种子名以 `msg-` 开头）。
- 执行种子后，平台库存在业务码 `msg_usage`、对应表单行与四个字段行；重复执行不产生重复行，异值抛 `ParamError`。
- msg **应用级视图** `app.state.form_registry` 含 `msg_usage`，`data_source_key` 指向 `msg_tenant_usage`；平台 `/api/v1/form-keys` 聚合产品表单的缺口已回 bms 登记（与 mdm 同项）。
- `GET /api/v1/msg/tenant-usage` 返回四列与 `items=[]`、`total=0`；列集合与 `sys_field` 完全一致。
- `GET /api/v1/msg/tenant-usage/quota` 返回 `{"items": []}`；`msg_quota_projection.path` 指向该路径，平台读取器可正常判 `default`。
- 角色权限配置在平台侧可选中该表单并为四个字段配置可见性（联合验证，平台侧既有能力；种子写 `sys_form` / `sys_field`）。
- `tenant.created` 消费：同一租户同版本重复投递只建一次目录（`data/{tenant_id}/`）并记 `.lifecycle.json`；新版本重跑幂等；处理失败原样上抛供重试 / 死信，租户开通仍成功，日志 / 计数可观测。
- 数据范围过滤与前端页面不在本期（已确认并登记遗留；前端 → 06-8）。
- 变更模块行 + 分支覆盖率 100%，静态检查全绿。
