### 7.4 口径沉淀

- **跨仓克隆需在目标项目登记 job token 入向白名单**（本项目 / 组级均可），新增产品仓或新增跨仓克隆依赖时同步登记；口径已写入 bms《开发部署规划》「开发工作流与 CI」节，并在 `scripts/tools/ci/{bms,engkit}_setup.sh` 头注释指路。
- **本机 Windows 平台类型检查不足以代表 CI**：凡使用平台专有属性（`socket.SO_*`、`os.*` Windows 专有项）的代码，本地验证须加 `--pythonplatform Linux` 复核一次。
- **跨文件共享的测试辅助一律放 `tests_support`**：`services/msg/tests` 不是包，用例里写 `from tests.conftest import …` 只在单文件运行下偶然成立（`tests` 同名包解析顺序决定），全量收集会崩；同类问题已第二次出现（前有 `tests_support/msg_fixtures.py`），新增用例照此办理。
- **本地单文件绿 ≠ CI 全量绿**：本地守卫禁止全量 pytest / 无过滤 vitest（重命令与全量测试只在 CI），故「同名包解析」「并行下的渲染开销」这类只在全量 + 多 worker 才暴露的问题，只能由 CI 首跑发现——这也是 00-2「CI 首次真机触发」被列为遗留的原因。
- **前端测试只放前端、后端测试只放后端**（2026-11-13 拍板）：前端生成器 / 页面 / 契约类型一律由前端 job 的 vitest 覆盖，后端 pytest 不得调用 `node` 或依赖前端 `node_modules`；反之亦然。跨端用例会让某个 job 天然缺依赖，是「本地过、CI 崩」的稳定来源（本次 #6）。
- **功能用例不依赖内核缓冲 / 时序细节**（2026-11-13 定）：当前阶段验功能，不验容量与压测口径——「停读后服务端是否真被挡住」「窗口暂停计数是否累加」这类由内核缓冲大小决定的现象不作断言；要么换成与内核无关的功能不变量，要么由可注入阈值的确定性用例覆盖（如 `test_frame_stream.py::test_window_stall_is_counted`）。
- **覆盖率门禁只判产品代码**（2026-11-14 拍板）：`coverage_packages` 不再写整包 `services`（会把 `services/<产品>/tests` 的测试代码计入 100%），而是逐个列出 `services/*.py` 产品模块；新增 `services/*.py` 时同步登记 `engkit.toml` 与 CI `--module` 列表。mdm 仓同口径对齐。
- **跨仓前端依赖必须钉版、不能留 caret**（2026-11-14）：msg 与 mdm 都写 `vite: ^8.2.2` 且各持锁文件，漂出 8.3.6 / 8.3.3 两个 patch；rolldown（vite 8 的打包器）在 1.2.16 对 MF `import: false` 共享包装的 named-export 链接检查更严，**只在一个平台（Linux CI）炸**、本机 Windows 同版本却过。凡与平台构建链相关的前端依赖（vite / vue / plugin-vue / rolldown）一律**精确版本**，并以「同构仓已验证组合」为基线；传递依赖用 `pnpm-workspace.yaml` 的 `overrides` 钉住（pnpm 11 起不再读 `package.json.pnpm.overrides`）。
