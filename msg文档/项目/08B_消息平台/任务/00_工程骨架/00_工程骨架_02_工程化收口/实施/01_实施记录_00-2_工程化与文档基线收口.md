| 1 | `msg#1612` 全部后端 / 前端 job 在克隆基座时 403：`remote: Authentication by CI/CD job token not allowed from msg to project #2` | **GitLab 项目设置缺失，非代码问题**。GitLab 的 job token 入向白名单配置在**被访问的目标项目**上（`bms/bms` 与 `bms/engkit`）；本实例已启用「Enable and enforce job token allowlist for all projects」，未登记的调用方一律 403。当时 `bms/bms` 白名单只有 `bms/bms` + `mjs/mdm`，`bms/engkit` 只有 `bms/bms` + `mjs/mdm` + `bms/engkit`，故 mdm 能跑、msg 不能 | 按「只加项目、不加组」逐项确认后，用 REST 接口把 `mjs/msg`（项目 17）加入两个目标项目的入向白名单：`POST /projects/2/job_token_scope/allowlist`、`POST /projects/16/job_token_scope/allowlist`（`target_project_id=17`）；回读白名单已含 `mjs/msg`。回滚命令 `DELETE /projects/<目标id>/job_token_scope/allowlist/17` |
| 2 | `msg#1613` 的 `backend-typecheck` 失败：`internal_server.py:167` `Type of "SO_EXCLUSIVEADDRUSE" is unknown` / `is not a known attribute of module "socket"`（3 条） | `socket.SO_EXCLUSIVEADDRUSE` 是 **Windows 专有常量**，`hasattr()` 只挡运行期、挡不住类型检查：本地（Windows）pyright 通过，CI（Linux 存根）判定属性不存在——跨平台静态缺陷，本地无法暴露 | 改 `exclusive = cast("int | None", getattr(socket, "SO_EXCLUSIVEADDRUSE", None))`，有则用、无则回落 `SO_REUSEADDR`；两分支保留 `pragma: no cover` 及理由。语义与原来完全一致 |
| 3 | `msg#1614` 的 `backend-test` 在**收集阶段**即失败：`services/msg/tests/broker/test_replay_lease_0284.py:15 from tests.conftest import ManualClock` → `ModuleNotFoundError: No module named 'tests.conftest'`（2266 例 collected，1 error） | 用例靠「同名包 `tests`」跨目录取 `services/msg/tests/conftest.py` 的 `ManualClock`。单文件跑时 `tests` 恰能解析到该目录，**全量收集时**先解析到仓内另一个 `tests` 命名空间（`backend/tests`，只有 `ops`）→ 崩。属「本地单文件过、CI 全量崩」的同一类盲区 | 把 `ManualClock` 下沉到 `tests_support/clock.py`（仓内约定的共享测试辅助包，`tests_support/msg_fixtures.py` 已按同口径解决过同类问题），conftest 与用例统一从该处导入；`tests_support` 已在 `pyproject.toml` 的 packages 内，无需改打包 |

### 7.4 口径沉淀

- **跨仓克隆需在目标项目登记 job token 入向白名单**（本项目 / 组级均可），新增产品仓或新增跨仓克隆依赖时同步登记；口径已写入 bms《开发部署规划》「开发工作流与 CI」节，并在 `scripts/tools/ci/{bms,engkit}_setup.sh` 头注释指路。
- **本机 Windows 平台类型检查不足以代表 CI**：凡使用平台专有属性（`socket.SO_*`、`os.*` Windows 专有项）的代码，本地验证须加 `--pythonplatform Linux` 复核一次。
- **跨文件共享的测试辅助一律放 `tests_support`**：`services/msg/tests` 不是包，用例里写 `from tests.conftest import …` 只在单文件运行下偶然成立（`tests` 同名包解析顺序决定），全量收集会崩；同类问题已第二次出现（前有 `tests_support/msg_fixtures.py`），新增用例照此办理。
- **本地单文件通红 ≠ CI 全量绿**：本地守卫禁止全量 pytest / 无过滤 vitest（重命令与全量测试只在 CI），故「同名包解析」「并行下的渲染开销」这类只在全量 + 多 worker 才暴露的问题，只能由 CI 首跑发现——这也是 00-2「CI 首次真机触发」被列为遗留的原因。
