## 1. 概述 <a id="overview"></a>

- **目标**：补齐 msg 后端工程骨架，使 `import bms_msg.main`、应用装配、测试运行不再被 `ConfigError` 阻断；同时建立与平台一致的「业务域 × 数据源」迁移清单与版本目录，供后续表落地直接写脚本。
- **口径**：**不新建迁移机制**——清单注册、表集派生、URL 解析、方言适配全部复用 `bms_core/db/migration.py` 与基座 `alembic/env.py` 范式（与 mdm 产品仓同构）；本仓只提供工程根标记、env 引导、配置段与版本目录。
- **依据**：任务 [00-1](../00_工程骨架_01_后端迁移框架与装配可启动.md)；《[数据库设计总览](../../../../../../设计/数据库设计/01_数据库设计_总览.md)》§7；bms《数据库开发规范》「迁移与建表口径」；同构先例 mdm `backend/alembic.ini` / `alembic/env.py`。

| 项 | 现状（实测） | 差距 |

## 4. 契约设计 <a id="contract"></a>

### 4.1 `alembic.ini` 配置段 <a id="ini"></a>

```ini
[alembic]                     # 缺省清单（裸 alembic 命令用）：msg 首域 × 平台库
script_location = %(here)s/alembic
prepend_sys_path = .
path_separator = os
version_locations = %(here)s/alembic/versions/msg/platform
file_template = %%(rev)s_%%(slug)s

[alembic:msg:platform]        # 显式清单：业务域 msg × 数据源 platform
...（同上四项）
```

- 清单名 = 配置段名 = `{业务域}:{数据源}`（基座口径）；`[alembic]` 段仅作裸命令便利，**指向与缺省清单同一目录**，避免两段漂移；
- `version_locations` **必须在 ini 声明**（Alembic 在 `env.py` 之前读取）；
- URL 不在 ini 硬编码（由 env.py 经配置基座 / `BMS_MIGRATION_URL` 解析）。

### 4.2 `env.py` 执行口径 <a id="env"></a>

与 mdm 同构，逐条对齐基座语义：

| 语义 | 口径 |
| --- | --- |
| 清单选择 | `alembic -n alembic:{domain}:{datasource} upgrade head`；段名经 `resolve_series_from_section()` 解析 |
| 目标元数据 | 取 `bms_core/db/migration.py` 的清单表集（**唯一来源**）；本仓不重复登记表集 |
| 表归属 | 装载期调用 `services.table_registry.register()`（空清单幂等） |
| URL 优先级 | `-x url=` > `BMS_MIGRATION_URL` > 配置（清单对应库）；支持 `-x db_key=` 与达梦 `-x schema=` |
| 空清单 | 无脚本时打印「无脚本（跳过）」并正常退出，**不报错** |
| 方言 | 达梦同步引擎，其余异步引擎 + `run_sync` |

### 4.3 失败分支 <a id="fail"></a>

| 场景 | 语义 |
| --- | --- |
| `alembic.ini` 缺失 | 基座 `ConfigError`（fail-closed，不静默回落其他目录） |
| 配置段与版本目录不一致 | Alembic 在 `env.py` 之前报错（`version_locations` 路径不存在） |
| 清单名非法 / 未登记 | `ConfigError`（信息含合法清单清单） |
| 空清单执行 | 打印「无脚本（跳过）」，退出码 0 |

1. 落 `alembic.ini`（两段 + 日志段）与 `alembic/env.py` / `script.py.mako`（自 mdm 同构迁移，改 docstring 与清单口径）。

3. 跑 `import bms_msg.main` 与现有 msg 用例，确认装配恢复。
