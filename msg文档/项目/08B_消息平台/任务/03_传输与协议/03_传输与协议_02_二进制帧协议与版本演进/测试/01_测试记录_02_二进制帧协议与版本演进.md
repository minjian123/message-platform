## 2. 策略与范围 <a id="scope"></a>

| 层 | 验什么 | 不验什么（归口） |
| --- | --- | --- |
| 帧结构 | 15B 定宽头、大端、magic、版本、标志位、多帧拼接与不完整尾包 | 与 TLS / 网关的字节透传（07-1） |
| 上限 | header 64 KiB / payload 1 MiB 含端点可通过，超 1 字节即 `350006`，先判后读 | 磁盘与内存总量水位（02 域） |
| 版本 | 主版本不符 `350019`（layer=transport）、次版本任高任低接受 | 服务端连接级 `GOAWAY`（03-4） |
| 忽略口径 | 未知类型（有 / 无 `need_response` 两态）、未知 header 键、未知 flags 位 | 帧式订阅推送（03-5） |
| 错误帧 | 字段齐全、码 → layer → retryable 映射、帧内错误 200 / 不可解析 4xx | 客户端 SDK 的重试策略（8B_03） |
| 入口 | 同路径按 `Content-Type` 分派、JSON 形态零改动、鉴权仍回 JSON | 网关透传与限流（07-1 / 03-5） |
| 契约 | `x-msg-frame` 随导出进入快照、与常量同值、运行时 OpenAPI 不含 | 跨仓 SDK 生成（8B_03） |

## 4. 测试向量 <a id="vectors"></a>

入库 `backend/services/msg/tests/data/frames/*.json`：

| 组 | 向量 | 期望 | 断言要点 |
| --- | --- | --- | --- |
| 合法 | `legal_publish` | 解出 | 类型 1、头 4 键、payload `payload` |
| 合法 | `legal_ack_min` | 解出 | 类型 3、空 payload |
| 边界 | `boundary_max_header` | 解出 | header 恰 64 KiB（填充未知键）可解 |
| 边界 | `boundary_max_payload` | 解出 | payload 恰 1 MiB 可解 |
| 非法 | `invalid_short` / `invalid_magic` / `invalid_length_mismatch` | `350018` | 短包 / magic / 截断三态 |
| 超大 | `oversize_header` / `oversize_payload` | `350006` | 声明 64 KiB + 1 / 1 MiB + 1 |
| 版本 | `version_major_2` / `version_minor_9` | `350019` / 解出 | 主版本拒、次版本过 |
| 未知类型 | `unknown_type` | 解出 | 码层可解，闸门按 `need_response` 决定 |
| 未知字段 | `unknown_header_key` | 解出 | 未知键保留在头里、业务忽略 |

> 11 条用**冻结 hex** 回放（防「用实现验证实现」）；两条上限向量的 payload 达 1 MiB，hex 体积过大，
> 改存尺寸由用例构造后立即解码——验的是「含端点可通过」这条边界，不涉及字节布局。

## 8. 问题与偏差 <a id="issues"></a>

| # | 现象 | 归因 | 处置 |
| --- | --- | --- | --- |
| 1 | 首轮「缺 `request_id`」用例期望 `350018`，实得 `350001` | 信封字段不在请求模型里，必填集漏了它 | 必填集补 `request_id`（实施记录 §4） |
| 2 | consume 结果帧编码抛 `TypeError: can not serialize 'ConcurrentStableList'` | 平台集合类不是 `list` 子类 | `encode_header` 统一 `normalize_collections` |
| 3 | 边界向量头部填充一次补差后差 2 字节 | msgpack 字符串长度前缀档位从 1B 变 3B | 迭代逼近（`_pad_header`） |
| 4 | 真机冒烟首轮 `350010`（命名空间未启用） | 冒烟装置未装载服务目录 | 装置补 `services.module_registry` 与错误码声明（非实现问题） |
| 5 | 「超大帧 400」与注册表 413 不一致 | 设计初稿只写「4xx 里的 400」 | 以注册表为准取 413，设计 §6.5 已回写 |
