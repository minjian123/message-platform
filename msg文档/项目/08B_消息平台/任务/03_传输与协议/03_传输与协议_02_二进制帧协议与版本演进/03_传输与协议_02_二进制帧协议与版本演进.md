## 2. 任务内容 <a id="content"></a>

1. **帧结构**：`magic` + `ver` + `type` + `flags` + `header length` + `header` + `payload`；字节序、magic 取值、各字段宽度在详细设计定稿并写入协议契约。
2. **头体分离**：header 用 **MessagePack**，payload 为原始字节；broker 只解 header（路由 / 租户 / trace），**不解析 payload**（零拷贝前提）。
3. **帧类型**：`publish` / `ack` / `subscribe` / `error` / `heartbeat`；`admin` / `rpc` 作为预留类型；**未知帧类型必须忽略**，不得报错断连。
4. **版本规则**：主版本不兼容即断连并返回 error；次版本只增字段、不删不改；版本必须在连接元数据 / 日志中可见（排障第一问）。
5. **三条演进铁律**：只增可选字段、未知字段 / 未知帧类型忽略、版本可见；写进协议契约与评审清单。
6. **大小上限**：单帧与单条消息 **1 MiB**（已拍板），超限返回 `350006`；`header length` 与 `length` 字段做上限与溢出校验，不得先分配再判断。
7. **错误帧**：传输层错误（magic 不符 / 版本不支持 / 帧过大）→ 返回 error 后断开；协议层错误（缺必填头 / 类型不合法）→ 返回 error 帧但不断连；业务层错误（主题不存在 / 限流）→ error 帧 + `retryable`。
8. **编解码性能**：header 只解析一次并复用；payload 以切片 / 视图传递，避免整包复制；与 03-1 的 stream 读写对接，支持流式解码。
9. **测试向量与契约**：合法帧、边界帧、非法帧、未知类型、未知字段、超大帧各一组测试向量；帧结构登记进 `deploy/contracts/msg.json`。
10. **边界**：不做传输层与 stream 管理（03-1）、不做序列化语义与压缩（03-3）、不做连接心跳 / GOAWAY（03-4）、不做背压（03-5）。

## 3. 完成标准 <a id="accept"></a>

- 新增可选 header 字段后，旧客户端 / 旧服务端仍能正常收发（兼容用例）。
- 未知帧类型被忽略而非报错；未知 header 字段被忽略。
- 超大帧 / 超长 header 被拒绝并返回 `350006`，无内存放大。
- 主版本不兼容时明确断连；连接元数据能读到协商版本。
- 帧测试向量全绿；契约快照与实现一致。
- 变更模块行 + 分支覆盖率 100%，静态检查全绿。
