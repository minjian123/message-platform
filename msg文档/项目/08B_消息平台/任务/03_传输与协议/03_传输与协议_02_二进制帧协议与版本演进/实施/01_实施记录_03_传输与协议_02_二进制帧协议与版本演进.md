## 2. 实施概览 <a id="overview"></a>

```mermaid
flowchart LR
    A["Kiwi 2421 登记"] --> B["依赖与常量<br/>msgpack + 15B 帧头"]
    B --> C["protocol 包<br/>frame / codec / contract"]
    C --> D["错误码<br/>350006 / 350018 / 350019"]
    D --> E["响应装配 + 依赖闸门"]
    E --> F["路由装配<br/>Content-Type 协商 / connection 扩字段"]
    F --> G["JSON 上限 + 契约注入 + 重导"]
    G --> H["向量与用例"]
    H --> I["真机 h2c 冒烟 + 门禁 + 记录"]
```

结果：`/msg/{publish,consume,ack}` 在同一路径上按 `Content-Type: application/x-msg-frame` 提供帧形态，
JSON 形态与 `/api/v1` 一字未改；帧头 15B 自描述、未知类型可滑过、超出上限先判后读；帧协议契约以
`x-msg-frame` 进入公开契约快照，零漂移由 `ops.contract_snapshot check` 在提交环自动判。

## 3. 实施过程 <a id="process"></a>

1. **Kiwi 登记**：登记 1 条用例，平台回读编号 **2421**（分类「平台骨架」/ P2 / CONFIRMED / 标签「自动化」）。
2. **依赖**：`uv add "msgpack>=1.1" --package bms-msg`（实测装 1.2.4），`backend/uv.lock` 随之重同步。
3. **协议层**（`bms_msg/protocol/`）：
   - `frame.py`：`FRAME_MAGIC=b"MS"`、`PROTOCOL_VERSION="1.0"`、`FrameType`（分组区间）、`FrameFlags`（5 位）、
     `Frame` / `FrameBatch`、`encode_frame` / `decode_frames` / `decode_frame`；上限 `MAX_FRAME_HEADER_BYTES=64 KiB`、
     `MAX_FRAME_PAYLOAD_BYTES=1 MiB`；帧头用 `struct.Struct(">2sBBBHII")`（15B，大端）。
   - `codec.py`：`decode_header` / `encode_header`（msgpack，强制 `Map[str, Any]`）；
     平台集合类经 `bms_core.core.serialization.normalize_collections` 规整后再编码。
   - `contract.py`：`frame_contract()`（字段 / 类型 / 预留区间 / 标志位 / 上限 / 版本规则 / 错误帧字段）。
4. **错误码**：`errors.py` 增 `MsgPayloadTooLargeError`(350006/413)、`MsgFrameInvalidError`(350018/400)、
   `MsgVersionUnsupportedError`(350019/400)；`deploy/registry/msg.toml` 增 3 条 `[[errcodes]]`，
   `[[domains]].paths` 增 `protocol/**/*.py`。
5. **载荷上限**：`broker/delivery.py::decode_payload` 解码后判 1 MiB（普通发布与延迟发布共用，JSON 路径同判）。
6. **入口**：`api/data/messages.py` 的 `DataPlaneRoute` 增 `frame_type` / `request_model`，`mount_data_plane()`
   增 `frame_gate` 形参（`/api/v1` 传 None，行为不变）；`api/frame/gate.py` 提供 `build_frame_gate()`
   与 `FrameHandled` 异常处理器；`api/frame/routes.py` 只给根路径注入闸门。
7. **响应装配**：`api/frame/responses.py`：`result_frame()`（publish 字段进 header、consume 元数据进 header +
   消息体拼接进 payload、ack 单字段）、`error_frame()`、`classify()`（码 → layer → retryable）。
8. **版本可见**：`schemas/transport.py::ConnectionInfo` 增 `protocol_version`（帧请求非空）与
   `supported_protocol_version`（恒有值）；响应帧 header 带 `protocol_version`；日志 `event=msg_frame`。
9. **契约**：`ops/contract_snapshot.py` 在 `build_openapi()` 注入顶层 `x-msg-frame`；重导 `deploy/contracts/msg.json`
   （+203 行）。
10. **测试**：9 个新文件 / 91 条用例 + 13 个向量；真机 h2c 冒烟（最小装配 + 真 hypercorn）。

## 4. 问题与处置 <a id="issues"></a>

| 问题 | 现象 | 处置 |
| --- | --- | --- |
| 隐藏路由被基座判违规 | 原打算同路径再挂一条 `include_in_schema=False` 的帧路由 | 读 `service_contract.hidden_route_violations()` 源码确认「按路径集合判」，`/msg/publish` 入隐藏集即违规；改用**依赖闸门 + 异常短路**（详细设计 §6.1 三种做法对比） |
| 双可见路由覆盖公开契约 | `paths` 以路径为键、后挂者胜 | 同上排除；最终运行时 `app.openapi()` 的请求体 schema 与 03-1 完全一致（`test_both_mounts_share_the_same_spec` 仍绿） |
| 依赖里抛异常回响应 | FastAPI 依赖不能「返回响应」 | 自定义 `FrameHandled(response)` + `register_frame_handlers(app)`；装配期在 `configure_service` 与测试最小装配同时登记 |
| `request_id` 未被必填校验拦住 | 首轮用例收到 `350001` 而非 `350018` | 信封字段不属于请求模型，`build_frame_gate()` 的必填集补 `("request_id", *模型必填字段)` |
| `ConcurrentStableList` 无法 msgpack 编码 | consume 响应头含平台集合类，`TypeError: can not serialize` | `encode_header` 统一走基座 `normalize_collections`（一处规整，调用方不必各自 `dict()` / `list()`） |
| msgpack 无类型标注 | strict 模式下 `unpackb` / `packb` 为 Unknown | 模块级 `_UNPACK` / `_PACK` 类型化视图 + 定向 `pyright: ignore`（不引入自制 stub） |
| 边界向量头部填充不收敛 | 一次补差后 msgpack 字符串长度前缀从 1B 变 3B，长度差 2 | 改为按实测差值迭代逼近（`_pad_header`，最多 8 轮） |
| 真机冒烟首轮 `350010` | 服务目录未装载，命名空间 `msg` 不可用 | 冒烟脚本补 `import services.module_registry` 与错误码声明装载（与用例夹具同口径）；属**装置**问题，非实现问题 |
| 提交环跑了 50/50 选测却被全量守卫拒 | `messages.py` 是被几乎所有用例 import 的枢纽 → 选测 100% → engkit 把 50 个文件「目录折叠」成 `pytest -q services` → 全量守卫按目录文件数（> `dir_test_threshold`）立即拒绝 | **跨仓修 engkit**（用户拍板）：`collapse_to_dirs` 增 `threshold`，折叠目标若会被守卫判成全量则不折叠、保持显式文件分批；engkit 仓 `dbcac75`（含 3 条用例与文档口径） |
| 「忽略未知类型」在 HTTP 上没有天然形态 | 「滑过」对单个请求而言等于不回应 | 定为：未知类型且未置 `need_response` → `200 + 零字节体`（不回错误帧），客户端据「无响应帧」判定被忽略；已回写设计 §6.5 |

## 7. 偏差与遗留 <a id="deviances"></a>

| # | 事项 | 归口 |
| --- | --- | --- |
| 1 | 实现形态由「同路径第二条路由」改为「依赖闸门 + 异常短路」 | 已回写设计 §6.1；原因见 §4 前两条 |
| 2 | 新增用例文件而非扩 03-1 的 `test_frame_entry.py` / `test_data_messages.py` | 避免 `kiwi_id` 混标（2420 与 2421 不同任务）；设计 §8.2 已回写 |
| 3 | 超大帧的 HTTP 状态取注册表 413（设计原写 400） | 已回写设计 §6.5；与 JSON 路径同一码同一状态，避免「同码两状态」 |
| 4 | 帧路径消息体仍经 base64 往返一次（`PublishRequest.payload` 契约未改） | **03-3**：定 `content_type` 后 payload 直通二进制，可省这次编解码 |
| 5 | 帧式订阅推送未落地（`subscribe` 只登记编号，回 `350018` 并提示） | **03-5**：需新增 `message` 类帧（属只增类型，升次版本即可，不需主版本） |
| 6 | 心跳端点与连接级 `GOAWAY` 未落地（`heartbeat` 只登记编号） | **03-4** |
| 7 | 「客户端断开连接」只有契约约束，无服务端强制手段（ASGI 无连接标识） | **03-4**（`GOAWAY`）+ **8B_03**（客户端 SDK 落实义务） |
| 8 | 帧内 `trace_id` 只在 publish 上参与补位（consume / ack 模型无该字段） | 03-3 / 05 域追踪落地时统一 |
| 9 | 网关与监控按 HTTP 状态码统计时，帧路径呈「全 200」 | **06 域**：指标改看业务码与 `layer`（口径已写进设计 §6.5） |
