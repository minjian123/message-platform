## 4. 真机窗口实验（机制判据，非性能判据） <a id="window"></a>

| 项 | 内容 |
| --- | --- |
| 装置 | 真 hypercorn（空闲端口）+ `httpx.AsyncClient(http2=True, http1=False)`（h2c prior knowledge）；临时文件库引擎（多连接） |
| 数据 | 主题 1 分区，预置 120 条 × 8 KiB（> h2 缺省 64 KiB 连接窗口） |
| 步骤 | 开 `GET /msg/subscribe`（`max_messages=100`）→ 只读 `open` 事件 → **停止读取** 0.6s → 测 CPU → 恢复读取至 `close(deadline)` |
| 断言 | ① 停读期间进程 CPU 增量 < 0.2s（协程挂起而非忙等）；② 在途条数 ≤ 100（阈值约束仍生效）；③ 恢复后实收 ≥ 20 条；④ `msg_window_stall_total` ≥ 1 |
| 结论 | 窗口耗尽 ⇒ 应用侧停住、不烧 CPU、不越阈值 ⇒ 恢复读取后继续。绝对值不作容量结论（容量归平台级容量实测） |
| 隔离实验 | 慢连接（停读）与快连接（另一 h2 连接、另一主题）并行：快连接 3 条全部收完，未被牵连 |

> 同**一条**连接上的多条流仍受 h2 连接级窗口共享约束——这是协议语义，已写进契约 `x-msg-frame.stream.connection_window`，验收口径是「应用层不受影响」。
