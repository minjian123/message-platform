## 2. 背景与范围 <a id="scope"></a>

`POST /msg/subscribe` 是**帧形态**端点：成功时返回 `open` 帧 + `message` 帧 + EOF，失败时约定返回**单帧 error**（预检失败已如此实现）。但「单连接长驻流名额已满」这条路径直接调用 `connections.open_stream(...)`，异常（`350021`）逃出到框架层，客户端收到的是 **JSON 错误体**——帧客户端按帧解析会失败，且与同端点其它失败形态不一致。

本子任务只做：把该路径（以及同端点预检失败路径）统一收敛为 error 帧。

**不做**：SSE 形态（`GET /msg/subscribe`）保持 JSON 错误（其承载就是 JSON / SSE）；连接数上限 `350020`（连接守卫，属 03-4）；流内错误帧（04-3）。

## 3. 完成标准 <a id="accept"></a>

- 帧订阅在「长驻流名额已满」「预检失败」两种情况下都返回**单帧 error**（不再出现 JSON 错误体）；
- 超限错误的 `detail` 带 `max_streams` / `active_streams`，客户端可直接提示用量；
- 名额归还语义不变（失败不占名额，关闭后可再开）；
- 变更模块行 + 分支覆盖率 100%，静态全绿。

## 4. 边界 <a id="boundary"></a>

| 项 | 处理 |
| --- | --- |
| SSE 形态错误 | 保持 JSON（现状正确） |
| 帧流内错误（推送中途） | 归 04-3（`error` 帧 + EOF 已定） |
| 连接级上限 | 归 03-4（`350020`，守卫层统一 JSON / 帧由闸门处理） |
