## 1. 概述 <a id="overview"></a>

### 1.1 目标

帧形态订阅（`POST /msg/subscribe`）的所有**建立期**失败都返回单帧 error，与成功路径（`open` 帧起头）同一承载；帧客户端不需要辨认「这次回的是 JSON 还是帧」。

### 1.2 现状核对

| # | 现状 | 处置 |
| --- | --- | --- |
| 1 | `subscribe_frames` 的 `connections.open_stream(...)` 未包 `try`：超限抛 `MsgStreamLimitExceededError`（`350021`）→ 框架 JSON 错误体 | 改为捕获后返回单帧 error |
| 2 | 预检失败（`_preflight` 抛 `MsgError`）已返回单帧 error，但与新增分支各写一遍 | 两条路径收敛到 `_subscribe_error_frame(...)` |
| 3 | 请求帧解析失败 / ACL 拒绝两处也用 `_single_frame(error_frame(...))` 内联构造 | 一并改用同一辅助函数（行为不变，仅去重） |
| 4 | `350021` 已在 `_SUBSCRIBE_ERROR_CODES`（端点 `x-error-codes`）与 `_BUSINESS_CODES`（帧分类 business） | 无需改动 |

## 2. 决策（已逐项确认 2026-11-14） <a id="decisions"></a>

| # | 决策 | 结论 |
| --- | --- | --- |
| 1 | 错误帧字段 | `code` + `message` + `request_id` + `detail={max_streams, active_streams}`（用量可见） |
| 2 | 用例落点 | 新建 `tests/api/test_frame_subscribe_limit_0351.py`（避免 `test_frame_stream.py` 的模块级 `kiwi_id(2425)` 双重标注） |
| 3 | 错误路径写法 | 收敛到 `_subscribe_error_frame(...)` 辅助函数，四条建立期失败路径共用 |

## 3. 接口与行为 <a id="contract"></a>

### 3.1 失败帧形态

```text
type=error（+ response 位），header: { code, message, request_id?, detail?, retry_after_ms? }
```

| 场景 | code | detail |
| --- | --- | --- |
| 请求帧头非法 / 缺必填 | `10001` / `350018` | — |
| 主题 / 命名空间 / 租户不允许 | 现有码（如 `350001` / `350010` / `350027`） | — |
| 预检失败（组 / 位点 / 配额等） | 现有码 | 保持原样 |
| **单连接长驻流名额已满** | `350021` | `{max_streams, active_streams}` |

### 3.2 名额语义

- `open_stream` 抛错时**未占用**名额（既有实现先判后加），故失败后无需归还；
- `active_streams` 取 `connections.get(connection_key)` 的当前值；记录不存在（防御分支）时省略 `detail`。

## 4. 失败分支与边界 <a id="failures"></a>

| # | 场景 | 行为 |
| --- | --- | --- |
| 1 | 同一连接已开满 N 条流再订阅 | 单帧 error `350021` + detail；连接与已开流不受影响 |
| 2 | 失败后关闭一条流再订阅 | 成功（名额归还语义不变） |
| 3 | SSE 形态同名场景 | 仍返回 JSON 错误（承载不同，不改） |
| 4 | 请求帧本身无法解析 | 沿用既有单帧 error（无 `request_id`） |

| # | 用例 | 断言 |
