## 2. 实施过程 <a id="process"></a>

1. **辅助函数**：`api/frame/routes.py` 新增 `_subscribe_error_frame(*, code, message, request_id, detail, retry_after_ms)`，统一构造「只含一帧 error」的 `StreamingResponse`。
2. **四条建立期失败路径收敛**：请求帧解析失败 / ACL 拒绝 / **名额超限（新增）** / 预检失败，全部改走该辅助函数（行为不变，仅去重）。
3. **名额超限**：`connections.open_stream(...)` 外包 `try/except MsgStreamLimitExceededError`，`detail` 取 `{max_streams, active_streams}`（记录被并发清扫时省略）；失败不占名额（`open_stream` 先判后加，语义未改）。
4. **文档口径**：端点 docstring 原文「单连接长驻流超上限仍返回 350021（由连接守卫按帧形态给出）」有误（实际由 `open_stream` 抛出），改为「建立期失败一律单帧 error（含 350021）」。

## 3. 问题与处置 <a id="issues"></a>

| # | 问题 | 处置 |
| --- | --- | --- |
| 1 | 首轮用例把「帧头缺必填」的码写成 `10001`，实测为 `350018`（帧格式非法） | 用例与详细设计同步改为 `350018`；`10001` 是 JSON 形态的参数码，帧形态由帧解析层给 `350018` |
| 2 | `detail` 的「记录不存在」分支实际不可达（`open_stream` 抛错时记录必然存在） | 改为三元表达式 + `# pragma: no cover - 记录被并发清扫（防御分支）`，避免覆盖率门禁把不可达分支计入 |
