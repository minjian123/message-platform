## 2. 任务内容 <a id="content"></a>

1. **基座服务器替换（跨仓前置，归 bms 任务，已交付）**：bms `core/run.py` 已由 uvicorn 换 **hypercorn**（2026-11-04，Kiwi 2419）；保留 `[server]` 的 host / port、单进程口径、`ServiceRuntime` 的「信号先摘流、再优雅收尾」（SIGTERM / SIGINT → `start_drain()` → drain）、structlog 日志与健康探针；hypercorn 原生支持 h2c 与 TLS。全产品回归由 bms 任务覆盖（bms 9 服务 + mdm 已冒烟），**msg 的启动与传输入口在本任务验**。
2. **同端口路径（已拍板）**：hypercorn 单实例监听 8000；数据面帧入口 `/msg/*`；管理面仍 `/api/v1/msg/admin/*`；**现有 HTTP/1.1 数据面端点保留**，作为基准对照与回退路径。
3. **h2c 与 TLS**：开发 / PoC 用 **h2c prior knowledge**（客户端直接发 HTTP/2 preface）；不支持 `Upgrade: h2c`（RFC 允许不实现，客户端须 prior knowledge）；生产可切 TLS + ALPN `h2`；明文 h2c 仅限内网或网关到 broker 一跳。
4. **单连接多 stream**：同一条连接上 publish / subscribe / ack 并发，互不阻塞；支持 **server streaming** 订阅长驻流；客户端 `RST_STREAM` 取消后服务端释放对应资源；`MAX_CONCURRENT_STREAMS` 由 03-4 定值。
5. **生命周期**：hypercorn 的 lifespan 与基座应用工厂集成；连接建立 / 关闭 / 协商到的 HTTP 版本写入连接元数据，供排障第一问使用。
6. **基准对比**：同一 hypercorn 实例、同机同数据量、同并发与预热；
   - 基线：现有 HTTP/1.1 端点 + JSON；
   - 对比：h2c 帧入口 + MessagePack；
   - 判据：**吞吐 ≥ 基线 2 倍，且 p99 ≤ 50ms**（8B_01 go/no-go）；
   - 基准脚本落 msg `scripts/`（可复现、参数化），报告落任务测试记录。
7. **网关兼容**：对外仍经平台网关 `/api/msg/v1/msg/*`；网关到 msg 的 h2c 透传能力由 07-1 部署任务验证，PoC 阶段先直连 8000。
8. **契约**：新增 `/msg/*` 帧入口登记进 `deploy/contracts/msg.json`；帧入口复用 01 域投递服务，不改业务语义与错误码。
9. **边界**：不做帧编解码（03-2）、不做序列化语义（03-3）、不做心跳 / GOAWAY（03-4）、不做应用层背压（03-5）、不做 RPC（8B_03）、不做管理模块（8B_06）、不做零拷贝段读（02-1）。

## 3. 完成标准 <a id="accept"></a>

- h2c 同一条连接上多 stream 并发可用，publish / subscribe / ack 互不阻塞；`RST_STREAM` 取消后无资源泄漏。
- server streaming 可长驻推送，客户端断开后服务端连接与 stream 均被释放。
- 基准脚本与报告可复现；**性能不作本任务验收门禁**——2026-11-05 刹车评审把原「吞吐 ≥ 2 倍且 p99 ≤ 50ms」降为容量观测（归 8B_12），依据见[规划 §9.3](../../../../../规划/01_规划_消息平台.md#review-8b01)。
- 基座 hypercorn 启动器已交付且全产品回归通过（bms 任务），msg 服务可启动，`/health` / `/ready` 正常。
- 管理面与现有 HTTP/1.1 数据面端点行为不变（回归全绿）；连接元数据能看到协议版本。
- 8B_01 五项验证中的 1 / 2 / 4 / 5 项通过；变更模块行 + 分支覆盖率 100%，静态检查全绿。
