## 2. 落实的口径 <a id="decisions"></a>

| 口径 | 落实方式 |
| --- | --- |
| JSON 数据面首发 | 传输层只发 `application/json` 到 `/msg/*`；换帧的前置条件（服务端把 `exc.data` 传进错误帧）留在设计 §3.1 未动 |
| 批量 = 客户端并发窗口 | `publish_many` 用有界并发跑单发，逐条独立成败；`fail_fast` 只拦「未开始」的条目，已在途的等其自然结束 |
| 幂等 = 本地表 + 歧义不重试 | 幂等键写进 `headers["x-msg-idem-key"]`，本地 TTL 表按插入序淘汰；`350032` / 读超时默认只发一次，`retry_ambiguous` 打开后才重试 |
| 消费 = 拉取循环 + 成员保活 | `join` → 按 `partitions` 轮转 `poll` → `ack` / `nack` → 按服务端间隔心跳 → `close` 时 `leave`；`350014` 自动重新加入一次 |
| 错误两维 | `category` 复用基座 `ErrorCategory`；`action`（`retry` / `refresh` / `fatal`）由码表给出，不在别处二次判定 |
| 重试不留第二套公式 | `compute_backoff_ms` / `parse_retry_after` / `RetryPolicy` / `Clock` / `JitterSource` 全部复用基座件 |

## 3. 代码改动 <a id="code"></a>

| 模块 | 内容 |
| --- | --- |
| `messaging/config.py` | `MessagingConfig`：地址池 / 租户 / 鉴权注入 / 节点地址表 / 超时 / `RetryPolicy` / 改投与幂等参数；构造期校验（协议、主机、路径、租户、数值为正） |
| `messaging/codes.py` | 生产与消费两张码表：码 →（基座 `ErrorCategory`，本层 `ClientAction`，是否结果未知）；未登记码兜底 `server_bug` + 不重试 |
| `messaging/errors.py` | `MsgClientError`（码 / 类别 / 动作 / `data` / 结果未知 / 建议间隔）；`CLIENT_ERROR_CODE = 0` 表示客户端自造，不占产品码段 |
| `messaging/transport.py` | `MessagingTransport`：httpx JSON 传输，把异常翻成「未发出（可重试）」与「已发出无结果（未知）」两类；解析统一响应体，`Retry-After` 与 `data.retry_after_ms` 双来源 |
| `messaging/producer.py` | `MsgProducer`：`publish`（幂等查询 → 发送 → 改投 / 退避 / 抛出）、`publish_many`（并发窗口 + 快速失败）、请求体组装、本地幂等表（TTL + 容量淘汰） |
| `messaging/consumer.py` | `MsgConsumer`：`join` / `poll` / `ack` / `ack_many` / `nack` / `heartbeat` / `close`；分配轮转、成员失效重连、心跳循环、关闭时取消任务并吞掉离开失败 |
| `messaging/stats.py` | `ClientStats`：进程内计数器（名 + 标签串），快照不可变 |
| `bms文档/后端基类清单.md` | 消息平台协议客户端那一行补登 `msgclient/messaging/` 与对外值对象名 |

## 4. 偏差 <a id="deviation"></a>

| # | 设计原文 | 实施口径 | 原因 |
| --- | --- | --- | --- |
| 1 | §5.3 `ack(message_or_offset)` 两种入参 | 只接受消息对象（`ack` / `nack` 同） | 确认必须带分区号，裸位点无法确定分区；硬塞「取分配里第一个分区」会把错分区当默认值 |
| 2 | §6.3 `350007`（重投超限已进死信）由 SDK 记日志并跳过 | 抛 `fatal`，由调用方决定是否跳过该条 | 单条 `ack` 里「吞掉错误继续」等于静默丢消息；跳过属业务策略，不该固化在客户端 |
| 3 | §5.1 配置含 `payload` 类型前置校验 | 只校验命名空间 / 主题 / `acks` / 分区键长度 | `payload` 已声明 `bytes`，运行时 `isinstance` 恒真，静态检查判冗余 |
| 4 | §5.4 错误对象只有三分类字段 | 增 `category`（基座枚举）与 `action` 两维 | 并入基座后不宜再立第二套错误类别枚举；两维的分工见 `codes.py` 里 `350022` 的例子 |
| 5 | §5.3 返回类型名 `AckResult` | 改名 `CommitResult`（`bms` 仓 `cc6cf8f`） | 与 msg 侧 `schemas/message.py::AckResult` 同名，msg 仓基类门禁按类名索引父类会误判形态；确认与拒绝都返回「已提交位点」，改名后语义更贴 |
