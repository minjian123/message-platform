## 2. 任务内容 <a id="content"></a>

1. **生产端完整**：单发与批量、`acks` 语义（all / 1）、幂等键去重、可重试错误分类与退避、租户与主题元数据缓存。
2. **元数据刷新**：收到 `350033` 或发现 leader / 任期变化时，按 `metadata_version` / `leader` / `epoch` 改投，无需人工重启；刷新频率有上限，不因抖动打成循环。
3. **消费端最小集**：拉取（含 `maxWait` 长轮询）、位点提交与回退、按分区消费。
4. **错误分类**：服务端错误码归成「可重试 / 需刷新元数据 / 需人工」三类，调用方不必自己判码。
5. **配置与安全**：租户标识、服务地址、超时、批量大小可配；不内置凭据、不落盘密钥。
6. **接口口径文档**：方法名、参数、返回与错误分类先定成语言无关的文档，Python 为首个实现，其他语言照此实现。
7. **边界**：不做跨分区事务、不实现消费组再均衡与心跳、不做本地缓冲落盘、不替代 04 域 RPC 客户端、不改服务端协议。

## 3. 完成标准 <a id="accept"></a>

- 接入方不写 HTTP / 帧逻辑即可完成「发一条 → 消费到 → 提交位点 → 重启后从位点继续」；
- 切主后客户端按元数据改投成功，且不需要人工介入或重启；
- 可重试与不可重试错误分类可从返回值断言，重试有次数与退避上限；
- 接口口径文档能支撑其他语言照抄实现（方法、参数、错误分类齐全）；
- 新增包的行 + 分支覆盖率 100%，静态检查与文档校验通过；
- 服务端代码零改动（除必要的契约补充），不动既有发布 / 订阅路径。
