## 2. 背景与范围 <a id="scope"></a>

03-6-1 把 SDK 传输层换成帧形态，但成员三端点（加入 / 心跳 / 离开）仍走 JSON——`FrameType` 里没有 JOIN / LEAVE，帧闸门也只挂在数据面四端点，因此帧实现里留了一条「帧类型为空就委托 JSON」的分支，同一次会话混着两种承载。

本子任务把这条尾巴收掉：

1. 服务端登记 JOIN / LEAVE / 成员心跳三个帧类型，并把帧闸门挂到成员三端点（同一路径双形态，与数据面同哲学）；
2. 成员三端点补挂到根路径接入面（与 `mount_data_plane` 对称），根路径双形态、`/api/v1` 保持纯 JSON；
3. SDK 去掉委托分支，三个成员请求改走帧；
4. 契约快照与前端类型重导。

**不做**：连接心跳（类型 17）语义与实现不动；订阅长驻流；位点回退；服务端发布幂等；根路径数据面端点的审计排除缺口（只登记，另立台账）。

## 3. 完成标准 <a id="accept"></a>

- 成员三端点在根路径 `/msg/{join,heartbeat,leave}` 同时接受帧与 JSON 形态，业务语义仍只有一份实现；
- SDK 默认配置下加入 / 心跳 / 离开全部走帧，`FrameTransport` 不再持有 JSON 实现、不再有「委托」分支；
- 两通道参数化跑同一组用例，成员端点断言完全相同；
- 契约快照含新增三个帧类型与三条根路径，前端类型重导无差异残留；
- 变更模块行 + 分支覆盖率 100%，静态检查与文档校验通过。

## 4. 边界 <a id="boundary"></a>

| 项 | 处理 |
| --- | --- |
| 连接心跳（`/msg/connection/heartbeat`） | 语义与实现不动（连接保活、不触库、不解析租户）；与成员心跳是两件事，类型号必须分开 |
| `/api/v1/msg/*` | 保持纯 JSON（与数据面同口径）；帧形态只在根路径接入面 |
| 根路径数据面五条的审计缺口 | 只报不动，另立台账 |
| 客户端通道选择 | `channel=JSON` 仍可选；运行期切换不做 |
