## 2. 落实的口径 <a id="decisions"></a>

| 口径 | 落实方式 |
| --- | --- |
| 帧类型号 | 加入=7、离开=8、成员心跳=9；契约数据面预留段顺延 `10-15` |
| 成员心跳 | 走帧且独立取号（类型 9）；连接心跳（类型 17）语义与实现一字未动 |
| 兼容分支 | 删除「帧类型为空则委托 JSON」：`ApiRequest.frame_type` 收窄为必填，`FrameTransport` 不再持有 JSON 实现 |
| 挂载位置 | 新增 `mount_member_plane()`：根路径 `/msg/{join,heartbeat,leave}` 双形态，`/api/v1` 保持纯 JSON |
| 闸门复用 | `_handle_frame` 只收「租户 + 调用回调」，`build_frame_gate`（数据面）与 `build_member_frame_gate`（成员面）各自声明依赖集 |
| 审计排除 | `[audit_log].exclude_paths` 补三条根路径；根数据面五条只登记不动 |
| 验收口径 | 两通道参数化；Kiwi 登记一条（2514） |

## 4. 偏差 <a id="deviation"></a>

| # | 设计原文 | 实施口径 | 原因 |
| --- | --- | --- | --- |
| 1 | 设计称成员端点「规格内容」三条，未写明端点定义形式 | 把原有 `@router.post` 装饰器改为规格表驱动（端点函数变普通函数） | 若保留装饰器，路径 / 权限 / 错误码会在装饰器与规格表各写一份，正是 03-2 要消灭的双出处 |
| 2 | 设计未提 `_ensure_frame_type` 的提示条数 | 三条新提示各配一例用例 | 覆盖率要求下每条分支都要有用例，且跨端点错发确实是客户端最常见错误 |
| 3 | 设计 §4.2 写「根路径守卫继承数据面聚合路由」 | 同设计：成员面挂在 `/msg` 聚合路由上，继承连接守卫 | 与数据面同一入口口径，无需另建守卫 |
