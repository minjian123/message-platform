## 4. 关键断言摘录 <a id="asserts"></a>

| 完成标准 | 断言（节选） |
| --- | --- |
| 网络中断后连接在超时内被识别并释放 | `registry.evict(now=120, idle_timeout_ms=10_000)` → 条目转 stale 且名额归零；`now=141` → 条目删除；「未超阈值不动」单列一条断言 |
| 滚动重启（GOAWAY）不丢在途、客户端能重连 | `keep_alive_max_requests=2` 下三次请求后连接键**必然变化**（`len(set(keys)) >= 2`）且 `connection_registry.count() >= 2` |
| 重连带指数退避 + 抖动，不形成脉冲 | `next_backoff_ms(0..3)` = 200 / 400 / 1600 / 3200（rand=0.5）；`rand=0` 与 `rand≈1` 分别取下 / 上界且不相等 |
| 并发流 / 连接数超限返回明确错误 | 连接数满：JSON `429 + 350020`、帧 `200 + error(code=350020, layer=business, retryable=true, retry_after_ms=10)`；长驻流满：`429 + 350021` |
| 连接元数据可查 | `ConnectionInfo` 18 字段与登记表逐项对齐（`requests` 第二次请求为 2、`last_heartbeat_at` 首查为 null、心跳后非 null） |
| 心跳与业务互不阻塞 | 心跳端点只读 `app.state`（不取工作单元、不触库），用例在延迟发布进行中发心跳仍即时 200 |

## 6. 真机演练（最小客户端 + 真 hypercorn） <a id="drill"></a>

**装置**：最小装配（`build_frame_app` + 桩租户源 + 内存库）起真 hypercorn（h2c），建主题并 `join`，跑
`scripts/client/min_client.py --attempts 3 --duration 40 --heartbeat-interval 0.3`；运行中把
`app.state.draining` 置真（模拟基座 `start_drain()`；真信号路径由 bms 02_04 用例覆盖），保持摘流态观察重连。

**输出（原样）**：

```text
已加入消费组：分区=[0] 世代=1
连接参数：http=HTTP/2 心跳=0.3s 超时=30000ms 空闲=30000ms 连接上限=1024 单连接流上限=100
第 1 轮：原因=drain 消息=0 心跳错误=0 退避=197ms
第 2 轮：原因=drain 消息=0 心跳错误=0 退避=347ms
—— 汇总 ——
轮次=3 原因=drain / drain / drain
退避序列=[197, 347] 最小=197ms 最大=347ms （抖动来自 ±20%，相邻轮不相等即未形成脉冲）
```

**结论**：

1. `draining` 经心跳（帧 17）在**第一轮结束前**就被客户端看到，未等到下一次长驻流事件——drain 协商通道有效；
2. 每轮都按 `next_backoff_ms` 重连，退避 197ms → 347ms 呈指数增长且两次不相等（抖动生效），**未形成同步脉冲**；
3. 服务端日志侧对应 `msg_connection_drain_started` 一次、`msg_connection_drain_signal_sent` 一次（每连接只记一次，未刷屏）。

**演练暴露并已修的缺陷**（详见实施记录 §4 第 5、6 条）：轮次到期判断挂在 SSE 事件循环里（空闲期只有注释行，条件永不求值，首版一轮跑 45s）；只发连接心跳导致 30s 后成员会话超时（`350014`）。

## 7. 偏差与遗留 <a id="deviances"></a>

| # | 项 | 说明 / 归口 |
| --- | --- | --- |
| 1 | 全栈演练（platform + msg + 真 SIGTERM）未做 | 本次以「最小装配 + 真 hypercorn + 置 draining」替代；真信号摘流与全栈联调归 部署域（已剥离，待重建） / 平台级容量实测 |
| 2 | 半开连接的「TCP 层关闭」不由应用执行 | 应用只回收登记与名额；TCP 由 hypercorn 空闲回收（不发 GOAWAY），已由本记录第 2 条真机用例证明「复用旧连接必报错」 |
| 3 | 短请求并发不受应用层约束 | 由协议层 `h2_max_concurrent_streams`（默认 100）约束，契约已写明两层分工 |
| 4 | 连接数 / 长驻流上限为经验值（1024 / 100） | 容量定参与真实连接规模归平台级容量实测 |
