## 1. 域说明 <a id="intro"></a>

本域对应需求 [03 传输与协议](../../需求/03_需求_传输与协议.md)，承载客户端与 broker 之间的「用什么协议、怎么连、说多快」：HTTP/2 传输、二进制帧与版本演进、序列化、连接管理、背压与流控。

本域即 **8B_01 传输与协议 PoC 本体**，是 8B 阶段的 **go/no-go 刹车点**：PoC 不达标即退回「只换远程调用」的局部方案（RocketMQ 已下线，不再作为回退项）（规划 §7 / §9）。任务按「一个可独立验收的交付单元」拆分，与需求 03-1~03-5 **一一对应**。

**前置与跨仓**：HTTP/2 由基座统一改用 **hypercorn** 承载（2026-11-04 拍板），基座 `core/run.py` 的服务器替换、信号摘流与全产品回归**归 bms 仓另立任务**；本域任务以「基座 hypercorn 启动器已交付」为前置契约，不在 msg 仓重复实现。

文档格式依 bms《[任务文档规范](../../../../../bms文档/规范/任务文档规范.md)》。

### 2.1 8B_01 五项验证 <a id="poc"></a>

| # | 验证 | 判据 | 主责任务 |
| --- | --- | --- | --- |
| 1 | 单连接多 stream | 同一条 h2c 连接上 publish / subscribe / ack 并发互不阻塞 | 03-1 |
| 2 | 二进制帧端到端 | 帧 publish → 存储 → subscribe 拉取 → ack 全链路通 | 03-2 / 03-1 |
| 3 | 重试与死信 | 未 ack 超时重投；超过重投上限进死信 | 03-5 / 01-2（已交付语义） |
| 4 | 订阅长驻流 | server streaming 可长驻推送，客户端断开可释放 | 03-1 |
| 5 | 基准对比 | 同机同数据量：吞吐 ≥ HTTP/1.1+JSON 的 2 倍且 p99 ≤ 50ms | 03-1 |

> **不达标处置**：任一项不通过即触发 8B_01 刹车评审，结论回写阶段计划 §5 门禁 2；不得带病进入 02 域实施。

## 3. 依赖与风险 <a id="dep"></a>

| 项 | 说明 |
| --- | --- |
| 上游依赖 | **bms 基座 hypercorn 启动器**（跨仓，另立 bms 任务：`core/run.py` 换服务器 + 信号先摘流 + 全产品回归）；01 域已交付的数据面端点与投递语义（publish / consume / ack / 延迟 / 重放） |
| 下游影响 | 02 域读取原语与零拷贝、8B_03 远程调用、8B_06 管理模块、平台级生产部署架构迁移；帧契约与错误码一旦上线即长期兼容 |
| 关键风险 | ① hypercorn 在基准测试中普遍低于 uvicorn httptools，吞吐判据可能吃紧——先用基准脚本实测，不达标按刹车点处置；② 基座换服务器影响 biz / mdm / 其它服务，必须由 bms 任务做全产品回归；③ h2c 明文无加密，仅限内网 / 网关到 broker 一跳；④ 帧与版本规则一旦发布不可破坏，需测试向量与契约快照兜底；⑤ 基准环境噪声会让「2 倍」结论失真，须固定机器、数据量、并发与预热 |
