## 2. 任务内容 <a id="content"></a>

1. **镜像构建**：新增 `deploy/Dockerfile`，构建上下文为工作区根；多阶段构建、`uv` 锁文件 `--frozen` 安装，镜像内只含后端工程与 `deploy/` 声明目录；非目标产品源码不入镜像；不写入任何凭据。
2. **容器编排**：新增 `deploy/compose/msg.yml`，服务名 `msg`、容器内 8000；镜像引用 `${MSG_REGISTRY_IMAGE_PREFIX}:${MSG_TAG}` 并以 `:?` 强制必填（无 `latest` 兜底）；经 `PLATFORM_NETWORK` 外部网络接入平台；`env_file: .env` 注入凭据；不发布公网端口，经平台网关访问。
3. **持久化卷**：消息日志挂独立卷（容器内 `/var/lib/msg/data`），位点文件挂独立卷（`/var/lib/msg/offsets`），元数据库随平台库；卷与系统盘分离，目录权限仅服务账号可读写；容器重建不得落在可写层。
4. **启动与停机**：配置 `stop_grace_period`，配合 03-4 的 GOAWAY / drain；健康检查指向 `/healthz`；重启策略与平台其他服务同构；启动前完成建表 / 恢复流程（由 07-1-2 校验）。
5. **本机规格**：更新 `deploy/local_stack.toml` 与 `deploy/compose/README.md`，写清构建、启动、停止、日志与卷检查命令；不写死服务器地址、内网 IP、端口或账号。
6. **边界**：不改基座网关 / 认证 / Redis / MySQL / 可观测后端；不做多实例编排、分区迁移与容器内 TLS 终止（按架构 08 §11 待定项另行定稿）；不把 `.env` 或真实凭据提交入库。
7. **测试**：`docker compose config` 可解析；缺 `MSG_TAG` 时启动被拒绝；端口、网络、卷挂载断言；构建后容器可启动并通过 `/healthz`；重启后消息日志与位点文件仍在；停机时在途请求完成或明确失败。

## 3. 完成标准 <a id="accept"></a>

- `deploy/Dockerfile` 可从工作区根稳定构建，镜像不含凭据与前端 / 其他产品源码；
- `deploy/compose/msg.yml` 可解析并启动，容器加入平台网络，容器内 8000 可访问，镜像 tag 必填且无 latest 兜底；
- 消息日志与位点文件挂载到独立持久卷，容器重启后数据仍在；元数据库随平台库；
- 优雅停机配置生效，在途连接按 GOAWAY / drain 处理；
- 部署说明可复现，未出现服务器地址、内网 IP、端口或账号；
- 变更模块行 + 分支覆盖率按项目口径达标，静态与文档校验全绿。
