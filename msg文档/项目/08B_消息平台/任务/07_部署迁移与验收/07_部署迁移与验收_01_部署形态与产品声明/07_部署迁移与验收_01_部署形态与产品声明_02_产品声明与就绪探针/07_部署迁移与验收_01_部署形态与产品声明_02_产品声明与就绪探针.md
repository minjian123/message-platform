## 2. 任务内容 <a id="content"></a>

1. **产品声明校验**：以 `deploy/registry/msg.toml` 为唯一声明源，校验七段记录齐备且唯一性通过；产品档案、服务行、产品路由、数据源、能力、种子、错误码与业务域均可被平台装载；服务行 `module_key` / `service_key` / `table_prefix` / `business_code` / `errcode_segment` / `event_domain` 与实现一致。
2. **路由口径**：对外命名空间 `/api/msg/v1/msg/...` 由平台网关按服务目录生成；内部前缀 `/api/v1/msg/...` 由服务自身挂载；两条口径在声明、契约快照与实际请求中一致，不出现模块自拼产品前缀或自建 HTTP。
3. **探针接线**：`/healthz` 反映进程存活与服务身份；`/readyz` 聚合就绪检查——元数据可达（必需）、日志目录可写（必需）、存储水位未超拒绝阈值（必需）、恢复台账无阻断（按 02-6 口径）；检查项来自 msg 自持注册表，不新增第二套探针端点。
4. **就绪语义**：只有「能写」才返回 200；磁盘满、日志目录不可写、元数据不可达或水位拒绝时返回 503，并输出失败检查项；`/readyz` 每次探测不污染拒绝指标；容器 `HEALTHCHECK` 与网关摘流使用同一判据。
5. **重启验证**：在容器重启 / 重建后验证元数据库、位点文件、消息日志三样仍在；恢复流程完成后 `/readyz` 转 200；未完成恢复时保持 503，不提前接流量。
6. **优雅关闭**：SIGTERM 后先 GOAWAY 停止接新流、等待在途完成，再关闭存储；关闭顺序保证「先日志后位点」（沿用 02-3 的关闭偏序），不产生位点越过日志尾。
7. **边界**：不改基座探针实现与网关路由生成器；不实现多实例健康聚合与分区迁移（归 8B_05）；容器内 TLS 终止按架构 08 §11 待定项处理。
8. **测试**：产品装载正反用例（缺段 / 重名 / 非法服务行拒绝启动）；路由命名空间断言；`/healthz` 与 `/readyz` 正反用例（可写 / 磁盘满 / 元数据不可达 / 恢复未完成）；重启后三样数据保留；SIGTERM drain 与关闭偏序断言。

## 3. 完成标准 <a id="accept"></a>

- 平台可识别 msg 产品、服务行与产品路由，网关可按 `/api/msg/v1/msg/...` 路由到 `msg:8000`；
- 内部 `/api/v1/msg/...` 与对外命名空间一致，契约快照零漂移；
- `/healthz` 与 `/readyz` 行为符合基座探针口径，就绪探针在不可写时返回 503 并给出失败项；
- 容器重启后元数据库、位点文件、消息日志均保留，恢复完成前不接流量；
- SIGTERM 下按 GOAWAY / drain 优雅关闭，关闭偏序正确；
- 变更模块行 + 分支覆盖率达标，静态与文档校验全绿。
