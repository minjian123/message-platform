# 六类故障演练记录（汇总）

> 任务 07-6-1。明细见同目录六份 `<场景>.json` + `<场景>.md`（JSON 与 Markdown 同源，由
> `python -m ops.drill run <场景>` 产出）。执行形态：本机真装配隔离实例（真路由 / 真文件存储 /
> 真水位 / 真探针 / 真指标），三处替代逐条写在每份记录的 `deviations[]`。

## 1. 结论总览

| # | 场景 | 注入 | 结论 | 退出码 | 恢复耗时 | 已确认消息丢失 | 明细 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | 进程崩溃 | SIGKILL / SIGTERM 各一轮，同数据根重启 | 通过 | 0 | 14 024 ms | 否 | [process_crash.md](process_crash.md) |
| 2 | 磁盘满 | 受控填充 + 成对收紧水位 | 通过 | 0 | 4 436 ms | 否 | [disk_full.md](disk_full.md) |
| 3 | 慢盘 | 后台线程持续写同卷 + fsync | 降级通过 | 2 | 1 648 ms | 否 | [slow_disk.md](slow_disk.md) |
| 4 | 网络分区 | 客户端侧代理：pass / drop / loss / delay | 通过 | 0 | 5 308 ms | 否 | [network_partition.md](network_partition.md) |
| 5 | 消费者卡死 | 只拉不确认填满 inflight | 通过 | 0 | 0 ms | 否 | [stuck_consumer.md](stuck_consumer.md) |
| 6 | 毒消息 | 非法载荷 + 重投超限 + 主动 nack | 降级通过 | 2 | 221 632 ms | 否 | [poison_message.md](poison_message.md) |

四类通过、两类降级通过，**无失败**；六份记录的 `data_loss` 均为 `false`（没有已确认消息丢失）。

## 2. 通过项的关键证据

| 场景 | 硬证据 |
| --- | --- |
| 进程崩溃 | 两档杀进程后同数据根重启：已确认 4 条不回退（恢复后只投 offset 4/5）、未确认 2 条重投、新消息 offset 连续为 6 |
| 磁盘满 | 注入期发布返回 **HTTP 507 + 业务码 350022**、`/readyz` 转 **503**、`/healthz` 仍 200（进程不退出）、清理填充后发布 200 且 `/readyz` 回 200 |
| 网络分区 | 代理 `drop` 档发布抛连接错误、`delay` 档仍可发、恢复 `pass` 后发布成功；已确认消息不重投 |
| 消费者卡死 | 在途填满 100 条后 `consume` 返回 `paused=true` 且 `inflight_messages=100`（不越上限）；逐条确认后拉取为空 |

## 3. 降级项的原因与处置

| 场景 | 降级判据 | 原因 | 处置 |
| --- | --- | --- | --- |
| 慢盘 | `latency_visible` | 本机 SSD 上受控写入不足以抬升 `msg_fsync_duration_ms` / 发布延迟（两项基线均为 0，无样本可比） | 判据按「方向性」保留，绝对阈值归部署阶段（真盘延迟注入归 07-6 部署侧） |
| 毒消息 | `dead_letter_created` / `nack_to_dlq` / `not_blocking_followers` | ① 管理面死信列表在有死信行时返回 500（`MissingGreenlet`：ACL 释放后读 ORM 属性）；② 毒消息重投到上限 5 次后未在预算内终结，后续消息按分区停等被阻塞 | 已登记为遗留归 06-4（见 §4），修好后复跑本场景即可转「通过」 |

毒消息的**重投有界**已取证：`delivery_count` 到 5 即不再增长（`MAX_DELIVERY_ATTEMPTS`），没有无限重投。

## 5. 复跑方式

```bash
cd backend
export MSG_DRILL_WORK_DIR=../tmp/drill MSG_DRILL_REPORT_DIR=../tmp/drill/reports
python -m ops.drill plan
python -m ops.drill run process_crash --confirm process_crash
python -m ops.drill run disk_full --confirm disk_full
python -m ops.drill run slow_disk --confirm slow_disk
python -m ops.drill run network_partition --confirm network_partition
python -m ops.drill run stuck_consumer --confirm stuck_consumer
python -m ops.drill run poison_message --confirm poison_message      # 需等满重投预算
```

复跑会覆盖同目录的同名记录；对比前后结论即可看回归。
