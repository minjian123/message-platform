## 3. 任务内容 <a id="content"></a>

1. **六类必做场景**：进程崩溃、磁盘满、慢盘、网络分区、消费者卡死、毒消息；每类给出注入方式、观察指标、恢复时间与数据完整性判据。
2. **脚本化与可重复**：每类场景一个可重复执行的注入 / 清理脚本，参数化目标环境与时长；演练前备份、演练后清理，默认拒绝在生产环境执行，需显式环境开关与确认。
3. **观测口径**：演练期间采集 `/readyz`、指标（吞吐 / 延迟 / 积压 / 死信 / 磁盘 / 连接 / 错误率）、日志与追踪；每类场景记录「注入前 / 注入中 / 恢复后」三段数据与原始样本。
4. **恢复判据**：崩溃后不丢已确认消息；磁盘满可拒绝写并在清理后恢复；慢盘不产生假确认；网络分区恢复后连接可重连、无重复消费；消费者卡死可观测积压并恢复；毒消息进入死信、不无限重试。
5. **问题回写**：演练发现的问题回写架构设计或详细设计；不能在本任务闭环的登记遗留并明确承接阶段与归口，不得只写「已知问题」。
6. **发版前复跑**：演练脚本纳入发版前检查清单，每次发版前可按同一脚本复跑；脚本与记录随任务 `测试/` 留痕。
7. **边界**：不做多实例选主 / 分区迁移 / 脑裂演练（归 8B_05 / 8B_09）；不在生产环境注入故障；不修改业务代码规避故障。
8. **测试**：六类脚本 dry-run 与 cleanup；每类场景至少一次完整注入与恢复；数据完整性断言；脚本重复执行结果一致；演练记录字段完整。

## 4. 完成标准 <a id="accept"></a>

- 六类场景（进程崩溃 / 磁盘满 / 慢盘 / 网络分区 / 消费者卡死 / 毒消息）均有可重复执行的注入脚本与演练记录；
- 每类记录含注入方式、观察指标、恢复时间、是否丢数据与原始数据；
- 崩溃后不丢已确认消息；磁盘满可恢复；毒消息进入死信、不无限重试；
- 演练脚本纳入发版前检查清单，可重复执行；
- 发现问题已回写设计或登记遗留，有归口；
- 变更模块行 + 分支覆盖率达标，静态与文档校验全绿。
