## 2. 任务内容 <a id="content"></a>

1. **判据表**：为六类场景逐项定义「通过 / 不通过」判据——崩溃后已确认消息不丢、位点不越尾；磁盘满拒绝写且清理后恢复；慢盘无假确认；网络分区恢复后连接重连、无重复消费；消费者卡死积压可见且可恢复；毒消息进死信、不无限重试、不阻塞后续消息。
2. **观测与取证**：每类场景记录注入前 / 注入中 / 恢复后三段指标（吞吐、P50 / P95 / P99 延迟、积压、死信、磁盘、连接、错误率）、`/readyz` 状态、关键日志与追踪；保留原始数据与命令，保证可复现。
3. **恢复时间与完整性**：记录恢复开始 / 结束、RTO、是否丢数据、重复消费次数；数据完整性以「已确认消息可读、消费效果一次、位点与日志对齐」判定，不以「服务起来了」代替。
4. **演练执行**：在隔离环境按六类场景逐项执行，每项形成一条演练记录；失败场景不跳过，记录失败现象、根因与处置。
5. **问题回写**：演练发现的问题回写架构设计或详细设计；不能在本任务闭环的登记遗留，明确承接阶段与归口；修复后复跑同一场景验证。
6. **发版前复跑**：将六类场景纳入发版前检查清单，每次发版前按同一脚本复跑；记录版本、配置、环境与原始数据，保证可比较。
7. **验收证据**：形成「场景 × 判据 × 证据」对照表，作为 07-7 阶段验收「可靠性 / 高可用」域的输入；未通过项不得默认通过。
8. **测试**：判据表完整性检查；演练记录字段完整性；失败场景复跑闭环；证据链接可达。

## 3. 完成标准 <a id="accept"></a>

- 六类场景均有明确判据与演练记录，记录含注入方式、观察指标、恢复时间、是否丢数据与原始数据；
- 崩溃后不丢已确认消息；磁盘满可恢复；慢盘无假确认；网络分区可重连；消费者卡死可恢复；毒消息进死信；
- 失败场景有根因、处置与复跑结论，不跳过、不默认通过；
- 发现问题已回写设计或登记遗留，有承接阶段与归口；
- 六类场景纳入发版前检查清单，可按同一脚本复跑；
- 形成「场景 × 判据 × 证据」对照表，供阶段验收引用；
- 变更模块行 + 分支覆盖率按项目口径达标，静态与文档校验全绿。
