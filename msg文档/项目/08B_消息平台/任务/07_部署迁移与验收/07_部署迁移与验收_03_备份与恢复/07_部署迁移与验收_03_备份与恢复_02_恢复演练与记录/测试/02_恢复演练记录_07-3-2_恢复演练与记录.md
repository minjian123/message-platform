## 3. 校验结论 <a id="checks"></a>

| 校验项 | 结论 |
| --- | --- |
| 清单与快照 | schema 1；`recovery_order` 四项一致；`offsets.files` 逐文件 sha256 可复算；`files` 与 `offsets.files` 交叉一致 |
| 元数据库 | 期望 9 张 `msg_*` 表全部在 dump 中（`msg_dead_letter` / `msg_partition` / `msg_quota` / `msg_replay_task` / `msg_tenant_lifecycle` / `msg_topic` / `msg_topic_acl` / `msg_topic_acl_scope` / `msg_topic_cleanup`）；历史多余表不判失败 |
| 位点恢复 | 1 个位点文件；恢复后 size + sha256 与清单一致；身份（group / topic / partition）与路径相符 |
| 段确认 | 清单 1 个分区，实际段齐全；无保留期裁剪、无段间空洞、无段尾缺失 |
| 对齐 | 每分区显式夹取一次；无越尾位点；LEO 与清单一致（5）；位点在可用区间内 |
| 已确认消息 | 从已提交位点向前抽样 4 条，全部可读、offset 递增且严格小于已提交位点 |
| 延迟消息 | 重建 1 条有效记录；`deliver_at` 与源扫描逐条一致（不提前）；无截断 / 隔离 / 未知 `kind`；未执行转投 |
| 配置 | 备份时与当前配置摘要一致，无漂移 |
| 环境清理 | 工作根已删除；源数据根零改动；备份根只多了「演练前自动备份」目录（随工作根一并清理） |

## 4. 失败分支演练（自动化用例） <a id="failure-injection"></a>

| 分支 | 注入方式 | 预期 | 结果 |
| --- | --- | --- | --- |
| 位点快照损坏 | 改快照位点文件末字节 | 清单 / 快照步失败，工作根未创建，源目录零改动 | 通过 |
| 清单缺失 / 版本过高 / 路径穿越 | 删清单、改 `schema_version`、改 `files[].path` | 指名拒绝，不进入恢复 | 通过 |
| 指针损坏 | 删 / 写坏 `current.json` | 告警并回退到最近完整快照 | 通过 |
| 日志段间空洞 / 段尾缺失 / 分区缺失 | 删中间段 / 删末段 / 删分区目录 | 结论「降级通过」（退出 2），缺口区间登记 | 通过 |
| 位点越过日志尾 | 快照位点改大 | 夹取到 LEO 并立即落盘，降级通过 | 通过 |
| 位点低于可用起点 | 段基址前移 | 降级并登记原因 | 通过 |
| 延迟段截断 | 截掉 `.delay` 末 3 字节 | `truncated_bytes > 0`，降级通过 | 通过 |
| 恢复中途 IO 失败 | 注入写失败 / 复制失败 | 失败步留痕、后续步骤 `skipped`、退出 1 | 通过 |
| live 命令失败 / 超时 | runner 返回非 0 / 超时 | 退出 1，脱敏命令与退出码入记录 | 通过 |
| 就绪超时 | 就绪探针持续 503 | 退出 1，`ready` 步失败 | 通过 |
| 降级但要求启动 | 段尾缺失 + live 无 `--allow-degraded` | 停在启动前，退出 2 | 通过 |
| 生产环境 | `target_env = prod` | 一律拒绝，零命令执行 | 通过 |
