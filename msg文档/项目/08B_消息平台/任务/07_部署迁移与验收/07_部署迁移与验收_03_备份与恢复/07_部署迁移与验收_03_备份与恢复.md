## 3. 任务内容 <a id="content"></a>

1. **元数据库**：随平台库备份（首期与平台共库），不另建第二套数据库备份；备份清单须覆盖 `msg_*` 表并能在恢复时校验表集合完整。
2. **位点文件**：按日定期快照，快照包含组目录、`topic_id-partition.offset` 与校验信息；快照与 `data/` 平级，独立于消息日志卷；保留期可配置，过期快照按策略清理。
3. **消息日志**：不做全量备份（成本高、价值低于元数据），依靠副本与保留期；备份清单登记分区段范围与 LEO 摘要，便于恢复后对齐，不复制完整日志。
4. **恢复顺序**：严格按「元数据库 → 位点文件 → 消息日志（缺失则从最近段开始）→ 校验对齐」执行；恢复后位点不得越过日志尾，已确认消息不得丢。
5. **演练留痕**：备份与恢复必须有演练记录（环境、版本、备份时间、步骤、RTO / RPO、数据完整性结论、问题与处置），不能只写方案；重要事件按业务侧 outbox / 归档兜底，不依赖消息日志备份。
6. **边界**：不备份容器可写层；不把生产数据带入演练；不在 msg 仓重复实现平台数据库备份；恢复不自动执行数据库降级（沿用部署发布规范）。
7. **测试**：备份脚本 dry-run、清单生成、保留期清理、失败不破坏上一份备份；恢复顺序与对齐断言；位点越尾 / 日志缺口 / 快照缺失等失败分支；一次完整恢复演练记录。

## 4. 完成标准 <a id="accept"></a>

- 元数据库随平台库备份、位点文件按日快照、消息日志不做全量备份的口径落地为脚本与清单；
- 备份可定时执行，失败有告警或非零退出，且不会破坏上一份可用备份；
- 可按「元数据库 → 位点文件 → 消息日志 → 校验对齐」完成一次恢复演练；
- 恢复后位点与日志对齐，不丢已确认消息，未到期延迟消息按剩余时间恢复；
- 演练结论有记录，问题与遗留有归口；
- 变更模块行 + 分支覆盖率达标，静态与文档校验全绿。
