## 2. 任务内容 <a id="content"></a>

1. **四层配置**：基线 `backend/config.toml`、环境覆盖 `config.dev.toml` / `config.test.toml` / `config.prod.toml`、环境变量（`BMS_` 前缀）四层齐备；优先级固定为「环境变量 > 环境覆盖 > 基线」，并由启动期断言验证，不靠文档约定。
2. **敏感项只走环境变量**：数据库连接串与密码、Redis URL、OTLP 端点、服务令牌密钥、用户令牌密钥、TLS 证书路径六类只从环境变量读取；配置文件中只保留占位与结构，不出现真实凭据、密钥、证书内容。
3. **凭据文件纪律**：`deploy/.env` 必须 gitignore，仓库只保留 `.env.example`；示例文件中的键位完整、值全部为空或占位；`git ls-files` 不得出现 `.env`；模板不出现服务器地址、内网 IP、端口与账号。
4. **启动校验**：缺关键密钥时按「可装配、使用时 fail-closed」口径处理（沿用基座服务令牌 / 安全密钥行为）；生产配置不得出现缺省密钥、`debug=true`、`docs` 开启或 SQLite 兜底；缺配置时给出可定位的错误，不静默降级。
5. **唯一来源**：数据库连接串与 SQLite 路径只经 `Settings` / `[database]` 读取，代码、脚本、CI 不写死连接串或库路径；切换环境只改配置与环境变量。新增配置项须同时补基线、各环境覆盖与 `.env.example` 三处。
6. **凭据扫描**：新增仓库级检查（脚本或预检步骤），扫描 `deploy/`、`backend/`、`frontend/` 与文档中的明显凭据形态（私钥头、`password=` 非空、真实 token）；命中即失败并给出文件与行号；公开文档不得出现服务器 / 内网 IP / 端口 / 账号。
7. **边界**：不改基座 `Settings` 契约与配置源实现；不把生产密钥写入 CI 变量以外的位置；不引入第二套配置框架；容器内 TLS 终止是否启用按架构 08 §11 待定项。
8. **测试**：四层优先级断言（环境变量覆盖环境文件、环境文件覆盖基线）；敏感项从环境变量读取的断言；缺密钥 fail-closed 用例；`.env` 未被跟踪断言；凭据扫描正反用例；生产配置无 debug / docs / SQLite 兜底断言。

## 3. 完成标准 <a id="accept"></a>

- 四层配置齐备，优先级按「环境变量 > 环境覆盖 > 基线」生效，并有自动化断言；
- 六类敏感项只从环境变量读取，配置文件、镜像与仓库中均无真实凭据；
- `.env` 已被 gitignore，仓库只保留 `.env.example`，且示例不含服务器地址、内网 IP、端口、账号；
- 缺关键密钥时按 fail-closed 处理，生产配置无 debug / docs / SQLite 兜底；
- 凭据扫描与公开文档检查通过，未出现红线违规；
- 变更模块行 + 分支覆盖率达标，静态与文档校验全绿。
