## 3. 实施过程与关键取舍 <a id="process"></a>

```mermaid
flowchart LR
    A["核对基座加载链<br/>六源 → 对外四层"] --> B["抽纯函数<br/>启动期 + 离线双落点"]
    B --> C["资产补齐<br/>模板 / 编排 / 忽略 / 门禁"]
    C --> D["凭据扫描 C1~C6<br/>规则分级与白名单"]
    D --> E["历史公开文档红线清理"]
    E --> F["Kiwi 先登记 → 用例 → 覆盖率"]
    F --> G["计划 / 架构 / 前序文档回写"]
```

1. **不改基座**：`Settings` 的加载链、深合并、`extra="forbid"` 与 `validate_startup` 原样保留；msg 侧只加「摊平 + 纯函数判据」与离线自检。守卫只判结构与生产禁用项，缺密钥仍由基座在使用时失效关闭。
2. **四层链口径**：基线 → `config.{env}.toml` → `backend/.env` → 进程 `BMS_` 变量；任务书三段优先级中的「环境变量」拆成 dotenv 与进程两层。分层覆盖顺序由用例逐层撤除验证，启动期与离线 C5 只判结果与禁用项，不宣称能重放加载链。
3. **单一事实源**：六类敏感项与三个运行旋钮的键位只在 `check_credentials.py` 的注册表登记；模板补键、编排补键、配置文本检查、用例断言、预检必填键清单一律由它派生或对照。
4. **双落点接线**：纯函数放服务包内（镜像带得到），离线脚本经 `load_settings()` 调同一函数；镜像不含 `ops/`，故离线命令只在仓内跑。
5. **历史红线一并清理**：按补拍板不设存量基线，13 份历史文档只替换账号 / 地址字面量；脚本保持「命中即失败」，误报靠规则分级与白名单解决，不靠放行豁免。

## 4. 实施中遇到的问题与处置 <a id="issues"></a>

| # | 现象 | 原因 | 处置 |
| --- | --- | --- | --- |
| 1 | 任务字面「四层」与基座真实六源链不一致 | 任务把环境变量层写成一层 | 按基座加载链收敛为四层，详细设计写明与三段优先级的映射，并在对齐记录登记 |
| 2 | 首跑凭据扫描 134 项命中，几乎全是误报 | 通用 `token` / `secret` 变量名、测试夹具私网地址、`user:query` 权限码、回环与服务名端口被判红线 | 规则按目录分级（凭据形态全目录、公开文档红线仅文档 / 部署资产），关键词收敛为密码 / 密钥类赋值，真实令牌改由 JWT / AK 形态判定，补显式白名单；命中降至 11 项真实存量 |
| 3 | 剩余 11 项均为历史文档里的内网地址与账号 | 02 / 03 / 04 / 06 / 07 域历史记录写了 Kiwi 登记命令与冒烟镜像地址 | 补拍板「本任务一并清理」：13 份文档占位化，不设基线；07-1-1 测试记录同步说明 |
| 4 | 新增用例源码与设计文档自身被 C1 扫中 | 反例夹具与规则描述文本含完整凭据形态 | 反例字符串用拼接 / 分段常量构造；设计文档规则描述改写；夹具的行尾与引号形态同步调整 |
| 5 | dotenv 层在四层用例里不生效 | 基座 `Settings.model_config["env_file"]` 在类定义时锚定 `backend/.env`，不随 `_config_dir()` 或工作目录变化 | 用例 monkeypatch 该键指向临时目录；设计补记说明「测试模拟 dotenv 落点」，不改基座 |
| 6 | `test_four_layer_precedence` 等 4 例首跑失败 | 除 dotenv 外还有引号值形态、用例源码命中导致真实仓自检变红 | 逐项修夹具并复跑，23 例全绿、真实仓自检六项全绿 |
| 7 | 第三个水位旋钮 `MSG_STORAGE_SAMPLE_TTL_MS` 未在原确认范围 | 07-1-2 遗留写「`MSG_STORAGE_*` 等」，第 8 项拍板只列两个键 | 执行中补问并拍板「一并透传」，模板 / 编排 / 注册表 / 用例同批 |
| 8 | 开发服务器 `docker compose config` 正例首跑报「undefined volume placeholder」 | 占位卷路径写成相对路径，被 Compose 当具名卷 | 改绝对路径占位复跑：正例退出码 0、新键位全部进入渲染结果；缺 `MSG_TAG` 反例按预期报错；临时文件用完即删 |
| 9 | 详细设计与实现出现三处口径偏差 | C6 键集合全等不可行、规则需分级、第三个旋钮补入 | 先回写设计（§6.2 / §7.1 / §7.2 / §13 实施期对齐补记）再继续实施，未默默绕过 |
| 10 | 计划表新增的实施 / 测试记录链接暂时断链 | 记录文件尚未落盘 | 两份记录落盘后复跑链接校验归零 |
| 11 | 提交前预检的并行选测中 T3 失败：prod 装配缺三个库 URL | 用例清掉 `BMS_` 变量后直接构造 prod `Settings()`，而生产库 URL 本就只经环境变量注入；串行本地跑被宿主残留变量掩盖 | 改为用构造的 prod 扁平映射验「守卫不判密钥」，不依赖真实 prod 装配与宿主环境；基座启动校验行为由基座自身用例覆盖 |
