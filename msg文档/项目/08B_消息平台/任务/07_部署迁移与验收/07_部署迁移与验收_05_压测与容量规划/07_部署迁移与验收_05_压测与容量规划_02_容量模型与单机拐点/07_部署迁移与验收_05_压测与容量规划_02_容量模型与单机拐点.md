## 2. 任务内容 <a id="content"></a>

1. **容量公式**：日增字节 = 峰值 msg/s × 平均消息大小 × 86400 × 峰值占比；所需磁盘 = 日增字节 × 保留天数 × 副本数 × 1.3；分区数 = 峰值消费并行度 × 1.5~2；实例数 = 峰值吞吐 / 单机安全吞吐 × 1.5，按「N−1」设计。
2. **参数定值**：fsync 三档策略、默认分区数、保留期、副本数 / `min.insync.replicas`、默认配额、TLS 开关、单条消息大小上限、慢盘绝对阈值等逐项定值，写明依据与实测条件。
3. **单机拐点**：在独立环境测吞吐 / 延迟曲线，找到拐点并解释瓶颈（CPU / 磁盘 / 网络 / 解释器 / GC）；给出安全吞吐与扩容 / 分片建议。
4. **N−1 校验**：按副本数 N 验算坏一台后的余量；首期单实例时明确「不能把单机跑到极限」。
5. **不达处置**：容量不达模型时按规划 §9.2 给出扩容 / 分片 / 换实现 / 云托管的处置，不把同机基准比值当结论。
6. **报告**：容量模型、参数表、拐点曲线、N−1 结论与建议成文，供 07-9 / 07-7 引用。

## 3. 完成标准 <a id="accept"></a>

- 容量公式与参数表齐全，每项参数有依据与实测条件；
- 单机拐点有曲线与瓶颈解释，安全吞吐可计算；
- N−1 余量结论明确，单实例阶段的限制写明；
- 不达容量模型项有处置建议，不默认通过；
- 报告可被 07-9 / 07-7 直接引用。
