## 3. 任务内容 <a id="content"></a>

1. **独立压测环境**：客户端与服务端分离部署，避免同机 CPU 争抢；压测机与目标环境固定，环境、版本、配置与网络条件记录在报告里。
2. **编译型客户端**：用 `h2load` 或等价编译型客户端替代同机 Python 客户端，报 **P50 / P95 / P99**，不只报平均；同机 Python 客户端只作诊断记录，不作判据。
3. **容量模型**：按「N−1」设计，给出日增字节、所需磁盘、分区数、实例数的公式与参数；定 fsync 策略、分区数、保留期、副本数 / `min.insync.replicas`、默认配额、TLS 影响、消息大小上限等参数。
4. **单机拐点**：找到单机吞吐 / 延迟拐点并解释瓶颈（CPU / 磁盘 / 网络 / 解释器）；给出扩容 / 分片建议与不达容量模型时的处置。
5. **基线回归**：形成可重复的性能基线（脚本、数据、报告、版本），03 / 04 / 05 域每次性能敏感变更后可按同一入口复测。
6. **阈值回填**：把 07-6 慢盘绝对阈值、06-3 告警阈值、03-5 限速与窗口阈值、04-4 熔断阈值、02-3 fsync 容量、06-2 影响预检上限等回填到对应设计 / 规范 / 配置。
7. **边界**：不替代 07-9 的验收压测与 07-7 的阶段验收报告；不在本地跑全量测试；容量结论必须来自独立环境，不用同机基准比值代替。

## 4. 完成标准 <a id="accept"></a>

- 独立压测环境与编译型客户端可复现，报告含版本、配置、环境与原始数据；
- P50 / P95 / P99 数据齐全，容量模型参数可解释，单机拐点有结论；
- 性能基线可重复回归，性能敏感变更后有复测入口；
- 阈值与默认参数已回填，不再以占位值交付；
- 未达容量模型项按规划 §9.2 登记处置，不默认通过；
- 变更模块行 + 分支覆盖率达标，静态与文档校验通过。
