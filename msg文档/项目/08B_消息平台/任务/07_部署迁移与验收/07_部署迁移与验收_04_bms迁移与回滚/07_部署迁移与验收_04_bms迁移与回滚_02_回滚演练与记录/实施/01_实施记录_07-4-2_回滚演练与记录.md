## 3. 关键实现决策 <a id="decisions"></a>

| # | 决策 | 理由 |
| --- | --- | --- |
| 1 | 新增 `ops/rollback.py`，判据函数复用 `ops.migration` | 闸门、开关判定与记录三态只有一份；回滚不另造一套切换语义 |
| 2 | 主证据为进程内双链路（真 msg 应用 + 真 outbox + 真 `HttpServiceClient`） | 本地无 Docker / broker；真路由、真帧、真数据面才能证明「切过去—退回来」；CLI 网络形态共用同一 `run_rollback_drill` |
| 3 | 三类注入写死在场景单源，`criterion` 逐字校验矩阵原文 | 判据漂移会制造「脚本通过、生产不通过」；改判据必须先改矩阵 |
| 4 | 原链路事件侧 broker 未部署时 `recover.*` 记 `degraded`、结论 `降级通过` | 无法确认的残留必须显式登记，不得默认通过；真实集群归 bms `8B_08` |
| 5 | 回滚时间分两段：`config_change_ms`（配置改完）+ `recovery_ms`（双链路恢复） | 只报一个总时间无法区分「配置慢」与「原链路慢」，也无法核对预算 |
| 6 | 四类一致性各自独立断言 | 「效果一次 / 无丢失 / 位点死信重放 / 审计链」任一失败都足以停切换，不能合并成一个布尔 |
| 7 | 记录沿用 07-4-1 同源契约并扩字段 | JSON 作为 07-6-2 故障演练的对接契约；失败也落盘，原因不只存在于终端 |
| 8 | 在途 / 未确认 / outbox / 双写四个窗口各有步骤与计数 | 回滚事故多发生在窗口交界；只验「最后能发」会漏掉重复副作用与丢失 |

## 4. 实施过程 <a id="process"></a>

1. 读规范与上下文：`AI开发规范`、07-4 父任务、需求 07-4、07-4-1 交付、bms `06_01` 回滚三态与 outbox 用例、07-3 记录范式；核对 8B_05（02-4 / 02-5）仍搁置；
2. 逐项确认 16 项口径（§16 对齐记录），登记 Kiwi 2478 并回读一致；
3. 落详细设计：回滚原则、闭环流程、场景单源、端口与步骤、三类注入、四窗口、四类一致性、记录契约、失败分支、测试映射；
4. 实现 `ops.rollback`：TOML 解析与守卫、闸门复用、双链路编排、注入、回滚、恢复、一致性、记录渲染、三子命令与网络目标；
5. 写 `rollback_scenarios.toml`，把 `python -m ops.rollback matrix` 渲染表贴回设计文档；
6. 写 89 例用例（正例走真应用，失败分支走真实损坏 / 可控目标），逐轮补覆盖率到 100%；
7. 跑一次完整演练并落 JSON + Markdown，整理为入库演练记录；
8. 更新前置清单与 README，回归 07-4-1 用例并同步两处闸门断言。

## 5. 问题与处置 <a id="issues"></a>

| # | 问题 | 处置 |
| --- | --- | --- |
| 1 | 发件箱投递器持有可切换发布端口；回滚只改端口解析、不重置投递器持有的 publisher 时，outbox 补发仍会走 msg | 进程内目标在 `switch_to_original()` 同步重置投递器 retry 的 publisher；用例断言回滚后投递载体为原链路 |
| 2 | 同一发件箱库连续多轮演练会撞 `event_id` 唯一约束 | `_event()` 加 `run_nonce` 前缀，`run_rollback_drill` 缺省取开始时刻；用例每轮传 `run{序号}` |
| 3 | `error_rate` 注入中成功发布的探针消息未消费，导致 `published_msg == consumed_msg` 不成立 | 采样成功数 drain 后计入消费计数，失败数只计判据，不进消息计数 |
| 4 | `ConcurrentStableDict` 不是 `dict` 子类，直接序列化会把记录写成字符串 | `write_record` 先 `dict(record.items())` 再 `json.dumps`；用例读回断言字段类型（沿用 07-4-1 结论） |
| 5 | 进程内恢复若用真实时钟会引入等待与不确定 | 端口注入单调假时钟，`elapsed_ms` 可断言；超预算用例调大步长构造，不 `sleep` |
| 6 | `HttpRollbackTargets` 的原链路只读地址是必填，但参数解析缺省为空串以便测试注入工厂 | `build_targets` 统一校验：网络形态缺地址即 `RollbackError`，用例覆盖两条分支 |
| 7 | `rollback_drill` 改 `satisfied` 后，07-4-1 两处闸门断言（生产阻断项含 `rollback_drill`）失败 | 同步更新 `test_migration.py`：断言 `rollback_drill` 不再阻断、`blocked_by` 只剩 `copy_replication`；回归 289 例全绿 |
| 8 | 测试文件在 pyright strict 下访问模块私有替身报 `reportPrivateUsage`，改 `getattr(常量名)` 又被 ruff B009 拦 | 私有替身直接访问并在 5 处行尾注 `# pyright: ignore[reportPrivateUsage]`（仅豁免私有可见性，运行时仍覆盖真实构件）；未注解 lambda 改为带注解局部函数，`--pythonpath` 指向仓内 venv 后 pyright **0 errors** |
