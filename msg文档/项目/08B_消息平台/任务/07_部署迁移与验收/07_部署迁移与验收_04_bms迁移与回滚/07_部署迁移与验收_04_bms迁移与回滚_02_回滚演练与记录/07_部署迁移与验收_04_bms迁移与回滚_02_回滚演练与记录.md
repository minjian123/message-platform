## 2. 任务内容 <a id="content"></a>

1. **回滚原则**：回滚只改配置（`provider` / 域级开关），不重新发布业务代码、不执行数据库降级；切回原链路后业务行为恢复。
2. **演练场景**：在隔离环境完成「切到 msg → 跑一条事件链与一个只读远程调用 → 注入失败（msg 不可用 / 错误率超阈值 / 延迟超阈值）→ 配置层回滚 → 验证原链路恢复」的完整闭环。
3. **在途与未确认处理**：演练覆盖切换瞬间在途请求、未确认事件、outbox 重投与双写窗口；回滚后核对无重复副作用、无丢失事件；无法确认的残留显式登记，不默认通过。
4. **数据一致性校验**：事件链两端记录业务效果，按幂等键核对「效果一次」；消费组位点、死信、重放任务状态不因回滚错乱；审计链完整性可校验。
5. **演练记录**：固定字段——环境、版本、配置版本、切换域、注入方式、观察指标、回滚开始 / 结束、恢复时间、数据完整性结论、问题与处置、遗留与归口；记录随任务 `测试/` 留痕。
6. **可重复**：回滚脚本 / 步骤参数化，同一场景可重复执行；演练前备份、演练后清理隔离环境；每次发版前可按同一脚本复跑。
7. **问题回写**：演练发现的缺陷回写详细设计或架构设计；不能在本任务闭环的登记遗留并明确承接阶段，不得只写「已知问题」。
8. **边界**：不在生产环境做回滚演练；不删除原 RocketMQ / outbox / HTTP 链路；不把 bms 真实业务迁移纳入本任务（归 bms 8B_08）。
9. **测试**：配置层回滚用例；在途 / outbox / 双写窗口用例；事件效果一次与无丢失断言；回滚后原链路可用断言；脚本重复执行结果一致。

## 3. 完成标准 <a id="accept"></a>

- 回滚开关已在隔离环境演练过一次，且只通过配置层完成；
- 切回原链路后事件链与只读远程调用行为恢复，业务代码未重新发布；
- 在途请求、未确认事件、outbox 重投与双写窗口均有处置，回滚后无重复副作用、无丢失事件；
- 消费组位点、死信、重放任务状态与审计链在回滚后保持一致；
- 演练记录含环境、版本、配置、注入方式、观察指标、恢复时间、数据完整性结论、问题与遗留；
- 回滚步骤可重复执行，发现问题已回写设计或登记遗留；
- 变更模块行 + 分支覆盖率达标，静态与文档校验全绿。

## 6. 收口说明 <a id="closure"></a>

- **回滚原则**：只改 `[event].provider` / `[service_client].provider`（8B_08 域级键落地后改域级键）+ 重启调用方，不重新发布业务代码、不执行数据库降级；
- **演练闭环**：切到 msg → 跑一条事件链与一个只读调用 → 注入失败（msg 不可用 / 错误率 / 延迟超阈值）→ 配置层回滚 → 验证原链路恢复；
- **在途与未确认**：切换前 drain；无法 drain 时以幂等键与服务端去重兜底；未确认事件留在 outbox 由既有投递器补发，切回后不重投已确认行；
- **归口**：真实集群回滚与生产窗口归 bms `8B_08`；阈值数值归 `8B_12`。
