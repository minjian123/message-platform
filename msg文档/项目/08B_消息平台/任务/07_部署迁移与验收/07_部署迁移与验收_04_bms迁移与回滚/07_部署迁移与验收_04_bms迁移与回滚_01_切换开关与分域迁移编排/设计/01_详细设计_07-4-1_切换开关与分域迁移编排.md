## 1. 任务级边界与输入基线 <a id="scope"></a>

**做什么**：把「什么时候可以迁移（前置清单 + 生产闸门）」「迁哪个域、按什么顺序、看什么指标、什么条件下回滚（切换矩阵）」「开关怎么配、配错会怎样（开关契约）」三件事落成**机器可读的单源**与**可重复执行的演练**，并在隔离环境用真 msg 应用跑通「一条事件链 + 一个只读远程调用」。

**不做什么**：

- 不实现 bms `EventPublisher` / `BaseServiceClient` 的 msg 实现（04-5 + bms 07B `06_01` 已交付），不改 bms 代码；
- 不实现域级白名单 / 灰度的运行期读取（归 bms 8B_08，本任务只交付契约规格与校验器）；
- 不执行生产环境切换（归 bms 8B_08），不执行完整「注入失败 → 回滚 → 恢复」闭环（归 07-4-2）；
- 不改 RocketMQ / outbox / HTTP 原链路，不改 `BaseServiceClient` / `EventPublisher` 端口契约；
- 不实现 outbox 投递器与重投（bms 既有能力），只断言端口失败语义与「不双写」；
- 不在生产环境运行本站演练（`drill` 的 `--env prod` 直接拒绝）；
- 不修改需求 / 任务文档正文的进度字段（进度只在计划表回写）。

**输入基线**：

| 输入 | 事实 |
| --- | --- |

| bms 异常口径 | `provider = "msg"` 但实例地址 / 命名空间缺失 → 装配期 `ConfigError`；未注册实现 → `PluginError`；**均不静默回落** |

### 4.2 守卫规则 <a id="preconditions-guard"></a>

| # | 规则 | 处置 |
| --- | --- | --- |
| 1 | `status` 只允许 `satisfied` / `not_ready` | 其它取值 → 清单非法（退出 1）并指名条目 |
| 2 | `required_in` 只允许环境标识子集（`prod` / `test` / `dev`） | 非法 → 退出 1 |
| 3 | `evidence` 非空；`id` / `label` 唯一且非空 | 缺失 → 退出 1（空证据等于没核对） |
| 4 | `check --env prod`：任一 `required_in` 含 `prod` 且 `not_ready` | **拒绝**（退出 1），逐条列阻断项与证据锚点 |
| 5 | `check --env test` 或 `--env dev`：生产阻断项仍逐条登记，但 `allowed` 按当前环境判定 | 只记录、退出 0（隔离环境允许演练，但记录里 `blocked_by` 非空即代表「生产仍被阻断」） |
| 6 | 未登记的 `--env`（如 `staging`） | 参数错误（退出 2），不猜语义 |

- 闸门只读清单、不探测代码符号：能力是否交付是**人 + 计划表**的事实，代码符号探测会在「有骨架没能力」时误放行；
- 8B_05 交付后只改一行 `status = "satisfied"` + 证据，不改代码、不重新发布业务镜像；
- 闸门不提供覆盖开关：生产迁移由 bms 8B_08 执行，本命令只负责「不许进」。

## 5. 切换矩阵（TOML 单源） <a id="matrix"></a>

### 5.1 域划分与批次 <a id="matrix-domains"></a>

| 批次 | 名称 | 范围 | 放行条件 |
| --- | --- | --- | --- |
| 1 | 低风险通路 | 一条低风险事件域 + 一个只读远程调用 | 前置清单全绿（生产）+ 切换前备份成功 |
| 2 | 审计事件 | 审计事件域（操作审计 / 访问异常） | 批次 1 观察窗口通过 |
| 3 | 业务事件与写调用 | 业务事件逐域 + 写远程调用（幂等键必须覆盖） | 批次 2 观察窗口通过 |

## 6. 配置开关契约 <a id="switch-contract"></a>

### 6.1 键位与合法值 <a id="switch-keys"></a>

| 端口 | 键 | 合法值 | 缺省 / 原实现 | 切换到 msg 的前提 |
| --- | --- | --- | --- | --- |
| 事件发布 | `[event].provider` | 注册表中的实现名 + `""`（回落 `null`）；当前为 `null` / `rocketmq` / `msg` | `rocketmq`（已部署 broker）；未部署时 `""` → `null`（不投递） | `[event].options.namespace` 或 `[app].service` 非空且为 msg 已启用 `module_key`；实例地址可解析 |
| 服务调用 | `[service_client].provider` | `""`（`null` 占位）/ `http` / `msg` | `http`（bms 基线配置） | `[service_client].instances.msg` / `endpoints.msg` / `options.base_url_template` 至少一条可用且为 `http(s)` |
| 发件箱投递 | `[outbox].provider` | `poll` / `msg` / `""`（null 占位） | `poll`（原 relay） | `provider = "msg"` 时 msg 实例地址与命名空间齐备；由 [01-8-1](../../../../01_消息模型与投递/01_消息模型与投递_08_可靠性与事务/01_消息模型与投递_08_可靠性与事务_01_outbox适配与relay切换/设计/01_详细设计_01-8-1_outbox适配与relay切换.md) 交付，本表按协同契约补录 |

补充键（均为既有键，不新增配置节）：

| 键 | 作用 | 非法 / 缺失行为 |
| --- | --- | --- |
| `[event].options.namespace` | 事件命名空间 | 与 `[app].service` 同时为空 → 装配期拒启（`ConfigError`） |
| `[service_client].instances.msg` | 多实例地址列表 | 非 `http(s)` / 空列表 → 装配期拒启 |
| `[service_client].endpoints.msg` | 单实例覆盖 | 同上 |
| `[service_client].options.base_url_template` | 基址模板 | 缺 `{service}` 占位 → 装配期拒启 |
| `[service_client].options.instance_strategy` | `round_robin` / `least_inflight` | 其它值 → 装配期拒启 |
| `[service_client].options.attach_service_token` | 是否附服务 JWT | 布尔；非布尔由配置校验拦截 |

### 6.2 合法 / 缺失 / 非法三态 <a id="switch-three-states"></a>

| 态 | 判据 | 行为 | 用例 |
| --- | --- | --- | --- |
| 合法-原实现 | `provider` 为空串或原实现名（`http` / `rocketmq` / `null`） | 走原链路，与切换前逐字节一致 | T5 |
| 合法-msg | `provider = "msg"` 且地址 / 命名空间齐备 | 解析出 `MsgEventPublisher` / `MsgServiceClient`，业务调用点不改 | T6 |
| 缺失 | `provider` 未配置或空串 | 按原实现解析（`event` → `null`；`service_client` → `null` 占位） | T5 |
| 非法-未注册 | 任意未注册实现名 | 装配期 `PluginError`，**不回落** | T7 |
| 非法-配置不全 | `provider = "msg"` 但地址 / 命名空间缺失或非法 | 装配期 `ConfigError`，指名键名 | T8 |

**fail-safe 口径（定稿）**：fail-safe 不等于「悄悄回原链路」。未配置 = 原实现是**缺省语义**；非法配置 = **拒启**，因为静默回落会让「以为切到 msg、实际还在 http」的假切换进入观察窗口，长期比启动失败更贵。该口径与已交付的 bms `06_01` 行为一致，本任务不改 bms。

### 6.3 开关变更的生效方式 <a id="switch-effect"></a>

- 只改配置文件 / 环境变量 + **重启调用方服务**，不发布业务代码、不重建业务镜像；
- 插件装配在启动期完成，运行期不监听配置文件（bms `06_01` 口径）；因此「不要求业务代码发布」成立，「必须重启」也如实写明；
- 每次切换在记录里记 `config_fingerprint`（**三个** `provider` 值：`[event]` / `[service_client]` / `[outbox]` + 命名空间 + msg 实例地址 + 策略的规范化摘要），用于切换点对账；第三个键由 [01-8-1](../../../../01_消息模型与投递/01_消息模型与投递_08_可靠性与事务/01_消息模型与投递_08_可靠性与事务_01_outbox适配与relay切换/设计/01_详细设计_01-8-1_outbox适配与relay切换.md) §6.4 扩展并已交付，摘要算法不变；
- 域级键（8B_08）落地后语义为：`""` 跟随全局 / `msg` / `original`（显式回原实现），非法值同样拒启；本任务只校验键形与 `pending_8b08` 状态。

## 7. 迁移编排与观察窗口 <a id="orchestration"></a>

### 7.1 每域切换步骤（运维口径） <a id="orchestration-steps"></a>

```mermaid
flowchart LR
    A["前置清单 check --env prod"] --> B["切换前备份 ops.backup"]
    B --> C["确认在途收敛 / 暂停接新"]
    C --> D["改 provider + 重启调用方"]
    D --> E["冒烟：事件发布 + 只读调用"]
    E --> F["观察窗口"]
    F --> G{"判据全过？"}
    G -- 是 --> H["放行下一域"]
    G -- 否 --> I["按 07-4-2 回滚（只改配置）"]
```

| 步 | 动作 | 留痕 |
| --- | --- | --- |
| 1 | `python -m ops.migration check --env prod` | 阻断项 / 通过项进记录 |
| 2 | 切换前备份：`python -m ops.backup --reason pre-migration-<域>`（07-3-1 入口） | 备份标识进记录 |
| 3 | 在途收敛：停止接新（发布侧暂停投递器 / 调用侧摘流），等在途请求与未确认事件收敛或超时 | `drain_ms`、残留数 |
| 4 | 改 `provider` + 重启调用方服务 | `config_fingerprint`、重启命令（脱敏） |
| 5 | 冒烟：一条事件链 + 一个只读调用（与演练同一判据） | 冒烟结果 |
| 6 | 观察窗口（缺省 30 分钟，可配） | 指标快照与判据结论 |
| 7 | 通过 → 下一域；不通过 → 回滚（07-4-2） | 结论与归口 |

## 8. 在途、未确认事件、outbox 与双写窗口 <a id="windows"></a>

| 场景 | 风险 | 处置（生产） | 本任务断言 |
| --- | --- | --- | --- |
| 在途请求 | 切换瞬间旧链路请求未返回，重试造成二次执行 | 先 drain（停新、等在途收敛或超时）；无法 drain 时靠**同一幂等键**全程稳定 + 服务端去重 | 首跳失败重试两次，两次帧头 `idempotency_key` 相同，服务端只执行一次（T9） |
| 未确认事件 | 事件已写 outbox 未确认，切换后丢或重投 | 事件侧**不双写**；未确认行留在 outbox，由既有投递器在 `provider` 生效后补发；投递器每条只成功一次 | msg 不可达时发布必须抛 `EventPublishError`（不吞）；恢复后同一事件发布一次、消费一次（T10） |
| outbox 重投 | 切换后重复投递 | 投递器按 `event_id` 标记已投递，切回不重投（bms `tests/outbox/test_provider_switch.py` 已交付证据） | 记录引用该证据；本任务不重写 outbox |
| 双写窗口 | 两 provider 同时在线导致重复副作用 | 首期**禁止双写**：`resolve_plugin` 单值解析、装配只产出一个实现；灰度分流归 8B_08 域级键 | 一次调用只产生一条消息 / 一条帧；两次调用恰好两条（T11） |
| 切回 | 未确认事件未清就切回 | 先确认 `EventPublisher.publish` 失败路径可观测（outbox 保留行），再切回；切回后不重投已确认行 | 回滚完整闭环归 07-4-2；本任务只验证「失败不丢信号 + fallback 可用」（T12） |

## 9. 演练设计（`check` / `drill` / `matrix`） <a id="drill"></a>

### 9.1 子命令 <a id="drill-cli"></a>

| 命令 | 用途 | 关键参数 |
| --- | --- | --- |
| `python -m ops.migration check` | 校验前置清单 + 生产闸门 + 矩阵 + 阈值符号；不跑流量 | `--preconditions`（缺省 `deploy/migration/preconditions.toml`）、`--matrix`、`--env`（缺省 `test`） |
| `python -m ops.migration matrix` | 渲染矩阵表与「域 → 开关键 → 指标」速查 | `--matrix` |
| `python -m ops.migration drill` | 在隔离环境跑「切到 msg + 事件链 + 只读调用 + 在途 / 未确认 / 双写 / fallback」并写记录 | `--msg-url`、`--namespace`、`--env`（只允许 test / dev）、`--report`、`--read-only-service` / `--read-only-method`、`--fallback-base-url` |

- `drill` 的 `--env prod` / `production` **直接拒绝**（退出 2），无覆盖开关；
- 进程内演练（用例）不经 CLI：用例把 `DrillTargets` 实现为「真 msg 应用 + 真帧 + 真数据面」，调同一份 `run_drill()`；
- CLI 的网络实现只做「构造端口 + 转发调用」，不复制判据（判据只有一份在 `run_drill()`）。

### 9.2 步骤表（声明序即执行序） <a id="drill-steps"></a>

| 步 | 名称 | 断言 | 记录字段 |
| --- | --- | --- | --- |
| 1 | `preconditions` | 清单可解析、字段合法、生产阻断项被识别 | `blocked_by[]` / `production_gate.allowed` |
| 2 | `matrix` | 两类端口齐备、批次 1 同时含事件与只读调用、字段非空、指标已登记、域级键形合法 | `domains` / `phases` |
| 3 | `switch_semantics` | 两个端口按配置解析出预期实现（`msg` 或原实现）；`config_fingerprint` 可复算 | `event` / `service_client` / `config_fingerprint` |
| 4 | `event_chain` | 建主题 → 发布一条事件 → 消费端拿到 1 条，载荷 / 属性 / 租户逐项一致 | `published` / `consumed` / `payload_digest` |
| 5 | `readonly_call` | 只读调用经真帧往返，结果与 fallback 同构 | `read_only_target` / `records` |
| 6 | `inflight_idempotency` | 首跳失败后重试，两次 `idempotency_key` 相同，服务端只执行一次 | `attempts` / `executions` |
| 7 | `unconfirmed_event` | 不可达时发布抛 `EventPublishError`；恢复后发布一次、消费一次 | `failed_publish` / `delivered` |
| 8 | `dual_write` | 端口只解析出一个实现；两次调用 = 恰好两条消息 | `implementations` / `messages` |
| 9 | `fallback` | 原链路（HTTP）可继续调用且结果一致；未提供时记 `skipped` 并写明原因 | `fallback` |
| 10 | `business_zero_change` | 真实业务函数签名 / 端口方法集不变；两通道复用同一函数对象 | `callables` / `signature` |

- 任一步硬失败即中止后续步（后续记 `skipped`），结论 `失败`、退出 1；
- `fallback` 缺省跳过记 `降级通过`、退出 2（「没验 fallback」不能算全绿）；
- 每步用注入的单调时钟取 `elapsed_ms`，用例注入假时钟避免真实等待。

### 9.3 端口抽象 <a id="drill-ports"></a>

```text
DrillTargets（协议，ops.migration 定义）
├── prepare_event()            建主题 + 加入消费组（真实 msg 管理面 / 数据面）
├── publish(event)             经 msg 通道发布（失败抛 EventPublishError）
├── publish_unavailable(event) 指向不可达实例的发布（必须抛 EventPublishError）
├── consume_events()           拉取消息条目（真数据面）
├── read_only()                只读远程调用（用例 = fetch_catalog_snapshot；网络 = 指定 RPC 方法）
├── fallback_read_only()       原链路只读调用（可选；None 表示未提供）
└── aclose()                   释放连接
```

- 用例侧实现：`msg_app` 夹具 + `AsgiRpcTransport` + `msg_event_publisher(..., transport=ASGITransport(app))`；
- 网络侧实现：`MsgEventPublisher`（真 HTTP）+ `MsgServiceClient`（生产 `H2Transport`）+ `httpx.AsyncClient`（管理面 / 数据面）；
- 两类实现共用 `run_drill()` 的判据，避免「用例一套、脚本一套」。

### 10.2 结论与退出码 <a id="record-conclusion"></a>

| 结论 | 条件 | 退出码 |
| --- | --- | --- |
| `通过` | 无硬失败、无降级项、fallback 已验 | 0 |
