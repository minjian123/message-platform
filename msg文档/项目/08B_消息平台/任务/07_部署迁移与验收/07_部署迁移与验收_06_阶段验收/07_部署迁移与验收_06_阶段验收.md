## 2. 任务内容 <a id="content"></a>

1. **九域逐项验收**：传输性能、存储恢复、消费组、远程调用、可靠性、高可用、运维、多租户、迁移九域逐项核对；每项写明判据、证据位置与结论，不用「已测试」代替证据。
2. **证据要求**：每项必须有可复现证据——测试记录 / 报告 / 演练记录 / 覆盖率报告 / 发布记录；证据链接指向具体文档或命令输出，不复制大段数据。
3. **覆盖率门禁**：变更模块行 + 分支 100%（口径见《AI开发规范》「覆盖率要求」节）；提交环 / 推送环 / CI 的分工按规范执行，阶段验收不手工采集覆盖率。
4. **文档校验**：`engkit links`（相对链接与锚点）、`engkit docs-scope`（进度只落计划）、`engkit eol`（行尾）三项通过；文档与计划、需求、任务、设计链路可追溯。
5. **容量口径**：传输性能与容量结论引用 8B_12 的独立压测环境与 P50 / P95 / P99 数据；8B_12 未完成时按「待容量实测」登记遗留，不以同机基准比值代替，不默认通过。
6. **未通过项处理**：未通过项必须登记遗留（现象、根因、影响、承接阶段 / 任务、归口），不得默认通过；影响阶段结论的 blocker 必须明确处置后再收口。
7. **验收报告**：形成阶段验收报告，含九域对照表、证据索引、覆盖率与文档校验结论、遗留清单与结论；报告与计划 §5 门禁状态一致。
8. **边界**：不新增功能、不在验收阶段改业务代码；不在本地跑全量测试（由 CI 复核）；不替代 8B_09 的阶段测试报告与 8B_12 的容量报告，只做汇总与判定。
9. **测试 / 核对**：九域证据完整性检查；覆盖率报告 `coverage_report.py --module` 核对；三项文档校验；遗留清单与计划 §6.1 台账对齐。

## 3. 完成标准 <a id="accept"></a>

- 九个域验收项均有判据、证据与结论，证据可复现、链接可达；
- 变更模块行 + 分支覆盖率达标，覆盖率结论来自规定入口；
- `engkit links` / `docs-scope` / `eol` 三项通过；
- 容量结论引用 8B_12 独立压测数据；未完成项登记为遗留，未用同机比值代替；
- 未通过项全部登记遗留，含承接阶段 / 任务与归口，无默认通过；
- 阶段验收报告成文，与计划 §5 门禁状态一致；
- 需求 ↔ 任务 ↔ 计划 ↔ 设计 ↔ 实施 ↔ 测试链路可追溯。
