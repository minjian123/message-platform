## 2. 任务内容 <a id="content"></a>

1. **删主题**：新增 `DELETE /api/v1/msg/admin/topics/{topic_id}`，要求 `confirm=true`；先把主题置为 `deleting` 并停止新读写，再投递异步清理任务，请求立即返回受理结果。清理内容：分区日志段、延迟区记录、位点、消费组、死信、配额计数；清理完成后物理删除 / 归档主题元数据。清理任务幂等、可重试，失败保持 `deleting` 并在下一轮扫描重试；每次结果写审计与结构化日志。
2. **主题状态机**：`msg_topic.status` 由 `active` / `disabled` 扩为 `active` / `disabled` / `deleting`；**先改数据库表文件并追加变更记录**，再改模型与校验；列表默认不展示 `deleting`，详情可查清理进度。
3. **扩分区**：新增 `POST /api/v1/msg/admin/topics/{topic_id}/partitions`，调用既有 `TopicService.expand_partitions()`；只允许增加，目标分区数不大于当前值即拒绝；提交成功后失效主题缓存；不迁移既有 key 映射。
4. **改保留期**：新增 `PATCH /api/v1/msg/admin/topics/{topic_id}`，支持 `retention_ms` / `retention_bytes`；校验范围与清理策略一致；即时生效并写审计；不回溯删除已保留记录，后续清理按新值执行。
5. **位点重置**：新增 `POST /api/v1/msg/admin/offsets/reset`，路径沿用 02-3 已登记常量；入参 `namespace` / `topic` / `group` / `partition` / `offset` / `confirm`；复用 `OffsetResetter.reset()`；早于 `start_offset` 显式报错（`350003`）；不改变活跃成员分配；写 `record_ref` 审计。
6. **配额调整**：复用 05-2 既有 `GET/POST /api/v1/msg/admin/quotas`，本任务只补管理模块入口所需的错误码与审计核对，不重复实现。
7. **二次确认**：删主题、位点重置、批量重放要求后端显式确认参数；缺失 `confirm=true` 返回参数错误并留痕；确认值不通过前端传递默认值补齐，防脚本绕过。
8. **审计**：全部写操作挂 `msg:manage`；删主题 / 位点重置为强审计，记录操作人、IP、`trace_id`、影响范围；扩分区、保留期、配额调整为配置变更审计；审计失败按 05-4 口径处置。
9. **不绕过日志链路**：写操作只经 `TopicService` / `MessageStore` / `OffsetStore` / `DelayStore` 端口；不直接改日志文件、不直接 UPDATE 消息记录。
10. **测试**：删主题全资源清理与重复执行幂等；部分失败重试；`deleting` 状态不可读写；扩分区只增；保留期与配额即时生效；位点重置越界 / 前跳 / 倒退；二次确认缺失拒绝；审计 `record_ref` 可查；变更模块行 + 分支覆盖率 100%。

## 3. 完成标准 <a id="accept"></a>

- 删主题返回受理结果，异步清理日志段 / 延迟区 / 位点 / 组 / 死信 / 配额计数，重复执行无二次副作用；
- 清理失败可重试、可观测，主题在 `deleting` 状态停止读写；
- 扩分区只增不减，目标值与当前值比较有明确判据；
- 保留期 / 配额调整即时生效并留痕；
- 位点重置复用 02-3 端口，越界报 `350003`，二次确认缺失即拒绝；
- 所有写操作有 `msg:manage` 与审计，未绕过 `router → log`；
- 变更模块行 + 分支覆盖率 100%，静态检查全绿。

## 6. 后续增补：手动切主管理入口 <a id="followup"></a>

02-5 已于 2026-11-11 交付内部领域服务（`LeaderSwitchService.switch_partition` / `switch_topic`）、`LeaderSwitchDep`、`msg:partition.failover` 审计与 `msg_partition.last_switch_*` 结果列。本任务后续增补：

| 项 | 约束 |
| --- | --- |
| 端点 | `POST /api/v1/msg/admin/partitions/{...}/failover`（单分区）与主题批量（逐分区 CAS）；权限 `msg:manage` |
| 二次确认 | 必须显式 `confirm=true`，影响预检给出目标 / 水位 / `retained_tail` 预期 |
| 参数 | `target`（缺省自动选）、`expected_epoch`、`force`（默认 false，界面上必须二次提示降级风险）、`reason` |
| 结果 | 直接返回 `SwitchResult` / `SwitchBatchResult`；失败项按 `reason` 映射文案，不回滚已成功分区 |
| 审计 | 内部服务已写 begin / finished 两段；端点只需写请求侧操作留痕（触发人 / 原因） |
