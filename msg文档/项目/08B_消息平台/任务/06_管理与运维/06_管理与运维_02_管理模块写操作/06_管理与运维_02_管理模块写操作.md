## 3. 任务内容 <a id="content"></a>

1. **写操作范围**：建 / 删主题、扩分区（**只能增**）、改保留期、改配额、位点重置；配额调整复用 05-2 既有端点，不重复实现。
2. **删除主题**：二次确认后异步清理全部资源——元数据逻辑删除、分区日志段、延迟区记录、位点、消费组、死信、配额计数；清理任务幂等、可重试、有台账与审计；请求不阻塞等待全量清理。
3. **扩分区**：调用既有 `TopicService.expand_partitions()`；只允许增加，减少或非法值拒绝；更新分区记录并使主题缓存失效。
4. **改保留期**：支持 `retention_ms` / `retention_bytes` 调整，校验范围与清理策略一致性；即时生效并留痕；不影响已写入记录的可读性。
5. **位点重置**：复用 02-3 `OffsetResetter`，可倒退可前跳；早于 `start_offset` 须显式报错；重置后不改变活跃成员分配；必须二次确认并留痕（`record_ref` 定位到组 / 主题 / 分区 / 位点）。
6. **权限与审计**：全部写操作挂 `msg:manage`；所有写操作写基座审计链，删主题 / 位点重置为强审计；审计失败按 05-4 口径处置，不静默通过。
7. **二次确认（前后端双保险）**：前端弹窗说明影响范围；后端要求显式确认参数（如 `confirm=true`），缺失即拒绝并留痕；批量重放同样适用。
8. **不绕过日志链路**：写操作只能经 `router → log` 或既有服务端口，不得直接改日志文件、不得绕过 `MessageStore` / `OffsetStore` / `TopicService`。
9. **测试**：建 / 删 / 扩分区 / 保留期 / 位点重置各至少一条；只增不减；异步清理幂等与部分失败重试；二次确认缺失拒绝；审计与 `record_ref` 可查；变更模块行 + 分支覆盖率 100%。

## 4. 完成标准 <a id="accept"></a>

- 写操作全部有 `msg:manage` 权限校验与审计记录；
- 删主题异步清理全部资源，重复执行不产生二次副作用，部分失败可重试并留台账；
- 分区数不可减少，扩分区后路由与缓存一致；
- 保留期与配额调整即时生效且留痕；
- 位点重置可倒退 / 前跳，越界显式报错，二次确认前后端均生效；
- 写操作未绕过 `router → log`，未直接改日志文件；
- 变更模块行 + 分支覆盖率 100%，静态检查全绿。
