## 2. 任务内容 <a id="content"></a>

1. **头字段契约**：消息头新增 `span_id` / `parent_span_id`（可选，字符串，长度上限与 `trace_id` 一致），保留既有 `trace_id`；可选携带采样标记（如 `trace_flags` / `trace_sampled`），由 SDK 解释，broker 不解释。
2. **broker 原样透传**：发布、存储、投递、延迟转投、重放全链路只透传头字段，**不解包 payload、不修改 `trace_id` / `span_id` / `parent_span_id`**；延迟转投沿用发布时字段，重放沿用原消息字段（重放分配新 `log_id`，但 trace 字段不变）。
3. **消费端契约**：消费响应（JSON 与帧形态）返回每条消息的 `trace_id` / `span_id` / `parent_span_id`；批量消费时**逐条**返回，SDK 为每条消息创建新 span，parent 指向生产 span，禁止用批级单一 span 串链。
4. **生产端契约**：发布请求接收三个字段并原样存储；未提供时保持 `null`，不伪造、不生成服务端 span；服务端日志带 `trace_id` / `span_id` / `parent_span_id` 关联。
5. **采样**：按 trace 采样，采样决策在链路根部（SDK / OTel）做；broker 只透传采样标记，不自行丢弃、不改变链路完整性；批量消费中同 trace 的消息保持同一采样决定。
6. **可观测关联**：结构化日志、审计、指标事件携带 `trace_id`；消息检索（06-1）可展示 `trace_id` 便于排障；payload 不落日志，只记长度与摘要。
7. **契约**：新增头字段为 additive，旧客户端不传即为 `null`；契约快照重导；JSON 与帧形态字段名一致；不新增端点、不改现有投递 / 位点语义。
8. **客户端边界**：`bms_core/msgclient` / SDK 的 span 创建、OTel 导出、采样器配置归 bms 仓另立任务；本任务只交付 msg 侧头字段、透传、消费响应契约与文档，不用假 span 冒充端到端。
9. **测试**：JSON / 帧发布头字段往返；延迟转投与重放字段保持；批量消费逐条字段；broker 不解包 payload（字节原样）；采样标记透传；日志字段关联；契约快照；变更模块行 + 分支覆盖率 100%。

## 3. 完成标准 <a id="accept"></a>

- 消息头可携带 `trace_id` / `span_id` / `parent_span_id`，JSON 与帧形态一致；
- 发布 → 存储 → 投递 → 延迟转投 → 重放全链路原样透传，broker 不解包 payload；
- 批量消费逐条返回 trace 字段，SDK 可按条创建 span，不串链；
- 采样标记随消息透传，broker 不改变采样决定；
- 日志 / 审计 / 消息检索可凭 `trace_id` 关联；
- 客户端 span 创建与导出明确归 bms 任务，本任务不假装端到端已完成；
- 变更模块行 + 分支覆盖率 100%，静态检查全绿。
