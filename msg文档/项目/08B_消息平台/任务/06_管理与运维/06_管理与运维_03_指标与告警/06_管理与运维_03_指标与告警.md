## 3. 任务内容 <a id="content"></a>

1. **四大黄金信号**：延迟（发布 / 消费 P50 / P95 / P99）、流量（消息数 / 字节数）、错误（发布失败 / 消费失败 / 转投失败）、饱和度（inflight / 磁盘 / 连接 / 长轮询等待）。
2. **消息特有指标**：分区积压、inflight、死信增长、ISR 收缩、fsync 耗时、延迟待投与转投失败、重放进度与失败。
3. **标签纪律**：核心指标按 `service` / `tenant` / `topic` 聚合；`partition` / `group` 不进 Prometheus 标签，明细走消息平台管理模块（06-1），避免标签基数爆炸。
4. **统一出口**：暴露 Prometheus 文本格式 `/metrics`，复用既有采集器快照（`StorageMetrics` / `DelayMetrics` / `BackpressureMetrics` / RPC 事件 / 重放 / 死信），不重复采集、不在请求内全量扫描。
5. **告警分级**：P0~P3 四级；每条告警可行动、有抑制、有恢复通知；阈值可配置，缺省值待 8B_12 容量模型回填。
6. **告警交付**：规则文件入 msg 仓 `deploy/` 声明式版本管理，接入 bms Prometheus / Alertmanager；Grafana 看板 JSON 同批交付，供 06-1 概览页跳转。
7. **不显著影响吞吐**：采集为只读快照，指标导出不得在每次请求内做全量遍历；高基数保护沿用 `topic_key_limit` 与 `__other__` 归并。
8. **测试**：指标名 / 类型 / 标签 / 数值与采集器一致；`/metrics` 文本可被 Prometheus 解析；规则语法与抑制 / 恢复用例；采集开销基准；变更模块行 + 分支覆盖率 100%。

## 4. 完成标准 <a id="accept"></a>

- 积压 / 延迟 / 死信 / 磁盘 / inflight / fsync 等核心指标可从 `/metrics` 获取；
- 指标标签只到 `service` / `tenant` / `topic`，无 `partition` / `group` 高基数标签；
- P0~P3 告警规则可触发、可抑制、可恢复，接入 bms Alertmanager；
- Grafana 看板可展示四张核心卡与趋势，06-1 概览页跳转目标可用；
- 指标采集不显著影响吞吐（基准对比留痕）；
- 变更模块行 + 分支覆盖率 100%，静态检查全绿。
