## 2. 任务内容 <a id="content"></a>

1. **规则文件**：新增 `deploy/observability/rules/msg.yml`（Prometheus rules），按指标清单定义 recording / alerting rules；文件头注明加载路径、校验命令与分级口径。
2. **分级 P0~P3**：P0 全平台不可写 / 数据损坏；P1 单 topic 积压超阈值且持续增长（含 `for` 持续时长）；P2 死信快速增长 / ISR 频繁收缩 / 延迟转投失败；P3 磁盘接近高水位 / 连接或等待器接近上限。P0 / P1 映射 Alertmanager `critical`，P2 / P3 映射 `warning`，另以 `priority` 标签保留 P0~P3。
3. **可行动**：每条告警带 `summary` / `description` / `runbook_url` / `dashboard_url`，说明影响、排查入口与处置动作；不可行动的阈值不进规则。
4. **抑制**：同实例 P0 抑制 P1 / P2；同 topic P1 抑制 P3；维护窗口 / 计划重放通过 Alertmanager 静默处理，不在规则里写死。
5. **恢复通知**：`send_resolved: true`；恢复条件与触发条件对称，避免抖动；必要时用 `for` 与滞回阈值。
6. **接入 bms**：规则文件与 Grafana 看板 JSON 归 msg 仓；接入 bms 栈时同步更新 `bms/deploy/observability/prometheus.yml` 的抓取目标 / `rule_files` 与 `compose/observability.yml` 挂载（跨仓提交、两仓同步发布），并在测试记录登记接入证据。
7. **Grafana 看板**：新增 `deploy/observability/grafana/dashboards/msg.json`，含吞吐 / 积压 / 死信 / 磁盘四张核心卡与趋势、按 topic 下钻；供 06-1-2 概览页跳转。
8. **阈值口径**：缺省阈值写为可识别占位并注明“待平台级容量模型回填”；不得把未实测数字写成最终结论。
9. **测试**：`promtool check rules` 通过；规则表达式引用指标均存在；分级 / 抑制 / 恢复断言；Grafana JSON schema 校验；接入后触发与恢复实测（或本地 Prometheus + Alertmanager 等价验证）；变更模块行 + 分支覆盖率 100%。

## 3. 完成标准 <a id="accept"></a>

- 规则文件可被 `promtool check rules` 通过，指标引用不悬空；
- P0~P3 分级、抑制、恢复通知配置完整，P0/P1 映射 `critical`、P2/P3 映射 `warning`；
- 每条告警有 summary / description / runbook / dashboard，可行动；
- Grafana 看板可展示四张核心卡与趋势，06-1 概览页跳转可用；
- 接入 bms Alertmanager 后可触发与恢复（证据登记测试记录）；
- 阈值占位明确标注待平台级容量实测回填，未把未实测值写成结论。
