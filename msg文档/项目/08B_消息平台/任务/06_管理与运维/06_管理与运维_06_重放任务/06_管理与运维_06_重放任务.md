## 3. 任务内容 <a id="content"></a>

1. **复用已交付能力**：01-6 已交付任务化重放——按 offset / 时间 / key 创建、限速、暂停、恢复、取消、进度查询、`msg:manage`、审计；本任务不重做执行器、不改 `msg_replay_task` 既有字段语义。
2. **任务列表**：新增 `GET /api/v1/msg/admin/replay`，按状态 / 主题 / 时间过滤，分页返回任务摘要与进度；既有 `GET /admin/replay/{task_id}` 保持。
3. **影响可见**：重放任务详情展示目标消费组的积压变化——创建时记录受影响组与基线积压，详情返回基线 / 当前 / 变化值；组范围按主题订阅关系解析，不要求调用方逐个指定。
4. **状态同步**：死信重放（06-5）经 01-6 创建的任务在终态回写死信状态；本任务提供任务终态查询 / 影响视图，不重复实现状态机。
5. **页面**：死信与重放页“重放任务”页签——创建表单（条件 / 分区 / 速率 / 二次确认）、任务列表、详情（进度 / 影响 / 暂停 / 恢复 / 取消）；与死信页签共用页面骨架。
6. **权限**：创建 / 暂停 / 恢复 / 取消 `msg:manage`，查询 `msg:query`；批量重放二次确认的前端交互在本域实现，后端 `confirm` 强制由 06-2-1 补；审计沿用 01-6 的创建 / 取消 / 终态留痕。
7. **边界**：不改变原 `message_id`，重放仍分配新 `log_id`；不绕过消费端幂等；不做跨租户重放；不重做限速算法。
8. **测试**：列表过滤 / 分页；影响基线 / 当前值；死信任务终态回写；页面创建 / 暂停 / 取消交互；权限与二次确认；与 01-6 既有用例回归；变更模块行 + 分支覆盖率 100%。

## 4. 完成标准 <a id="accept"></a>

- 重放任务可列表查询，既有单任务详情契约不变；
- 任务详情可见目标消费组积压基线 / 当前 / 变化；
- 死信重放任务终态可回写死信状态；
- 页面可创建、暂停、恢复、取消并展示进度与影响；
- 权限、二次确认、审计与 01-6 口径一致；
- 变更模块行 + 分支覆盖率 100%，静态检查全绿。
