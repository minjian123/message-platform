## 2. 实施过程 <a id="process"></a>

| 序 | 动作 | 结果 |
| --- | --- | --- |
| 1 | 契约 | `schemas/dead_letter.py`：`DlqItem` / `DlqDetail`（含 `detail` 失败上下文）/ `DlqList` / `DlqReplayRequest`（`confirm` + `rate_per_second` 1~1000，缺省 100）/ `DlqIgnoreRequest`（原因 1~256，基座 `str_strip_whitespace` 兜底全空白）/ `DlqArchiveRequest`（原因可选、空白归一为 `None`）/ `DlqDisposeResult` |
| 2 | 端点 | `api/admin/dlq.py` 五个端点：`GET /admin/dlq`（七项筛选 + 分页）、`GET /admin/dlq/{id}`、`POST .../replay`、`POST .../ignore`、`POST .../archive`；统一挂 `msg:query` / `msg:manage` 依赖，查询按 ACL `describe`、处置按 `manage` 逐行鉴权 |
| 3 | 确认与前置 | 三处置端点统一 `_require_confirm()`（缺失记 `msg_dlq_confirm_missing` 并回 `10001`）；重放前按原分区 / offset 取原记录，缺失回 `350031`；状态迁移只经 `DeadLetterService` |
| 4 | 重放编排 | 复用 01-6 `ReplayService.create()` 建单条任务（`partitions=[partition]`、`offset_from=offset`、`offset_to=offset+1`、`rate_per_second`），成功后 `mark_replaying` 写任务 ID；任务审计沿用 `ReplayAuditor.record_created` |
| 5 | 审计动作 | `audit/trail.py` 新增 `msg:dlq.replay` / `msg:dlq.ignore` / `msg:dlq.archive` 三个动作（记录级强审计，`record_ref=msg.message/log_id`，附原因 / 速率 / 任务 ID） |
| 6 | 错误码 | `errors.py` 新增 `MsgDeadLetterNotFoundError`（350029）/ `MsgDeadLetterInvalidStateError`（350030）/ `MsgDeadLetterNotReplayableError`（350031）；`msg.toml` `[[errcodes]]` 同步；HTTP 映射 404 / 409 / 409 |
| 7 | 路由与装配 | `api/router.py` 挂载死信路由；`main.py` 装配持久化队列与启动恢复；契约快照 `ops.contract_snapshot export` 重导，`@msg/api-types` 再生成 |
| 8 | 前端服务层 | `admin-service.ts`：`fetchDeadLetters` / `fetchDeadLetter` / `replayDeadLetter` / `ignoreDeadLetter` / `archiveDeadLetter` + `loadDeadLetters` 投影取数器；类型全部取 `@msg/api-types` |
| 9 | 前端页面 | `DlqPage.vue`：筛选（状态 / 原因 / 主题 / 分区 / 时间窗 / 关键字）、列表（状态标签、原因文案、详情入口）、详情抽屉（基本信息 + 失败上下文 JSON）、处置确认（重放速率、忽略 / 归档原因、影响范围、状态前置按钮）、无 `msg:manage` 隐藏操作列；重放任务列表占位归 06-6 |

| 11 | 原型 | `07_原型设计_死信与重放.html` 补列表 / 详情 / 处置确认 / 无权限四场景深链（`?scene=list|detail|dispose|denied`）；处置弹窗标题改为函数调用（原写成函数引用，界面显示源码） |

## 3. 遇到的问题与处置 <a id="issues"></a>

| # | 现象 | 根因 | 处置 |
| --- | --- | --- | --- |
| 1 | 前端用例 `document.body` 里找不到表格与按钮 | `mount()` 默认挂到游离节点，未进 `document.body`；弹窗内容因 teleport 在 body，产生「部分可见」假象 | 用例统一 `attachTo: document.body`，`afterEach` 先卸载再清 body |
| 2 | ElInput 的 `data-test` 选择器取不到 textarea | Element Plus 把透传属性落在内层 `textarea` | 选择器改为 `textarea[data-test="..."]` |
| 3 | 详情请求断言失败（实际多传了 `{}`） | 服务层统一 `toParams()`，无参数也传空对象 | 断言按 `('/admin/dlq/101', {})` 锁定 |
| 4 | 忽略原因「全空白」的契约校验分支不可达 | 基座 `BaseSchema` 已开 `str_strip_whitespace`，空白先被剥成空串并被 `min_length` 拦下 | 删除重复的 `field_validator`（行为不变：仍回 `10001`），覆盖率不留死代码 |
| 5 | 死信页旧用例仍断言占位表与「进入不取数」 | 06-1-2 交付时端点未就绪，页面为占位 | 更新为「进入即取数、空态渲染」，无权限仍断言两处 denied |
| 6 | 原型处置弹窗标题显示 `function dialogTitle() {...}` | 模板写成 `:title="dialogTitle"` 传了函数引用 | 改为 `:title="dialogTitle()"`，浏览器复核标题为「重放死信 / 忽略死信」 |
| 7 | 死信页既有测试文件 `admin-pages.spec.ts` 未随页面改造 | 页面从占位改为真实取数，旧断言过时 | 同批更新断言，未改变其它页面逻辑 |
| 8 | 前端 lint 报两处存量未使用变量 | 06-1-2 交付时遗留 | 顺手修复（`page` 未使用、`ElDialog` / `ElInputNumber` 未使用），不涉及业务逻辑 |
