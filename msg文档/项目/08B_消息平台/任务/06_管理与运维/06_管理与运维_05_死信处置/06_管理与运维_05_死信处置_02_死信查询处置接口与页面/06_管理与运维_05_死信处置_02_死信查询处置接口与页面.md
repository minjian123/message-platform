## 2. 任务内容 <a id="content"></a>

1. **查询接口**：新增 `GET /api/v1/msg/admin/dlq`，按状态 / 原因 / 主题 / 分区 / 时间过滤，分页 `page` / `size`；返回死信摘要（`id` / 原因 / 重试次数 / 原 offset / `message_id` / `log_id` / 状态 / 时间）；新增 `GET /api/v1/msg/admin/dlq/{id}` 返回详情与失败上下文。
2. **重放处置**：新增 `POST /api/v1/msg/admin/dlq/{id}/replay`，要求 `confirm=true` 与速率上限；复用 01-6 已交付的任务化重放，按该死信所在分区 / offset 区间创建单条任务（06-6 只在其上补影响可见与页面）；任务创建成功把死信置 `replaying` 并记录 `replay_task_id`；任务终态回写——`completed` → `resolved`，`failed` / `cancelled` → `pending`（再次失败回 pending），由状态同步器或查询时惰性回写。
3. **忽略处置**：新增 `POST /api/v1/msg/admin/dlq/{id}/ignore`，**原因必填**（非空、长度上限）；状态置 `ignored`，记录处置人 / 时间 / 原因；缺原因返回参数错误。
4. **归档处置**：新增 `POST /api/v1/msg/admin/dlq/{id}/archive`，状态置 `archived`，从活跃列表隐藏；原始消息仍在日志保留期内可查；归档不删除记录。
5. **权限与审计**：查询 `msg:query`，replay / ignore / archive `msg:manage`；全部处置写基座审计链（强审计 + `record_ref`：死信 ID + `log_id`）；审计失败按 05-4 口径处置。
6. **指标与告警**：死信总数 / 增长 / 处置结果接 06-3 指标；死信增长触发 P2 告警；处置失败与重放再次失败有指标 / 日志。
7. **页面**：死信与重放页“死信”页签——列表筛选、详情抽屉、重放 / 忽略 / 归档入口；高危与批量操作二次确认，展示影响范围；无 `msg:manage` 不渲染处置按钮；空态 / 错误态 / 加载态完整。
8. **边界**：不删除原始日志；不做冷归档存储；不绕过 01-6 任务化重放直接写日志；不改 `nack` 契约。
9. **测试**：列表 / 详情 / 过滤 / 分页；重放创建任务与状态回写；忽略缺原因拒绝；归档隐藏；权限与审计 `record_ref`；死信指标；页面交互与原型对照；变更模块行 + 分支覆盖率 100%。

## 3. 完成标准 <a id="accept"></a>

- 死信可按状态 / 原因 / 主题 / 时间查询，详情含失败上下文；
- 重放复用 06-6 任务，状态 `replaying` → `resolved` / `pending` 可回写；
- 忽略必须填原因，归档后活跃列表隐藏；
- 处置有 `msg:manage` 与审计，`record_ref` 可定位到死信与 `log_id`；
- 死信增长接 P2 告警，处置失败可见；
- 页面逐页对照原型，变更模块覆盖率 100%。
