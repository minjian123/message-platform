## 1. 域说明 <a id="intro"></a>

- **覆盖范围**：08B 需求域 06 的 8 条需求——消息平台管理模块只读视图、写操作、指标与告警、链路追踪、死信处置、重放任务、主题授权界面、租户用量视图；依据《[架构设计 · 控制面：元数据与运维](../../../../设计/架构设计/06_架构设计_控制面_元数据与运维.md)》与 bms《[运维与可观测](../../../../../bms文档/资料/知识档案/消息与事件驱动/10_事件驱动_运维与可观测.md)》。
- **端范围**：后端控制面接口 + msg 前端模块页面（注册 `routes` 接入 bms 宿主，并注册 1 张概览工作台卡片与 1 个租户记录页 region）；指标图表不自绘趋势图，统一跳转 bms Grafana 看板。
- **术语口径**：本域统一称“**消息平台管理模块**”（不使用易与 bms 首页工作台混淆的旧称）；需求 06 与相关文档已同步改名。
- **已有基础（复用并补齐，不重做）**：`/admin/topics` 列表 / 详情 / 创建、`/admin/groups` 列表 / 详情（`committed` / `LEO` / `lag`）、`/admin/delayed` 待投列表、`/admin/replay` 任务化重放、配额查询 / 调整、主题授权端点、租户用量端点已由 01-4 / 01-5 / 01-6 / 05-2 / 05-3 / 05-1 交付；本域只补只读视图缺口、写操作缺口、指标告警、追踪、死信与重放影响可见、主题授权界面与租户用量视图。
- **执行顺序**：`06-3 指标与告警`（P1，先行）→ `06-1 管理模块只读视图`（前端骨架与只读页）→ `06-5 死信处置` → `06-6 重放任务` → `06-2 管理模块写操作` → `06-4 链路追踪` → `06-7 主题授权管理界面` → `06-8 租户用量视图`；具体见[阶段计划](../../计划/01_计划_消息平台.md)。
- **执行纪律**：界面类子任务开工前必须先补对应可交互原型；06-5 涉及新建表，须先改数据库表文件并在《数据库设计总览》登记，再改模型与建表；06-4 的客户端 span 归 bms 仓另立任务，本域只交 msg 侧头字段与消费契约。

## 3. 依赖与风险 <a id="dep"></a>

- **关键依赖**：bms 前端模块契约（`routes` / `cards` / `regions` / `i18nPacks` 与 `api.product`）；bms 可观测性栈（Prometheus / Grafana / Alertmanager，告警接入依赖 bms 08_02）；02-1 段删除、02-3 位点重置端口、02-6 `force_refresh()`、02-7 延迟区清理；01-4 / 01-5 / 01-6 已交付的只读端点与重放任务；05-3 主题授权端点；05-1 租户用量端点；bms 平台用户 / 角色查询接口（06-7 主体候选）。
- **风险**：① 前端页面直接操作 bms 宿主内部状态会违反模块契约——只注册 `routes` / `cards` / `regions`，经注入的 `api.product('msg','msg')` 取数；② 指标标签基数失控——只按 `service` / `tenant` / `topic` 聚合，`partition` / `group` 明细走管理模块；③ 删主题异步清理部分失败——清理任务须幂等、可重试、留台账与审计，不得阻塞请求；④ 死信表与重放影响字段属新增表结构——先改表文件再模型，表文件 ↔ 总览 ↔ 目录一致性校验通过；⑤ 06-4 的客户端 span 不在本仓，须在 bms 任务交付前明确契约，不得让 msg 仓假装端到端已完成；⑥ 06-7 的主体候选依赖 bms 平台 `user:query` / `role:query`，操作人无对应权限时须降级手填主体标识，不得阻断 `msg:manage` 授权；⑦ 06-8 的租户用量页与 05-2 配额页签存在数字重叠——固定分工为「用量页看四列总量、配额页签看限额与软硬限状态」，同源于 05-1 端点，不重复计算。
