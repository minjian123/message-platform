## 3. 问题与处置 <a id="issues"></a>

| # | 现状与偏差 | 处置 |
| --- | --- | --- |
| 1 | 05-1 `/tenant-usage` 返回裸 JSON 且不挂权限依赖，宿主产品通道强制解包信封，浏览器直连必然抛业务错误；模块隔离护栏 R4 又禁止自建 HTTP 与自拼前缀 | 拍板新增同源管理面端点（统一响应 + `msg:query`），不改 05-1 端点；取数装配提升为公共函数，口径仍只有一份 |
| 2 | 指标卡把非数字 `value` 判为空值并渲染 `—`，前端若先做千分位 / 单位换算再传字符串，会把所有数值显示成占位符 | 计数改为传原始数字 + `format='number'`；字节列用 `splitBytes` 拆成数值与单位分别传入；「非整数保留一位」下沉到 `splitBytes`，避免指标卡按 `number` 输出三位小数 |
| 3 | 指标卡占位态整卡只渲染一句降级文案，会丢掉列名与口径，单列不可用时四卡结构不一致（实现快照对照时发现） | 改为 `#degrade` 插槽自绘「标题 / 暂不可用 / 脚注」，与其余三卡同构 |
| 4 | 指标卡每张自带「刷新」按钮，四张并列在独立页与页签内都多余，页签内还挤占宽度 | scoped `:deep(.bms-metric-card__refresh)` 隐藏卡内入口，刷新统一由页面 / 页签传参触发 |
| 5 | 首次加载时列名未知（尚无 `columns`），按原设计渲染四卡会出现零卡或空区 | 首次加载（`state='loading'` 且无行）渲染四块 `el-skeleton`；刷新（已有行）保留旧值，不把数字换成加载文案 |
| 6 | 页签的统计租户口径来自登录态（`X-Tenant-ID`），与记录页租户可能不同，易被误读为「记录页租户的用量」 | 页签显式提示「按当前登录租户统计」并给出记录页租户标识对照；不改 05-2 已交付页签（按拍板只动新页签） |
| 7 | 实现快照只引用 Element Plus 样式，指标卡为产品组件自带样式，快照里布局退化（四卡堆叠、刷新按钮裸露） | 快照页补 `--bms-*` 变量回退与指标卡 / 页面 scoped 规则的等价还原，使快照可读；真实视觉仍以产品组件为准，测试记录注明该前提 |
| 8 | 页签刷新按钮文案为既有通用键「重新加载」，与原型「刷新」字面不同 | 沿用既有通用文案（与 06-7 同口径的已登记偏差），不新增近义键 |

## 6. 偏差与遗留 <a id="leftover"></a>

| # | 项 | 去向 |
| --- | --- | --- |
| 1 | 05-1 端点仍无服务端权限校验（平台投影以服务身份读取），浏览器直连可读当前租户用量 | 平台投影通道权限模型（bms），非本任务范围 |
| 2 | 页签展示的是登录租户用量，与记录页租户可能不同；仅提示不做上下文切换 | 需求 06-8 边界（跨租户不在本期） |
| 3 | 「今日投递量」为进程内 UTC 日计数，服务重启清零 | 8B_05 持久化 |
| 4 | 消息存储采集失败时显示「暂不可用」，看不出水位趋势 | 05-1 既有口径 |
| 5 | 趋势图不在页面自绘，`GRAFANA_OVERVIEW_URL` 当前为空，页面无跳转入口 | 部署期配置 |
| 6 | 字节单位封顶 TiB（超过仍以 TiB 显示） | 与配额页签一致 |
| 7 | 前端门禁不在 msg 预检步骤表内，依赖本地逐条执行 | 工程化（engkit） |
| 8 | 两个页签提示口径不一致（用量页签有「按当前登录租户统计」，配额页签没有） | 后续统一（本任务按拍板不动 05-2） |
| 9 | 页签与独立页刷新文案沿用「重新加载」，与原型「刷新」字面不同 | 既有通用文案口径，与 06-7 同类偏差一致 |
