## 1. 实施范围与顺序 <a id="scope"></a>

依[详细设计](../设计/01_详细设计_06-1-2_前端管理模块骨架与只读页面.md)执行。顺序：`口径引用 → engkit 前端护栏 → 产品前端基类清单与契约 → 六页原型 → 详细设计 → Kiwi 登记（2464）→ 编码 → 用例 → 原型逐页截图 → 门禁 → 登记回写`。原型经用户「继续」指令确认定稿后进入设计与编码；用例先登记平台编号再落文件。

跨仓改动按仓独立：`bms` 只加一行条文引用；`engkit` 新增前端基类检查器；`msg` 承载全部前端代码、文档与测试资产。`bms/frontend/packages/core`、`ui_ep`、宿主装配源码与 `packages/api-types/src/` 生成物零改动。

## 3. 关键实施决策 <a id="decisions"></a>

| # | 事项 | 决策 | 依据 |
| --- | --- | --- | --- |
| 1 | 基类分轨 | msg 自建主体功能走继承轨，产品自持清单 + 契约 §7；`defineModule` 只是宿主接入机制 | bms《前端开发规范》§3.1「必须从根派生（强制 · 零例外）」、《后端开发规范》架构铁律；用户纠正 |
| 2 | 口径回写 | bms 三份基座规范恢复原文，仅《AI开发规范》铁律块加一行条文引用 | 用户最终拍板 |
| 3 | 卡片注册形态 | `new WorkbenchCardProvider('msg:overview-card', loader, '消息平台概览')`，非普通对象 | `assemble.ts` 直接把 `cards` 元素当 provider 注册 |
| 4 | 详情路由 | `meta.menu === false` 的路由不进菜单但宿主仍注册路由；主题详情路径按 `topic_id` 定位 | `assemble.ts` / `host.ts` 源码核对；详情端点路径参数 |
| 5 | 分区页 | 接口必填 `namespace` + `topic`，无全平台列表端点，故做「先选主题」查询页，未选为待选条件态 | 契约快照 `parameters` |
| 6 | 死信与重放 | 无只读列表端点，按空表 + 后续任务占位实现，不造端点、不伪造示例数据 | 06-1-1 交付范围；原型只读形态 |
| 7 | 类型迁移 | 删除 `domain.ts`，页面 / 服务 / 存量配额面板一律 `import type { msg } from '@msg/api-types'`，不留 re-export 兼容层 | 第 3 项确认 |
| 8 | 权限 | 路由与菜单由宿主守卫按 `meta.perm` 判定；模块内只按注入用户权限集合做展示层判定 | 宿主 `guard.ts` 与模块契约 |
| 9 | 体积预算 | 页面 / 卡片各自独立异步块；实测入口闭包 13.3 KB 未膨胀，阈值按实测取整留余量 | 第 8 项确认 |
| 10 | 覆盖率 | 纯模板 / 纯声明用「可挂载 / 可解析」护栏用例；显式 `--coverage.include` 列出改动文件，不用 `pragma` 与 `omit` | 第 11 项确认 |

## 4. 事实偏差与处置 <a id="deviations"></a>

| # | 发现 | 处置 |
| --- | --- | --- |
| 1 | `tests/module.spec.ts` 原断言「routes 为空」 | 随九路由注册改为「九路由 + 一卡片」，编号 2454 不改派 |
| 2 | `cards?: unknown[]` 但装配器要求 provider 实例 | 改用 `WorkbenchCardProvider`；`admin-routes.spec.ts` 断言实例类型 |
| 3 | 死信 / 重放任务列表端点缺失 | 占位空表 + 引导文案；测试记录逐页对照登记为已登记偏差 |
| 4 | `MessageItem` 无顶层 `trace_id`、`DelayedItem` 无该字段 | 消息头在 `headers` 详情展示；延迟列显示 `—` 占位；不新增契约字段 |
| 5 | 装载 `@msg/api-types` 后 `QuotaView.items` 可空、`ElTable.data` 不接受 `readonly` 数组 | 解包处 `?? []` 兜底；投影 `rows` 产出可变数组副本 |
| 6 | 原型 06 页示例行 | 明确归 06-5 / 06-6 补端点后接线，本轮不伪造数据 |
| 7 | 原型内联样式引用未定义的 `--bms-*` 变量，`proto-table` / `proto-button` / `proto-header` / `proto-main` 等公共类无定义（页面无边框、控件无外观） | 新增 `设计/原型设计/资源/原型样式.css`（令牌 + 公共类，色板对齐 bms / mdm 原型），八份原型统一引用；修激活按钮配色与状态徽标语义类，七张原型截图重取 |
| 8 | 公共类补样式后仍与正式组件观感差异明显（手写表格 / 按钮 / 分页 / 状态徽标），与 bms / mdm 原型「真实组件库渲染」的做法不一致 | 六页（03~08）整体改为 bms 同款本地 vendor 的 Vue 3 + Element Plus 真组件渲染：`el-menu` / `el-form` / `el-table` / `el-pagination` / `el-alert` / `el-result` / `el-skeleton` / `el-empty` / `el-card` / `el-descriptions`；`资源/原型样式.css` 收缩为外壳与布局类；新增 `?scene=<状态>` 深链便于评审与截图；十一张原型截图重取。02 配额管理属 05-2 交付物，本轮不改 |
