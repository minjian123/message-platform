## 2. 用例清单 <a id="cases"></a>

单用例「生成 / 零漂移 / 漂移判定 / 缺失判定 / 门禁登记」（`frontend/modules/msg/tests/api-types-generation.spec.ts`）内串行执行以下断言：

| # | 断言 |
| --- | --- |
| 1 | 契约快照存在；生成物头注含来源文件名与「请勿手工修改」 |
| 2 | 四条新只读端点路径在 `src/msg.ts` 的 `paths` 中；`src/index.ts` 按域名空间导出 |
| 3 | 连续两次 `generate` 逐字节一致；生成物 LF、末尾单换行 |
| 4 | `--check` 无漂移通过；从仓根作为工作目录调用仍通过，输出含 `info.version` |
| 5 | 人为改坏生成物后 `--check` 退 2 并打印首处差异行号 |
| 6 | 删掉 `index.ts` 后 `--check` 退 2 并提示「缺少生成物」，不自动补写 |
| 7 | 所有写操作在 `finally` 中恢复现场，恢复后 `--check` 仍通过 |
| 8 | `engkit.toml` 登记了 `--check` 步骤与 `cwd = "frontend"`，且与 `contract_snapshot check` 并列 |
| 9 | 用例在 vitest 多 worker 并行环境下不产生共享文件竞态（单用例串行 + `finally` 恢复现场） |

## 4. 问题与处置 <a id="issues"></a>

| # | 现象 | 处置 |
| --- | --- | --- |
| 1 | 首版拆成六个用例，在并行下 `test_generate_is_idempotent_and_lf` 偶发读到被其它用例改写的生成物 | 合并成单用例串行执行，所有写操作包在 `try/finally` 内恢复；第二次预检后未再复现 |
| 2 | `Path.write_text(..., newline="\n")` 在 Windows 下可能落成 CRLF | 显式传 `newline="\n"`；恢复现场用 `write_bytes` 保留原字节 |

## 5. 偏差与遗留 <a id="leftovers"></a>

- 生成器只覆盖 `msg.json` 一份快照；新增服务契约时需按同一形态扩展。
- 存量手写 `domain.ts` 的迁移、生成物进入构建体积预算的判定归 06-1-2。
- 三仓生成器脚本尚未统一到基座，属工程化专项，不在本任务范围。
