## 3. 关键命令 <a id="commands"></a>

```text
cd frontend
pnpm install --offline --ignore-scripts
node packages/api-types/scripts/generate.mjs
node packages/api-types/scripts/generate.mjs --check
pnpm run api-types:check
```

## 4. 问题与处置 <a id="issues"></a>

| # | 现象 | 根因 | 处置 |
| --- | --- | --- | --- |
| 1 | 直接跑生成器报 `ERR_MODULE_NOT_FOUND: openapi-typescript` | pnpm 严格隔离，新包未声明依赖就没有符号链接 | 新包声明 `^7.13.0`（与 bms / mdm 同版本），`pnpm install --offline` 复用已有 store |
| 2 | `pnpm-workspace.yaml` 无需改动 | 工作区已声明 `packages/*`，新包自动纳入 | 回写详细设计 §2 / §5.2，去掉「追加 packages 列表」的表述 |
| 3 | 生成物实际是两份（`msg.ts` + `index.ts`） | mdm 同款形态按域名空间导出 | 回写详细设计 §4.1，生成物与零漂移比对都覆盖两份 |
| 4 | `--check` 用例在并行下偶发 `first != second` | 多个用例并发改写 / 删除同一份生成物 | 合并为单用例串行执行 + `finally` 恢复现场；既消除竞态又符合「一条用例一个编号」口径 |
| 5 | CI 首跑后端 job 执行该用例报 `ERR_MODULE_NOT_FOUND`（`node` 在 `python:3.14-slim` 里跑不到前端依赖） | 用例跨端：后端 job 测前端生成器 | 按「前端测试只放前端、后端测试只放后端」整体迁入前端 vitest（`frontend/modules/msg/tests/api-types-generation.spec.ts`，Kiwi 2463 沿用），后端 pytest 删除该文件 |
