## 1. 任务边界与已确认口径 <a id="scope"></a>

**本任务做什么**

1. 补 `msg文档/设计/原型设计/09_原型设计_主题授权.html`（9 场景），并同步总览与 02~08 原型页导航入口。
2. 在 msg 前端模块注册「主题授权」菜单路由（`/msg/acls`，路由名 `msg.acl`，`meta.title=主题授权`、`meta.group=消息平台`、`meta.icon=el:Key`、`meta.order=80`、`meta.perm=msg:manage`）。
3. 列表：分页展示命名空间、主题、主体类型、主体、动作、效果、状态、更新时间；支持命名空间 / 主题 / 主体类型 / 主体标识 / 动作 / 状态过滤；筛选与页码写入路由查询参数，支持深链与刷新保持。
4. 授予 / 更新：抽屉内规则行编辑器，单行即单条、多行即批量；命名空间可搜索、主题从主题列表接口搜索并自动带出命名空间、主体可选用户 / 角色、动作四类、效果允许 / 拒绝；整批提交 `PUT /api/v1/msg/admin/acls`。
5. 收回：行内收回 + 二次确认，调 `DELETE /api/v1/msg/admin/acls/{acl_id}`；软停用，已停用规则不显示收回。
6. 主体名称：优先经宿主注入的请求能力调 bms 平台用户 / 角色接口做搜索选择与批量名称解析；无 `user:query` / `role:query` 或接口失败时降级手填主体标识、列表显示标识并提示「名称暂不可用」。
7. 权限与隔离：页面、菜单、按钮挂 `msg:manage`；请求经宿主 `api.product('msg','msg')`，页面不自拼租户参数；错误码 `350001` / `350010` / `350027` / `10001` 按后端映射，`350027` 在本页明确「无目标主题的管理权限」。
8. 文案：页面标题、字段、动作、效果、状态、空态、确认与错误文案全部入模块 i18n；中文界面统一称「主题授权」。
9. 测试：组件 / 契约 / 服务用例，原型逐页截图对照，构建体积预算，变更模块行 + 分支 100%。

**不做什么**

- 不改 05-3 的端点、两表、判定顺序、缓存版本戳与审计；
- 不做授权变更历史页、通配符主题、预授权、批量导入 / 导出；
- 不在 msg 侧保存主体目录、不写入用户 / 角色名称；
- 不新建第二个 msg 前端模块、不自建 HTTP 客户端、不自拼 `/api` 前缀、不持久化凭据；
- 不做跨租户查询与租户切换；
- 不重做既有 06-1 / 06-2 / 06-5 / 06-6 页面，只统一取数 helper 与既有测试 mock。

## 4. 跨仓协同：bms 用户 / 角色列表 `ids` 过滤 <a id="bms-ids"></a>

### 4.1 为什么需要

任务要求「列表按主体标识批量解析名称（用户、角色各一次批量查询，避免逐行请求，即 N+1）」。ACL 行的 `principal_key` 是雪花主键十进制字符串，现有公开列表接口的关键字 `kw` 只匹配账号 / 姓名 / 邮箱 / 手机号或角色码 / 名称，**不能按主键过滤**；逐行 `GET /users/{id}`、`GET /roles/{id}` 即 N+1。

bms 仓储层已支持按 id 集合过滤（`UserRepository.list_filtered(ids=...)`、`RoleRepository.list_filtered` / `count_filtered(ids=...)`），只缺 API 参数与服务透传。按 [`AI开发规范`](../../../../../../../bms文档/规范/AI开发规范.md) 的跨仓协同口径，本任务做 additive 小改，并追加到既有任务记录。

### 4.2 接口口径

| 端点 | 新增参数 | 说明 |
| --- | --- | --- |
| `GET /api/v1/users` | `ids`（可选，字符串） | 逗号分隔用户主键；正整数；单次 ≤200；空串 / 纯逗号视为不过滤 |
| `GET /api/v1/roles` | `ids`（可选，字符串） | 逗号分隔角色主键；同上 |

- `ids` 与 `kw` / `status` 可组合；`page` / `size` 仍生效。
- 非法项（非数字、≤0）或超过 200 项 → `ParamError`（`10001`），不静默忽略。
- 响应结构不变（`BasePageResponse[UserItem]` / `[RoleItem]`），属**向后兼容新增**。

## 5. 取数层：产品域请求 helper 与既有服务统一修正 <a id="product-api"></a>

### 5.1 契约事实

bms 宿主请求层 `api.product(产品键, 域)` 的 `get/post/put/patch/del` **已经统一解包**：成功返回 `data`，业务码非 0 抛带 `code` 的错误（`ApiError`），401 由宿主刷新 / 跳登录。mdm 模块 `fetchPlatformUsers` / `fetchDeptTree` 均直接消费 `data`。

msg 既有 `admin-service.ts` / `quota-service.ts` 把返回当 `{code,data}` 再解包，属于历史偏差；测试 mock 信封掩盖了问题。

### 5.2 新增 `product-api.ts`

```ts
/** 产品键 / 命名空间（与平台产品登记同源）。 */
export const MSG_PRODUCT = 'msg'
export const MSG_NAMESPACE = 'msg'

/** 业务码错误（用于 `data` 为空等本地契约违背；宿主业务错误自带 code）。 */
export class MsgQueryError extends Error { readonly code: number }

/** 取产品域作用域。 */
export function productScope(): ModuleApiScope

/** 清理空查询参数（保留 0 / false）。 */
export function toParams(params?: object): Record<string, unknown>

/** 必填 data（null / undefined → MsgQueryError(10000)）。 */
export function requiredData<T>(data: T | null | undefined): T

/** GET / POST / PUT / PATCH / DELETE（直接返回宿主解包后的 data）。 */
export function getData<T>(path: string, params?: object): Promise<T>
export function postData<T>(path: string, body?: unknown): Promise<T>
export function putData<T>(path: string, body?: unknown): Promise<T>
export function patchData<T>(path: string, body?: unknown): Promise<T>
export function delData<T>(path: string, params?: object): Promise<T>
```

- 不吞错、不把业务码折成 `10001`；页面通过 `errorCodeOf(error)` 取码映射文案。
- `MsgQueryError` 仅用于「接口成功但 `data` 为空」这类契约违背；`admin-service` 重新导出以兼容既有引用。

### 5.3 既有服务迁移

| 文件 | 改动 |
| --- | --- |
| `admin-service.ts` | 删除本地 `scope` / `request` / `requestWrite` / `required`；改用 `getData` / `postData` / `putData` / `patchData` / `delData` / `requiredData`；导出函数签名与空数据兜底不变 |
| `quota-service.ts` | 同上；`updateQuotas` 去掉 `response.code` 判断，错误由宿主抛出 |
| `acl-service.ts` | 新建，按同一 helper 取数 |

## 8. 路由查询参数同步 <a id="query-sync"></a>

### 8.1 `useAdminRoute` 扩展

```ts
export interface AdminRouteState {
  path: string
  params: Record<string, string>
  query: Record<string, string>
  go: (path: string) => void
  replaceQuery: (query: Record<string, string>) => void
}
```

- `replaceQuery` 调 `router.replace({ path: route.path, query })`，不新增历史记录、不替换宿主路由表。
- 既有 `params` / `query` / `go` 行为不变。

### 8.2 主题授权页查询键

| 键 | 来源 | 写入 URL |
| --- | --- | --- |
| `namespace` | 筛选输入 | 非空时写 |
| `topic` | 筛选输入 | 非空时写 |
| `principal_type` | 筛选下拉 | 非空时写 |
| `principal_key` | 筛选输入 | 非空时写 |
| `action` | 筛选下拉 | 非空时写 |
| `status` | 筛选下拉 | 非空时写 |
| `page` | 分页 | `>1` 时写 |
| `size` | 页长 | `≠20` 时写 |

- 进入页面：从 `route.query` 读取白名单键，构造 `initialFilters` / `initialPage` / `initialPageSize`；非法 `page` / `size` 回落 1 / 20；枚举值不前端校验，交给后端（非法即错误态，保持单一事实源）。
- 应用筛选 / 重置 / 翻页：更新 `view` 后调用 `replaceQuery`。
- 刷新 / 深链：初始 query 直接作为首次加载参数，无需额外请求。

### 8.3 不做的部分

- 不监听浏览器前进 / 后退回填筛选（任务只要求深链与刷新保持）；
- 不改既有列表页的 URL 行为；
- 不把抽屉开关、编辑行等临时状态写入 URL。

### 9.1 `acl-service.ts`

| 导出 | 语义 |
| --- | --- |

### 9.2 `platform-directory.ts`

| 导出 | 语义 |
| --- | --- |
| `PLATFORM_SERVICE='platform'`、`USER_QUERY_PERMISSION='user:query'`、`ROLE_QUERY_PERMISSION='role:query'` | 常量 |
| `PlatformUserItem` / `PlatformUserPage` / `PlatformRoleItem` / `PlatformRolePage` | 取 `@bms/api_types` 的 `platform` 命名空间 |
| `searchPlatformUsers(keyword, size=20)` | `get('platform','/users',{kw,page:1,size})` |
| `searchPlatformRoles(keyword, size=20)` | `get('platform','/roles',{kw,page:1,size})` |
| `fetchPlatformUsersByIds(ids)` | `get('platform','/users',{ids: ids.join(','),page:1,size:ids.length})` |
| `fetchPlatformRolesByIds(ids)` | 同上 `/roles` |
| `mapUserNames(page)` / `mapRoleNames(page)` | `id → name`（用户取 `name`，空则 `username`；角色取 `name`） |

- 平台请求走宿主 `api.get('platform', ...)`，同样由宿主解包。
- 不缓存到模块级单例，避免跨租户 / 跨挂载泄漏。

### 9.3 主体目录投影 `usePrincipalDirectory`

| 状态 / 方法 | 语义 |
| --- | --- |
| `userNames` / `roleNames` | `Map<string,string>`（仅当前页面生命周期） |
| `userUnavailable` / `roleUnavailable` | 平台查询不可用 / 无权限；一旦置真，本页不再尝试该类型 |
| `resolving` | 批量解析中 |
| `resolve(rows, codes)` | 收集未缓存的主键；按权限码与可用性决定是否请求；成功后合并，失败置 `unavailable` |
| `label(type, key)` | 返回名称；未命中返回空串（页面显示标识 + 名称暂不可用） |
| `hasName(type, key)` | 是否已解析到名称 |

- 权限码已装载且缺 `user:query` / `role:query` → 直接置 `unavailable`，不发注定 403 的请求。
- 权限码未装载（`hostPermissions() === undefined`）→ 尝试请求；失败即降级。
- 同一页翻页 / 刷新：已缓存的主键不再重复请求；新主键再批量一次。
- 不持久化（无 localStorage / sessionStorage / cookie）。

### 10.3 筛选栏

- 命名空间（输入）、主题（输入）、主体类型（下拉）、主体标识（输入）、动作（下拉）、状态（下拉）、查询 / 重置。

- 过滤条件与 `AclQuery` 同名，不自造参数。

### 10.4 状态与反馈

- 五态复用 `ReadOnlyList`：`loading / empty / error / denied / ready`；无「待选条件」态。
- 无 `msg:manage`：`denied`，文案用页面级 `state.denied.manage`（不显示 msg:query）。
- 成功 / 无变化：页面顶部 `el-alert` 反馈条（`data-test="acl-feedback"`），下一次操作前清空。
- 错误：列表错误走 `error.<码>`；授予 / 收回错误在抽屉 / 确认框内展示，`350027` 用页面级文案。

### 10.5 行操作语义

| 行状态 | 操作 | 行为 |
| --- | --- | --- |
| `enabled` | 更新 | 打开抽屉编辑模式，锁定五字段，仅改 `effect`；提交同一唯一键 |
| `enabled` | 收回 | 二次确认 → `DELETE`；`changed=false` 提示「无变化」 |
| `disabled` | 重新授予 | 打开抽屉编辑模式，锁定五字段，仅改 `effect`；提示「提交后恢复启用」 |
| `disabled` | 收回 | 不渲染 |

- 更新 / 重新授予都走 `PUT`（后端唯一键 upsert；重复授予恢复 `enabled`）。
- 更新时若用户需要改主题 / 主体 / 动作，引导「收回后重新授予」，不提供跨唯一键的隐式迁移。

## 11. 授予抽屉、收回确认与校验 <a id="grant"></a>

### 11.1 抽屉模式

| 模式 | 入口 | 行数 | 字段 |
| --- | --- | --- | --- |
| `create` | 页面「授予授权」 | 1 行起，可增删 | 六字段全可编辑 |
| `update` | 行「更新」 | 固定 1 行 | 五字段锁定，仅效果 |
| `regrant` | 行「重新授予」 | 固定 1 行 | 五字段锁定，仅效果；提示恢复启用 |

### 11.2 规则行

```ts
interface AclGrantRow {
  uid: number
  namespace: string
  topic: string
  principalType: 'user' | 'role'
  principalKey: string
  principalLabel: string
  action: string
  effect: string
  error: string
}
```

- `AclNamespaceSelect`：`el-select` `filterable` `remote` `allow-create`；远程搜索 `fetchTopics({keyword,size:20})` 后取 distinct namespace；允许直接输入未出现在候选中的命名空间。
- `AclTopicSelect`：`el-select` `filterable` `remote`；搜索 `fetchTopics({namespace,keyword,size:20})`；选中后回传 `{name, namespace}`，行内自动填命名空间。
- `AclPrincipalSelect`：主体类型切换时重置；用户 / 角色搜索；无权限 / 失败切换手填；手填值只允许数字、≤64。
- 动作 / 效果：固定枚举下拉，中文文案。
- 每行右上角「删除」；最后一行不可删（至少保留一条）。

### 11.3 校验（提交前）

| # | 规则 | 错误键 |
| --- | --- | --- |
| V1 | 至少一行 | `msg.admin.acls.grant.empty` |
| V2 | 六字段非空 | `msg.admin.acls.grant.required` |
| V3 | 主体标识为数字且 ≤64 | `msg.admin.acls.grant.principalInvalid` |
| V4 | 同批六字段无重复 | `msg.admin.acls.grant.duplicate` |
| V5 | 命名空间 ≤64、主题 ≤200（与契约一致） | `msg.admin.acls.grant.required` |

- 校验逐行进行，错误写回 `row.error`；有任一行错误不提交。
- 提交请求：`{ items: rows.map(({namespace,topic,principalType,principalKey,action,effect}) => ({...})) }`，不含 `tenant_id`、不含 `uid` / `principalLabel`。

### 11.4 提交结果

| 结果 | 反馈 |
| --- | --- |
| 成功且 `changed.length > 0` | 关闭抽屉、刷新列表、反馈「授权已保存」 |
| 成功且 `changed.length === 0` | 关闭抽屉、刷新列表、反馈「无变化」 |
| 失败 | 保留抽屉，按 `error.<码>` 展示；`350027` 用页面级「无目标主题的管理权限」 |

### 11.5 收回确认

- 复用 `MsgConfirmDialog`；标题「收回授权」，危险色。
- 影响行：命名空间、主题、主体（名称 + 标识）、动作。
- 风险提示：「该主体将立即失去该主题该动作的授权」。
- 确认后 `DELETE`；`changed=true` → 「已收回授权」；`changed=false` → 「无变化」；失败按错误码文案。
- 已停用规则不渲染收回按钮，后端幂等仍兜底。

## 12. 失败分支、权限与降级 <a id="failure"></a>

### 12.1 权限

| 层 | 权限 | 说明 |
| --- | --- | --- |
| 菜单 / 路由 | `msg:manage` | `meta.perm`，宿主守卫拦截 |
| 页面状态 | `msg:manage` | 投影 `permission`，缺码显示 denied |
| 列表 / 写入 | `msg:manage` | 后端端点校验 |
| 目标主题 | `manage` | 后端 `PUT` / `DELETE` 另判；前端不预判 |
| 用户 / 角色查询 | `user:query` / `role:query` | 仅用于候选与名称；缺码降级手填，不阻断授权 |

### 12.2 错误码映射

| 码 | 场景 | 文案键 |
| --- | --- | --- |
| `350001` | 主题不存在 / 不属于当前租户 | `error.350001` |
| `350010` | 命名空间未登记 / 未启用 | `error.350010` |
| `350027` | ACL 拒绝 | 列表等通用：`error.350027`（中性）；本页授予 / 收回：`msg.admin.acls.error.350027`（无目标主题的管理权限） |
| `10001` | 参数非法 | `error.10001` |
| `30001` | 无权限 | `error.30001` |
| 其他 | — | `error.fallback` |

- 全局 `error.350027` 改为「无目标主题的授权（该操作被拒绝）」，避免 describe 场景被误读为 manage。
- 页面级键只在授予 / 收回 / 重新授予的错误展示处使用。

### 12.3 降级

| 场景 | 行为 |
| --- | --- |
| 权限码已装载且缺 `user:query` / `role:query` | 主体选择直接手填；列表不请求批量解析，显示标识 + 名称暂不可用 |
| 权限码未装载，搜索失败 | 该类型切手填 + 提示；不影响另一类型 |
| 列表批量解析失败 | 仅名称不可用；列表、筛选、授予、收回均可用 |
| 平台接口返回部分命中 | 命中显示名称，未命中显示标识 + 名称暂不可用 |
| 主题候选接口失败 | 主题下拉可手输主题名；命名空间仍可手输（不阻断授权） |
| 宿主请求能力缺失 | 页面显示错误态（`error.fallback`），不白屏 |
