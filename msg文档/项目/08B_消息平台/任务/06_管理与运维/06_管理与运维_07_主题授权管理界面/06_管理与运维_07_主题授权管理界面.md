## 2. 任务内容 <a id="content"></a>

1. **原型先行**：补 `msg文档/设计/原型设计/` 下页面 09「主题授权」可交互原型（列表、授予抽屉、收回确认），并更新总览链接与状态；原型定稿后才进入详细设计与实现，验收按原型逐页截图对照。
2. **页面与路由**：在 msg 前端模块注册「主题授权」菜单路由（路径 `/msg/acls`，路由名 `msg.acl`），`meta.title` 为「主题授权」、`meta.group` 归入消息平台管理模块、`meta.icon` 复用宿主图标键；权限码 `msg:manage`。详情 / 抽屉不进菜单。
3. **列表**：分页展示命名空间、主题、主体类型、主体、动作、效果、状态、更新时间；支持命名空间 / 主题 / 主体类型 / 主体标识 / 动作 / 状态过滤；过滤条件写入路由查询参数，支持深链与刷新保持；空态、错误态、加载态完整。
4. **授予与更新**：抽屉表单支持单条与批量规则；命名空间可搜索，主题从 01-4 的主题列表接口可搜索选择并自动带出命名空间；主体选用户或角色；动作取发布 / 订阅 / 描述 / 管理；效果取允许 / 拒绝。提交调 `PUT /api/v1/msg/admin/acls`，整批成功 / 失败；成功后刷新列表并提示，幂等未变更时明确提示「无变化」。
5. **收回**：行内收回并二次确认，确认文案说明「该主体将立即失去该主题该动作的授权」；调 `DELETE /api/v1/msg/admin/acls/{acl_id}`；已停用规则不显示收回按钮。收回为软停用，界面按状态区分「已启用 / 已停用」。
6. **主体选择与名称解析**：优先经宿主注入的请求能力调 bms 平台用户 / 角色查询接口做可搜索选择；列表按主体标识批量解析名称（用户、角色各一次批量查询，避免逐行请求，即 N+1）；无 `user:query` / `role:query` 权限或接口失败时降级为手填主体标识，列表显示标识并给出「名称暂不可用」提示。主体名称不写入 msg 库，不在 msg 侧自建用户 / 角色目录。
7. **权限与隔离**：页面、菜单与按钮挂 `msg:manage`（与 05-3 列表端点同码）；请求经宿主 `api.product('msg','msg')`，租户上下文由宿主注入，页面不自拼租户参数；不提供跨租户查询。错误码 `350001` / `350010` / `350027` / `10001` 按后端映射展示，`350027` 明确提示「无目标主题的管理权限」。
8. **文案与审计**：页面标题、字段、动作、效果、状态、空态、确认与错误文案全部入模块 i18n；中文界面统一称「主题授权」，不出现英文缩写。授予 / 更新 / 收回的强审计由后端写，前端只展示结果，不重复写审计。
9. **边界**：不改 05-3 的端点、两表、判定顺序、缓存版本戳与审计；不做授权变更历史页（历史在 bms 审计链查询）；不做通配符主题、不做预授权、不做批量导入 / 导出；不新建第二个 msg 前端模块。
10. **测试**：组件用例覆盖列表过滤 / 分页 / 空态 / 错误态 / 权限态、授予表单校验 / 批量提交 / 幂等无变化、收回二次确认、主体选择与名称解析失败降级；模块契约用例覆盖路由、菜单、权限码与 i18n；原型逐页截图对照并登记测试记录；构建体积预算；变更模块行 + 分支覆盖率 100%。

## 3. 完成标准 <a id="accept"></a>

- 原型页面 09 已补齐并登记，页面按原型逐页对照通过；
- 主题授权页可列表、过滤、授予 / 更新、收回，操作后即时刷新；
- 主体可选用户或角色，列表名称可读；无平台查询权限时降级手填且不阻断授权；
- 权限、租户隔离、错误码文案与 05-3 契约一致；
- 未改后端、未在 msg 侧保存主体目录、未做授权变更历史页；
- 组件与契约测试全绿，变更模块行 + 分支覆盖率 100%，文档三项校验通过。
