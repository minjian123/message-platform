| 9 | 三个选择件 | `AclNamespaceSelect`（命名空间候选 + 手填）、`AclTopicSelect`（远程搜索并回带命名空间）、`AclPrincipalSelect`（平台用户 / 角色搜索，缺权限或失败降级手填数字主键，附「名称暂不可用」与校验提示） |
| 10 | 骨架扩展 | `BaseMsgReadOnlyView` 构造增 `permission`（主题授权页挂 `msg:manage`）与 `replaceFilters()`；`useMsgReadOnlyView()` 增 `permission` / `initialPage` / `initialPageSize` / `setFilters()`；`useAdminRoute()` 增 `path` 与 `replaceQuery()` |

## 3. 问题与处置 <a id="issues"></a>

| # | 问题 | 处置 |
| --- | --- | --- |
| 1 | 既有 `admin-service` / `quota-service` 按 `{ code, data }` 信封二次解包，真实宿主已解包，页面会读到 `undefined` | 新增 `product-api.ts` 统一入口并迁移两处；测试 mock 改 `wrapScope()` 模拟宿主解包（不掩盖缺陷） |
| 2 | 主体名称解析原计划逐行查询，会产生 N+1 | 规划阶段拍板：bms `/users`、`/roles` 增 `ids`，每页用户 / 角色各一次批量请求（单次 ≤200） |
| 3 | 收回确认影响表第二列显示「数量」，与原型「内容」不一致（值为主题名 / 主体标识等） | 共享键 `msg.admin.confirm.impactValue` 改「内容 / Content」（逐项确认后执行），全站语义统一 |
| 4 | 名称降级时主体列显示「7001 名称暂不可用 7001」，标识重复 | 主体列改为「名称 或 名称暂不可用」+ 标识两行，与原型 09 降级场景一致；收回影响行同步改「名称暂不可用（标识）」 |
| 5 | 实现快照缺少组件库样式，表格行不可见，无法与原型对照 | 快照页补基座 `element-plus.css` 相对路径与页面关键局部样式；同时补齐授予 / 批量 / 收回 / 降级 / 无权限 / 错误态快照 |
| 6 | 既有实现快照每次重跑都因 `el-id-*` 与滚动类名产生噪声 diff | 本次只保留 06-7 新增快照；其余任务快照从工作树还原，不夹带无关改动 |
| 7 | 覆盖率为 0 的两处：`AclPrincipalSelect` 初始已选值的两个占位分支、`AclPage` 收回影响行名称降级分支 | 补「初始已选值有 / 无名称」与「收回名称降级」用例后回到 100% |
| 8 | msg 侧 `pnpm install` 后 bms `@bms/desktop` 构建报 `ComputedRef` 不匹配（存量失败） | 根因：`msg/frontend/pnpm-workspace.yaml` 为解析包内 `workspace:*`，把 `../../bms/frontend/packages/*` 声明为工作区成员；msg 装依赖时 pnpm 会把 bms 这几个包的 node_modules 重建并链接到 **msg 的 store**（vue 3.5.45 / vue-tsc 3.3.14 / element-plus 2.14.8），bms 侧出现两份 Vue 类型。按 `还原依赖 → pnpm install → 外置依赖` 修复后 desktop 构建通过；并给 bms `scripts/tools/deps/重装依赖.py` 增加安装前自愈（检出指向本仓外 `.pnpm` 的 node_modules 整目录删除，按本仓 lockfile 重建），实测模拟污染后一次重装即恢复 vue 3.5.43 |
