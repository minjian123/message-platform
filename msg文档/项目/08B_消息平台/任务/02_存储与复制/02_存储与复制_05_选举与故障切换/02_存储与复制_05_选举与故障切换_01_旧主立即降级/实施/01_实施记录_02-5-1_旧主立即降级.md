## 2. 落实的口径 <a id="decisions"></a>

| # | 事项 | 落实 |
| --- | --- | --- |
| 1 | 修法 | 取方案乙：通知重发 + 水位后置 + 未确认停写可查（不中止切换） |
| 2 | 通知预算 | 单次 `300ms`、最多 2 次（`DEMOTE_ATTEMPT_TIMEOUT_MS` / `DEMOTE_MAX_ATTEMPTS`），总预算短于拓扑刷新周期 `1000ms`；两个参数走构造入参，用例可注入更小值 |
| 3 | 水位 | 通知确认后重取旧 leader 快照，水位取 `max(预检 HW, 最终 HW)`；旧主此后再不可达则退回预检水位 |
| 4 | 目标落后 | 目标 LEO < 最终水位时**不截断**，转保留尾部（复用既有 `truncate=False` 路径），避免按目标不具备的水位截断 |
| 5 | 记账 | 指标新增 `demote_unconfirmed`；`SwitchResult` 增 `demote_confirmed` / `watermark_source`；审计 `finished` 落同名字段；日志增 `msg_leader_switch_demoted`（含 attempts / confirmed / 水位来源） |
| 6 | 缺口 B | 纳入本任务，与缺口 A 同一条判据闭环 |

## 3. 代码改动 <a id="code"></a>

| 位置 | 改动 |
| --- | --- |
| `election.py` 常量 | 新增 `LEADER_SWITCH_RESULT_DEMOTE_UNCONFIRMED`、`DEMOTE_ATTEMPT_TIMEOUT_MS`、`DEMOTE_MAX_ATTEMPTS`、`WATERMARK_SOURCE_PRECHECK` / `WATERMARK_SOURCE_POST_DEMOTE` |
| `election.py::SwitchResult` | 新增 `demote_confirmed: bool = True` 与 `watermark_source: str = precheck`（带默认值，既有构造点无需改动） |
| `election.py::LeaderSwitchService.__init__` | 新增 `demote_timeout_ms` / `demote_attempts` 入参（默认取常量） |
| `election.py::_notify_demote` | 新方法：`asyncio.timeout` 套单次预算，失败继续下一次，返回「是否确认 + 实际尝试次数」 |
| `election.py::_finalize_watermark` | 新方法：确认停写后重取旧主 HW 定最终水位；目标 LEO 不足则转保留 |
| `election.py::_finish` | 原「一次调用 + `except` 吞掉」替换为上述两步；指标按 `demote_unconfirmed` 单独记账；结果 / 审计 / 日志补字段 |
| `election.py::_audit_finished` | `finished` 审计增 `demote_confirmed` 与 `watermark_source` |

**为什么不新增错误码**：降级未确认不是请求侧错误，切换仍成功；用结果标签 + 审计字段表达，避免为一个观测维度扩错误码表。

## 4. 偏差 <a id="deviation"></a>

| # | 设计原文 | 实际 | 原因 |
| --- | --- | --- | --- |
| 1 | 设计 §5 表未写明 `SwitchResult` 字段默认值 | 两个字段带默认值（`True` / `precheck`） | 保持既有构造点（含 `noop` 路径与迁移服务）零改动；`noop` 本来就是「无需降级」 |
| 2 | 设计 §3.2 未区分「确认后旧主又不可达」与「确认后目标快照不可得」 | 两者都补了分支与用例（水位退回预检 / 仍按最终水位截断） | 覆盖率要求 100% 分支，且两种情形语义不同，必须显式定义 |
| 3 | 设计 §5 预留「新增结果标签影响看板」 | 仅新增标签，未动 `degraded` 语义 | 与确认口径一致：两类风险分开计数 |
