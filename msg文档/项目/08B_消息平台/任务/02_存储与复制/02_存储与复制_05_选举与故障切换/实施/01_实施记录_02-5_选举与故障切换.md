## 3. 关键决策落地 <a id="decisions"></a>

| # | 决策 | 落地位置 |
| --- | --- | --- |
| 1 | 内部领域服务 + 审计；管理端点归 06-2 | `LeaderSwitchService`；`app.state.leader_switch`；`api/deps.py::LeaderSwitchDep` |
| 2 | 单分区 + 主题批量（逐分区 CAS） | `switch_partition` / `switch_topic`（串行、部分失败不回滚） |
| 3 | 显式目标；未指定选 ISR 内 LEO 最大 | `_pick_target` 排除旧 leader、并列按副本集顺序 |
| 4 | 未提交尾部：可达截断 / 不可达保留 | `SwitchApplyCommand.truncate` + `apply_switch`；结果 `truncated` / `retained` / `noop` |
| 5 | 已提交不丢以 ISR 为前提；`force` 降级 | `isr_verified` 来自旧 leader 当前 ISR 或目标 `last_known_isr` + 新鲜窗口 |
| 6 | 所有发布档位校验 leader / epoch | `ReplicatedMessageStore.append` → `ensure_write_allowed`；`ensure_writable` 先判 leader 再判 ISR |
| 7 | epoch 持久化 + 本地租约 | `msg_partition.epoch` CAS；`leadership_confirmed_at` + `MSG_REPLICATION_LEADER_LEASE_MS` |
| 8 | 两阶段先停写 | phase 1 `switching` + `leader=target` + `epoch+1`；phase 2 `idle` + 结果列 |
| 9 | 幂等 / 中断续跑 | 同 target / 同 `switch_from_epoch` 续跑；不同 target `switch_in_progress`；phase 2 重读幂等 |
| 10 | 客户端元数据 | `TopicDetail.metadata_version = max(epoch)`；分区 `epoch`；`350033.data` 带 leader / epoch |
| 11 | 审计 | `msg:partition.failover`：begin fail-closed、finished fail-open |
| 12 | 结果可查 | `msg_partition.last_switch_*` / `last_truncate_to` 进 topic 详情；管理面分区 `epoch` |
| 13 | 单实例零变化 | 复制关闭：`ensure_*` 直接返回、`refresh_once` / `demote` 空操作 |

## 5. 问题与处置 <a id="issues"></a>

### 5.1 `pyright` 直接调 venv 入口会误报全部 `bms_core` 导入

与 02-4 同因：`.venv\Scripts\pyright.exe` 拿不到 `uv` 注入的工作区解析配置，满屏 `reportMissingImports`。处置：统一 `uv run pyright <文件>`。

### 5.2 02-4 的两条既有断言按 02-5 语义更新

- `test_follower_ensure_rejects_and_wait_is_noop`：follower 收到 `acks=all` 从 `350032(not_leader)` 改为 `350033(not_leader)`（设计 §5.3 的分工）；
- `test_follower_diverged_when_ahead_of_leader`：从「抛分叉」改为「按 leader 末端自动截断后重新拉取」（02-5 §6.3 的发散尾部处理）。

### 5.3 分支覆盖率差 6 处，靠补真实场景而不是 `pragma` 收口

| 缺口 | 处置 |
| --- | --- |
| `election.py` 821->814（候选 LEO 未超过当前最优） | 自动选主用例改成「首个候选 LEO 更大、后续更小」 |
| `election.py` 845->839（最后已知水位遍历遇不可达副本） | force 用例加入第 4 个无快照副本 |
| `replication.py` 1550->1552（水位置空的分支） | 补「watermark=None、truncate=False」激活用例 |
| `replication.py` 1588->1591（demote 非 leader） | 补 follower 收到 demote 用例 |
| `replication.py` 1631->1633（已在 switching 时再次刷新） | 补连续两次刷新用例 |
| `replication.py` 1668->1675（follower → follower 换 leader） | 补三副本、本节点非 leader 的 leader 变更用例 |

仅保留 2 处 `pragma: no cover`：`refresh_once` 的「键快照与读取之间并发卸载」、`pull_once` 拿锁后角色已变的并发窗口——两处都是无法在单线程事件循环用例中稳定复现的防御分支。

### 5.4 格式与行尾

`ruff format` 对长条件 / 多行字典有固定折行；`Set-Content` 批量改写测试文件时产生 CRLF，统一用 `engkit eol --fix` 回 LF 后再进提交环。

## 7. 偏差与遗留 <a id="leftovers"></a>

| # | 项 | 处置 / 归口 |
| --- | --- | --- |
| 1 | 进程内控制传输不是生产形态；真实跨实例 demote / apply 未验证 | 接口已定；网络实现与多实例编排归 **02-8** |
| 2 | 旧 leader 不可达时保留尾部，未提交记录可能转正 | 已定稿口径；02-8 演练记录 `retained_tail` 并判定是否可接受 |
| 3 | `force=True` 无法证明目标在 ISR，可能丢失未验证的已提交尾部 | 默认 `force=False`；`isr_verified=false`，02-8 判「降级」不计通过 |
| 4 | 租约依赖平台库可用性；DB 不可用超过租约时写停止 | 安全优先；02-8 演练「元数据库故障」场景；若需降级另立决策 |
| 5 | `switching` 卡住（目标长期不可达）没有取消 / 强制改目标入口 | 重试同 target；取消 / 强制切换归 **02-8**（或 06-2 后续） |
| 6 | 管理端点、二次确认、操作权限未做 | **06-2**（内部服务与 `LeaderSwitchDep` 已就位） |
| 7 | 客户端 SDK 按 `metadata_version` / `epoch` 主动刷新未做 | 03 / 05 域（8B_03 SDK） |
| 8 | 自动选举（心跳超时 + 多数派投票 + 稳定期）未做 | 后续任务；`LeaderSwitchService` 接口可复用 |
| 9 | 本任务不新增 Prometheus 指标 | 切换以审计 + 结构化日志 + 结果列可观测；02-8 需要时补 `msg_leader_switch_total{result}` |
