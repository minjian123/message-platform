## 4. 实测口径 <a id="measure"></a>

| 项 | 值 | 说明 |
| --- | --- | --- |
| 新增用例 | 83（38 + 29 + 11 + 5） | 单文件运行均 < 1s |
| 定向选测 | 2 316 passed / 181 文件 / 60.5s | 提交前预检口径 |
| 切换簇 | 两个真实 `InMemoryMessageStore` + `InProcessReplicaTransport` + 可变拓扑加载器 | 不做网络与部署变量，只验机制 |
| 时钟 | 可推进单调毫秒时钟 | 租约 / 刷新 / 发散判定确定性 |
| 宽限 | 用例注入 0（除专门用例 500ms → 0.5s 断言） | 不真实睡眠 |
| 旧 leader 不可达 | 控制传输返回 None / 快照抛错 | 覆盖最后已知 ISR 与 force 降级 |

**机制层面的关键断言**：

1. **两阶段不产生双写窗口**：phase 1 后 DB `switching`，旧 leader 立即降级（控制通道可达）或超租约拒写（不可达）；
2. **统一错误语义**：follower 写 / 切换中 / 超租约都是 `350033`，`data.reason` 四值可区分；ISR 不足仍是 `350032`；
3. **尾部口径**：可达按真实 HW 截断；不可达保留且 `retained_tail>0`；`force` 保留但 `isr_verified=false`；
4. **发散可修**：旧 leader 降级后本地 LEO 超过新 leader，拉取前自动截断；起点已越过则报不可修复；
5. **元数据可感知**：`metadata_version = max(epoch)`，切换后必然增大；管理面分区 `epoch` 与快照一致。
