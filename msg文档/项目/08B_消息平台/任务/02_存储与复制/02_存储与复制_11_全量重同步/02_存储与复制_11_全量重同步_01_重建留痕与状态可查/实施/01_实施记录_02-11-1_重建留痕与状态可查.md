## 2. 落实的口径 <a id="decisions"></a>

| # | 设计口径 | 落实 |
| --- | --- | --- |
| 1 | 拓扑补租户三字段 | `PartitionTopology` 增 `tenant_id` / `namespace` / `topic`，均带默认值（既有构造点与用例零改动） |
| 2 | 身份与分区行同源同缓存 | 加载器缓存值扩为「时刻 + 分区行 + 主题身份」，`_topic_rows` 改名 `_topic_snapshot`；主题行经既有 `get_by_id_unscoped` 取，避开租户作用域 |
| 3 | 身份随刷新收敛 | `_observe_topology` 每次合入拓扑时同步刷新三字段，不出现「分配已变、身份还是旧的」 |
| 4 | 成功与转人工两态各一条审计 | 协调器 `_audit_resync`：成功带丢弃条数 / 起点 / 耗时，转人工带累计失败次数 / 最后一次原因；失败重试只走指标与日志 |
| 5 | 无租户不写伪审计 | 租户 ≤ 0 或命名空间 / 主题名为空时跳过审计，记 `msg_replica_resync_audit_skipped` 告警一条 |
| 6 | 普通审计不阻断 | 动作登记为敏感类、`strong=False`；审计出口抛错时重建仍成功、状态仍转追赶中 |
| 7 | 状态五值闭集与三处投影 | 新增类型别名 `ResyncState`；内部快照响应、管理面分区列表、跨实例远端解析三处同集声明，老节点缺字段按正常处理 |
| 8 | 契约重导两处 | `ops.contract_snapshot export` 与前端类型生成器各跑一次，均为「新增可选字段 + 枚举」的纯增量 |

## 4. 偏差 <a id="deviation"></a>

| # | 设计原文 | 实际 | 原因 |
| --- | --- | --- | --- |
| 1 | 审计参数列出「丢弃条数 / 起点 / 耗时 / 累计失败次数 / 最后原因」 | 实现额外新增运行态字段 `resync_last_reason`（只在失败时写，成功后不落审计） | 转人工审计要带「最后一次原因」，而该信息在异常处理块内才知道，必须由运行态暂存 |
| 2 | 设计未提测试补齐 | 额外补了两个**既有分支**的用例：审计同事务写入优先、重建成功但未装配唤醒器 | 选测范围收敛后这两个分支不在本轮选中文件里，模块级 100% 会掉；补的是既有行为的断言，不改实现 |
