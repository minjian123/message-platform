## 2. 任务内容 <a id="content"></a>

1. **拓扑携带主题身份**：`PartitionTopology` 增「租户标识 / 命名空间 / 主题名」三字段；加载器联查主题表一次带回，并与分区行同缓存同过期，不为审计单开查询通道。
2. **重建审计两态**：重建**成功**与**转人工**（连续失败达上限）各写一条审计，动作统一、以参数区分结果；成功记丢弃条数、leader 起点、耗时，转人工记累计失败次数与最后一次原因。失败重试只走日志与指标，不写审计。
3. **无租户上下文时的降级**：拓扑行缺失（配置兜底）或主题行查不到时拿不到租户，此时**不写审计**，改为结构化告警一次并带明原因，绝不写零租户的伪审计。
4. **运行态字段暴露**：`ReplicationSnapshot` 增 `resync_state`（五值闭集：正常 / 已发现落后 / 重建中 / 追赶中 / 转人工），内部快照响应与管理面分区列表同时投影，跨实例远端快照解析同步补齐。
5. **契约重导**：改完响应契约后重导契约快照与前端类型两处，保证类型门禁零漂移。
6. **不改动的部分**：重建触发判据、退避与阈值语义、重建步骤均沿用 02-11，不因本次留痕改动而调整；管理面只出字段与类型，不改前端页面。

## 3. 完成标准 <a id="accept"></a>

- 重建成功与转人工各产生一条审计，含租户、命名空间、主题、分区号、丢弃条数、leader 起点与结果；审计查询可按动作检索到这两类记录；
- 拿不到租户时**没有**零租户审计落库，且存在一条带原因的告警日志可查；
- 管理面分区列表与内部快照均能读到 `resync_state`，其取值在契约里是五值闭集（前端类型可穷举）；
- 契约快照与前端类型重导后无差异，类型门禁通过；
- 变更模块行 + 分支覆盖率 100%，静态检查与文档校验通过；
- 既有重建行为不回归（重建追平、幂等、转人工三态用例保持通过）。
