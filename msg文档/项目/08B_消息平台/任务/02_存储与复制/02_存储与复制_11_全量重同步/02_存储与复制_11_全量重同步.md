## 2. 任务内容 <a id="content"></a>

1. **触发判据单一**：副本拉取发现「本地 LEO < leader 起点」即判 `needs_full_resync`；迁移预检遇到同一判据不再直接拒绝，转重建后再迁移。
2. **重建动作**：丢弃本节点该分区的日志段与索引（保留主题目录与元数据），本地 LEO 重置为 leader 起点，清空 ISR / 发散标记，重建恢复点与索引，然后走普通拉取路径从起点追赶。
3. **不暴露半初始化视图**：重建期间该分区的读 / 写 / 消费按既有「未就绪」语义拒绝，不返回重建中的残缺数据。
4. **幂等与互斥**：以分区运行态锁串行，重复触发为 no-op；同一分区同一时刻只有一次重建。
5. **失败处置**：重建失败按退避重试并告警，连续失败达阈值转 `blocked` 交人工，不无限重试打爆 IO。
6. **安全与审计**：只在「本节点是副本集成员」时执行；重建事件进审计（分区、leader 起点、丢弃范围、触发原因、结果），指标 `msg_replica_resync_total{result}`。
7. **边界**：不引入归档、不补裁剪掉的历史（裁剪策略即能力边界）；不重建 leader 自身；复制关闭时不装配、不产生 DB 查询。

## 3. 完成标准 <a id="accept"></a>

- 保留期裁剪后新增 / 落后的副本能在无人工干预下重新进入 ISR，数据自 leader 起点起与 leader 一致；
- 重建期间不出现「半初始化可读」视图，读请求命中原有「未就绪」语义；
- 重复触发幂等；失败有退避与告警、达阈值转人工且状态可查；
- 迁移预检遇该情形转重建并在台账留痕，不再一律拒绝；
- 审计与指标可查每次重建的触发原因、范围与结果；
- 变更模块行 + 分支覆盖率 100%，静态与文档校验通过。
