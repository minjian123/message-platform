## 3. 关键决策落地 <a id="decisions"></a>

| # | 决策 | 落地位置 | 实现要点 |
| --- | --- | --- | --- |

| 2 | 非尾部损坏检测 | `file_store.py::_verify_stamps` / `segment.py::verify_stamp` | 恢复点段清单逐段 O(1)：比 `size` + 读段尾一条比 CRC |
| 3 | 截断语义 | `segment.py::isolate_tail` + `_PartitionLog._load` | 截断到第一条坏记录前；被截字节另存 `{base}.log.corrupt-{ts}`；尾随记录数只计数不恢复 |

| 8 | `scan_tail` CRC 参数 | `segment.py::scan_tail` | `verify_crc=False` / `anchor=None` 双缺省，02-1 既有调用与三条用例语义不变 |

补充口径（设计 §15.2 已记）：恢复点给**锚点**、文件长度给**上界**、索引项给**兜底**，三者取较大者作为扫描起点——「启动只信恢复点」落实为「不把恢复点当唯一真相」，否则会丢掉未 fsync 但已落盘的好数据。

## 5. 问题与处置 <a id="issues"></a>

### 5.1 索引残条会让后续条目整体错位（数据级，已修）

02-1 的 `_read_entries` 按 `len(blob) // entry_size` 取整、**忽略尾部残条**；而 `_append_entry` 用 `O_APPEND` 从**物理尾**追加。崩溃若把某条目写了一半（offset 索引 8 字节、时间索引 12 字节），残条会留在文件里，后续条目整体偏移 4 字节——索引从此全段读偏，`scan_tail` 的锚点也跟着偏。

- 处置：`SegmentFile.repair_index_tail()` 在加载末段时把两个索引截到条目整数倍，丢弃字节数进恢复报告（`index_repair_bytes`）。
- 只处理末段：崩溃只可能发生在最后写的段（历史段在轮转时已 fsync 并关闭）。
- 覆盖：R9（追加 4 字节残条 → 加载后文件回到整数倍 → 此后追加仍能定位）。

### 5.2 `verify_stamp` 未捕获框架非法（会让恢复崩掉，已修）

初版对账直接 `read_frame(...)`，若恢复点记的末条位置落在垃圾区，`CorruptedRecordError` 会冒泡到 `_load`，**整个分区拒绝启动**——把「段损坏」升级成「服务不可用」，与任务 §2.5「不阻塞其他分区启动」相悖。

- 处置：包 `try/except CorruptedRecordError` 返回 `(False, 0)`，按 `crc_mismatch` 标记。
- 覆盖：R36（恢复点末条位置指向 `length=0` 的垃圾框架）。

### 5.3 懒加载让恢复报告「取不到」与 `await` 优先级

首轮 7 个用例失败，两类原因都不在实现：

| 现象 | 原因 | 处置 |
| --- | --- | --- |
| `KeyError: (31, 0)` 取 `_partitions` | `FileMessageStore` 是懒加载，构造不加载分区；断言恢复报告前没触发过访问 | 辅助改成 `async`，内部先 `await leo()` 一次 |
| `'coroutine' object has no attribute 'recovery_point'` | `await f().attr` 先取属性再 await | 改为 `(await f()).attr` |
| 索引残条用例断言 28 字节未变 | 同上：`_store()` 构造后未加载，`repair` 还没执行 | 断言前先 `await leo()` |

### 5.4 覆盖率两轮才到 100%

首轮 97.60%（缺行 34 / 缺分支 15），逐项补：

| 缺口 | 补法 |
| --- | --- |
| `recovery` 的 9 处「不可用」分支 | 参数化用例：顶层非对象 / payload 非对象 / crc 非整数 / 版本非整数 / leo 非整数 / segments 非数组 / 项非对象 / 字段非整数 |
| `segment.last_record_stamp` 的扫描分支（11 行） | R28：重开后（段对象无写入缓存）调 `aclose` → 写恢复点时现算末段 stamp |
| `position_of` 无索引的 `(0, 0)` | R29 改为「删**非末段**索引」（末段索引会被补建，删了也测不到） |
| 尾随计数的两个 `break` | R30（非法框架）/ R31（声明超长） |
| `verify_stamp` 的两个失败分支 | R33（读不全）/ R36（框架非法） |
| `persist_recovery_point` 目录不存在 | R34：直接构造 `_PartitionLog` 指向不存在目录 |
| `StorageCloser.aclose` | R35：替身 store 断言转调 |
| `isolate_tail` 的短读 | 加 `# pragma: no cover - seek 与 size 一致，读不满只可能是并发截断` |

### 5.5 测试里访问私有类触发 pyright `reportPrivateUsage`

`from ... import _PartitionLog` 被判私有越界。改为 `cast("Any", file_store_module)._PartitionLog` —— 与 02-1「`cast("Any", store)._partitions[...]`」同法，测试不引入新的公开面。

### 5.6 覆盖率旧数据残留

`.cache/coverage/` 里有 02-1 的 `.coverage` / `.coverage.json` / `changed.json`，合并后会产生假缺口（02-1 实施记录 §5.5 同坑）。本次先归档到 `archive-02-1/`，每次判定前清 `.coverage.*` 分片。
