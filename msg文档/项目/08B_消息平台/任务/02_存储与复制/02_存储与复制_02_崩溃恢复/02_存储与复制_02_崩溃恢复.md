## 2. 任务内容 <a id="content"></a>

1. **恢复点文件**：每分区维护 `recovery-point`（含 LEO、`epoch`、CRC、更新时间）；采用「临时文件 + rename」原子替换；启动只信恢复点，不以文件长度为依据。（**02-2 实施精化**：恢复点落后于文件是 `os` 档常态，故它给**扫描锚点**、文件长度给**上界**、索引项作**兜底**，三者取较大者为起点——详见[详细设计 §15.2](设计/01_详细设计_02_崩溃恢复.md#diff) #2。）
2. **尾部扫描**：从恢复点 LEO 向后逐条校验 `length` 与 `crc`；遇到不完整或校验失败的记录，**截断到上一条完整记录**；只扫尾部，不扫全量。
3. **索引补建**：扫描过程中补建缺失的 `.index` / `.timeindex` 条目；截断后索引不得再指向已截断区间。
4. **位点对齐**：已提交位点若超过截断后的 LEO，回退到新 LEO 并**告警**（数据丢失事件，必须可见）；与 02-3 的位点持久化协作，回退结果落日志。
5. **段损坏与隔离**：尾部损坏走截断；非尾部段静默损坏只标记并告警（不在本任务做副本修复），不阻塞其他分区启动。
6. **恢复日志**：记录扫描范围、截断位置、重建索引条数、位点调整与耗时；日志可按分区与段定位。
7. **延迟恢复支撑**：提供「自某 offset 起扫描 `.log` 尾部并收集 `log_id`」的只读原语，供 02-7 的恢复期去重使用；本任务不实现延迟区本身。
8. **优雅关闭**：停止接新写 → 日志刷盘 → 更新恢复点；与位点刷盘保持「先日志后位点」的偏序（最坏重复，不可丢失）。
9. **边界**：不做全量校验（中间静默损坏靠副本比对）、不做段修复、不做自动删段（02-1）、不做副本恢复（02-4）。

## 3. 完成标准 <a id="accept"></a>

- 人为制造半条记录后重启：服务正常启动，只丢最后一条，后续写入从截断点继续且 offset 连续。
- 恢复日志能定位截断位置与重建索引条数；位点越界时产生告警并回退。
- 非尾部段损坏被隔离并告警，其他分区可正常启动。
- 优雅关闭后重启，LEO 与位点一致，无额外丢失。
- 尾部扫描复杂度为 O(尾部)，有「不扫全量」的护栏用例。
- 变更模块行 + 分支覆盖率 100%，静态检查全绿。
