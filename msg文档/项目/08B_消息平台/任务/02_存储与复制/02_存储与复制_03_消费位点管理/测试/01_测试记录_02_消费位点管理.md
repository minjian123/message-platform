## 4. 实测口径 <a id="measure"></a>

| 项 | 值 | 说明 |
| --- | --- | --- |
| 新增用例 | 57 | 单文件 `pytest` 约 0.4s |
| 变更范围 | 393 passed / 70.4s | 10 个 broker / 装配文件 + `tests/api` 全部 29 个文件 |
| 刷盘窗口缺省 | 1000ms | 崩溃最多重复 1 秒内的提交（业务侧幂等兜底） |
| 脏阈值缺省 | 256 文件 | 同时是单轮 fsync 次数的上界 |
| 位点文件体积 | `19 + len(group) + 48` 字节 | 组名 5 字节时 72 字节；含两槽与两层 CRC |
| 关闭释放序 | `BackgroundLoops → OffsetFlushLoop → StorageCloser → OffsetFlusher` | O25 逐项断言 |

**崩溃窗口的三种情形**（设计 §7.3，本任务只做逻辑保证，断电实测归平台级容量实测）：

| 时刻 | 后果 |
| --- | --- |
| `commit` 后、刷盘前 | 重读旧值 → 重复消费这段（不丢） |
| 写 `.tmp` 未 rename | 目标文件仍是上一版 → 重复消费（不丢） |
| 日志已刷、位点未刷（关闭中途） | 位点落后 LEO → 重复消费（不丢） |
