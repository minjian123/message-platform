## 2. 任务内容 <a id="content"></a>

1. **文件布局**：`data/{tenant_id}/offsets/{group}/{topic_id}-{partition}.offset`；键使用不可变 `tenant_id` / `topic_id`（主题改名不漂移），`group` 按 `GROUP_NAME_PATTERN`；路径示意与架构 04 §2.1 的对应关系在详细设计写明并回写。
2. **文件格式**：magic + `format_version` + `group` + `topic_id` + `partition_no` + `offset` + CRC + `updated_at`；写入采用「临时文件 + rename」原子替换（或追加日志 + 恢复点，详细设计二选一并给出崩溃语义）。
3. **提交语义**：处理完再提交，提交值 = **已处理完的最后一条 + 1**；只前进不后退，重复提交幂等；负数或越过 LEO 的位点拒绝（`10001`），不得默默夹取。
4. **刷盘**：定期刷盘 + 优雅关闭强制刷盘；频率可配（架构 04 §11 #5，实测后回填）；设计写明崩溃重复窗口。
5. **损坏与丢失**：CRC / 解析失败或文件缺失时，回退到**最近已持久化位点**（不得直接跳 LEO、也不得直接归零），并告警；只有从未持久化过才按 0 起。
6. **位点重置**：提供 `reset(group, topic_id, partition_no, offset)` 存储能力与审计事件（复用平台 `sys.operation.logged`，权限 `msg:manage`）；管理端点、二次确认与操作留痕由 [06-2](../../../需求/06_需求_管理与运维.md#r06-2) 挂载，本任务只保证底层能力可被安全调用。
7. **多租户与隔离**：按 `tenant_id` 分目录，不跨租户读写；组不存在 / 分区越界由上层契约判定，本任务不替代组协议。
8. **装配**：以文件实现替换 `InMemoryOffsetStore`，`OffsetStore` 端口签名不变；启动时与 02-2 的位点对齐联动。
9. **边界**：延迟消息到期前不占位点（01-5 口径）；不做消费组元数据落盘（01-4 语义已交付，组表归 8B_02 后续 / 06 域）；不做位点查询端点（06-2）。

## 3. 完成标准 <a id="accept"></a>

- 重启后从正确位点续读；未提交消息重投（至少一次）。
- 人为损坏位点文件：回退到最近持久化位点并告警，不重头消费也不跳过消息。
- 位点重置的底层调用带审计事件；越权或未二次确认的入口在 06-2 侧被拒绝。
- 只前进不后退、重复提交幂等、越界拒绝均有护栏用例。
- 变更模块行 + 分支覆盖率 100%，静态检查全绿。
