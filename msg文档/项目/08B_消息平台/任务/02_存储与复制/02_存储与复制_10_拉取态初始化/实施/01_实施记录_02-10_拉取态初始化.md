## 5. 问题与处置 <a id="issues"></a>

### 5.1 非成员守卫必须在「拓扑」与「分配」两侧一致，否则用例测不到

初版用例用「分配事实里 `replicas` 不含本节点」来验证 `hosted=False`，但惰性挂载走的是**拓扑加载器**（`ReplicaTopologyLoader`），两者的副本集并不必然相同——用例失败（`hosted` 仍为 `True`）。处置：用例侧显式让拓扑只含 `n1`，让「分配过滤」与「运行态守卫」分别被覆盖：分配侧由 G2 的非成员跳过用例覆盖，运行态侧由本用例覆盖。

### 5.2 单文件 `uv run pyright` 缺 `--project backend` 会把 `bms_core` 全报成未解析

在仓根直接 `uv run pyright <文件>` 得到 52 个 `reportMissingImports`（连未改动文件也一样）。处置：`uv run --project backend pyright <文件>`，错误降到 3 个，且均为 `main.py` 的 `services.*` 导入——那是 `backend/services` 在全集分析路径内才可解析的相对导入，属**子集运行的工具边界**，预检（按项目配置跑）为零错误。

### 5.3 覆盖率首轮缺 10 行 1 分支，全部落在「新分支但用例走的是另一条路」

| 缺口 | 原因 | 处置 |
| --- | --- | --- |
| `replication` `pull_once` 的 `not hosted` 早返回（含分支） | 用例只走 `pull_round`（在轮次筛选时就跳过） | 补一条直接调 `pull_once` 的断言 |
| `replication` 枚举超时分支 | 只有普通异常用例 | 用例注入 `_MOUNT_LOAD_TIMEOUT_SEC=0.001` + 慢枚举替身 |
| `replication` 首拉失败分支 | 正常路径都成功 | 新增「拉取即失败」传输替身，断言挂载仍成立且登记退避 |
| `repositories.topic.list_assignments`、`replication_topology.list_assignments` | 只有单测替身、没有走真实仓储 / 加载器 | 各补一个用例（DB 级 + 替身仓储级） |

复跑后 `missing_lines=0 / partial_branches=0 / 100.00%`（7 模块）。

### 5.4 演练预热删除后，`warmup` 相关替身一并失效

`chain.DrillClient.warmup` 删除后，`publish` 重试里的「长时间未成功再预热」也一并去掉（保留 3s 轮次间隔），并把 `publish_batch` 的 `warm` 参数删除——否则会留一条「演练仍靠预热」的暗路，使「空闲分区自然收敛」的结论失真。用例替身的多余方法不清理（鸭子类型、无调用）。

### 5.5 采集脚本写日志落点错了目录

`cd msg && ... > ../../tmp/...` 实际落到 `D:/Develop/tmp`（`msg` 已是工作区下一级）。处置：统一改为绝对路径 `D:/Develop/bizs/tmp/msg-0210/`，已把误落日志移回工作区 `tmp/`。

### 5.6 真机演练暴露「主题目录未登记」——挂载必须在取 LEO 前补登记（`27e3913`）

第一次去预热复跑直接卡在 guard：`cluster-drill.guard ISR 未在预算内收敛到 9`；节点日志给出根因：

```text
msg_replication_mount_failed detail='主题目录未登记：topic_id=…（须先经 TopicRouter.resolve 解析）'
  reason=PartitionNotBoundError
```

**根因**：文件存储的分区目录按 `{租户}/{命名空间}/{主题}.{topic_id}` 定位，主题目录的登记发生在**请求路径**（`TopicRouter.resolve` → `PartitionDirectory.bind`）。后台挂载没有请求上下文，`FileMessageStore.leo()` 直接抛 `PartitionNotBoundError`——这才是「副本必须被某个请求碰过一次」的另一半原因（先前只识别出「协调器惰性挂载」这一半）。

**处置**（三条一起改，缺一条都不成立）：

1. 分配事实带上主题身份：`PartitionAssignment` 增 `tenant_id` / `namespace` / `name`；枚举时联查活跃主题（新增 `TopicRepository.list_active_unscoped()`，绕开租户作用域，与 `get_by_id_unscoped` 同源口径），删除中的主题不进清单。
2. 新增 `ReplicaDirectoryBinder` 协议 + `PartitionDirectoryBinder` 适配（`services/replication_topology.py`），把目录表桥接给挂载侧；`main.py` 注入 `app.state.partition_directory` 的适配实例——复制与存储两侧互不引用。
3. `_mount_one` 在 `attach_partition` **之前**登记三段名；缺身份（历史行 / 主题已删）跳过登记，行为回到旧的请求路径登记。

修后第二次复跑通过（§7）。设计 §2 / §4.2 / §6 / §7 已同步回写；用例补「挂载前登记」「账号缺身份不登记」「适配层委托」三例。
