## 2. 任务内容 <a id="content"></a>

1. **`.delay` 段**：与 `.log` 同分区目录、同「`length` + `crc` + `header` + `payload`」框架；头含 `deliver_at`、`delay_level`、`message_id`、`log_id`、`key`、`tenant_id`、`topic_id`、`partition_no`；**不占 offset**。
2. **写入**：发布时按 key 锁定分区并写入该分区 `.delay`；入队按 `log_id` 幂等覆盖（重试递增 `attempts`）；刷盘策略与日志段一致（详细设计定稿并写明崩溃语义）。
3. **启动重建**：扫描 `.delay` 段，未到期按**剩余时间**装填时间轮；已到期未转投的**立即转投**（限速并受追赶窗口约束，避免重启风暴）；重建完成后由恢复流程调用 `ensure_started()`。
4. **不丢不重**：转投先 `append` 到 `.log` 并刷盘、**再清 `.delay`**（崩溃最坏重复，不丢）；恢复期扫 `.log` 尾部建 `log_id` 集合（复用 02-2 原语），`.delay` 命中者直接清掉、不再 `append`；运行期由单进程串行转投 + 立即清理保证不重。
5. **TTL 与轮转**：延迟区另设 TTL 兜底；`.delay` 段按大小 / 时间轮转，边界与默认值在详细设计定稿（架构 04 §11 #6）。
6. **损坏隔离**：CRC 失败段改名隔离并告警（含段路径与损坏条数），不静默丢、不阻塞其他段与分区。
7. **优雅关闭**：停收新延迟 → `.delay` 刷盘 → 时间轮进度 / 恢复点落盘；关闭后重启无丢失（架构 04 §2.6 #6）。
8. **容量**：沿用 01-5 的每租户软上限与 `350015` 拒绝语义，补**全局软上限**计数；容量与拒绝计数可查（指标由 06-3 接）。
9. **装配**：以文件实现替换 `InMemoryDelayStore`，`DelayStore` 端口签名不变；启动重建统一走 `list_all()`，不新增端口方法。
10. **边界**：不改延迟语义（固定档位、到期才分配 offset、不参与停等 / 积压 / 位点）；不做改期 / 取消（06 域）；多副本重复转投由 02-4 / 02-5 的单写者与 fencing 收敛。

**03 域收口回写（2026-11-05；前置 8B_01 已达成）**

- **转投自动唤醒**：转投走 `MessageStore.append`，唤醒由最外层的 `NotifyingMessageStore` 承担，本任务**不必另做通知**；但延迟区实现若装配在包装器之外，长轮询会退化为「等到超时再拉」——装配时核对顺序。
- **转投不过生产限流桶**：03-5 的两级令牌桶只作用于**发布入口**（含 `delay_level` 档位）；内部转投若也被配额拒绝，重启追赶会形成「越限越追不上」的死循环，故转投只受本任务 §2.3 的追赶窗口节流。
- **三码分立**：延迟区满 = `350015`、生产限流 = `350005`、存储水位拒绝 = `350022`（02-6 占用），互不复用。


**实施回写（2026-11-05）**

- **段落点与命名**：同分区目录 `{seq:020d}.delay`，`seq` 是**独立延迟段序号**（只增不复用）——用 `.log` 的 base offset 命名会造出一个「没有记录占用的 offset」，且保留期删段后同号 `.delay` 仍在、`truncate_before` 删空后新段又复用同一 base。见[详细设计](设计/01_详细设计_02_延迟消息持久化与到期恢复.md) §4.1。
- **容量判定下沉到存储实现侧**：全局上限要判「总条数」，而端口不能新增方法，故两级上限一并落在 `enqueue()`（两个实现共用 `ensure_delay_capacity`）；`DelayService` 原配额预检删除，错误码优先级不变。
- **`attempts` 落盘节流**（30s / 10 次）：转投失败每 tick 重试一次，逐次落盘会把「1 KiB 记录卡一天」放大到几十 MB；口径与 02-3 位点「内存为准 + 关闭强刷」同源。
- **转投显式 fsync**：偏序的「已写入」是「已 fsync」而非「已 append」，否则 `os` 档下崩溃会两头皆空。
- **`350015` 的 `data` 用普通 dict**：HTTP 路径走 pydantic 序列化，自定义 Mapping 会让响应 500。
- 偏差与遗留（含 02-6 `350022` 同类缺陷的发现）见[实施记录 §7](实施/01_实施记录_02_延迟消息持久化与到期恢复.md#leftovers)。

## 3. 完成标准 <a id="accept"></a>

- 重启后未到期延迟消息按**剩余时间**投递（不提前、不丢）；已到期未转投的启动后补投完成。
- 转投崩溃窗口内不丢消息；重启后同一 `log_id` 在日志中**只出现一条**（单副本）。
- `.delay` 段损坏可隔离并告警（段路径 + 损坏条数），其他分区不受影响。
- 优雅关闭后重启无丢失；延迟区容量与拒绝计数可查。
- `DelayStore` 契约用例全绿；变更模块行 + 分支覆盖率 100%，静态检查全绿。
