## 4. 实测口径 <a id="measure"></a>

一次性脚本（不入库）在临时目录、`fsync_mode=os`、单进程下写入 500 条 1251 字节的记录：

| 项 | 数值 |
| --- | --- |
| 写入 500 条 | 625 780 字节（1251 B/条）、1 个段（未达 8 MiB） |
| 重建（全量扫 + CRC） | `records=500`、`scanned_bytes=625780`、`elapsed_ms=23`（约 27 MB/s） |
| 清除 500 条（tombstone） | `elapsed_ms=6.4`；段数仍 1（活动段不删） |
| 清后重建 | `records=0`、`cleared=500`、段数 1 |
| 指标快照 | `msg_delay_pending.__total__ = 0` |

**结论与边界**：重建成本随延迟区字节线性增长，读量 = 全量 `.delay`（这是可预期的、也是 `report.scanned_bytes` 上报的量）；tombstone 写入远低于重建成本。容量结论（50 万条上限下的内存与启动耗时）归平台级容量实测，本任务只给量级。
