## 6. 问题与处置 <a id="issues"></a>

### 6.1 帧闸门是第二条装配路径（设计漏项）

`api/frame/gate.py::_invoke` **直接调用端点函数**（`await publish(req=..., tenant=..., ...)`），不复用 FastAPI 依赖注入。给 `publish` 加 `gate` 参数后，帧路径立刻 `TypeError`——10 个帧用例（`test_frame_data_plane` / `test_frame_payload` / `test_frame_version` / `test_rate_limit`）全红。

处置：在闸门依赖上补 `StorageGateDep`，一路透传 `gate → _handle_frame → _invoke → publish`。**这比「在闸门里另建一个水位实例」正确**：两条入口必须用同一份缓存与滞回状态，否则帧路径与 JSON 路径会得出不同结论。

教训：数据面端点的依赖新增，**必须同时改 `DATA_PLANE_ROUTES` 的调用方**（`mount_data_plane` 走 DI、`_invoke` 走直调）。设计 §10 的装配表漏了这条，已回写本记录。

### 6.2 `BaseProvider.describe` 是抽象方法，pyright 拒绝实例化

`MsgStorageCheck` / `MsgRecoveryCheck` 只实现 `key` + `check` 时，pyright 报 `Cannot instantiate abstract class`。基座 `BaseHealthCheck` 继承 `BaseProvider`，`describe()` 是 `@abstractmethod`（"实现类强制提供"）。

处置：两个检查项各补 `describe()`；用例顺带断言其前缀（同时补上这两行的覆盖率）。

### 6.3 `DelayWheel` 的扫描指针取构造时刻，用例必须注入同一时钟

调度器用例首次跑出「零日志、记录仍在」。原因是 `DelayWheel()` 缺省用真实 `_utcnow()`，用例的 `now` 是 2026-11-05 12:00（早于真实时刻）→ `take_due` 命中「时钟回拨」分支直接返回空，`_transfer` 根本没被调用。

处置：`DelayWheel(now=lambda: now)` 与调度器同源。**这不是被测代码的缺陷**：回拨保护本身是 01-5 的既定行为。

### 6.4 台账字段语义一度写反

`RecoverySummary.truncated_bytes` 最初沿用了 `RecoveryReport.truncated_bytes`（"截断后**保留**的字节数"）的名，却按"被截掉的字节数"赋值，`degraded` 判据写成 `< 0`，永远为假。

处置：字段改为明确语义（"被截掉的字节数，`0` 表示未截断"），`degraded` 改为 `> 0 or corrupted_segments != ()`，并用「截断 20 字节」的用例钉住。

### 6.5 `.cache/coverage/.coverage.json` 是坏文件（预存遗留）

预检日志恒有 `CoverageWarning: Couldn't use data file '...coverage.json': file is not a database (SQLITE_NOTADB)`。属 `.cache/` 下历史产物，不影响门禁结论（门禁读 `.coverage` 分片）。本任务未处理，登记为遗留。
