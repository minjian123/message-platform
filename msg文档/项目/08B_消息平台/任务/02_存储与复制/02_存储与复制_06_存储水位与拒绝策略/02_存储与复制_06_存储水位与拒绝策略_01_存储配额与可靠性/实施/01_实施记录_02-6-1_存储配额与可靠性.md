## 6. 问题与处置 <a id="issues"></a>

### 6.1 裸集合护栏拦下 msgpack 编码入参与退避常量

`record.py::_pack_header` 的 `raw: dict[str, Any]` 是 `msgpack.packb` 的编码入参，改 `ConcurrentStableDict` 会改变编码器接受的映射类型；按框架边界加 `# bare-collections:allow` 并写明理由。`DELAY_RETRY_BACKOFF_MS` 由 `tuple[int, ...]` 改 `ConcurrentStableFrozenList`，保持只读且满足护栏。

### 6.2 F3 退避使两处存量用例失败（预期行为变化）

`test_delay_disposal::test_transfer_failure_log_is_suppressed_within_window` 原来连续两次 `run_once` 期望 attempts 3→5；退避后第一次失败 attempts=4、下一次基础退避 10s，必须推进 5s（半抖动下界）。`test_watermark::test_delay_transfer_failure_logs_reason_with_window_suppression` 第二次失败需要推进 1s。两处均改为注入确定性 jitter + 推进时钟，断言语义不变（日志抑制 / 记录不丢）。

### 6.3 F10 现有实现已正确，无代码修复

新增「毒消息 + 正常消息同分区」用例直接跑现有实现：毒消息 5 次重投后转死信、位点推进到 1，同批或下一批投出正常消息；ack 正常消息提交到 2；重建 `DeliveryService` 后空批、死信仍 1 条、毒消息 ack `350007`。**未改 `_collect` / `_dead_letter` / `_commit`**，避免为无证据的缺陷改 01-3 停等语义。

### 6.4 契约层 `MsgPayloadTooLargeError` 未被 pydantic 包装

`field_validator(mode="before")` 直接抛产品异常，FastAPI 请求校验只包装 `ValueError`，因此 350006 原样进入统一错误响应；`test_payload_over_limit_raises_product_code` 与既有 `test_payload_limit.py` 双重钉住 413 / 350006。

### 6.5 早闸只覆盖 JSON 发布

帧路径有自己的 64 KiB header / 1 MiB payload 判据与 error frame 语义，套 JSON 中间件会破坏「HTTP 200 + error frame」。中间件按「POST + `/msg/publish` 后缀 + `application/json`」匹配，帧请求直通；用例覆盖非 HTTP / 非 POST / 非发布路径直通。
