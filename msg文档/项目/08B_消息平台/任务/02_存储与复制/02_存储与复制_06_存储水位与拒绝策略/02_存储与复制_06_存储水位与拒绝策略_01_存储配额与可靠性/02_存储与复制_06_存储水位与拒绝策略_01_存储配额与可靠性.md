## 2. 任务内容 <a id="content"></a>

本任务把 02-6 收口后暴露的「配额与可靠性边缘缺陷」一次补齐，不新增外部依赖、不新增表、不新增错误码：

1. **B15 命名空间形态校验单点化**：`tenant/context.py` 抽 `validate_namespace`（形态 + allowlist），`CurrentTenant.ensure_namespace` 单点升级；`TopicService._ensure_namespace` 去掉重复形态判断、改为委托。配额查询 / 调整端点由此自动获得形态校验，非法命名空间不再可能落库。
2. **B17 JSON 发布载荷与头提前拦截**：
   - `payload` 在契约层按 1 MiB 精确换算声明 base64 上限，超限抛 `350006`（保持 413 / 350006）；发布路径加请求体大小早闸，超大 JSON 不进入解析；
   - `headers` 四重上限：对数 ≤32、单键 ≤64 字符、单值 ≤1024 字符、键值 UTF-8 字节和 + 结构开销 ≤8 KiB，超限统一 `10001`；记录层 1 MiB 硬顶保留为最后防线。
3. **B18 存储配额字节精确化**：发布入口在 ACL / 限流之后、存储配额之前解码一次并缓存原始字节；`_payload_bytes` 直接取长度，投递与延迟转投复用缓存，不再二次解码，也不再按 `len(base64)*3//4` 估算。
4. **B21 指标采样容错**：积压按 `(组, 主题)`、死信按主题逐项隔离；单个未绑定主题只影响该键，其余主题照常更新；失败键沿用上一轮快照值（不归零）；失败日志按键 60s 抑制。
5. **F3 延迟转投退避**：`DelayRecord` 增可空 `next_attempt_at` 并落盘（`DelayStamp` 新键、缺省 `None`、不升格式版本）；失败按 1/2/5/10/30/60s 封顶退避 + 半抖动；时间轮按 `next_attempt_at`（为空取 `deliver_at`）判到期，重启后继续退避。
6. **F10 毒消息同分区续消费**：先补仓内自动化用例证明「毒消息转死信后同分区后续消息可消费、复跑仍可消费」，用现有实现跑出现状；若暴露缺陷再定位停等 / 位点 / 死信顺序并修，测试记录留证。

**边界**：不做多实例租约 / 广播（归 8B_05）；不新增数据库表或列；不新增错误码（沿用 `10001` / `350006` / `350010`）；不做延迟改期 / 取消（06 域）；不把 `F10` 留在 02-3-1 双份任务——实施完成后计划表把 02-3-1 标注为「并入 02-6-1」。

## 3. 完成标准 <a id="accept"></a>

- 配额查询 / 调整端点对非法命名空间返回 `350010`，且不产生任何配额写入；主题 / ACL / 消费守卫仍走同一单点判定。
- JSON 发布超过 1 MiB 仍返回 `350006`（413）；超大请求体在进入 JSON 解析前被拒；`headers` 超四重上限返回 `10001`，边界值（32 / 64 / 1024 / 8 KiB）通过；帧路径同源生效。
- 存储配额按真实解码字节计算：`YQ==` 计 2 字节而非 3 字节；解码只发生一次，投递与延迟转投复用同一份字节。
- 一个未绑定主题不再让整轮积压采样失败：其余主题照常更新，失败主题保留上一轮值；失败日志 60s 内同键只一条，恢复记一条。
- 延迟转投失败后记录 `next_attempt_at` 落盘并按 1/2/5/10/30/60s + 半抖动退避；重启重建后仍按该时刻续退避；`deliver_at` 业务语义不变。
- 毒消息用例：同分区毒消息重投到上限转死信后，同批或下一批可消费后续正常消息；重建服务后仍可从已推进位点继续，且已死信 offset 的 ack 返回 `350007`。
- 变更模块行 + 分支覆盖率 100%；`ruff` / `pyright` / 裸集合护栏 / 文档三项 / 契约与前端类型零漂移全绿。
