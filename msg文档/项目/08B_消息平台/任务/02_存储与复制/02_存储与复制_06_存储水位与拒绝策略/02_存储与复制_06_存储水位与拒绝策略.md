## 2. 任务内容 <a id="content"></a>

1. **水位对象**：消息数据卷（`MSG_DATA_DIR` 所在卷）使用率；预留空间默认 10%~15%，可用阈值可配（详细设计定值并写默认）。
2. **滞回**：低水位告警（如 70%）、高水位拒绝写（如 85%）；必须降到低水位以下才解除拒绝，避免阈值附近反复抖动。
3. **拒绝语义**：高水位时拒绝新消息并返回 `350005`，**不允许静默丢弃**；延迟发布同样拒绝（不得先收进延迟区再丢）；错误信息带当前水位、阈值与数据卷。
4. **就绪探针**：`/ready` 校验「元数据可达 + 日志目录可写 + 水位未超高水位」，任一不满足即摘除实例（架构 08 §8「就绪探针必须检查能写」）。
5. **运维手段**：缩短保留期、清理过期段（复用 02-1 `truncate_before()`）、扩容磁盘；操作入口归 [06-2](../../../需求/06_需求_管理与运维.md#r06-2)，本任务提供能力与口径。
6. **指标**：`msg_disk_used_ratio` 等水位指标埋点；命名、标签与暴露方式由 06-3 统一，本任务只保证采集点只读、无副作用。
7. **恢复**：清理后**无需重启**即可恢复写入；水位跨越阈值时留日志（进入 / 解除各一条）。
8. **边界**：不做租户级配额（05-3）、不做传输层背压与流控（03 域 / 06 域）、不实现段删除（02-1）、不做告警渠道（06-3）。

## 3. 完成标准 <a id="accept"></a>

- 注入「磁盘将满」后，发布被拒绝并返回 `350005`，服务不崩溃；延迟发布不例外。
- 清理后无需重启即可恢复写入；进入与解除拒绝均有日志。
- `/ready` 在水位超高或日志目录不可写时失败，恢复后自动通过。
- 滞回有效：在阈值附近连续探测不产生状态抖动。
- 水位指标可被 06-3 采集（联调用例）。
- 变更模块行 + 分支覆盖率 100%，静态检查全绿。
