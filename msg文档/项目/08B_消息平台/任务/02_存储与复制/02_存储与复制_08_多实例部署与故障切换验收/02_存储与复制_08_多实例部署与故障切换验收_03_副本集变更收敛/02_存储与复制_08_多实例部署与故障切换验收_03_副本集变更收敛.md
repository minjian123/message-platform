## 2. 任务内容 <a id="content"></a>

1. **运行态随分配收敛**：02-5 的刷新循环（缺省 1s）读回 `msg_partition.replicas` 后，若与本节点运行态的副本集不同即收敛——无需等迁移台账状态、无需重启。
2. **缩容（成员被移出）**：被移出的节点停止拉取并卸载该分区（移出挂载表、删除 ISR / 延迟指标行、已挂载数减一）；leader 侧从 `followers` 与 ISR 中剔除该成员，并重算 HW。
3. **扩容（成员被加入）**：leader 侧为新成员建进度（`in_sync=False`、位点取日志起点），待其拉取追平后由既有扫描路径重入 ISR；新成员由 02-10 的挂载循环接上，不需要写请求。
4. **本节点不在新副本集**：运行态标记为非承载（不拉取、不进 ISR 推导），与 02-10 的 `hosted` 守卫同口径。
5. **脏数据不猜**：`leader` 指向不在新副本集内的节点时保留现 leader 并告警，不自动改——由迁移预检负责阻断。
6. **数据处置**：卸载**不删**本地分区数据（段 / 索引 / 偏移保留），分配误配或回切时数据仍在；磁盘回收另立。
7. **可观测**：`msg_replication_mounted_partitions` 随之减少；新增收敛日志（卸载 / 成员变更 / 脏数据告警）。
8. **单实例零变化**：复制关闭时刷新循环不启动，本路径不触达。

**边界**：不做「按台账状态」的二次确认（幂等收敛已足够）；不做本地数据删除；不做跨机房；不新增数据表、不改记录格式、不改 ISR 判据与 HW 语义。

## 3. 完成标准 <a id="accept"></a>

- 副本集缩容后，被移出节点在刷新周期内停止拉取并卸载；leader 的 `followers` / ISR 中不再有该成员，ISR 收敛到新副本集大小；
- 扩容后新成员在无写请求的情况下被挂载、追平并重入 ISR；
- 同一分区连续两次变更（先扩后缩）各自收敛一次，不出现「中间态误卸」；
- `leader` 不在新副本集时不自动改主，有告警且状态可查；
- 单实例（复制关闭）行为与既有版本逐项一致；
- 真机 `ops.rebalance` 缩容 → 扩容复跑有记录，结论不默认通过；
- 变更模块行 + 分支覆盖率达标，静态与文档校验通过。
