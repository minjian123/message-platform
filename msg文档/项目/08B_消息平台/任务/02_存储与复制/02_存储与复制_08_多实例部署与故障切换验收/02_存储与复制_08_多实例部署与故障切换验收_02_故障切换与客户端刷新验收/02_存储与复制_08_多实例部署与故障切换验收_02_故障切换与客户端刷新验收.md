## 2. 任务内容 <a id="content"></a>

1. **单节点故障**：强杀 leader 与优雅停 leader 两档，验证选举、任期推进、fencing 与 ISR 收缩；已提交（HW 之前）消息不丢，未提交部分可回退并说明。
2. **网络分区**：隔离 leader / follower 两种分区形态，验证多数派与 fencing 行为、双主防护、恢复后 ISR 重入。
3. **进程崩溃**：实例崩溃后重启，复用 02-2 恢复口径；恢复后不丢已确认、未确认可重投，分区不重排。
4. **客户端刷新**：`acks=all` / `acks=1` 行为差异；实例摘除、重连、位点不越过 HW；流式与一元调用在切换期间的行为。
5. **演练记录**：每类场景记录注入方式、观察指标、恢复时间、是否丢数据、偏离项与遗留；结论区分通过 / 降级 / 失败，降级不计通过。
6. **测试**：三类场景各至少一次完整注入与恢复；数据完整性断言；脚本可重复执行；变更模块行 + 分支覆盖率达标。

## 3. 完成标准 <a id="accept"></a>

- 单节点故障后已提交消息不丢、消费可继续；未提交部分回退范围可说明；
- 网络分区不产生双主写入，恢复后 ISR 正常重入；
- 进程崩溃重启后不丢已确认、未确认可重投、分区不重排；
- 客户端在切换期间可重连，位点不越过 HW，不产生重复副作用；
- 三类演练记录齐全，结论不默认通过；变更模块行 + 分支覆盖率达标。
