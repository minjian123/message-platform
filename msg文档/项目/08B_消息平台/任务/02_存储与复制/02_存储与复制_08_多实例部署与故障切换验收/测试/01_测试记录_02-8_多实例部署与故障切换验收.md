共同口径：

- 每轮前置重置（重启三实例）并新建主题 `drill.replica.probe.<场景>.<时间戳>`，不复用上一轮脏状态；
- `acks=all` 预热向每个实例各写一轮（副本需被写一次才建拉取态）；
- 判据数据来自真实 HTTP 与平台库直读，不依赖管理面主题接口；
- 三份记录均带 `config_digest` 与 `backup=mode=not_applicable + 理由`，`verify` 的 G2 / G7 通过；
- 记录与 `verify` 均无 `force` / `isr_verified=false` 降级项；
- **收口复跑（2026-11-12 晚）**：02-9 为 `replica_crash` 增加硬判据 `auto_switch_within_budget`（自动换主预算 30s），旧记录缺该键导致 `verify` 复验失败 → 按当前口径重跑并替换归档；另两类记录未变，三份记录 `verify --records` 复验 **exit 0**；
- 演练后 `ops.cluster_drill cleanup` 已执行：容器 / 卷 / 自建网络 / `msgdrill_*` 库 / Redis `/13` / 工作区与宿主数据目录 / `drill/msg:drill-*` 镜像全部归零；空白环境下幂等重跑 exit 0（数据清理按「无镜像」跳过）。
- 数据清理脚本另做隔离实测：一次性容器 + 临时库 `msgdrill_probe` → `DROP DATABASE` 成功、Redis `/13` flush 成功、二次执行幂等无残留；删除地址与账号只落不入库的 `cluster.env`。
