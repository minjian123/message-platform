## 2. 实施过程 <a id="process"></a>

1. **重放租约**：`msg_replay_task` 增 `lease_owner` / `lease_expires_at` 与 `(status, lease_expires_at)` 索引；`ReplayTaskRepository` 增 `claim` / `update_owned`，`list_active` 支持按「无租约 / 已过期 / 本实例持有」过滤；`ReplayRunner` 增 `owner` / `lease_seconds`，每拍先 CAS 抢租约再推进，续约随进度更新，被接管即让出；终态清空租约。实例重启后原租约过期，新实例自动接管并从落库游标续跑。
2. **死信索引**：`DatabaseDeadLetterQueue.contains` 改为查库（唯一三元组），进程内只保留 5 秒有界缓存（正负结果都缓存，`cache_size` 暴露条目数）；`add` 成功后回填正缓存，`purge_topics` 同步剔除；`load()` 降级为可选预热。
3. **主题缓存 TTL**：`TopicCache` 增 `ttl_ms` 与注入时钟，`get` 判 `loaded_at_ms` 过期即视为未命中并删除；本实例写操作仍 `invalidate` 立即生效。
4. **概览快照与入口计数**：新增 `models/overview.py`（`msg_overview_snapshot` 每租户一行、`msg_ingress_counter` 租户 × 时间窗）与仓储；采样器每拍按租户聚合积压 / 死信，写入当前窗口增量与覆盖写快照，清理 1 小时前的窗口；`/admin/overview` 优先读库（45 秒过期阈值），无行 / 过期回退进程内快照。
5. **`log_id` 索引**：每分区新增 `log_id.idx`（`hash64 + offset` 定长条目），`append` 同步追加；查找顺序为 LRU → 已加载分区索引 → 磁盘分区索引；索引缺失按段头重建；哈希命中后回读记录比对完整 `log_id`。
6. **装配与登记**：`main.py` 的 `ReplayRunner` 注入 `owner=replica_config.node_id`；新模型登记进 `MODEL_MODULES`、`services/table_registry.py` 与测试建表清单。

## 3. 问题与处置 <a id="issues"></a>

| # | 问题 | 处置 |
| --- | --- | --- |
| 1 | 采样器读维度复用请求会话，读后留下隐式事务，写快照 `begin()` 报 `InvalidRequestError` | `_write_observability` 先 `rollback()` 释放隐式事务再显式开短事务；读维度保持既有「不自持事务」写法，避免破坏测试替身 |
| 2 | 测试替身 `FakeTenantSource.by_code` 不接受 `readonly` 关键字 | 采样器改调 `by_code(code)`（采样本身只读，`readonly` 只影响停用态判定） |
| 3 | 哈希碰撞时索引字典只保留最后一个候选 | 命中后回读比对；失败再按索引文件里的同哈希候选逐个校验 |
| 4 | 分区卸载后 `close_tenant` 再查会重新挂载（冷查的必然副作用） | 用例按「冷查后再次关闭」断言；行为本身是 02-8-4 的目标（冷记录可定位） |
