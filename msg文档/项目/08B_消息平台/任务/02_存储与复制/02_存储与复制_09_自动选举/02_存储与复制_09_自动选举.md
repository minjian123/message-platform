## 2. 任务内容 <a id="content"></a>

1. **判活与判据**：进程内看护循环按固定节拍，对「已挂载且本节点非 leader」的分区探活 `msg_partition.leader` 指向的节点（复用 `LeaderControlTransport.snapshot`，单次超时封顶）；同一分区连续 N 次探活失败才判「leader 不可用」，成功一次即清零。判据不看数据库，探活与元数据读取互不替代。
2. **发起资格与错峰**：发起前必须读到元数据权威（`leader` / `epoch` / `switch_state` / `last_switch_at`），读失败本轮不动作；`switch_state` 非 `idle` 时让位（人工切换优先）；同一分区按副本序（死 leader 的后继顺序）只由第一个可达节点发起，其余节点按序号错峰等待并复核元数据。
3. **复用两阶段切主**：发起动作只调用 `LeaderSwitchService.switch_partition`（`target=None` 由服务按「ISR ∩ LEO 最大」选新 leader、`force=False`、`operator="system:auto-election"`、`reason` 带探活失败次数）；epoch 条件更新即抢占点，落败方按 `switch_conflict` / `noop` 处理，不再重试本轮。
4. **安全前置与降级边界**：候选不可达时在条件更新**之前**失败（不把 DB 改成 `switching`）；无法验证 ISR、无候选、激活失败三种情形计 `blocked` 并告警，自动路径不降级、不使用 `force`；激活失败按同 target 续跑同一轮切换。
5. **退避与冷却**：单分区尝试次数上限、指数退避、成功切换后的冷却（跨节点按 `last_switch_at` 判定）、单轮并发上限；冷却期内新 leader 再次失效不再自动切，只告警；不做自动回切。
6. **可观测**：新增自动选举结果计数（`triggered` / `succeeded` / `blocked` / `conflict` / `exhausted`）与结构化日志；切主结果与审计沿用 02-5 的 `msg_leader_switch_total` 与 `msg:partition.failover`，用 `operator` 区分自动 / 人工。
7. **配置与单实例零变化**：新增独立开关与节拍 / 阈值 / 上限 / 冷却 / 并发 / 错峰键位；复制关闭时不装配、不启动；节拍 × 阈值 + 宽限超出「最后已知视图新鲜窗口」时拒绝启动。
8. **演练改造**：`ops.cluster_drill` 的 `replica_crash` 场景由「杀 leader 后人工切主」改为「杀 leader 后在预算内等自动切主」，人工切主降为超预算兜底（结论记降级）；新增「自动切换完成」判据与对应事实采集。

**边界**：不做 Raft 多数派与跨机房强一致；不做客户端 SDK 改投（沿用 02-8 已验的 `350033` / `metadata_version` 刷新路径，SDK 归 8B_03）；不修 02-4「拉取态初始化」（从未被写过的空闲分区无最后已知视图，只能 `blocked` 并登记回 02-4 后续）；不新增数据表，不改记录格式。

## 3. 完成标准 <a id="accept"></a>

- leader 进程不可用后，集群在预算内自动选出新 leader，`msg_partition.leader` 与 `epoch` 正确推进，客户端改投后可继续写；
- 自动切换期间与切换后不出现双主可写；已提交（HW 之前）消息不丢，未提交尾部按 02-5 口径处理且结果可查；
- 数据库抖动、控制通道整体不可用、冷却期内二次故障均不触发换主风暴，`blocked` / `exhausted` 原因可查；
- 单实例（复制关闭）行为与既有版本逐项一致（无新增指标、无新增日志、无新增行为）；
- 多实例演练中「不人工切主也能恢复」有记录、可复跑，结论不默认通过；
- 变更模块行 + 分支覆盖率达标，静态与文档校验通过。
