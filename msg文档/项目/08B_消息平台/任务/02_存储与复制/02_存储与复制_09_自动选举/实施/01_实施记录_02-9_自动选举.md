## 4. 问题与处置 <a id="issues"></a>

| # | 现象 | 原因 | 处置 |
| --- | --- | --- | --- |
| 1 | 设计假定 `load_partition` 能取到 `last_switch_at` 做跨节点冷却，实际 `SwitchPartitionState` 没有该字段 | 02-5 的值对象只带切换前置字段 | 给 `SwitchPartitionState` **additive** 增 `last_switch_at: datetime \| None = None` 并在 `DbLeaderSwitchStore._state` 映射；旧构造不受影响，无 DB 变更 |
| 2 | 冷却与尝试上限同时命中时，`exhausted` 后又记一次 `blocked(cooldown)` | `_inspect` 先判冷却再判尝试上限 | 达上限后置 `exhausted_reported`，下一轮直接返回（不再是「冷却中」语义），计数只记一次 |
| 3 | 单文件 `pyright` 报 82~32409 个假错误 | `.venv/Scripts/pyright.exe -p pyproject.toml <file>` 解析不到 `bms_core`（缺 venv 解析） | 改用 **`uv run pyright <files>`**（与预检同环境），单文件 0 错误 |
| 4 | 用例断言 `int("5_000")` 回落缺省失败 | Python 的 `int()` 接受下划线分隔 | 改用非法字母（`"abc"`）验证回落 |
| 5 | 演练首次失败：`Unknown database 'msgdrill_msg'` | 上一轮 `cleanup` 会把 `{前缀}_*` 库 DROP 掉 | 用演练账号重建 `msgdrill_msg` / `msgdrill_archive` / `msgdrill_msg_demo` 三库 |
| 6 | 演练再次失败：`guard ISR 未在预算内收敛到 9` | 宿主卷 `/home/minjian/drill/vol/*` 被重建为 `root` 属主，容器 uid 10001 无法建目录 → 发布 500 `error.10000`（日志 `FileNotFoundError: /var/lib/msg/data/<tenant>/msg`） | `sudo chown -R 10001:10001 /home/minjian/drill/vol` 后复跑通过；该前置已记入测试记录 |
| 7 | 演练原本「先人工切主再杀容器」，无法证明自动恢复 | 02-8 的编排口径 | `replica_crash` 改为「杀 leader → 等库内 `leader` 自己变（预算 30s）」，人工切主降为超预算兜底并记降级 |
| 8 | Python 脚本改文件后 git 提示 CRLF | Windows 下 `Path.write_text` 默认转 CRLF | 提交前 `eol` 护栏复跑（0 违规），由 `.gitattributes` 归一化 |
| 9 | 首次推送复判报 `auto_election` 缺 2 个分支（597→601、602→601） | ①「本节点不在后继序」的循环耗尽边在调用方 `_claim_if_eligible` 已保证「本节点在副本集且非 leader」后**不可达**；②「前序多个副本逐个探活」的循环回边缺用例 | ① 改用 `order[: order.index(node)]` 取前序副本，**删除死分支**（不留 `pragma`）；② 补 `test_claims_when_all_earlier_replicas_unreachable`（4 副本、前序两个均不可达）；修复后模块 100% 行 + 分支 |

## 6. 偏差与遗留 <a id="deviations"></a>

**与设计的偏差**

1. `SwitchPartitionState` 增 `last_switch_at`（additive）——设计 §6.1 已回写；数据库仍零变更。
2. 演练编排辅助从「内联脚本串」抽为 `_manual_switch` / `_wait_auto_switch` 两个函数，便于用例覆盖；设计 §12.3 已回写。
3. `exhausted` 后不再走冷却分支（见问题 #2），比设计所述「进入冷却」更严格：不再对已死环境做无意义循环。

**遗留（已登记归口）**
