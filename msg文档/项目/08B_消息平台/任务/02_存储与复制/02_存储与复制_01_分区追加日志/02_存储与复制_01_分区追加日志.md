## 2. 任务内容 <a id="content"></a>

1. **目录布局**：每分区一组目录 `data/{tenant_id}/{namespace}/{topic}/{partition}/`；租户目录用**不可变雪花 `tenant_id`**（不随租户 `code` 改名漂移，架构 04 §2.1）；数据根取部署环境变量 `MSG_DATA_DIR`（开发态默认 `var/lib/msg`），代码与脚本不写死绝对路径。
2. **记录格式**：`[length][crc][header_len][header][payload]`；头为 MessagePack，字段含 `format_version`、`topic_id`、`partition_no`、`tenant_id`、`message_id`、`log_id`、`key`、`trace_id`、`epoch`，并**预留** HW / 副本位点（02-4 / 02-5 使用）；`crc` 覆盖头 + 体，`length` 用于顺序扫描与尾部判定；broker 只读头，**不解析 payload**。
3. **段文件**：按 base offset 命名（20 位零填充）切分为 `.log` / `.index` / `.timeindex`；按大小 / 时间轮转；段内只追加；删除以**整段**为单位（不做段重写）；`SegmentMeta.size_bytes` 取真实文件大小。
4. **索引**：稀疏 offset 索引（每 N 字节一条，间隔在详细设计定稿并实测）、时间索引、`log_id` 索引（形态在详细设计定稿：常驻映射 / 有界 LRU / 落盘稀疏索引，架构 04 §11 #10）；索引条目必须与 `append` 同源生成。
5. **读取路径**：按 offset 段名二分 → `.index` 二分最近索引项 → 顺序扫描定位；支持批量读；对外提供「段文件 + 偏移 + 长度」**读取原语**，由 03 域传输层接 `sendfile`，本任务不写 socket、不做帧协议。
6. **写入路径**：支持多消息一次 append；offset 只由本模块分配（概要设计 §5 约束）；fsync 默认**按批**、可配「每条 / 按时间 / 依赖 OS」（默认值实测后回填），并在设计文档写明各档位的崩溃窗口。
7. **格式演进**：字段只增不删、旧版本可读；启动校验 `format_version`，拒绝写入高于实现支持版本的段（部署文档「格式不回滚」）。
8. **装配**：以文件实现替换 `InMemoryMessageStore`，`MessageStore` 端口签名不变；`RETENTION_SEGMENT_RECORDS` 段替身退役，内存实现保留供轻量用例。
9. **边界**：不做 compaction（架构 09 D39）；不做副本复制（02-4）、不做延迟区落盘（02-7）、不做指标采集（06-3）、不做传输层零拷贝与帧协议（03 域）。

**03 域收口回写（2026-11-05；前置 8B_01 已达成）**

- **端口签名不得变**：`append` 带 `content_type` / `compression` / `uncompressed_len` 三个可选字段（03-3 起随消息落库并在三出口回显）；`fetch` 返回的 `StoredMessage.payload` 必须是**原始线上字节**——03-5 的 inflight 字节阈值按 `len(payload)` 计，broker 不解压。
- **唤醒不在本任务**：长轮询与长驻流的「写入即唤醒」由传输层的 `NotifyingMessageStore` 包装器在 `append` 之后 `notify((topic_id, partition_no))` 完成。文件实现**不要自己通知**，也不要假设包装器可省（装配顺序：内层实现 → 再包一层；顺序错只丢即时唤醒，长轮询退化为「等到超时再拉」）。
- **保留清理**：仍由 `RetentionService` 每请求触发（03-5 的消费路径也会调），段删除必须**幂等**，且与 `truncate_before()` 的起点前移一致。

**实施回写（2026-11-05；[详细设计](设计/01_详细设计_01_分区追加日志.md) §17.2）**

- **记录头字段以端口为准**：除本节列出的字段外，还必须带 `headers` / `published_at` / `content_type` / `compression` / `uncompressed_len`——它们都是 `append` 的入参且 `fetch` 要原样回显（03-3 三出口），不落盘就会丢字段。
- **目录名带 `topic_id`**（`{topic}.{topic_id}`）：删除重建同名时天然隔离，架构 04 §2.1 已同步。
- **恢复职责两段**：本任务只做 `length` 级尾部判定与截断（不做 CRC），CRC / `recovery-point` / 索引补建 / 位点对齐归 02-2。
- **段边界前移**：文件实现把 `truncate_before` 的 `offset` 向下取整到段边界（内存替身保留任意切片，属超集；非段边界行为不作契约）。
- **实测索引体积比 35.0 倍**（1000 条 × 200 字节），明细见[测试记录 §4](测试/01_测试记录_01_分区追加日志.md#measure)。


## 3. 完成标准 <a id="accept"></a>

- 顺序追加、offset 单调不跳号；重启后已落盘消息与 LEO 不变。
- 按 offset 可定位读取，跨段读取结果连续；索引体积显著小于数据体积（给出实测比值）。
- 段按大小 / 时间轮转，整段删除不影响其他段；`SegmentMeta` 与实际文件一致。
- `log_id` 可精确定位记录；延迟转投沿用 `log_id`、重放分配新 `log_id`（两类 ID 分工不被破坏）。
- 读取原语可被传输层零拷贝消费（以最小联调用例验证）。
- `MessageStore` 契约用例全绿；变更模块行 + 分支覆盖率 100%，静态检查全绿。
