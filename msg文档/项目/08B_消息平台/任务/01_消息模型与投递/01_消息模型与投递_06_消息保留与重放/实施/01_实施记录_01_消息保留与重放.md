## 3. 关键实现说明 <a id="impl"></a>

| 点 | 做法 | 为什么 |
| --- | --- | --- |
| 起点前移 | `_logs[key]` 只保留可读记录 + `_starts[key]` 记起点；`leo = start + len`、`append` 的 offset = `start + len` | offset 保持**绝对编号**：重排会让已提交位点指向另一条消息 |
| `fetch` 越界 | `from_offset < start` 时按 `start` 返回，不抛错 | 「位点早于起点 → `350003`」只该在 `consume` 一处给；端口抛错会盖掉业务码，也让重放扫描被迫处理异常 |
| 段替身 | 按 `segment_records`（缺省 1000，用例注入 2）等分切块，段元数据按需计算 | 与真实「整段删」语义同构；不预建段索引，8B_02 换文件实现时端口不变 |
| 容量不删空 | 容量维度最多删到只剩最后一段 | 宁可短暂超配额，也不把刚写入的数据删空（时间维度可删到 0 段） |
| 重放游标上界 | 建任务时把每分区扫描上界锁定为当时的 `LEO` | 否则任务会选中自己刚写入的记录（自噬），加锁也治不了 |
| 额度与回退 | 令牌按经过时间累计（上限 1 秒量）；命中但额度用完时游标**回退一条** | 保证「一条不多、一条不少」，且长停摆后不爆发 |
| 事务边界 | 服务与执行器的每个入口都自开事务并提交 | 会话会被同一次请求 / 执行器复用；不留隐式读事务，否则下一次 `begin()` 撞 `InvalidRequestError: A transaction is already begun`（实测，见 §5） |
| 审计两条 | 创建 / 取消由接口层写（有真实操作人与 IP），完成 / 失败由执行器写 | 「谁迁移谁记」，同一终态不会两条；执行器侧 `user_id` 取任务 `created_by` |
| 审计出口 | `AuditSink`（`emit` 单方法协议）在装配期注入基座 `AuditEventEmitter` | 用例可注替身；不把 bms 具体类型泄漏进测试替身 |

## 5. 问题与处置 <a id="issues"></a>

| # | 问题 | 根因 | 处置 |
| --- | --- | --- | --- |
| 1 | `InvalidRequestError: A transaction is already begun on this Session` | 仓储 / 主题解析的 SELECT 触发 autobegin，随后 `uow.begin()` 再开事务必炸（正是 01-1 记录过的坑） | 把「读 + 判 + 写」整体放进一个 `async with uow.begin()`：`create` / `get` / `_transition` / 执行器 `_active_ids` 与 `_advance` 全部自开事务 |
| 2 | 执行器与请求抢同一会话 | `ensure_started()` 后立刻 `run_once()`，而建任务请求还没结束 | `_loop` 改为**先等一个周期**再推进（ticker 语义），并把该口径回写设计 §6.4 |
| 3 | 区间次序校验改用 `PydanticCustomError` | 裸 `ValueError` 会把异常实例塞进错误的 `ctx`，统一错误响应序列化报 `Unable to serialize unknown type: <class 'ValueError'>` | 契约层改抛 `PydanticCustomError`（无 ctx），仍是 `10001` |
| 4 | 契约快照首轮 diff 达 +3888/−3026 | Windows 下 `write_text` 把 `\n` 译成 `\r\n`，而仓内快照是 LF | 以 `newline="\n"` 重导，diff 收敛为 +865/−3（只含预期项） |
| 5 | 用例里 `replay_service` 与替身存储不是同一实例 | 夹具服务绑定 `message_store`，替身另建 | 用例加局部 `_service(store=...)` 组装（P8 / P13 / S8） |
| 6 | `_count` / `_advance_cursor` 读空时的收尾分支不可达 | 构造上 `end <= leo`，正常读取不会空 | 确认为**并发清理前移起点**时的真实防御（不处置会原地打转），用「分页 + 空洞」存储替身覆盖（S8 / P13） |
| 7 | 执行器的「任务消失 / 已取消」分支不可达 | `list_active` 只捞活跃任务，单进程顺序执行撞不到 | 用「只替换拣任务步骤」的用例模拟竞态窗口覆盖（P14 / P15），任务表仍走真实仓储 |
