## 2. 任务内容 <a id="content"></a>

1. **元数据模型**：确立 `tenant / namespace / topic / partition / offset` 的层级与定位规则，消息以 `(topic, partition, offset)` 三元组唯一定位；`message_id` 由 broker 生成、全局唯一，与 offset 解耦。
2. **主题定义**：`msg_topic` 承载租户、命名空间、主题名、分区数、保留期、清理策略、状态；`msg_partition` 承载分区号、leader、副本集、检查点 LEO / HW。
3. **分区数约束**：创建时确定分区数；提供「增分区」能力并校验，**减少分区一律拒绝**（会破坏 key → partition 映射）。
4. **分区键路由**：按 `hash(key) % partition_count` 选分区，同 key 必落同分区；未提供 key 时按轮询分配，保证分布均匀。
5. **主题接口**：内部与管理面提供创建 / 查询 / 列表接口；创建需 `msg:manage`，查询需 `msg:query`；返回结构包含分区数与创建时间。
6. **登记与装配**：主题表登记到 `backend/services/table_registry.py`（表归属）；服务目录与产品声明保持一致；应用装配后元数据可读写。
7. **测试**：覆盖主题创建 / 查询 / 列表、分区键路由可复现、分区数不可减少、`message_id` 唯一；变更模块行 + 分支覆盖率 100%。

## 3. 完成标准 <a id="accept"></a>

- 可创建指定分区数的主题，返回完整元数据（含 `topic_id`、分区数、创建时间）。
- 同一 key 多次路由结果一致；不同 key 在多个分区上分布均匀。
- 尝试减少分区数时返回明确错误，数据不变。
- `message_id` 在高并发创建下不重复，且与 offset 无绑定关系。
- 主题接口具备权限校验：无 `msg:query` 不可查、无 `msg:manage` 不可建。
- 主题表已登记表归属，应用装配期校验通过。
- 变更模块行 + 分支覆盖率 100%，静态检查（ruff / pyright）全绿。
