## 2. 实施内容

### 2.1 投递扫描（`bms_msg/broker/delivery.py`）

| # | 改动 | 说明 |
| --- | --- | --- |
| 1 | `_collect` 改为停等扫描 | 扫描优先级：已死信跳过 → 未过期在途**停止本批** → 本批已含重投且当前是新消息**停止本批** → 超上限转死信 → 投出；删掉原 `blocked` 变量（它只影响 `acks=0` 的提交游标、不阻断投递） |
| 2 | 已死信跳过 | 扫描入口先 `DeadLetterQueue.contains`；命中即 `mark_acked`（补记已确认暂存）+ 前移 `contiguous` + `continue`，不投、不阻塞 |
| 3 | 重投批内隔离 | 本批一旦投出重投消息（`existing is not None`），后续新消息停止投递、留到下一批；避免「0 刚重投未 ack、2 同批下发」的失败重试与主链路并行 |
| 4 | `_deliver` 签名收敛 | 新增 `existing: InflightDelivery \| None` 入参（调用方已判定未过期），`None` 返回值只表示「本次刚转死信」；未过期在途的判定上移到 `_collect` |
| 5 | 文档字符串 | 模块与 `_collect` / `_deliver` docstring 补顺序性五条口径与扫描优先级 |

**未改动**（与设计 §5.3 一致）：`MessageStore` / `OffsetStore` / `DeadLetterQueue` 端口签名、`DeliveryState` 结构、`TopicRouter`、`schemas/message.py`、`errors.py`、`deploy/registry/msg.toml`、`main.py`、`api/deps.py`。

## 4. 问题与处置

| # | 问题 | 处置 |
| --- | --- | --- |
| 1 | 重投用例首轮失败：期望重投批次只含 `[0,1]`，实际返回 `[0,1,2]` | 停等只判「未过期在途」，重投后同批继续投后面的新消息——正是「失败重试与主链路并行」。**回写设计**（§4.2 规则 3、§4.4「批内隔离」、对齐记录 #11）后加 `retried` 标志：本批一旦含重投，后续新消息停止投递 |
| 2 | 覆盖率缺 1 条分支（`if message.offset == contiguous` 的假分支） | 停等语义下「死信 offset 前面还有未确认缺口」不可达（顺序扫描保证跳过时它必是当前连续前缀）。按「不可达即删分支、不留 `pragma`」改为无条件前移 `contiguous`，并加注释说明依据 |
| 3 | 已死信 offset 在「死信那次位点提交失败」后会永久卡住位点（`_commit` 抛错时未 `mark_acked`，后续 ack 的连续前缀永远缺这一位） | 跳过已死信 offset 时补 `self._state.mark_acked(key, offset)`；`acks=0` 同时前移 `contiguous`。加两例覆盖：`test_dead_letter_commit_failure_allows_later_ack`（ack 补齐后位点越过 0 到 2）、`test_acks_zero_skips_dead_letter_and_advances`（位点直接到 2） |
| 4 | 改 `consume` 端点 docstring 导致契约 `description` 漂移 | 先写 `.cache/contracts/msg.new.json` 与现有快照 diff，确认仅 1 处后覆盖重导；路径 / schema / 错误码无变化 |
| 5 | 存量 `test_acks_zero_does_not_jump_unacked_gap` 断言与新语义冲突 | 按设计 §7.3 改为「`delivered == []` 且位点仍 0」，docstring 写明语义从「不越位点」升级为「不越队头」 |

## 6. 偏差与遗留

| # | 项 | 归口 |
| --- | --- | --- |
| 1 | 停等降低单分区吞吐：队头未 ack 时整分区空转（含已到期的后续消息） | 01-4 组内多分区并行；06 域积压监控与告警 |
| 2 | 批次内允许多条在途，客户端并发处理会乱序 | 客户端契约（详细设计 §4.1）；需要严格串行时用 `max_messages=1` |
| 3 | 进程内 `DeliveryState` 不跨实例，多副本下同一分区可能被两个实例同时投递 | 首期单副本（`workers = 1`）；8B_02 文件段 / 8B_05 复制 |
| 4 | 无 owner / lease，再均衡期间可能重复投递（仍满足至少一次） | 01-4 消费组；消费端幂等兜底（01-2 口径） |
| 5 | 同一分区混用 `acks=0` / `acks=1` 时会互相阻塞（`acks=0` 受他人在途队头约束） | 01-4 组语义统一；文档已写明不建议混用 |
| 6 | 契约快照仍为人工重导，未纳入 msg 预检 | 8B_01（`contract_snapshot` 导出 / 零漂移校验） |
| 7 | 死信落盘与位点文件的原子性未处理（内存态无此问题） | 8B_02（死信随存储持久化）、8B_07（位点文件） |
