## 2. 任务内容 <a id="content"></a>

1. **分区内有序**：同分区按 offset 顺序投递，消费端按序处理。
2. **同键有序**：同聚合键必落同分区（复用 01 的路由规则），从而保证同键事件按发布顺序被消费。
3. **重试不破坏顺序**：同 key 消息失败时，阻塞该 key 的后续投递（或回到原分区尾部重投），不得与主链路并行消费。
4. **并发与顺序的取舍**：分区内串行处理；需要吞吐时按分区并发，不得在分区内并发处理同一 key。
5. **再均衡不跳消息**：再均衡期间允许短暂停摆，但位点不得跳过未处理消息，也不得丢消息。
6. **测试**：同 key 顺序、失败重试后顺序、再均衡后无跳过；变更模块行 + 分支覆盖率 100%。

## 3. 完成标准 <a id="accept"></a>

- 同一 key 的多条消息严格按发布顺序被消费，重复验证多次结果一致。
- 模拟某条消息处理失败并重试，后续同 key 消息不会越过它先被消费。
- 再均衡后位点连续，无消息被跳过或重复投递到不同消费者。
- 跨分区不承诺顺序的边界在文档中写明，并有测试覆盖「不同 key 可并行」。
