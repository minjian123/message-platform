## 2. 任务内容 <a id="content"></a>

**A 语义与接口（本任务）**

1. **固定档位**：`delay_level` 取 1s / 5s / 10s / 30s / 1m / 5m / 10m / 30m / 60m；档位非法由契约层拒绝（`10001`），档位表落 `core/config.py`（只增不删）。
2. **延迟区端口**：`DelayStore`（入队 / 按到期时间取批次 / 计数 / 清记录）+ 内存实现，8B_02 换 `.delay` 段落盘；发布时按 key **锁定分区**并写入该分区延迟区，**不占 offset、不参与停等、不计入积压**；发布时同时分配 `message_id` 与 `log_id`（`log_id` 随延迟记录保存，转投沿用）。
   **端口扩展**：`MessageStore.append` 与 `StoredMessage` 增加 `log_id`（发布时生成、转投沿用、重放新分配）；`DeliveryService.publish` 同步补参。论证见架构 04 §2.2「两类 ID 的分工」——不用 `message_id` 做记录级去重，因为重放会合法产生同 `message_id` 的多条记录。
   **契约增量**：`PublishResult` additive 增加 `log_id`（普通与延迟发布均下发；消费响应不下发），供上游（尤其审计域）发布即引用；契约快照随之重导。
3. **到期驱动**：分层时间轮（L0 秒级 60 桶 / L1 分钟级 60 桶 / L2 小时级 24 桶）+ 后台定时任务推进；到点批量取出 → `append` 到同分区日志（**此刻才分配 offset**）→ 清延迟记录。
4. **不可见期与后续语义**：到期前对任何消费组不可见；到期后完全复用既有链路（至少一次、分区内停等、死信上限、保留期从 `append` 起算、重放不改 `message_id`）。
5. **健壮性**：到期转投失败**不删延迟记录**（退避重试 + 告警）；时钟回拨不得提前投递、前跳须限速批量到期；延迟区按软上限（租户 + 全局）拒绝并返回 `350015`（不占用预留的 `350004/005/006`）。
6. **只读视图**：`GET /msg/admin/delayed`（待投列表 + 计数 + 剩余时间），权限 `msg:query`；06 域在此基础上扩筛选与指标看板。首期不做改期 / 取消。
7. **边界**：定时消息（绝对时间）不在本任务范围；任意精度延迟同样不做（固定档位）。

**B 持久化与到期恢复（归 8B_02，需求 02-7）**

8. `.delay` 段落盘与 CRC 校验、启动扫描重建时间轮（未到期按剩余时间、已到期未转投立即补投）、转投偏序（先写后清，不丢）与恢复期按 `log_id` 去重（不重）、延迟区 TTL 与段损坏隔离、优雅关闭刷盘。

## 3. 完成标准 <a id="accept"></a>

- 延迟消息在设定时间前不可被任何消费者读取；到期后可被正常消费，且顺序 / 死信 / 保留口径与普通消息一致。
- 延迟消息不占 offset：发布延迟消息不改变 LEO、不推进位点、不计入积压。
- 到期转投失败时延迟记录仍保留（可见、可重试）；延迟区超软上限返回 `350015` 而不是静默丢弃。
- 时钟回拨场景下不出现提前投递；延迟中消息的待投列表与剩余时间可查。
- 非法档位由契约层拒绝（`10001`），档位表可查。
- **（归 8B_02 承接）** 进程重启后未到期延迟消息按剩余时间投递、不提前不丢失，且同一 `log_id` 不重复入日志（单副本）——判据见[需求 02-7](../../../需求/02_需求_存储与复制.md#r02-7)。
