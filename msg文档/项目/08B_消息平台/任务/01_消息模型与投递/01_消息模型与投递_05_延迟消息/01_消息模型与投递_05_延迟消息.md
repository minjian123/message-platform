## 2. 任务内容 <a id="content"></a>

1. **固定延迟级别**：支持固定档位（如 1s / 5s / 10s / 30s / 1m / 5m / 10m / 30m / 60m），不支持任意时间精度。
2. **不可见期**：延迟消息在到期前对消费者不可见；到期后进入正常投递流程。
3. **持久化**：延迟消息与普通消息一样落盘，进程重启后延迟计时不丢失。
4. **清理与死信**：延迟消息的超时清理、重试与死信策略与普通消息一致。
5. **边界说明**：定时消息（指定绝对时间）不在本任务范围，作为后续能力登记。
6. **测试**：延迟前不可消费、到期可消费、重启后延迟仍生效；变更模块行 + 分支覆盖率 100%。

## 3. 完成标准 <a id="accept"></a>

- 延迟消息在设定时间前不可被任何消费者读取。
- 到期后可被正常消费，且顺序与投递语义与普通消息一致。
- 进程重启后，未到期的延迟消息仍在剩余时间后投递，不提前也不丢失。
- 延迟档位在配置中可查，非法档位被拒绝并返回明确错误。
