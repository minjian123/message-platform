### 2.3 延迟区（`bms_msg/broker/delay.py`，新建）

| # | 交付 | 说明 |
| --- | --- | --- |
| 7 | `DelayRecord` | 不可变记录：`log_id` / `message_id` / 租户 / 主题主键 / 命名空间与主题名（展示 + 排障）/ 锁定分区 / 档位名 / 载荷与头 / `deliver_at` / `attempts` |
| 8 | `DelayStore` 端口 | `enqueue` / `count_for_tenant` / `list_for_tenant` / `list_all`（B 段重建入口）/ `remove`；端口**不含时间轮**；`quota` 是本实现承载的每租户软上限 |
| 9 | `InMemoryDelayStore` | 按 `log_id` 幂等覆盖（重试更新 `attempts` 走同一入口）；列表按 `(deliver_at, log_id)` 升序（结果确定可断言） |
| 10 | `delay_level_ms()` | 档位名 → 毫秒；未知档位 `10001`（服务层防御性二次校验，与契约层同码） |
| 11 | `ensure_delay_span()` | 跨度上限校验，由 `enqueue` 调用（**端口层**，所有入口 / 所有实现共用同一上限） |
| 12 | `DelayService.publish()` | 判定顺序：命名空间（`350010`）→ 主题（`350001`）→ 分区锁定（`350009`）→ 档位（`10001`）→ 配额（`350015`）→ 生成 `message_id` / `log_id` → `enqueue` → `wheel.place`；返回 `DelayedOrder`（无 offset） |
| 13 | `DelayInspector.list_delayed()` | 只读：过滤（命名空间 / 主题 / 分区 / 档位）→ 到期升序 → 分页；`remaining_ms = max(0, deliver_at - now)` |
| 14 | `with_attempt()` | 转投失败时整条替换记录（`attempts + 1`，不丢弃） |

### 2.4 到期驱动（`bms_msg/broker/scheduler.py`，新建）

| # | 交付 | 说明 |
| --- | --- | --- |
| 15 | `DelayWheel` | 三层分桶（L0 60×1s / L1 60×60s / L2 24×3600s），槽位按**绝对时间**取模；`layer_of` 按剩余时间选层；`place` 统一装填入口（发布 / 重试 / 重建）；`take_due` 统一推进入口；`clear` 供 B 段重建 |
| 16 | 追赶窗口 | 单轮推进 ≤ 60s（含端点秒位），长停摆 / 前跳的剩余秒位留给后续轮次，逐轮补齐不丢不早投 |
| 17 | 时钟纪律 | 回拨（`now < last_scan`）本轮返回空、指针不后退；同刻重扫（`now == last_scan`）仍重扫当前秒位，使被批上限挡下的记录下一轮能被取出 |
| 18 | `_overdue` 待重试队列 | 已到期记录（重试 / 重建补投）不进已扫过的秒位，由下一次推进首先取出——这是「失败保留 + 下一轮重试」的实现依据 |
| 19 | `DelayScheduler.run_once()` | 取候选 → 逐条判 `deliver_at <= now` → 未到期重新装填 → 达批上限留待下一轮 → 转投；返回本轮转投条数（纯步进，不 sleep） |
| 20 | 转投偏序 | `append`（沿用 `log_id`，`published_at` 取 `deliver_at`）成功后才 `store.remove`；任一环节异常走失败处置：记录保留、`attempts + 1`、日志 `delay_deliver_failed`、下一轮重试 |
| 21 | 生命周期 | `ensure_started()` 幂等（有任务即返回）、`stop()` 幂等（取消并等待退出）、`_loop` 单轮异常只记日志不终止任务 |

## 4. 问题与处置

| # | 问题 | 处置 |
| --- | --- | --- |
| 1 | 时间轮首轮「指针未知」时按 `now - 60s` 起扫：早于 60s 装填的桶永远扫不到（前跳用例暴露出「早期记录被跳过」） | 指针在**构造时**落位（`_last_scan = now()`），装填只可能落在其后的秒位，窗口从指针起算；顺带删掉 `None` 分支（不留不可达分支） |
| 2 | 同一时刻连续 `run_once` 若按「`now <= last` 直接返回」处理，被批上限挡下的记录永远取不出来 | 回拨判据改为严格 `now < last`；同刻调用重扫当前秒位 + 清待重试队列，正好接住「上一轮重新装填的记录」 |
| 3 | L2 桶与「跨度超上限」分支走正常档位不可达（档位最长 60m） | 按设计用端口级直接入队造 7200s / 90000s 记录覆盖（用例 #6 / #7 + 小时桶追赶用例），**未使用 `pragma`** |
| 4 | 只读视图的 `page < 1` 在接口层被 `Query(ge=1)` 挡在门外，服务层护栏无覆盖 | 与 01-4 同口径：在服务层直接断言 `ParamError`（`test_inspector_rejects_invalid_paging`） |
| 5 | 命名空间过滤分支不可达：发布链路只能产出本域记录（`ensure_namespace` 只放行已启用 module_key） | 端口级入队一条 `namespace="nope"` 的记录，再用 `?namespace=msg` 过滤掉（`test_inspector_filters_by_namespace`） |
| 6 | 推进任务若在 `_loop` 里裸跑，单轮异常会让后台任务静默退出，延迟投递永久停摆 | `_loop` 单轮 `try/except` 记日志后继续；用例 `test_loop_survives_tick_failure` 用首轮抛异常的时间轮替身验证「下一轮照常转投」 |
| 7 | 生命周期用例想断言「只建一个任务」需读私有 `_task`，`pyright strict` 报 `reportPrivateUsage` | 改为行为断言：两次 `ensure_started()` 后 `stop()` 只有一个任务可停——若多建一个，`stop` 后留下的任务会把后续记录投出去，断言即失败 |
| 8 | 三处存量接口用例装配缺延迟区 / 推进器 → 发布路由 500 | 三处 `api_app` 补齐 `delay_store` / `delay_scheduler`（用例装配与生产装配同源，缺一项即暴露） |
| 9 | 契约漂移比设计多一项：`/msg/publish` 的 `x-error-codes` 追加了 `350015` | 属「新增错误码须在端点声明」的必然结果（跨仓 `check_modules` 反向对账要求），已记入 §2.6 并回写设计 §3 口径说明 |

## 6. 偏差与遗留

| # | 项 | 归口 |
| --- | --- | --- |
| 1 | 延迟区与时间轮均为进程内状态，重启即空（延迟消息丢失，但已入日志的不受影响） | 8B_02（`.delay` 段落盘 + 启动重建 + 恢复期按 `log_id` 去重，需求 02-7） |
| 2 | 多副本各自推进同一分区，会重复转投 | 首期单副本（`workers = 1`）；8B_05（单写者 / fencing） |
| 3 | 转投失败无退避（每轮 1s 一次，`attempts` 只计数） | 设计 §6.2 定为「下一轮重试」；连续失败量大时由 06 域告警 + 人工处置（指标 `msg_delay_deliver_failed_total` 待 06 域落地，本任务只有日志） |
| 4 | 配额计数为全量扫描（内存实现） | 条数有软上限（每租户 10 万）；8B_02 换索引计数 |
| 5 | 启动后若从未发布延迟消息，进程不推进（含 B 段恢复出的存量记录） | 惰性启动的设计取舍（§12 风险 2）；**B 段恢复路径须自行 `ensure_started()`** |
| 6 | 显式注册进程级启动任务（不依赖首个发布） | 8B_01（基座 `service_lifespan` 产品启动钩子） |
| 7 | 待投视图只做最小集（无改期 / 取消 / 删除），未做聚合统计 | 06 域（指标看板与写操作） |
| 8 | 延迟区满只按「每租户」判，全局软上限未做（任务原文写「租户 + 全局」） | 06 域 / 8B_02 落盘时按段统计后补全局阈值（当前先守住租户维度，避免单业务吃满） |
| 9 | 契约快照仍为人工重导，未纳入 msg 预检 | 8B_01（`contract_snapshot` 导出 / 零漂移校验） |
| 10 | `PublishResult.offset` 放宽可空属**破坏性契约变更**（读 offset 做后续操作的客户端须判空） | 版本仍为 `0.1.0` 预发布、无外部调用方；8B_01 帧入口按同一契约实现 |
