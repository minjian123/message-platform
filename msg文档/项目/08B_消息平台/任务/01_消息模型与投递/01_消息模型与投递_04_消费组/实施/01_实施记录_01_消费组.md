## 2. 实施内容

### 2.1 组模型与存储端口（`bms_msg/broker/group.py`，新建）

| # | 交付 | 说明 |
| --- | --- | --- |
| 1 | `GroupMember` / `ConsumerGroup` | 不可变快照：成员含 `joined_at` / `last_seen` / `partitions`；组含 `tenant_id` / `topic_id` / `group` / `state` / `generation` / `members`（成员按 `consumer_id` 升序） |
| 2 | `GroupStore` 端口 | `load` / `save`（整条覆盖）/ `list_for_tenant`（`topic_id` 可选）；8B_02 换 `msg_group` 两表时签名不变 |
| 3 | `InMemoryGroupStore` | `(tenant_id, topic_id, group)` 为键；列表按 `(组名, 主题主键)` 升序（结果确定可断言） |
| 4 | `assign_range()` | range 纯函数：成员升序、分区连续切段、余数给靠前者、成员多于分区时靠后者为空 |
| 5 | 常量 | `empty` / `preparing_rebalance` / `stable` / `dead` 四态；策略位 `ASSIGNMENT_STRATEGY_RANGE` |

### 2.2 协议编排（`bms_msg/broker/coordinator.py`，新建）

| # | 交付 | 说明 |
| --- | --- | --- |
| 6 | `join` | 组不存在则建（`empty` / 世代 0）；清理超时成员；新成员 → `preparing_rebalance` → 分配 → `stable` 且世代 +1；同 `consumer_id` → 只刷新 `last_seen`（不递增世代） |
| 7 | `heartbeat` | 组不存在 `350013`、成员不在组内或已超时 `350014`；清理他人超时并重算；返回当前分配与节奏参数 |
| 8 | `leave` | 幂等（未注册成员也返回成功）；最后一人离开 → `empty`；仍有他人 → 立即重算 |
| 9 | `ensure_owner` | 数据面入口唯一校验：命名空间 → 主题 → 组（`350013`）→ 分区号（`350009`）→ 成员与归属（`350014`） |
| 10 | `_revoke` | 对比新旧 owner，仅对**易主分区**清在途（`DeliveryState.drop_partition`），位点与暂存确认不动 |
| 11 | `_stale` | `Σ 成员分配分区数 ≠ partition_count` 且成员非空即重算，覆盖 `expand_partitions()` 后的新分区 |

### 2.3 只读视图（`bms_msg/broker/inspector.py`，新建）

| # | 交付 | 说明 |
| --- | --- | --- |
| 12 | `list_groups` | 按租户取组 → 按 `topic_id` 反查主题（缺失即跳过，防孤儿记录脏展示）→ 命名空间 / 主题名过滤 → 组名升序 → 分页 |
| 13 | `describe` | 组详情 + 逐分区 `owner` / `committed` / `leo` / `lag`（只读，不写任何状态） |

## 4. 问题与处置

| # | 问题 | 处置 |
| --- | --- | --- |
| 1 | 归属校验一度插在分区号校验之前：`consume(partition=9)` 返回 `350014` 而非 `350009`，与设计 §6.1 的判定顺序冲突 | 在 `ensure_owner()` 里先调 `TopicRouter.partition()`（`350009`）再判成员归属；补用例 `test_ensure_owner_partition_out_of_range_returns_350009` 锁住顺序 |
| 2 | 扩分区用例报 `InvalidRequestError: A transaction is already begun`：主题解析留下隐式事务，`expand_partitions()` 自己 `begin` 失败 | 用例内先 `db_session.rollback()` 结束隐式事务；**回滚会让 ORM 属性过期**，故先把 `topic_id` 取到局部量（否则 `MissingGreenlet`） |
| 3 | `test_data_messages.py` 的既有装配缺成员路由与组存储 → 加入请求 404、消费触发 `AttributeError: group_store` | 用例装配补齐 `data_groups.router` 与 `app.state.group_store`（用例装配与生产装配同源，缺一项即暴露） |
| 4 | 覆盖率首轮缺 4 行 / 4 分支：重连 + 清理后的重算路径、`list_groups` 的分页护栏与命名空间过滤 | 补 4 例（`test_rejoin_after_peer_timeout_rebalances`、`test_inspector.py` 的 `page<1` / `size` 超限 / 跨命名空间跳过）；**未使用 `pragma`** |
| 5 | 设计与实测的契约增量口径不同（设计预估 +4 端点 / +8 schema，实测 +5 / +12） | 回写设计 §3 与 §7.5 的增量口径（含 4 个 `ApiResponse` 包装） |
| 6 | 共享字段下沉到 `schemas/fields.py` 后担心既有契约漂移 | 字段 `Field(...)` 逐字迁移，重导后比对：`/msg/publish` 与 `/msg/admin/topics` 的 schema / 路径**完全未变** |

## 6. 偏差与遗留

| # | 项 | 归口 |
| --- | --- | --- |
| 1 | 组元数据（组 / 成员 / 分配 / 世代）为进程内状态，重启即丢，客户端须重新 `join` | 8B_02（`msg_group` / `msg_group_member` 两表，端口不变） |
| 2 | 多副本下组状态不共享：同一组在两个副本各自维护分配 | 首期单副本（`workers = 1`）；8B_02 / 8B_05（协调者归属与复制） |
| 3 | 无后台定时器：全员静默时组停在 `stable`，清理靠下一次 `join` / `heartbeat` 被动触发 | 06 域可加周期扫描（不影响正确性，只影响状态显示时效） |
| 4 | eager 全量再均衡：每次成员变动全组重算，分区易主面最大、短暂重复投递 | cooperative + sticky 已预留（策略位 + `generation` 语义）；06 域评估落地 |
| 5 | `consume` / `ack` 新增必填 `consumer_id` 属破坏性契约变更（既有客户端须先 `join`） | 版本仍为 `0.1.0` 预发布、无外部调用方；8B_01 帧入口按同一契约实现 |
| 6 | 请求内主题解析两次（归属校验 + 投递服务），每条消费多一次元数据查询 | 8B_01 帧入口落地时合并为一次解析 |
| 7 | `consumer_id` 无身份校验：同组内可用他人 id 顶替（视为重连，拿到同一分配） | 05 域认证接入成员令牌后收紧，成员键不变 |
| 8 | 撤销清在途使 `delivery_count` 重计（消费端看到的重复计数可能回落） | 文档已写明「计数按 owner 移交重置」；幂等仍靠业务键（01-2 口径） |
| 9 | `dead` 态本任务不产生（常量与迁移条件已定义） | 06 域组删除时启用 |
| 10 | 组列表按 `topic_id` 反查主题（N+1），组多时查询放大 | 06 域做聚合视图时改联表 |
| 11 | 契约快照仍为人工重导，未纳入 msg 预检 | 8B_01（`contract_snapshot` 导出 / 零漂移校验） |
