## 2. 任务内容 <a id="content"></a>

1. **两表落库**：新建 `msg_consumer_group`（组：租户 / 主题 / 组名 / 命名空间快照 / 状态 / 世代）与 `msg_group_member`（成员：所属组 / 成员标识 / 实例标识 / 加入与心跳时刻 / 持有分区），组内成员唯一、按组整替；模型登记进 `MODEL_MODULES`，并补两份数据表设计。
2. **DB 组存储**：新增 `DatabaseGroupStore`（每次操作自开 UoW，`load` / `save` / `list_for_tenant` / `list_all` / `delete` / `purge_tenant` / `purge_topic` / `mark_idle_dead`），生产装配替换 `InMemoryGroupStore`，端口签名不变。
3. **成员租约**：心跳**写穿**（每次 `heartbeat` 更新 `last_heartbeat`），存活判据仍是 `last_heartbeat + 会话超时`；多实例看到同一份租约。
4. **空组回收**：后台扫描器把「`empty` 且空闲超过 7 天」的组置 `dead`（保留成员行与位点），显式删除才真删；`dead` 组重新 `join` 时回到正常流程。
5. **组删除端点**：`DELETE /api/v1/msg/admin/groups/{namespace}/{topic}/{group}`，默认**保留位点**，可选 `purge_offsets=true`；`msg:manage` + 主题级 `manage` + `confirm` + 强审计。
6. **B1 新组接入**：无已提交位点时从 `start_offset`（现存最早）开始，并把该起点写实为已提交位点；**提交过但已被保留期清理**才返回 350003。
7. **B12 长驻流 ACL**：长驻订阅流每 30 秒重判一次主题 `subscribe` 授权，且**每批判**一次；授权被收回时发 `error`（350027）+ `close(acl_revoked)`。
8. **B19 inflight 字节账**：字节额度按「分区」聚合（同一分区跨组只算一份），不再按组线性放大。
9. **前端**：消费组详情加「删除组」入口（`msg:manage`、二次确认、可选清位点复选）。

## 3. 完成标准 <a id="accept"></a>

- 组与成员落库：`join` / `heartbeat` / `leave` 后 DB 行与内存快照一致；进程重启（重建存储）后组、成员、分配、世代仍在，客户端 `heartbeat` 直接续用。
- 心跳写穿：每次心跳 `last_heartbeat` 前进；超时会话后同组任意请求清理该成员并触发再均衡。
- 空组超 7 天自动置 `dead`；`dead` 组不出现在活跃消费流程，但管理面可查；重新 `join` 恢复。
- 组删除：默认只删组与成员行、位点保留；`purge_offsets=true` 一并清位点；不存在返回 350013；`confirm` 缺失 10001；删审计 `msg:group.delete`。
- B1：新组（无提交记录）在 `start_offset > 0` 的分区上正常拉到现存最早消息，不再 350003；已有提交被清理仍 350003。
- B12：ACL 收回后最长 30 秒（或下一批）结束流，错误码 350027。
- B19：同分区被 N 个组同时消费时，字节额度只按一份计。
- 变更模块行 + 分支覆盖率 100%；ruff / pyright / 契约零漂移 / 文档三项全绿；前端相关门禁全绿。
