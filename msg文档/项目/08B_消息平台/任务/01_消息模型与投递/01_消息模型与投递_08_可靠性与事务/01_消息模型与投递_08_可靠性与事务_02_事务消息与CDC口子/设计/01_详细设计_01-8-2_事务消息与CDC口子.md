## 1. 任务级边界与输入基线 <a id="scope"></a>

**做什么**：把「事务消息 / CDC 首期不实现」从一句原则变成**可被后续任务直接接手的占位口径**——端口位置、事件类型、失败分支、触发条件、不做的后果、占位字段与未知字段处理策略全部有单一事实源；把边界回写到需求、架构、规划三处；用自动化护栏锁住「不宣称已支持」。

**不做什么**：

- 不实现事务消息（半消息 / 回查 / 提交或回滚 / 事务状态表 / 回查调度与接口），不改 bms `EventPublisher.publish_transactional()` 的「委托 `publish()`」现状；
- 不做通用 CDC 平台、不接 binlog / WAL、不尾随业务表、不承诺多源同步、不新增扫描端点、不写 outbox connector 实现；
- 不进公开契约快照 `deploy/contracts/msg.json`、不进 `deploy/events/contracts.json`、不新增端点 / 错误码 / 事件契约 / 配置节；
- 不新增业务能力用例，不改 01-8-1 已交付的实现与用例；不改 bms 仓任何代码、契约快照与端口形状；
- 不在本任务内推送远程、不触发 CI。

## 4. 后置口径定稿 <a id="postponed"></a>

### 4.1 事务消息 <a id="postponed-tx"></a>

**首期不实现**。`publish_transactional()` 继续委托 `publish()`；「业务提交 ⇒ 事件可投递」由 outbox 适配后的 relay 保证（01-8-1 形态 A），跨服务写仍走 TM + XA。

**触发条件**（全部满足才进入实现评审，定性口径；投入量级归阶段计划）：

1. 出现明确需求：业务侧不再维护 outbox 表 / relay，并愿意承担「本地事务结果持久化 + 回查依据」改造；
2. 平台持久化日志、位点与复制能力就绪（8B_05 交付后）；
3. 半消息存储 / 事务状态登记 / 回查调度 / 回查接口四类组件有明确归口与验收判据；
4. 真机验证「提交 / 回滚 / 崩溃回查 / 重复投递」四条路径；
5. 设计评审通过并完成投入登记。

**不做的后果**：业务继续维护 outbox 表与 relay，承担轮询延迟与表的运维成本；迁移期若把 `publish_transactional()` 误当真实事务通道，会形成「以为消息与本地事务原子、实际先发后提交」的静默不一致——因此文档与用例必须锁住「不宣称已支持」。

### 4.2 CDC 口子 <a id="postponed-cdc"></a>

**只保留 `outbox connector` 一种形态的接口口子**（消费 outbox 变更并转投）。不做通用 CDC 平台、不接 binlog / WAL、不尾随业务表、不承诺多源同步；msg 仓服务端不新增扫描端点；01-8-1 的形态 A（bms 侧 relay 的 msg 版本）不变。

**触发条件**：① 出现「零侵入接入」需求（业务完全不改代码即产生事件）；② 三库（MySQL / PostgreSQL / 达梦）日志差异与跨库权限模型有解（达梦无成熟 Debezium connector）；③ 平台复制能力与位点 / 幂等口径可复用；④ 明确仍以 outbox connector 为先、不直接尾随业务表；⑤ 设计评审通过并完成投入登记。

**不做的后果**：事件仍由业务写 outbox、relay 轮询投递，轮询延迟无法消除；不提供零侵入接入与多源同步。迁移期若把口子误读为已接入，会把业务表变更当作事件源，使事件契约与表结构强耦合、字段改名即破坏契约。

## 5. 占位契约单源 <a id="contract"></a>

### 5.1 落点与不承诺能力 <a id="contract-place"></a>

单一事实源为 `deploy/events/postponed_capabilities.toml`（TOML，`tomllib` 可解析）。它**不是公开契约**：不注入 `deploy/contracts/msg.json`、不进 `deploy/events/contracts.json`、不产生端点 / 错误码 / 配置键。选它的理由：后续任务把该文件升为正式契约即可接手、无需重写；同时公开承诺面不被占位字段污染。

**不承诺能力的三重锁**：

1. 顶层与每个条目的 `status` 恒为 `reserved`，用例断言不存在其它取值；
2. 顶层 `scope` 明示「不是公开契约，不构成已承诺能力」；
3. 公开快照与文档断言双重护栏（§8），且预留事件类型名不进事件契约快照。

### 5.2 字段边界 <a id="contract-fields"></a>

| 键 | 类型 | 语义 | 缺省 / 约束 |
| --- | --- | --- | --- |
| `schema_version` | 字符串 | 版本可见，语义化三段 | 当前 `1.0.0`；主版本不变即兼容 |
| `status` | 字符串 | 顶层状态 | 恒 `reserved` |
| `scope` | 字符串 | 归口与「不是公开契约」声明 | 必填 |
| `source` | 字符串 | 任务来源 | 必填 |
| `[compatibility]` | 子表 | `additive` / `unknown_fields` / `version_visible` / `major_change` 四条策略文本 | 必填 |
| `[transactional_message]` | 子表 | `status` / `port_position` / `state_model` / `future_components` / `reserved_event_types` / `failure_branches` / `trigger_conditions` / `consequence_if_skipped` | 全部为只读描述，不产生运行期行为 |
| `[cdc_outbox_connector]` | 子表 | `status` / `form` / `excluded` / `failure_branches` / `trigger_conditions` / `consequence_if_skipped` | 同上 |
| `[review]` | 子表 | 评审记录路径 / 结论 / 投入归口 | 不写具体数值 |
| `[ownership]` | 子表 | 消费方与归口阶段 | 只读 |

### 5.3 三条兼容策略（只增不删 / 未知忽略 / 版本可见） <a id="contract-policy"></a>

| 策略 | 口径 | 用例判据 |
| --- | --- | --- |
| **只增不删** | 新增字段一律可选，已有键不得删除、不得改语义；主版本内只增 | 单源 `compatibility.additive` 文本 + 帧契约 `version_rule.minor` 同口径；用例断言已知键集合稳定 |
| **未知字段忽略** | 解析按已知键取缺省，未知键既不报错也不进入结果；旧实现读到新增键照常工作 | 用例向单源文本注入未来键，解析结果不变且不含该键（§8 U2） |
| **版本可见** | `schema_version` 随契约返回；主版本变更须显式评审，占位期内不发生 | 用例断言版本字段可读、主版本与 `accept_major` 一致（§8 U3） |

> 与帧协议的关系：这三条沿用架构 D7 与 `frame_contract()["version_rule"]` 的既有措辞，但**不复用帧契约的字段结构**——占位单源是独立的后置能力登记，不是帧协议扩展。

### 5.4 失败分支与处置 <a id="contract-failures"></a>

| # | 分支 | 触发 | 占位期处置 |
| --- | --- | --- | --- |
| 1 | 半消息悬挂 | 生产者崩溃 / 未提交未回滚 | 只登记回查调度超时判据，不实现调度 |
| 2 | 回查依据缺失 | 操作 / 登录审计无业务行可查 | 必须显式失败，不得猜 COMMIT；审计暂存表归后续实现 |
| 3 | 提交 / 回滚冲突 | 重复 commit 或状态乱序 | 幂等拒绝并留痕，归后续实现 |
| 4 | 回查超时 / 超次数 | 调度器多轮无结果 | 显式失败 + 可定位记录，不静默丢弃 |
| 5 | 半消息对消费者可见 | 不可见标记失效 | 契约破坏，须在真实实现里拦截 |
| 6 | 本地事务失败但消息已发 | 发布成功、事务回滚 | 沿用至少一次 + 消费端幂等，不新增补偿 |
| 7 | CDC 位点丢失 / 重复 | 连接器崩溃后恢复 | 重投 + 消费端幂等，归后续实现 |
| 8 | 三库方言不一致 / 权限不足 | 达梦日志无法解析、跨库写回被拒 | 显式拒绝并停 connector，不降级猜读、不静默回落 |
| 9 | 占位被误读为已实现 | 文档 / 契约出现肯定式能力描述 | 文档断言护栏阻断（§8 U5） |

## 6. 端口 / 事件类型 / 失败分支占位 <a id="placeholder"></a>

### 6.1 端口位置（零代码） <a id="placeholder-ports"></a>

| 能力 | 现有端口位置 | 未来实现位置（只写语义） |
| --- | --- | --- |
| 事务消息 | bms `EventPublisher.publish_transactional()`（首期委托 `publish()`，无生产调用点） | msg 侧四类组件：半消息存储、事务状态登记、回查调度、回查接口 |
| CDC | bms `BaseOutboxStore` / relay（01-8-1 形态 A 已切到 msg 发布实现） | msg 侧 `outbox connector`：消费 outbox 变更并转投，不新增扫描端点 |

**零代码**：本任务不新增 ABC 端口、空声明模块、常量表或配置键。理由是可被导入的端口容易被误读为「已实现」，且纯声明模块需另加覆盖率护栏；只登语义位置同样能被后续任务直接接手。

### 6.2 事件类型预留名 <a id="placeholder-events"></a>

预留 `msg.transaction.prepared` / `msg.transaction.committed` / `msg.transaction.rolled_back` / `msg.transaction.check_requested` / `msg.outbox.change_captured` 五个名字，**只作命名占位**：不进 `deploy/events/contracts.json`、不进 `platform_events.py`、不进错误码登记、不产生订阅。`deploy/events/README.md` 的「当前无事件」事实不变。

### 6.3 失败分支清单 <a id="placeholder-failures"></a>

事务消息：悬挂 / 回查依据缺失 / 提交或回滚冲突 / 回查超时 / 不可见标记失效 / 事务失败但消息已发（§5.4 #1~#6）。CDC：位点丢失或重复 / 三库方言不一致 / 权限不足 / 业务表 schema 耦合（§5.4 #7~#8）。全部只写「触发 → 表现 → 后续处置」，不落实现。

## 8. 测试设计与验收映射 <a id="tests"></a>

## 9. 实现约束与提交口径 <a id="constraints"></a>

| 项 | 强制口径 |
| --- | --- |
| 解释器 | 只用 `D:/Develop/bizs/bms/backend/.venv/Scripts/python.exe`（3.14）；禁止 PATH 上的 `python` |
| 集合声明 | 用例内集合声明一律 `ConcurrentStable*` / `ConcurrentStableFrozen*`；`ConcurrentStableList` 用于列表，`ConcurrentStableFrozenList` 用于常量元组式清单 |
| 用例登记 | 设计定稿后**先登记 Kiwi 用例再编码**（平台骨架 / P2 / CONFIRMED / 自动化） |
| 文档校验 | `engkit links` / `engkit docs-scope` / `engkit eol --fix` 全绿；本设计链接均为相对链接 |
| 文档措辞 | 非计划文档不写进度类词面；架构节点只写语义、不写任务编号 / 字段名 / 路径 |
| 提交粒度 | msg 仓 `feat(01-8-2)`（占位单源 + 用例）与 `docs(01-8-2)`（设计 / 评审 / 记录 / 回写）两次；bms 仓 `docs(01-8-2)`（知识档案 15 / 16）一次；两仓独立提交 |
| 提交与推送 | 说「提交」只做 `commit`，说「推送」才走推送入口；本任务**不推送**、不触发 CI |
| 进度落点 | 进度类字段唯一落点是阶段计划表；需求与任务文档不承载 |
| 本地环境 | 跑预检 / 测试一律带 `CODEBUDDY_SAFE_DELETE_ENABLED=0`，避免安全删除拦截残留锁 |
