## 2. 任务内容 <a id="content"></a>

1. **形态选型**：在「relay 换成 msg 客户端」与「msg connector 扫 outbox」两种形态中定一种（详细设计拍板），另一种只保留接口口子；选型须说明失败重试、位点 / 游标、重复投递与清理责任。
2. **适配实现**：以 **bms 仓为主**落 `BaseOutboxStore` / relay 的 msg 版本；msg 仓只交付端口契约、跨仓用例与联调证据，不复制第二套客户端实现。
3. **配置切换**：开关复用既有 `[outbox].provider`，与 07-4 的 `[event].provider` / `[service_client].provider` 同口径；缺省 `poll` 为原实现，未注册实现名 → `PluginError`、`msg` 配置不全 → `ConfigError`，**均装配期拒启、不静默回落**（07-4-1 §6.2 / 07-4-2 输入基线已定稿口径，2026-11-11 回写冲突字面）；切换只改配置 + 重启调用方，不重新发布业务代码。详见[详细设计](设计/01_详细设计_01-8-1_outbox适配与relay切换.md) §6。
4. **失败处置**：投递失败按退避重试并留可定位记录；超过上限进死信或显式失败，不静默丢弃；审计事件不得因 outbox 适配失败而丢。
5. **在途与未确认**：迁移期在途请求、未确认事件与双写窗口的处置与 07-4 / 07-8 对齐；重复投递由消费端幂等兜底，不引入第二套去重。
6. **测试**：切换 / 回滚正反用例、业务代码零改动断言、审计事件不丢用例、失败重试用例；变更模块行 + 分支覆盖率按项目口径达标。

## 3. 完成标准 <a id="accept"></a>

- outbox relay 可在配置层切到 msg 实现并切回原实现，业务代码零改动；
- 切换后审计事件不丢，失败可重试且有可定位记录；
- 原链路保留，切换 / 回滚配置可复现；
- 跨仓用例与联调证据齐全，bms 仓与 msg 仓独立提交；
- 变更模块行 + 分支覆盖率达标，静态与文档校验通过。

| fail-safe | 缺省 `poll` = 原实现；未注册名 → `PluginError`、`msg` 配置不全 → `ConfigError`，**装配期拒启、不静默回落**（[07-4-1](../../../07_部署迁移与验收/07_部署迁移与验收_04_bms迁移与回滚/07_部署迁移与验收_04_bms迁移与回滚_01_切换开关与分域迁移编排/设计/01_详细设计_07-4-1_切换开关与分域迁移编排.md) §6.2） |
| 差异登记 | `[outbox]` 空串为 bms 既有 `null` 占位（不投递），**不等同** 07-4-1 的「空串 = 原实现」；验收按本条判读 |
| 职责分离 | `[outbox].provider` 的工厂固定解析 `msg` 事件发布实现，不读 `[event].provider`，避免漏改一键造成假切换 |
| 指纹 | 切换点 `config_fingerprint` 由两 provider 值扩为**三个**（`event` / `service_client` / `outbox`）；07-4-1 协同回写项，待代码交付后执行 |
| 全通道 | `ops/outbox.py` 的 CLI 投递器须同步按 provider 解析（现状硬编码 `poll`），否则切换不闭环 |
| 后置边界 | 事务消息与 CDC 首期不实现，只留口子；不得出现「已支持」描述 |
| 跨仓 | bms 仓为主（适配 / 装配 / CLI / 配置 / 用例），msg 仓交任务契约、跨仓联调用例与验收证据；两仓分别提交 |
