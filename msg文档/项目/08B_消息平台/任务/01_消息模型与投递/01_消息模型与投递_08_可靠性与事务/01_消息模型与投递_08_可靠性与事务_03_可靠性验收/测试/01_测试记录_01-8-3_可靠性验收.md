## 2. 用例清单 <a id="cases"></a>

文件：`backend/services/msg/tests/client/test_reliability_acceptance.py`（9 例）。夹具为临时 SQLite 发件箱三表 + 真 msg 应用（真路由 / 真数据面 / 真消费端），不复制协议实现。

| 编号 | 用例 | 覆盖 |
| --- | --- | --- |
| V1 | `test_audit_event_reaches_msg_and_keeps_record_ref` | `build_operation_event` + `AuditEventEmitter` → `sys_outbox` → msg relay → 真数据面 → 消费端解码；断言 `event_id` / 类型 / 租户 / `trace_id` / 载荷 / `record_ref` 一致，发件箱转 delivered |
| V2 | `test_duplicate_delivery_has_single_side_effect` | 确认丢失后重投同一条事件，消费端收 2 条但 `ProcessedEventStore` 只放行一次副作用 |
| V3 | `test_outbox_replay_keeps_single_side_effect` | `SqlOutboxStore.replay()` 重投已投递事件；消费端重复收到，副作用仍 1 |
| V4 | `test_in_flight_event_survives_switch_and_delivers_once` | 首轮连接失败保行计次；建主题 / 切到可用链路后补发恰好一次 |
| V5a | `test_unreachable_and_exhausted_failures_are_observable` | 主题缺失 404 / 连接失败 / 超限转死信；行保留、`error_msg` 可定位、死信可查、指标（failed / dead / backlog）有记录 |
| V5b | `test_dead_letter_recovery_delivers_once` | 转死信后建主题并 `replay()`，恢复投递恰好一次，消费端副作用 1 |
| V6 | `test_process_restart_delivers_pending_and_skips_delivered` | 重建 `EngineRegistry` / `SessionFactory` / dispatcher；pending 补发一次、delivered 不重投 |
| V7 | `test_two_dispatchers_do_not_duplicate` | msg 与 poll 两实现先后各跑一轮；msg 侧消息总数 1、已投递行不被另一实现再投 |
| V8 | `test_rollback_to_poll_restores_behavior` | msg 投 A → 切 poll 不重投 → 新 pending 由 poll 投一次 → 再切 msg 不重投 |

**复用**：01-8-1 的 T1~T9 / U1~U4（Kiwi 2481）与 01-8-2 的 U1~U6（Kiwi 2482）作为前置证据引用，本文件不重复其单点断言。
