## 3. 关键实现说明 <a id="impl"></a>

| 点 | 做法 | 为什么 |
| --- | --- | --- |
| 缓存内容 | `TopicSnapshot`（值对象，只含判定需要的列） | 缓存 ORM 会在会话关闭后 `MissingGreenlet`、且被并发请求多会话共享；快照也是「冷热两态同型」的结构保证 |
| 缓存键 | `(tenant_id, namespace, name)` | 平台库共库多租户；键不带租户即跨租户取主题（越权）。`TopicRouter` 在只给 cache 不给 tenant_id 时直接 `ValueError` |
| 命中成本 | `dict` 取键 + 一条整数比较 | 失效按精确键删除，不做全清（全清会让失效后首批请求同时打库） |
| 负结果 | 不缓存 | 新建 / 恢复启用后第一请求即可用；无需 TTL |
| TTL | 不加 | 加了就是「最迟 TTL 才生效」，与「下一次请求即生效」冲突 |
| 失效时机 | `TopicService` 写方法**提交成功之后** | 回滚时缓存与库本来就一致，不该清；提交成功才让下一次请求重载 |
| 装配口径 | 数据面 / 帧入口 / 长驻流 / join 一律经 `messages.topic_router()` | 8 处各自 `new TopicRouter` 的写法已消失，缓存参数不会漏传 |
| 节流键 | `(topic_id, partition_no)` | 清理本就按分区执行；按主题分键要么改扫描范围、要么让单请求耗时随分区数上升 |
| 节流判定 | `admit()` 全程无 `await` | 单事件循环内原子，不会出现「两个请求同时判定为窗口首个」 |
| 节流时机 | 在主题 / 分区判定之后 | 非法请求照旧先报 `350001` / `350009`，不会被「本窗口跳过」掩盖 |
| 帧闸门 | `build_frame_gate()` 的依赖里加两项并逐层下传 | 帧形态直接调数据面函数，不接就会在 `/msg/publish` 帧路径上绕过缓存与节流（两处挂载语义必须一致） |

## 5. 问题与处置 <a id="issues"></a>

| # | 现象 | 处置 |
| --- | --- | --- |
| 1 | 给 `create_topic` 的 docstring 补了一句「创建后失效缓存」，提交前预检判**契约漂移**（OpenAPI description 变了） | 撤回该句。判据要求「契约零变更」，一句描述不值得动快照；说明写在设计 §3.3 与服务层注释里 |
| 2 | `test_admin_topics.py` 的 11 条用例报 `State has no attribute topic_cache` | 该文件自建最小应用只挂管理面路由，不含数据面进程状态；补一行 `app.state.topic_cache = TopicCache()`（管理面写路径需要它做失效） |
| 3 | 增分区后立刻 `consume` 新分区得 `350014`（不是预期 200） | 分配不会因 `expand_partitions` 立即重算（01-4 口径：重连 / 心跳触发）；用例改为「改分区 → 重新 `join` → 拉取」，断言才落到缓存生效这一件事上 |
| 4 | 直接 `TopicService(...).expand_partitions()` 抛 `InvalidRequestError: A transaction is already begun` | 用例与服务共用同一个内存会话，前面的 HTTP 请求留下了自动事务；先 `commit()` 收尾再让服务层自己开事务 |
| 5 | `_monotonic_ms` 用默认时钟的路径在单元用例里覆盖不到 | 由数据面用例（`apply_retention` 构造 `RetentionService(store=...)`）覆盖；单测只验窗口逻辑（假时钟） |

## 6. 偏差与回写 <a id="deviations"></a>

| # | 项 | 原表述 | 实际 | 处置 |
| --- | --- | --- | --- | --- |
| 1 | 节流粒度 | 「同一主题每窗口一次」 | 同一（主题, 分区）每窗口一次 | 设计定稿时已回写任务 §3 与需求 01-7 |
| 2 | 验收并发 | 「同一实例同一并发下」 | 明确 `concurrency=1`（16 只作参考） | 同上；算术见设计 §1.2 |
| 3 | 管理面接缓存 | 设计初稿写「管理面不传 cache」 | 管理面**读**路径不经缓存，但**写**路径必须拿 cache 做失效 | 设计 §5.2 已按此写；`_service(uow, *, cache=None)` 只在 `create_topic` 传值 |
| 4 | 帧路径 | 任务只提「publish / consume / ack / subscribe 共用一份」 | 帧闸门直调端点函数，需单独接线 | 设计 §5.2 列了 `gate.py`；实施时补上并纳入装配表 |
