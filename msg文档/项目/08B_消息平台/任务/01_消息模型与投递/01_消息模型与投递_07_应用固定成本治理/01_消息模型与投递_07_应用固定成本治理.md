## 2. 任务内容 <a id="content"></a>

1. **主题元数据缓存**：把主题解析结果（分区数、保留配置、主题状态、租户归属）放进进程内缓存，publish / consume / ack / subscribe 共用同一份；主题增删改（含保留配置变更）经**同一处失效**，缓存不得让配置变更滞后生效。
2. **保留清理时间节流**：现状是每条请求都跑一次 `apply_retention()` 全量扫描；改为**同一（主题, 分区）每个窗口最多一次**（清理本就按分区执行，按主题分键要么改变扫描范围、要么让单请求耗时随分区数上升）。触发点仍保持请求驱动（后台定时器归 8B_02），窗口取模块常量，**不进 `Settings`**（基座 `Settings` 为 `extra="forbid"`，产品无法新增配置段——同 01-2 / 01-5 的约束，已登记的基座扩字段遗留不因此改变）。
3. **会话口径不动**（边界声明）：每请求一次短会话**保留**。长会话会把连接池拖死，代价大于收益；本任务只治理 1 / 2 两项，不得顺手改会话复用或引入连接池调参。
4. **语义绝对不变**：缓存与节流不得改变保留判定结果、位点推进、顺序停等、错误码与审计留痕口径。缓存命中与否，`/msg/publish`、`/msg/consume`、`/msg/ack`、`/msg/subscribe` 的响应结构与错误码**逐字段一致**。
5. **可观测**：主题解析与保留清理的耗时要可测量（结构化日志即可；指标面板归 06 域），用于自证治理效果，也为 8B_12 容量定参提供输入。
6. **测试**：缓存命中 / 失效 / 并发写读；节流窗口内同主题扫描次数断言；语义等价用例（同一请求在缓存冷热两种状态下响应逐字段一致）；变更模块行 + 分支覆盖率 100%。

## 3. 完成标准 <a id="accept"></a>

- 同一实例 `POST /msg/publish` 与 `GET /msg/connection` 的 **p50 差值 ≤ 5ms**（相对判据，只说明固定成本已降到与载荷处理同量级，**不作容量结论**）。并发取 **1**：03-1 已实证该装置在 16 并发下跑满（`p50 ≈ 并发数 × 单请求服务时间`），16 并发时本判据等价于要求固定成本降到 0.3ms；16 并发同参数复跑只作参考值。
- 保留清理在同一窗口内对同一**（主题, 分区）**最多执行一次（用例断言扫描次数，不是只看日志）。
- 主题配置变更后下一次请求即按新值生效（失效路径有用例）。
- 既有数据面用例全绿（含 01-1 ~ 01-6 的回归），变更模块行 + 分支覆盖率 100%，静态与契约门禁全绿。
- 响应结构与错误码在缓存冷 / 热两态下逐字段一致（语义等价用例）。
