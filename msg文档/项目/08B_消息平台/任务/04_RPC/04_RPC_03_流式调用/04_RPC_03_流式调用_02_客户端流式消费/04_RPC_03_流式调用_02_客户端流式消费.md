## 2. 任务内容 <a id="content"></a>

1. **传输层读队列**：`H2Stream` 从「等 `END_STREAM` 一次性返回」扩成「逐块读取」——`on_data` 追加并唤醒读等待者，新增 `read_chunk()` 返回字节或「流已结束」；`wait_response()` 的一元语义不变（两条路径共存，互不改写）。
2. **`RpcTransport` 协议扩展**：新增 `open_stream(request)`（异步上下文管理器，返回可 `read()` / `abort()` 的流对象）；`H2Transport` 给出生产实现，`AsgiRpcTransport` / `ScriptedRpcTransport` 同步实现（测试与生产同契约，避免「测试全绿、真机行为不同」重演）。
3. **`RpcClient.stream(...)`**：返回 `RpcStream` 句柄，**惰性打开**（首次 `__aenter__` / `__anext__` 才发请求）；句柄实现 `__aiter__` / `__anext__`、`aclose()`、`__aenter__` / `__aexit__`。
4. **帧解析与序号校验**：增量累积 `decode_frames` 切帧（不完整尾包保留）；校验 `seq` 从 0 单调 +1、`request_id` 与本次调用一致，不符即协议错。
5. **结束三态**：收到带 `end_of_stream` 的 `48` 帧 → 正常结束（本次产出后 `StopAsyncIteration`）；收到 `ERROR` 帧 → 抛 `RpcCallError`（`350004` 抛 `RpcCallTimeoutError`）；EOF 但两者都没收到 → 协议错「流异常中断」。
6. **取消与空闲兜底**：`aclose()` / `async with` 退出且流未结束 → `abort(cancelled)` 发 `RST_STREAM(CANCEL)`（复用 04-7-2 的幂等原语）；单次 `read()` 空闲超 `RPC_STREAM_CLIENT_IDLE_MS`（90s）→ `abort(timeout)` 并抛 `RpcCallTimeoutError`。
7. **不套用整段本地超时**：流式调用**不用**「预算 + `RPC_CLIENT_TIMEOUT_SLACK_MS`」包住全程（一元的做法）；整条流的期限由服务端的预算兜底，客户端只兜「长时间没有任何数据」。
8. **观测**：正常结束记 `msg_rpc_client_stream`（`frames` / `bytes` / `duration_ms` / `stream_id` / `seq_max`）；中止复用 `msg_rpc_client_cancel`（`reason` / `rst_sent` / `frames`）。
9. **端到端真机验收**：真 hypercorn + 生产 `RpcClient`：连续推送、慢消费者背压、`break` + `aclose()` 后服务端 ≤150ms 停推、同连接其它调用不受影响、空闲超时。
10. **边界**：不做 client streaming / 双向流 / 断点续传；不改服务端（04-3-1 已交付）；不引入重试（04-4）。

## 3. 完成标准 <a id="accept"></a>

- `async for reply in client.stream(...)` 可逐条拿到结果，`async with` 退出即释放；帧序与 `seq` 一致，末帧判定正常结束。
- 流内 `ERROR` 帧按码抛对应异常（`350004` → `RpcCallTimeoutError`，其余 → `RpcCallError`），错误层与重试标记来自服务端。
- `break` 后 `aclose()`（或 `async with` 退出）发出 `RST_STREAM(CANCEL)`：真机实测服务端 ≤150ms 内停止推送，同连接后续调用正常返回（沿用 04-7 判据）。
- 客户端空闲兜底：服务端不发任何帧且连接未断时，90s 后本地放弃并发 `RST_STREAM`，抛 `RpcCallTimeoutError`。
- 一元调用的 `RpcClient.call()` 行为、签名与错误码零变化（存量用例全绿）。
- 变更模块行 + 分支覆盖率 100%，静态检查全绿，文档三项（links / docs-scope / eol）通过。
