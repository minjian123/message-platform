## 3. 验收映射 <a id="accept"></a>

| 完成标准（任务 §3） | 断言落点 | 结论 |
| --- | --- | --- |
| 多层调用时下游不会在上游超时后继续长跑 | `test_three_hop_budget_decreases`（预算严格递减）+ `test_downstream_stops_at_its_own_budget`（下游按自身预算停止、handler 未跑完） | 通过 |
| 预算逐跳递减可断言 | 三跳用例断言 `top ≤ 5000−50`、`middle ≤ top−50`、`leaf ≤ middle−50` 且均为正 | 通过 |
| 客户端取消后服务端处理中断、资源释放 | `test_rpc_cancel_h2c`（连接关闭触发断开 → handler 取消 → 名额归 0）+ `test_injected_disconnect_probe_cancels_handler`（探测端口直验） | 通过（口径见实施记录 §6.2） |
| 等待项无泄漏 | 同上：长驻流名额恒 0；客户端取消后任务以 `CancelledError` 结束 | 通过 |
| 超时与失败在错误码 / `retryable` 上可区分 | `350004` business/false/504（`data.outcome=unknown`）vs `350023` business/false vs `350005` business/true vs `350006` transport/false | 通过 |
| 超时不被直接当作失败重试 | `350004` 不在 `_RETRYABLE_BUSINESS`；`outcome=unknown` 进 detail / data | 通过 |
| 变更模块行 + 分支 100%，静态全绿 | 见 §4 / §5 | 通过 |

## 6. 问题与处置 <a id="issues"></a>

| # | 问题 | 处置 |
| --- | --- | --- |
| 1 | 真 h2c 用例最初按「取消即 `RST_STREAM`」写，实测不成立（服务端跑满 10s） | 三个最小实验定位到客户端根本不发 `RST_STREAM`（实施记录 §6.2）；用例口径改为「连接关闭触发断开」，精确取消归 04-7 |
