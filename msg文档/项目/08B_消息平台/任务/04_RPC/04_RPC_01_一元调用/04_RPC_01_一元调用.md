## 2. 任务内容 <a id="content"></a>

1. **端点与挂载**：新增 `POST /rpc/{service}/{method}`，与 `/msg/*` 同挂根路径聚合（不走 `/api/v1` 管理面前缀）；`{service}` 为服务标识，`{method}` 为业务方法名；管理面 `/api/v1/msg/admin/*` 与既有数据面端点行为不变。
2. **关联与生命周期**：请求与响应以 HTTP/2 `stream_id` 关联，一 stream 一请求；**不新增 `correlation_id` 协议**；stream 关闭即清理等待项；连接断开清理该连接全部在途项。
3. **方法注册**：启动期静态注册表（`RpcHandler` + registry），装配期登记；重复 `service + method` 即拒启；未注册方法返回明确错误（`layer=protocol` 或 `business`、`retryable=false`，具体码值详细设计定稿），不得 500 裸抛。
4. **报文形态**：复用 03 帧协议——在 03-2 预留的 `6-15` 区间中取 `7-15`（`6` 已被 03-5 的 `message` 占用）新增 RPC 请求 / 响应帧类型；header 为 MessagePack，payload 原始字节，broker 不解析；只增字段、未知字段忽略、版本可见；不另造 RPC 私有帧头。
5. **调用方与 trace**：header 携带 `trace_id`、调用方服务标识、租户标识；服务端写入日志与响应头；本任务只做透传与记录，认证 / 授权归 05 域。
6. **路径配额**：与 `/msg/*` 共用连接时按 path 分配配额，复用 03-5 的两级限流与 `350005`；RPC 与事件并发时互不阻塞，大消息发布不得挤占 RPC；不另造限流器。
7. **最小 RPC stub**：msg 仓交付协议库中的最小 `RpcClient.call(service, method, payload, headers)`（一元调用、编解码、错误映射骨架）；deadline / 取消 / 流式 / 重试 / 实例选择分别由 04-2~04-6 扩展，本任务不提前实现。
8. **契约与登记**：新增端点登记进 `deploy/contracts/msg.json`；方法清单随契约导出；错误码在 `x-error-codes` 声明；契约快照零漂移。
9. **测试**：两个本地 handler 的跨服务调用；未注册方法；同一条 h2c 连接上 RPC 与 `/msg/publish` 并发；stream 关闭后等待项清理；契约快照 check。
10. **边界**：不做 deadline / 取消（04-2）、不做流式（04-3）、不做重试 / 熔断 / 幂等键（04-4）、不做 bms 端口适配（04-5）、不做实例选择（04-6）、不做认证授权（05 域）、不改 02 存储。

**实施回写（2026-11-05，详见[详细设计](设计/01_详细设计_04_RPC_01_一元调用.md) §17.2 与[实施记录](实施/01_实施记录_04_RPC_01_一元调用.md) §7）**：

- **帧类型取 `48` 而非本节第 4 条字面的「7~15」**：`reserved_types` 已把 `7-15` 登记为数据面预留、`48-63` 登记为 rpc；取 48 不侵占数据面扩展位，响应沿用仓内唯一的「同 type + `flags.response`」（与 `result_frame` / `open_frame` / 心跳响应同构），客户端只维护一条响应判定。
- **「按 path 分配配额」落为 `(tenant, service)` 独立令牌桶**：03-5 的 `RateLimiter` 只有 tenant / topic 两维、没有 path 维度；新增第三维而不是复用 topic 桶（复用会让 RPC 被 `topic_per_second` 连带限流）。缺省 0 = 关闭，与 03-5 同口径。
- **端点双形态的装配方式**：帧形态是**路由级依赖闸门**（不复用 `build_frame_gate`，它的必填键取自数据面请求模型）；路径参数从 `request.path_params` 取——声明成依赖参数会让端点的 `Path(pattern=…)` 失效、公开契约里约束整段消失（实测）。
- **未注册方法新占 `350023`**（business / `retryable=false` / 404）；方法名形态非法仍 `10001`。`350004` 保持为空，留给 04-2。
- **最小 stub 与租户传递**：`bms_msg.client.RpcClient` 发帧形态、错误码照搬服务端判定；构造与单次调用都可给 `tenant`（写 `X-Tenant-ID`）——RPC 与 `/msg/*` 共用同一基座中间件，不带这个头服务端解析不到租户。

## 3. 完成标准 <a id="accept"></a>

- 可完成一次跨服务一元调用并拿到结果；未注册方法返回明确错误（非 500 裸抛）。
- 同一条 h2c 连接上 RPC 与事件发布并发互不阻塞；stream 关闭后无等待项残留。
- 方法清单与端点进入契约快照，`contract_snapshot check` 零漂移。
- 变更模块行 + 分支覆盖率 100%，静态检查全绿。
