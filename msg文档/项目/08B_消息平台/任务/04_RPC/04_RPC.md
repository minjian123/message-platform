## 1. 域说明 <a id="intro"></a>

本域对应需求 [04 RPC](../../需求/04_需求_RPC.md)，承载消息平台上的**同步调用**能力：一元调用、deadline 传播、取消、服务端流、错误语义与幂等重试、bms 端口适配、服务发现与负载均衡。目标是替换现有 `HttpServiceClient` + FastAPI 同步链路；与事件总线共用 HTTP/2 连接，但可靠性模型独立——RPC 要「立即知道结果」，消息要「可靠送达」。

**阶段定位**：本域即 **8B_03 RPC**。硬依赖 **8B_01（已达成 2026-11-05，03 域 03-1~03-5 收口）**，**不依赖 8B_02 存储**；按阶段计划，本域整体排在 8B_02 存储块之后（优先级与连续块选择，不是硬依赖），状态与窗口见阶段计划。

**与 03 域的分工**：03 域已交付 HTTP/2 传输、二进制帧、序列化、连接管理、背压与流控；本域只在其上增加 RPC 语义（方法路由、deadline、取消、流式、错误分类、适配、发现），**不重复实现**帧编解码、连接心跳、窗口与 inflight 阈值。

**与 bms 的分工**：msg 仓交付 RPC 协议库 / stub 与服务端 dispatch；`EventPublisher` / `BaseServiceClient` 的插件装配、配置切换与实例选择落 **bms 仓另立任务**；两仓以契约测试对齐，业务代码不改。

**与 8B_02 的边界**：本域不建表、不改存储；RPC 方法注册表、幂等键去重、实例状态首期均为进程内实现，跨实例 / 重启持久化按需归 8B_05 或后续阶段。

文档格式依 bms《[任务文档规范](../../../../../bms文档/规范/任务文档规范.md)》。

### 2.1 执行顺序 <a id="order"></a>

`04-1 → 04-2 → 04-3 → 04-4 → 04-5 → 04-6 → 04-7`。04-3 / 04-4 均只依赖 04-2，单人串行按编号推进；04-5 需 04-4 与 bms 适配任务同时就绪；04-6 首期只接 bms 服务目录，DNS / 静态列表后置；**04-7 是 04-2 的补充**（客户端侧 `RST_STREAM` 发送端，2026-11-06 立项），排在本域最后，但服务端接收侧已在 04-2 就位，届时无需改服务端代码；2026-11-06 拆为两个嵌套子任务——**04-7-1 H2 传输层**（自持连接 / 流 / 池 / 注入面迁移）与 **04-7-2 取消发 RST**（取消与超时接线、真机验收），详见其任务文档。具体窗口见阶段计划。

## 3. 依赖与风险 <a id="dep"></a>

| 项 | 说明 |
| --- | --- |
| 上游依赖 | **03 域 03-1~03-5（已交付，8B_01 门禁 2026-11-05 达成）**：HTTP/2、二进制帧、序列化、连接管理、背压与流控；bms 基座 `EventPublisher` / `BaseServiceClient` / `ServiceCallPolicy` / 服务目录（均已交付，仅读契约）；**bms 适配任务（跨仓，待立）** |
| 下游影响 | 8B_06 管理台（RPC 指标 / 追踪 / 错误视图）、8B_08 bms 迁移（替换 `HttpServiceClient`）、8B_09 验收；错误码一旦发布即长期兼容 |
| 关键风险 | ① deadline / 取消在 Python asyncio 下的响应速度与资源释放；② 非幂等操作被自动重试导致重复副作用；③ bms 适配跨仓（msg 协议库 + bms 插件装配）版本错配与回滚；④ RPC 与事件共用连接时大消息挤占 RPC；⑤ 04-6 首期只有 bms 服务目录实现，DNS / 静态列表与多实例选主后置；⑥ 错误码段 `35xxxx` 最终以 07C 登记为准；⑦ **客户端取消能力缺口**：04-2 实测 `httpx` / `httpcore` 在等待响应头期间被取消时不发 `RST_STREAM`，一元调用只能靠预算兜底——由 04-7 补发送端，服务端接收侧不受影响 |
