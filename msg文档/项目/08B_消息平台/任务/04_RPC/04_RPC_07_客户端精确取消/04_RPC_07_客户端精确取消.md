## 2. 任务内容 <a id="content"></a>

1. **单个 stream 取消**：客户端能在**不关闭整条 h2 连接**的前提下取消一次调用（发 `RST_STREAM(CANCEL)`），同连接其它在途调用不受影响。
2. **传输层自持**：客户端侧连接池 / 并发流 / 流生命周期由本任务实现（或复用 `httpcore` 的流对象并显式关闭），不再依赖「关整个连接池」这种粗粒度手段。
3. **取消与超时分工**：取消发 `RST_STREAM`；预算耗尽仍由服务端回 `350004`（服务端日志 `outcome=cancelled` 与 `deadline_exceeded` 可区分）。
4. **对外契约不变**：`RpcClient.call(service, method, ..., deadline_ms=)` 与 `RpcCallTimeoutError(350004)` 保持不变，04-5 的适配不跟着改。
5. **对接服务端**：命中 04-2 已交付的断开探测（`invoke_rpc(disconnected=...)`），**不改服务端代码**。
6. **测试**：真 h2c 下取消单 stream → 服务端 100ms 内中断、同连接其它调用成功；沿用 04-2 的 `serve_service` 体例。
7. **边界**：不改帧 / 契约形状（RST 是传输层事实）；不做流式（04-3）、不做重试（04-4）、不做实例摘除（04-6）。

## 3. 完成标准 <a id="accept"></a>

- 取消单个在途调用后，服务端 100ms 内停止处理，同连接其它调用正常返回。
- `RpcClient` 对外签名与错误码不变（04-5 适配零改动）。
- 变更模块行 + 分支覆盖率 100%，静态检查全绿。
