## 2. 任务内容 <a id="content"></a>

1. **取消即中止**：`task.cancel()` 穿透到 `H2Transport.send()` 的取消路径 → `H2Stream.reset(CANCEL)` 发 `RST_STREAM` → 服务端 04-2 的断开探测命中并取消 handler。**服务端零改动**。
2. **超时同路**：本地兜底超时（预算 + 200ms）由 `asyncio.timeout()` 包住 `send()`，触发的取消同样走上 reset 路径；传输层仍保留分阶段超时（建连 / 等头 / 读体）。
3. **取消不吞、不新增形状**：`CancelledError` 原样穿透；不新增 `RpcCallHandle`、不新增异常类（沿用 04-2 决策 14）。
4. **中止幂等**：已 `Done` / 已中止的流再 `reset()` 不发帧（对已关闭流发 RST 属协议违规）；`close_reason` 区分正常 / 取消 / 超时 / 对端 reset / 连接故障。
5. **观测**：客户端事件 `msg_rpc_client_cancel`（`request_id` / `service` / `method` / `stream_id` / `reason` / `rst_sent` / `elapsed_ms`），为 06-3 指标出口留采集点；**不改**服务端 `msg_rpc` 四态。
6. **真机验收**：新建 `test_rpc_client_cancel_h2c.py`——真 hypercorn + 生产 `RpcClient`：取消后 handler ≤150ms 内被取消且未跑完、同连接后续调用 `200`、`stats().connections == 1`、收尾后 `open_streams == 0`。
7. **阈值口径回写**：任务 §3 与需求 §8 的「100ms」落为「≤150ms 硬断言（50ms 轮询 + 一帧往返 + 调度余量）+ 100ms 观测值」；04-2 的「连接关闭 → 断开兜底」用例保留不改。

## 3. 完成标准 <a id="accept"></a>

- 取消一个在途调用后，服务端在 **150ms 内**（一个轮询周期 + 一帧往返）停止处理且未跑完；实测值随用例输出，`≤100ms` 为观测口径。
- 同连接其它调用正常返回，连接数不因取消增长；`aclose()` 后在途流归零。
- `RpcClient` 签名与错误码不变；取消后仍是 `CancelledError`（不新增对外异常）。
- `msg_rpc_client_cancel` 能回答「RST 发了没有」（`rst_sent`）与「是哪条流」（`stream_id`）。
- 变更模块行 + 分支覆盖率 100%，静态检查全绿，文档三项通过。
