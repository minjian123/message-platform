## 1. 做了什么

按 07B `06_01` 步 3，在 msg 仓补「两仓契约用例」——这里是唯一能同时 import 两侧的地方（`bms-core` 是 msg 的路径依赖，反向不成立）：

- 新增 `backend/tests_support/bms_port_contract.py`：六类 wire 期望的**单一来源**（请求 / 响应 / 错误五类逐码 / timeout / cancel / 幂等键），含真实调用点的路径常量、快照载荷、目标方法处理器替身与 `MsgServiceClient` 构造器。
- 新增 `backend/services/msg/tests/client/test_bms_port_contract.py`（11 条，Kiwi **2442**）：`AsgiRpcTransport` 驱动真实 msg 应用（真路由 → 真帧 → 真处理器），bms 侧用 `fetch_catalog_snapshot`（真实业务函数）发起调用。
- **msg 源码零改动**：`bms_msg` 一行未动，已交付的 04-1 ~ 04-4 不回退。

判据（逐条）：

1. 真实调用点往返：`platform.modules.snapshot` 收到空载荷、返回统一响应包裹，业务函数解析出 `ModuleRecord`；
2. 同键去重：非幂等方法带同一 `idempotency_key` 调两次，处理器只执行一次且两次结果一致；
3. 错误五类逐码：`10001` / `350023` / `350005` / `350016` / `350004` / `350002` 各到 bms 预期异常与平台码，原始码保留在 `data`；
4. timeout 判「结果未知」（`data.outcome=unknown`，不是失败）；
5. cancel 原样穿透（不重试、不映射成业务异常）；
6. 未注册方法走真路由得 `350023`，映射为 `BizError` 而非「下游不可用」。

## 3. 对 04-5 的影响与遗留

- 04-5 的「契约测试」一项**已交付**；bms 侧步 1 / 2 / 3 均已交付，`06_01` 收口。本轮再补事件发布真链路（3 条：真实发布 / 租户 id / 缺失主题），msg 契约用例合计 14 条。
- **租户缺陷与返修**：真链路实测发现 `MsgEventPublisher` 把 `event.tenant_id`（雪花 id）写进 `X-Tenant-ID`，而 msg 租户解析链只认编码 → `350012`。按「内部统一 id、外部交换才用 code」重开 bms 07B `06_01`，修 `resolve_request_tenant` 接受 id（Kiwi **2443**）；msg 用例转绿，msg 源码零改动。
- **仍未完成的**：生产集群联调（真 msg 实例 + 真 platform 服务）——本地无 msg 编排，归部署阶段；「真实 `HttpServiceClient` 调用替换」的判定按进程内真应用 + 真帧 / 真数据面达成（bms 侧记录 §8.2、§9）。
- msg 侧不提供「转发到 bms 服务」的处理器：`/rpc/{service}/{method}` 分发的目标必须在 msg 注册表登记，跨服务真实迁移归 8B_08。
- 共享夹具只此一份；**bms 仓不复制**期望值（那边 CI 不 clone msg，复制必漂移）。
