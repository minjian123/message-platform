## 2. 任务内容 <a id="content"></a>

1. **错误对象**：每个错误含 `code` / `layer` / `retryable` / `message` / `details`；沿用 03-2 error 帧字段；业务错误不得以「200 + 空体」表达。
2. **错误分类**：参数错误（`10001`，不重试）、业务拒绝（不重试）、瞬时故障（可重试）、超时未知（`350004`，谨慎重试）、服务端 bug（不自动重试）；每类映射到 `retryable` 与客户端动作；**新 RPC 码在详细设计逐项定稿并按 07C 登记**，任务阶段只列分类与既有码。
3. **重试策略**：指数退避 + 抖动；最大次数 / 初始退避 / 倍数 / 抖动可配；禁止无退避的立即重试；遵守 `Retry-After`；重试预算在调用链共享（防重试风暴）；熔断打开时直接失败，不进入重试。
4. **幂等键**：非幂等操作必须携带幂等键；客户端生成稳定键；服务端按键去重（作用域 / TTL 详细设计定）；无键的非幂等操作**不得自动重试**；超时未知仅在带键时允许谨慎重试。
5. **熔断**：复用 bms `BaseCircuitBreaker` / `ServiceCallPolicy`，不另造；关闭 / 打开 / 半开三态；半开期限流探测；打开快速失败；阈值、窗口、半开探测间隔可配。
6. **错误映射**：msg 错误 → bms `ServiceUnavailableError` / `ParamError` / `RateLimitError` 等；保留 `retryable` 与原始码；trace / 日志可追溯；不泄露内部堆栈。
7. **客户端重试层**：`RpcClient` 统一重试中间层；只对 `retryable=true` 且「幂等或带幂等键」的调用重试；记录尝试次数、退避序列与最终错误。
8. **测试**：五类错误的 `retryable`；退避 + 抖动（fake clock）；非幂等无键被阻止；带键去重；熔断打开快速失败；`Retry-After`；调用链重试预算；覆盖率 100%。
9. **边界**：流式错误重试归 04-3 / 后续阶段；bms 错误映射归 04-5；认证归 05 域；幂等键跨实例 / 重启持久化按需归 8B_05 或后续阶段（首期进程内实现须在设计与记录中写明限制）。

## 3. 完成标准 <a id="accept"></a>

- 不同错误类型返回正确的 `retryable`；参数错误 / 业务拒绝 / 服务端 bug 不被自动重试。
- 重试有指数退避与抖动；熔断打开时直接失败；非幂等无键操作重试被阻止。
- 带幂等键的瞬时故障重试不产生重复副作用；超时未知不被当作普通失败直接重试。
- 变更模块行 + 分支覆盖率 100%，静态检查全绿。
