## 3. 关键决策落地 <a id="decisions"></a>

### 3.1 设计未写死、由实施补的口径（已回写设计 §10.2）

| 口径 | 为什么 | 落点 |
| --- | --- | --- |
| **试验自建 app 的幂等存储惰性装配** | 存量用例自建最小 app 不带 `app.state.idempotency_store`，直接读会 500；让测试辅助跟着改装配会波及 20+ 文件 | `get_idempotency_store` 在 `app.state` 缺失时补一份并挂回 `app.state`——每个 app 各持一份，不引入模块级全局，与仓内「进程级状态落 app.state」口径一致 |
| **`test_error_codes.py` 过滤平台码** | `MsgRpcInProgressError` 继承 `MsgError`，会被 `_raised()` 的反射扫描收进去；但 `10007` 是 bms 平台码，不属 msg 自持声明 | 对账按 `MsgErrorCode` 集合过滤，文件头「产品自持声明 ↔ 代码」的语义更准确；`msg.toml` / `MsgErrorCode` 枚举仍零改动 |
| **`compute_backoff_ms` 夹到 `raw_cap`** | 随机源是注入端口，替身可能给越界值；不夹会突破「封顶」承诺 | `min(max(1, raw_cap), max(1, jitter.uniform(...)))`，恒 `>= 1` 且 `<= cap_ms` |
| **上游预算收紧本跳预算对象** | 设计写「有上游时帧头取 `min(上游, 本地剩余)`」，但判定函数读的是预算对象；只改帧头会让 `retry_budget=0` 仍继续重试 | `call()` 进入时用 `min` 收紧 `chain_budget.remaining`，帧头与判定共用同一份，A→B→C 真正受同一上限 |
| **契约方法条目增 `form`** | 设计只写 `idempotent`；但 `declarations()` 要按形态过滤，方法条目带 `form` 后一元 / 流式清单同源可断言，SDK 也能一眼看出形态 | `rpc_contract._method_entries` |
| **`classify` 存量断言同步** | `classify` 升三元组会让 `test_frame_responses.py` 旧断言失效 | 参数化表补 `category` 列，同时补 `350004` / `350023` / `350022` 三行覆盖新分支 |

| 既有口径 | 本任务落法 |

## 6. 问题与处置 <a id="issues"></a>

### 6.1 首轮覆盖率缺 8 行 / 1 分支，7 行是「假缺口」

判定原文（首轮）：

```text
[coverage] 未达标：缺行 8 / 缺分支 1（bms_msg.api.deps、bms_msg.client.retry、bms_msg.main）
[coverage]   bms_msg.api.deps: 缺行 5（178、190、202、274、286）
[coverage]   bms_msg.client.retry: 缺行 1（230），缺分支 1（229->230）
[coverage]   bms_msg.main: 缺行 2（237、238）
[coverage] files=27 missing_lines=8 partial_branches=1 percent=99.68
```

- **`client/retry.py:230` 是真缺口**：`parse_retry_after` 的「头名不匹配 → `continue`」分支没有用例（既有参数化只给空头元组与单个 `Retry-After`）。补 `X-Other` 头 / 混合头两条参数化后归零。
- **其余 7 行全是既有提供者 / 工厂的 `return`**：`get_offset_resetter` / `get_offset_enumerator` / `get_offset_purger` / `get_replay_runner` / `get_audit_sink`、`platform_uow_factory._uow`。因为本任务改了 `deps.py` / `main.py`，模块级判定要求整文件 100%，而一次会话清单没跑触发它们的用例 → 与 04-3-2 那轮漏 `test_connection_heartbeat.py` 完全同类。
- **处置**：把 `broker/test_offset_file_store.py`、`api/test_admin_replay.py`、`test_entrypoints.py` 并入同一会话（37 → 40 个目标），重采后缺口归零。**没有用 `pragma: no cover`，也没有缩减 `--module` 清单**。

### 6.2 自建 app 未装配幂等存储导致 44 条存量用例 500

首轮跑存量回归时 44 条失败，根因是 `get_idempotency_store` 直接读 `app.state.idempotency_store`，而测试辅助 `build_frame_app` 与多个自建 app 不带这个状态。**处置**：改成惰性装配并挂回 `app.state`（见 §3.1），没有改一处测试辅助、也没有给依赖加「测试才走的分支」。

### 6.3 `classify` 升三元组与错误码对账

两处存量断言随契约演进而失效：`test_classify_table` 断言二元组、`test_declared_status_matches_exception` 反射扫到复用平台码的 `MsgRpcInProgressError`。前者按三元组扩展并补三行覆盖新分支；后者按「产品自持码」过滤（平台码本就不属对账范围）。`msg.toml` 与 `MsgErrorCode` 枚举零改动，符合决策 A3。

### 6.4 行尾：两个既有测试文件本来就是 CRLF

`test_frame_responses.py`（HEAD 240 CRLF）与 `test_frame_contract_snapshot.py`（HEAD 137 CRLF）被改后仍保持 CRLF；按 HEAD 逐文件核对后**不回正**（回正会让 diff 全红）。其余 27 个新增 / 改动文件均为 LF。`engkit eol --quiet` 报 0 违规。
