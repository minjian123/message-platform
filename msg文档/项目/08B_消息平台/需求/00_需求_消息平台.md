## 2. 消息平台目标与范围 <a id="goal"></a>

### 2.1 目标

自研一套**完整消息平台（L3）**，统一承载事件总线、同步远程调用与管理运维，替换平台原有 RocketMQ 事件投递（已下线）+ 事务性发件箱 + `HttpServiceClient` + FastAPI 同步链路；形态与 mdm 同构（独立仓、独立服务、独立库、独立部署，经产品声明接入 bms 基座）。

### 2.2 范围内

| 域 | 覆盖内容 |
| --- | --- |
| 01 消息模型与投递 | topic / partition / offset、投递语义、顺序、消费组、延迟消息、保留与重放、可靠性原语与 outbox 适配 |
| 02 存储与复制 | 分区日志、索引与分段、崩溃恢复、位点、ISR 复制、选举与切换、存储水位、多实例部署与故障切换验收 |
| 03 传输与协议 | HTTP/2 传输、二进制帧、序列化、连接管理、背压 |
| 04 远程调用 | 一元调用、超时与取消、流式、错误语义、与 bms 端口适配 |
| 05 多租户与安全 | 继承基座 + msg 扩展：资源作用域、数据面接入、配额、授权、审计、生命周期、用量板块；四类标准扩展点已由 bms 07D 任务 03 接入 |
| 06 管理与运维 | 只读视图、写操作、指标告警、追踪、死信、重放、主题授权、租户用量、契约类型自动生成 |

### 2.3 范围外

- 业务事件语义与业务消费逻辑（各业务服务负责）。
- bms 基座的用户 / 角色 / 菜单 / 权限 / 字典 / 参数。
- 跨服务写的一致性（仍走 TM + XA）。
- 对外 OpenAPI 契约的制定与发布。
- 商业化计费、多语言 SDK、跨机房复制、Schema Registry（见规划「非目标」）。
- 生产部署、容量压测与阶段验收（由平台级生产部署架构负责）。
