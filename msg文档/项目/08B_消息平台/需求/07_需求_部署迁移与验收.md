## 1. 域说明 <a id="intro"></a>

本域定义「平台怎么部署、怎么接管现有链路、怎么证明它可用」。前六个域解决「做得出来」，本域解决「敢不敢用」——迁移与验收是自研平台与玩具的分界线。

覆盖范围：部署形态与产品声明、配置与凭据、备份恢复、bms 迁移与回滚、压测与容量、故障演练、阶段验收；其中 **07-8 生产迁移与真实链路联调**、**07-9 验收与压测** 分别承接 8B_08 / 8B_09，**07-5** 的容量定参与持续回归归 8B_12。依据见《[架构设计 · 部署与运维](../../../设计/架构设计/08_架构设计_部署与运维.md)》《[架构设计 · 决策与风险](../../../设计/架构设计/09_架构设计_决策与风险.md)》。

## 2. 需求 07-1：部署形态与产品声明 <a id="r07-1"></a>

优先级：2（高）

**背景与动机**：msg 是 bms 之上的独立产品，必须按产品接入机制声明（服务目录 / 路由 / 表归属），否则平台无法识别、网关无法路由。

**内容**（《架构设计 · 部署与运维》第 1~2 节）：

1. 单服务 `msg`，容器内 8000，接入平台 Docker 网络。
2. 产品声明 `deploy/registry/msg.toml`：产品档案、服务行、产品路由。
3. 对外命名空间 `/api/msg/v1/msg/...`，内部前缀 `/api/v1/msg/...`。
4. 消息日志、位点文件、元数据库三样必须持久化。
5. 提供 `/healthz` 与 `/readyz` 探针，就绪探针必须检查「能写」。

**完成标准**：平台可识别 msg 产品与服务；网关可路由；重启后数据不丢；探针能正确反映可用性。

**参考文档**：《[架构设计 · 部署与运维](../../../设计/架构设计/08_架构设计_部署与运维.md)》第 1~2 节。

## 3. 需求 07-2：配置分层与凭据管理 <a id="r07-2"></a>

优先级：2（高）

**背景与动机**：凭据入库或入镜像是安全事故；配置不分层则本地与生产互相污染。

**内容**（《架构设计 · 部署与运维》第 3 节）：

1. 配置分四层：基线 `config.toml`、dev / test / prod 覆盖、环境变量。
2. 优先级：环境变量 > 环境覆盖 > 基线。
3. 数据库连接串、Redis、OTLP、服务令牌密钥、TLS 证书路径**只走环境变量**。
4. `.env` 必须 gitignore，仓库只保留 `.env.example`。
5. 公开文档不得出现服务器地址、内网 IP、端口、账号。

**完成标准**：镜像与配置文件中无凭据；环境变量可覆盖全部敏感项；仓库无 `.env` 提交记录。

**参考文档**：《[架构设计 · 部署与运维](../../../设计/架构设计/08_架构设计_部署与运维.md)》第 3 节；bms《安全开发规范》。

## 4. 需求 07-3：备份与恢复 <a id="r07-3"></a>

优先级：3（中）

**背景与动机**：复制不是备份——副本会同步删除与损坏。元数据与位点一旦丢失，恢复成本极高。

**内容**（《架构设计 · 部署与运维》第 6 节）：

1. 元数据库随平台库备份；位点文件定期快照。
2. 消息日志不做全量备份（成本高），靠副本与保留期。
3. 恢复顺序：元数据库 → 位点文件 → 消息日志 → 校验对齐。
4. 备份与恢复必须有演练记录，不能只写方案。
5. 重要事件另建归档（业务侧 outbox / 归档存储）。

**完成标准**：可按顺序完成一次恢复演练；恢复后位点与日志对齐；演练结论有记录。

**参考文档**：《[架构设计 · 部署与运维](../../../设计/架构设计/08_架构设计_部署与运维.md)》第 6 节。

## 5. 需求 07-4：bms 迁移与回滚 <a id="r07-4"></a>

优先级：1（紧急）

**背景与动机**：现有 01_01 事件总线已上线、06_01 已依赖，迁移不能一次性替换；必须有适配层、分域切换与回滚开关，否则出问题就是生产事故。

**内容**（《架构设计 · 决策与风险》第 2.6 节、《规划》第 7~8 节）：

1. 先完成适配层（`EventPublisher` / `BaseServiceClient` 的 msg 版本），业务代码不改。
2. 迁移顺序：一条低风险事件 + 一个只读远程调用→ 审计事件 → 业务事件逐域。
3. 回滚开关必须**演练过一次**，不是只写配置。
4. **8B 复制能力必须先于生产迁移**：无复制就迁移等于把单点故障放大到全平台。
5. 迁移期保留 RocketMQ / outbox / HTTP 作为 fallback。

**完成标准**：至少一条事件链与一个远程调用切换成功；切回原链路可在配置层完成；回滚演练有记录。

**参考文档**：《[架构设计 · 决策与风险](../../../设计/架构设计/09_架构设计_决策与风险.md)》第 2.6 节；《[消息平台规划](../../../规划/01_规划_消息平台.md)》第 8 节。

## 6. 需求 07-5：压测与容量规划 <a id="r07-5"></a>

优先级：2（高）

**背景与动机**：没有压测数据，容量规划只能拍脑袋；没有故障演练，无法判断「坏了会怎样」。

**内容**（《架构设计 · 目标与约束》第 3.1 节、《压测与容量规划》第 2~6 节）：

1. 五类压测：基准、负载、压力、稳定性、故障演练。
2. 指标必须报 P50 / P95 / P99，不能只报平均。
3. 客户端与服务端分离部署，避免争抢资源。
4. 容量模型按「N−1」设计，留故障余量。
5. 压测记录必须包含版本、配置、环境与原始数据，保证可复现。

**完成标准**：产出吞吐 / 延迟 / 资源报告；找到单机拐点；容量模型可解释扩容依据。

**参考文档**：《[架构设计 · 目标与约束](../../../设计/架构设计/02_架构设计_目标与约束.md)》第 3.1 节；bms《[压测与容量规划](../../../../bms文档/资料/知识档案/消息与事件驱动/12_事件驱动_压测与容量规划.md)》第 2~6 节。

> **任务落点**：本条需求由 **8B_12** 承接，任务编号 `07-5`；8B_09 的验收压测见需求 07-9，不在本条重复取证。

## 7. 需求 07-6：故障演练 <a id="r07-6"></a>

优先级：2（高）

**背景与动机**：压测只证明「正常时能跑」，故障演练才证明「坏了能恢复」。数据丢失往往发生在没人演练过的路径上。

**内容**（《架构设计 · 目标与约束》第 3.2~3.3 节、《压测与容量规划》第 7 节）：

1. 必做场景：进程崩溃、磁盘满、慢盘、网络分区、消费者卡死、毒消息。
2. 每个场景必须记录：注入方式、观察指标、恢复时间、是否丢数据。
3. 演练必须脚本化、可重复，每次发版前可跑。
4. 演练发现的问题必须回写架构设计或详细设计。
5. 恢复时间与数据完整性是验收判据。

**完成标准**：六类场景均有演练记录；崩溃后不丢已确认消息；磁盘满可恢复；演练可重复执行。

**参考文档**：《[架构设计 · 目标与约束](../../../设计/架构设计/02_架构设计_目标与约束.md)》第 3.2~3.3 节；bms《[压测与容量规划](../../../../bms文档/资料/知识档案/消息与事件驱动/12_事件驱动_压测与容量规划.md)》第 7 节。

## 8. 需求 07-7：阶段验收 <a id="r07-7"></a>

优先级：2（高）

**背景与动机**：L3 范围大，若无阶段性验收，容易长期处于「做了一半」的状态。验收是把「看起来能用」变成「可证明能用」。

**内容**（《架构设计 · 目标与约束》第 6 节、《规划》第 9 节）：

1. 验收按域逐项核对：传输性能、存储恢复、消费组、远程调用、可靠性、高可用、运维、多租户、迁移。
2. 每项必须有可复现的证据（测试记录 / 报告 / 演练记录）。
3. 变更模块覆盖率需达门禁要求（行 + 分支）。
4. 文档校验（链接 / 口径 / 行尾）通过。
5. 未通过项必须登记遗留，不得默认通过。

**完成标准**：九个域验收项均有证据；覆盖率与文档校验通过；遗留项有登记与归口。

**参考文档**：《[架构设计 · 目标与约束](../../../设计/架构设计/02_架构设计_目标与约束.md)》第 6 节；《[消息平台规划](../../../规划/01_规划_消息平台.md)》第 9 节。

## 9. 需求 07-8：生产迁移与真实链路联调 <a id="r07-8"></a>

优先级：1（紧急）

**背景与动机**：07-4 在 msg 仓交付的是迁移编排、开关契约与回滚演练，**真实生产链路没有联调过**——真实 msg 实例、真实平台服务、真实 RocketMQ / outbox fallback、域级灰度键、生产观察窗口都还停在「隔离环境闭环」。8B_08 的退出条件是「一条事件链 + 一个远程调用切换成功且可回滚」，没有这一条，07-7 的「迁移域」证据只能是降级通过；同时 8B_05 复制未交付前不得迁移（D24），必须把前置与生产执行分开写。

**内容**（《架构设计 · 部署与运维》第 5 / 9 / 11 节、《决策与风险》D23 / D24、《消息平台规划》§7~§8）：

1. **生产前置**：8B_05 复制能力验收通过（需求 02-8），07-1 / 07-2 / 07-3 部署、凭据、备份可用；生产闸门 `check --env prod` 放行，缺一项不迁移。
2. **真实链路联调**：真实 msg 实例（容器 + 平台网络 + 网关 h2c / TLS 一跳）+ 真实 platform 服务 + 真实 RocketMQ / outbox / HTTP fallback；跨服务 RPC 的目标方法在 msg 注册表登记；审计链端到端可查。
3. **分域切换**：按 `switch_matrix.toml` 的域级键与白名单 / 灰度，顺序为「一条低风险事件 + 一个只读 RPC → 审计事件 → 业务事件逐域」；每域有观察窗口、回退条件与责任人。
4. **生产回滚**：真实 RocketMQ 集群联调、生产回滚窗口、审计表行级对账；回滚只改配置，原链路保留一个版本，不重新发布业务代码。
5. **真实容器 / 真盘演练**：07-6 六类场景在真实容器（`tmpfs` 限额卷）与真盘 I/O 延迟 / 满盘上复跑；发版流水线接入 `release`，发版前自动复跑。
6. **边界**：不改 bms 端口契约与业务代码；不删除原链路；不替代 07-4 的编排与 07-7 的验收报告；bms 侧配置切换与业务域迁移可跨仓实施，任务文档留 msg 仓。

**完成标准**：

- 8B_05 复制能力验收通过且生产闸门放行；
- 至少一条事件链 + 一个只读 RPC 在真实链路切换成功，审计事件与业务事件按域推进，业务代码零改动；
- 每域有观察窗口记录与回退判据；至少一次生产回滚窗口演练，审计表行级对账通过；
- 真实容器 / 真盘六类演练可复跑，`release` 接入发版流水线；
- 变更模块行 + 分支覆盖率达标，文档三项校验通过。

**参考文档**：[需求 07-4](07_需求_部署迁移与验收.md#r07-4)；《[架构设计 · 部署与运维](../../../设计/架构设计/08_架构设计_部署与运维.md)》第 5 / 9 / 11 节；《[架构设计 · 决策与风险](../../../设计/架构设计/09_架构设计_决策与风险.md)》第 2.6 节（D23 / D24）；《[消息平台规划](../../../规划/01_规划_消息平台.md)》第 7~8 节；[07-4 bms 迁移与回滚](../任务/07_部署迁移与验收/07_部署迁移与验收_04_bms迁移与回滚/07_部署迁移与验收_04_bms迁移与回滚.md)、[07-6 故障演练](../任务/07_部署迁移与验收/07_部署迁移与验收_06_故障演练/07_部署迁移与验收_06_故障演练.md)。

## 10. 需求 07-9：验收与压测 <a id="r07-9"></a>

优先级：2（高）

**背景与动机**：8B_09 是「验收与压测」阶段，要回答「性能、稳定性、故障演练是否通过」；07-7 的最终九域验收依赖这一阶段的报告与证据。07-5 的容量定参与持续回归归 8B_12，本需求**不重复取证**；但没有本阶段的验收压测，07-7 只能拿零散任务记录拼结论，无法证明「平台在目标负载下稳定」。

**内容**（《架构设计 · 目标与约束》第 3.1~3.3 节、《部署与运维》第 9 节、bms《压测与容量规划》第 2~7 节）：

1. **性能验收**：五类压测中的基准 / 负载 / 压力 / 稳定性 / 故障演练；客户端与服务端分离部署；指标报 **P50 / P95 / P99**，不只报平均；记录版本、配置、环境与原始数据。
2. **稳定性**：24 小时 长稳（内存 / 句柄 / 积压 / 延迟 / 错误率），无泄漏、无持续劣化。
3. **故障演练复跑**：07-6 六类场景在验收环境复跑；8B_05 多实例故障切换与网络分区纳入；结论区分通过 / 降级 / 失败，降级项不计通过。
4. **验收证据**：性能报告、稳定性报告、演练矩阵、覆盖率报告、发布记录；证据可复现、链接可达，不复制大段数据。
5. **阶段测试报告**：汇总性能 / 稳定性 / 故障演练结论，给出是否进入 8B_12 与 07-7 的判定；未通过项登记遗留与归口。
6. **边界**：不替代 8B_12 的容量定参与持续回归；不替代 07-7 的九域阶段验收报告；不在本地跑全量测试。

**完成标准**：

- 五类压测按分离部署执行并产出 P50 / P95 / P99 报告；
- 24 小时 稳定性通过（无内存 / 句柄泄漏、积压可控）；
- 六类故障演练复跑结论明确，多实例故障切换通过；
- 阶段测试报告成文，证据索引完整，未通过项有遗留与归口；
- 覆盖率与文档三项校验通过。

**参考文档**：[需求 07-5](07_需求_部署迁移与验收.md#r07-5)、[需求 07-6](07_需求_部署迁移与验收.md#r07-6)、[需求 07-7](07_需求_部署迁移与验收.md#r07-7)；《[架构设计 · 目标与约束](../../../设计/架构设计/02_架构设计_目标与约束.md)》第 3.1~3.3 节；《[架构设计 · 部署与运维](../../../设计/架构设计/08_架构设计_部署与运维.md)》第 9 节；bms《[压测与容量规划](../../../../bms文档/资料/知识档案/消息与事件驱动/12_事件驱动_压测与容量规划.md)》第 2~7 节；[07-6 故障演练](../任务/07_部署迁移与验收/07_部署迁移与验收_06_故障演练/07_部署迁移与验收_06_故障演练.md)。
