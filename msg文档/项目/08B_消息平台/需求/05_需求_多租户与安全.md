## 1. 域说明 <a id="intro"></a>

本域只写**消息平台的扩展项**。租户身份、解析链、租户状态、用户与服务认证、RBAC、审计链、通用配额、模块注册、能力契约等能力由 bms 基座统一提供，消息平台继承，不在本文档重复定义。

- **基座权威**：bms《[架构设计 · 产品租户与安全接入](../../../../bms文档/设计/架构设计/41_架构设计_子系统_产品租户与安全接入.md)》与 bms 07D 产品租户与安全接入专项；接入口径与禁止项以该节点及 12 / 14 / 15 / 19 / 11 / 38 / 31 / 16 各能力节点为准。
- **本文档范围**：消息资源作用域、数据面同口径接入、消息维度配额、topic ACL、审计留痕类别与记录级定位、消息资源懒初始化、租户用量板块。
- **与原 05 的关系**：原 05 把租户解析、认证、RBAC、审计链等继承项写成「本域定义一套」，与代码事实不一致；本版重写为「基座能力引用 + 扩展项」，原 `05-1 租户用量板块与表单登记` 任务与记录保留，归入扩展项 `05-7`。

| --- | --- | --- | --- |
| 租户身份与解析链 | bms 07D `01-2`、架构 12 | 管理面读基座中间件上下文；数据面复用基座解析函数 | 同一请求在管理面与数据面解析出同一 `tenant_id` |
| 租户状态与生命周期 | bms 07D `01-2`、架构 12 | 复用基座租户源与全局版本戳；停用即拒绝 | 停用即时生效；租户源不可达 fail-closed |

## 3. 需求 05-1：租户标识与消息资源作用域 <a id="r05-1"></a>

优先级：2（高）

**背景与动机**：消息平台需要 `tenant_id / namespace / topic` 三级资源归属，但 `tenant_id` 与 `namespace` 的权威在基座：`tenant_id` 是基座雪花内部身份，`namespace` 必须取自已登记启用的 `module_key`。消息平台只需要定义 `topic` 如何映射为 `resource_key`、以及物理落点，不应另造一套租户标识。

**内容**（bms 架构 41 §4；bms 07D `01-1`）：

1. `tenant_id` 使用基座雪花内部身份，**不可变**；目录与元数据列一律使用它，不使用可变的租户编码。
2. `namespace` 取值为服务目录中**已登记且启用**的 `module_key`；未登记值拒绝创建（`350010`）。消息平台不自造模块键。
3. `topic` 作为消息平台的 `resource_key`，按 bms 07D `01-1` 登记资源类型与命名规则；主题名建议 `{对象}.{动作}`（如 `operation.created`），与 bms 事件契约命名一致。
4. 物理落点：`data/{tenant_id}/{module_key}/{topic}/{partition}`；不使用租户编码，租户编码只用于日志与展示。
5. 租户编码变更后目录与数据不受影响；拓扑变化（拆库 / 合库 / 换部署单元）不改变三级标识。

**完成标准**：可按三级结构创建与查询主题；未登记 `module_key` 被拒绝；`topic` 资源类型已注册；租户编码变更后目录与数据不受影响。

**参考文档**：bms《[架构设计 · 产品租户与安全接入](../../../../bms文档/设计/架构设计/41_架构设计_子系统_产品租户与安全接入.md)》第 4 节；bms 07D `01-1`；《[架构设计 · 多租户与安全](../../../设计/架构设计/07_架构设计_多租户与安全.md)》第 2 节。

## 4. 需求 05-2：数据面同口径接入 <a id="r05-2"></a>

优先级：1（紧急）

**背景与动机**：消息平台的 HTTP/2 数据面不走 ASGI 中间件；如果帧入口另写一套租户解析，就会出现「管理面看到 A 租户、数据面看到 B 租户」。数据面必须复用基座同一套解析与状态校验，只扩展「帧入口如何接入」这一层。

**内容**（bms 架构 41 §5.1；bms 07D `01-2`、`02-1`）：

1. 管理面 / RPC 直接复用基座中间件注入的租户上下文，不重复解析、不再回源。
2. 数据面在帧入口复用基座同一套解析函数；**只认已校验令牌里的租户位**，`Host` 与 `X-Tenant-ID` 一律不采信。
3. 异步消费、定时任务、批处理复用基座租户可用性守卫；每轮或每批入口调用，命名空间经 `scope` 校验。
4. 复用基座租户源与全局版本戳：停用即拒绝收发；**不自建 TTL 缓存**；租户源不可达按 fail-closed 返回 503。
5. 生产环境启用 h2 over TLS，开发环境可用 h2c；TLS 证书与服务 JWT 密钥轮换走基座「先加新、再切用、后删旧」口径。

**完成标准**：同一请求在管理面、数据面、异步路径解析出同一租户；跨租户访问被拒；停用租户收发被拒且即时生效；租户源不可达返回 503；TLS / h2c 可配。

**参考文档**：bms《[架构设计 · 产品租户与安全接入](../../../../bms文档/设计/架构设计/41_架构设计_子系统_产品租户与安全接入.md)》第 5.1 节；bms 07D `01-2`、`02-1`；《[架构设计 · 多租户与安全](../../../设计/架构设计/07_架构设计_多租户与安全.md)》第 3~4 节。

## 5. 需求 05-3：配额管理 <a id="r05-3"></a>

优先级：2（高）

**背景与动机**：消息维度（主题数、消息存储、吞吐、连接数）不属于 bms 通用配额，且 `sys_tenant_quota` 归属 bms tenant 服务，msg 不能跨服务直写。配额由 msg 自维护，平台只读回显。

**内容**（bms 架构 41 §5.3；bms 07D `02-3`）：

1. 配额由 **msg 自维护**（`msg_quota`），维度：主题数、消费组数、生产速率、消息存储、未确认数、连接数。
2. **不写入 bms `sys_tenant_quota`**（隔离纪律：不访问其他服务数据库）。
3. 平台侧经产品数据源只读加载 msg 用量接口，按 bms 07D `02-3` 的统一投影契约返回：维度、限额、用量、单位、周期、软硬限、更新时间、来源；**不做双写**。
4. 执行点前置：接收请求时判断；软硬两档（软限告警、硬限拒绝）。
5. 配额可查询、可调整，调整留痕；用量在 msg 管理台与 bms 只读板块均可见。

**完成标准**：超限时按软硬限正确响应；平台只读可见 msg 用量且与产品侧一致；配额调整立即生效并留痕；平台侧无双写。

> **承载方式（2026-11-04 拍板，保留）**：平台侧只读板块由 msg 自持交付——数据源声明、表单与字段元数据、`form_key` 登记、取数端点 `/tenant-usage`，全部在 msg 仓；bms 侧不为此立项。本需求「平台能看到用量」的判据为「平台侧可读到数据与元数据、角色权限可选中该表单并配置字段」。任务见 [05-7](#r05-7)。

**参考文档**：bms《[架构设计 · 产品租户与安全接入](../../../../bms文档/设计/架构设计/41_架构设计_子系统_产品租户与安全接入.md)》第 5.3 节；bms 07D `02-3`；《[架构设计 · 多租户与安全](../../../设计/架构设计/07_架构设计_多租户与安全.md)》第 6 节。

## 6. 需求 05-4：授权（RBAC + topic ACL） <a id="r05-4"></a>

优先级：2（高）

**背景与动机**：认证与 RBAC 继承基座；但「谁能对哪个主题 publish / subscribe」是消息域的资源级授权，基座 RBAC 只到功能级，需要 msg 自建 topic ACL。

**内容**（bms 架构 41 §3 / §4；bms 07D `02-5`）：

1. RBAC 权限码沿用基座：`msg:query`（只读）/ `msg:manage`（管理操作），与 bms 权限体系对齐。
2. 主题级 ACL 由 msg 自建，操作类型：`publish` / `subscribe` / `describe` / `manage`。
3. 校验顺序：RBAC → topic ACL → 租户 / `module_key` 归属；资源级授权只在同一 `module_key` 内生效。
4. 三个易漏点必须覆盖：跨租户订阅、管理接口只校验登录、重放任意主题。
5. ACL 变更留痕；ACL 存储与缓存失效口径由 msg 详细设计定，不引入基座第二套授权引擎。

**完成标准**：无权限操作被拒绝；跨租户订阅被拒绝；重放接口有资源级校验；ACL 变更可追溯。

**参考文档**：bms《[架构设计 · 产品租户与安全接入](../../../../bms文档/设计/架构设计/41_架构设计_子系统_产品租户与安全接入.md)》第 3、4 节；bms 07D `02-5`；《[架构设计 · 多租户与安全](../../../设计/架构设计/07_架构设计_多租户与安全.md)》第 7 节。

## 7. 需求 05-5：审计留痕 <a id="r05-5"></a>

优先级：2（高）

**背景与动机**：审计链与哈希链继承基座；msg 需要定义「哪些操作必须留痕」以及「记录级操作怎么定位」，不能自建审计体系。

**内容**（bms 架构 41 §5.4；bms 07D `02-4`）：

1. 配置变更、数据操作、权限变更、访问异常（含停用租户访问）四类必须留痕。
2. 留痕内容：谁、何时、对什么（`tenant_id` / `module_key` / `topic` / `group`）、做了什么、结果、来源 IP / `trace_id`；涉及具体记录时另带 `log_id`。
3. 审计写入 bms 审计链，不自建；审计记录不可被 msg 删除。
4. 普通读写不逐条留痕，只做指标统计；记录级定位字段只出现在涉及具体记录的操作上，不因 `log_id` 产生审计洪泛。
5. 审计扩展字段按 bms 07D `02-4` 契约提供；重放、删消息、位点重置、延迟转投异常处置等操作必须带 `log_id`，可从审计条目直接定位到一条日志记录。

**完成标准**：管理操作可在 bms 审计链查到；越权与停用访问有记录；普通读写不产生洪泛；涉及具体记录的操作可按 `log_id` 一次定位。

**参考文档**：bms《[架构设计 · 产品租户与安全接入](../../../../bms文档/设计/架构设计/41_架构设计_子系统_产品租户与安全接入.md)》第 5.4 节；bms 07D `02-4`；《[架构设计 · 多租户与安全](../../../设计/架构设计/07_架构设计_多租户与安全.md)》第 9 节。

## 8. 需求 05-6：租户生命周期（消息资源） <a id="r05-6"></a>

优先级：2（高）

**背景与动机**：租户开通 / 停用 / 启用继承基座；msg 没有租户库，不能复用建库流程，但需要在自己的资源模型里做「首次发布懒初始化命名空间与默认配额」以及「停用保留数据」。

**内容**（bms 架构 41 §4；bms 07D `01-2`）：

1. **懒初始化**：首次**发布**到未开通的 `(tenant_id, module_key)` 时自动创建命名空间与默认配额。
2. **查询不创建**：未开通时查询返回「不存在」，读路径无写副作用。
3. 并发首次发布靠唯一约束兜底，冲突时重查而非报错。
4. **停用**：拒绝生产与消费，管理查询仍可查看；**数据完整保留**，不自动清理、不归档；启用后立即恢复，无需数据迁移。
5. **平台租户**按普通租户处理，不引入「全局 topic」；跨租户广播由各租户各自消费一份。

**完成标准**：首次发布自动创建命名空间；查询未开通返回不存在且不建数据；停用后收发被拒但数据保留；重新启用后恢复；平台租户与普通租户行为一致。

**参考文档**：bms《[架构设计 · 产品租户与安全接入](../../../../bms文档/设计/架构设计/41_架构设计_子系统_产品租户与安全接入.md)》第 4 节；bms 07D `01-2`；《[架构设计 · 多租户与安全](../../../设计/架构设计/07_架构设计_多租户与安全.md)》第 5 节。

## 9. 需求 05-7：租户用量板块与表单登记 <a id="r05-7"></a>

优先级：2（高）

**背景与动机**：平台侧需要只读查看 msg 用量；按 2026-11-04 拍板，数据源声明、表单与字段元数据、`form_key` 登记、取数端点、前端页面全部由 msg 自持交付，bms 侧不为此立项。原任务 `05-1 租户用量板块与表单登记` 保留，归入本扩展项。

**内容**（bms 07D `02-3`；原 05-3 承载方式拍板）：

1. 在 msg 产品声明中登记数据源（`[[data_sources]]`），供平台按 `data_source_key` 只读装载。
2. 表单与字段元数据以种子写入平台库（`sys_business` / `sys_form` / `sys_field`），并完成 `form_key` 登记（`form_records()`）。
3. 提供取数端点 `/tenant-usage`，字段与表单元数据严格同源。
4. msg 管理台展示用量；平台侧保证可读到数据与元数据、角色权限可选中该表单并配置字段。
5. 原任务编号、Kiwi 用例与实施记录保留，不废弃、不重挂。

**完成标准**：平台侧可读到 msg 用量数据与元数据；角色权限可选中该表单并配置字段；msg 管理台可见；字段与取数端点同源；原任务记录完整保留。

**参考文档**：bms 07D `02-3`；bms《[架构设计 · 产品租户与安全接入](../../../../bms文档/设计/架构设计/41_架构设计_子系统_产品租户与安全接入.md)》「标准扩展点」节；原 [05-1 租户用量板块与表单登记](../任务/05_多租户与安全/05_多租户与安全_01_租户用量板块与表单登记/05_多租户与安全_01_租户用量板块与表单登记.md)。
