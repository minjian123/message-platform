## 1. 用途与维护 <a id="purpose"></a>

- **定位**：回答「msg 仓里有哪些类可被继承、父类是谁、代码在哪、由谁承接」。平台基类（`BaseObject` / `BaseComponent` / `BaseDataState` / `BaseTable` 等）不在此登记。
- **强制口径（平台基类体系，不得违反）**：
  1. 本仓任何类都必须能追到**平台体系根**（条文见 bms/bms文档/规范/前端开发规范.md §3.1「必须从根派生（强制 · 零例外）」与 bms/bms文档/规范/AI开发规范.md 架构铁律）；
  2. **不得新增体系根**——直接继承总基类一律拒绝，体系根由平台契约定；
  3. 新增可继承类须**先登记本表 + 在实现契约 §7 补链**，再写代码。
- **状态取值**：`已交付` / `占位`（接口就位、真实实现待回补）/ `待交付`（已设计未落地）。
- **代码位置口径**：**仓根相对路径**（本仓前端源码面 `frontend/modules/msg/src/`），供 `engkit base frontend-base` 做清单 ↔ 源码对账。
- **判定入口**：预检步骤「基座：check_frontend_base」（`[rules.frontend_base]`，`profile = "product"`）。

## 2. 基类登记表 <a id="registry"></a>

消息平台管理模块的两类横切各收敛为一个产品段组件基类：只读列表 / 详情（`BaseMsgReadOnlyView`）与写操作（`BaseMsgWriteAction`），分别由 `useMsgReadOnlyView()` / `useMsgWriteAction()` 投影消费。

| 类名 | 层 | 父类 | 代码位置 | 职责 | 状态 |
| --- | --- | --- | --- | --- | --- |
| `BaseMsgReadOnlyView` | 组件基类（产品段） | `BaseTable` | `frontend/modules/msg/src/base/BaseMsgReadOnlyView.ts` | 只读视图共用横切：分页、筛选、加载 / 空 / 错误 / 无权限四态、权限码判定入口（缺省 `msg:query`，页面可传 `msg:manage`）、批量替换筛选 | 已交付（06-1-2，2026-11-09；06-7 扩 `permission` / `replaceFilters()`；`engkit base frontend-base` 对账通过） |
| `BaseMsgWriteAction` | 组件基类（产品段） | `BaseAsyncTask` | `frontend/modules/msg/src/base/BaseMsgWriteAction.ts` | 写操作共用横切：提交 / 状态机 / 进度 / 取消（链上取得）、`msg:manage` 权限判定、错误码文案键、二次确认与影响范围、结果重置 | 已交付（06-2-2，2026-11-09；`engkit base frontend-base` 对账通过） |

## 3. 不入清单的两类 <a id="excluded"></a>

- **投影（薄适配）**：`useMsgReadOnlyView()` 只做「核心实例 ↔ 框架响应式」适配，不含判定逻辑，不是可继承类；与平台 `ui_ep` 的组合式同构（纯文本路径：bms/frontend/packages/ui_ep/src/composables/）。契约见[前端基类实现契约](设计/基类体系/前端基类实现契约.md) §4。
- **页面组件与视图模型**：只读页 / 写操作页的 Vue 单文件组件、本地视图模型与请求 / 响应生成类型不继承平台基类构成新的可继承层；生成类型的事实源是 `deploy/contracts/msg.json` 经 `frontend/packages/api-types` 产出。
- **共享件**：`MsgConfirmDialog.vue` / `ReadOnlyList.vue` 是具体件（消费页面传入的 props），不构成可继承层，不登记。

## 4. 与平台基类的关系 <a id="platform"></a>

- 唯一登记类直接继承 `BaseTable`（平台组件基类，位于 `frontend/packages/core/src/capabilities/table.ts`），链继续接到平台体系根；不新建中间体系根、不复制平台基类的公共字段与方法。
- 平台主干继承链与体系根清单以 bms/bms文档/前端基类清单.md §2.1 为唯一权威；父类解析经 `[rules.frontend_base].base_source_dirs` 指向 bms 前端 core 源码面。
- 双轨口径与条文引用见 bms/bms文档/规范/前端开发规范.md §3.1、§3.4，bms/bms文档/规范/后端开发规范.md 架构铁律，以及 bms/bms文档/规范/AI开发规范.md 架构铁律的「条文引用」。
