# msg 后端基类实现契约

> 本仓基类的逐类契约与继承链。平台基类语义（体系根、四段链、形态要求）以 bms《后端基类实现契约》为准，本文件只写 **msg 自己的端口契约与接线**，不复述平台口径。

## 1. 范围 <a id="scope"></a>

- **覆盖**：本仓全部可被继承的类（当前 5 个框架对象端口，见清单 §2）及其接入平台基类体系的链。
- **不覆盖**：平台基类（权威在 bms）、`Protocol` 结构契约、业务实现类（承接实现，不是新基类）。
- **判定入口**：预检步骤「基座：check_backend_base」（`[rules.backend_base]`，`profile = "product"`）。

## 2. 端口形态契约 <a id="shape"></a>

- 五个端口统一为 `BaseFrameworkObject` + `ABC`：**框架对象**（非数据对象），不声明 dataclass，不参与值语义与序列化输出。
- 方法一律 `@abstractmethod`；实现类（文件 / 内存 / 外部存储）必须全覆盖，装配缺失即拒启。
- 端口不自带生命周期实现：需要异步释放的实现类覆写平台提供的 `aclose` 钩子位。

## 3. 逐类语义 <a id="each"></a>

### 3.1 `MessageStore` <a id="message-store"></a>

分区日志读写与位点推进：追加、按位点读、段文件轮转与保留策略。实现形态见 `broker/log.py` 与 `broker/file_store.py`。

### 3.2 `DelayStore` <a id="delay-store"></a>

延迟消息落盘与到期扫描：写入延迟项、按到期时间取批、去重与重投。分片与恢复见 `broker/delay*.py`。

### 3.3 `GroupStore` <a id="group-store"></a>

消费组状态：组位点、成员分配与再平衡状态。

### 3.4 `OffsetStore` <a id="offset-store"></a>

位点持久化与重置：按分区读写位点，重置须留审计（记录级定位字段随审计写入）。

### 3.5 `DeadLetterQueue` <a id="deadletter"></a>

死信投递与保留：投递次数耗尽后转入死信，保留策略与清理由实现控制。

## 4. 结构契约（`Protocol`）的边界 <a id="protocol"></a>

`CloseableStore` / `RebuildableDelayStore` / `FlushableOffsetStore` / `DelayDedupeSource` / `OffsetEnumerator` / `OffsetPurger` / `OffsetRealigner` / `OffsetResetter` 为**结构契约**：只约束「有哪些方法」，不进入 MRO、不参与基类体系判定。改动其一为继承式基类时，须改继承平台基类并登记清单。

## 4.1 工厂类与插件类的归属 <a id="factory-plugin"></a>

按平台基类体系的分工，本仓各类落在下列基类上（**不得错层**：工厂接工厂基类、插件接插件基类、非插件端口接框架对象根）：

| 类别 | 本仓类 | 应继承（平台） | 说明 |
| --- | --- | --- | --- |
| 服务应用工厂 | `ApplicationFactory` | `BaseServiceApplicationFactory` | 服务身份 / 中间件 / 插件装配统一挂载 |
| 插件型工厂 | `MsgHealthCheckRegistryFactory` | `BasePluginFactory` | 产出注册表实例，经插件注册表解析 |
| 插件（可插拔能力） | 本仓当前无 | `BasePluggable` | 有 `plugin_key` 并经插件注册表取用的能力才归此层 |
| 非插件端口 | `MessageStore` / `DelayStore` / `GroupStore` / `OffsetStore` / `DeadLetterQueue` | `BaseFrameworkObject` | 无插件身份，由装配直接注入实现 |

**判定口径**：一个类是否属「插件」，看它是否有 `plugin_key` 身份并经插件注册表解析——不是看名字里有没有 `Store` / `Registry`；工厂是否合规，看它是否在 `BaseFactory` 链上（插件型工厂经 `BasePluginFactory`），不得直接继承 `BaseObject` 或裸 `ABC`。

## 5. 错误码段位 <a id="errcodes"></a>

本仓错误码为**产品码**：6 位 = 2 位段位 + 4 位序号，段位 `35` 取自服务行 `errcode_segment`，不在代码里手写段位。预检按段位与位数判定，段位不符即失败。

## 6. 迁移链 <a id="migrations"></a>

迁移脚本落 `backend/alembic/versions/msg/`；当前尚未建立迁移（目录为空时预检跳过链检查）。建立后要求**单 head**、不断链、分支标签与配置段一致。

## 7. 继承链与代码位置 <a id="chain"></a>

> 本仓**不新增体系根**：允许直接继承 `BaseObject` 的只有下列平台体系根；本仓自有基类一律挂在平台链的下方。

**体系根清单（允许直接继承 `BaseObject`）**：

- `BaseValueObject`
- `BaseDataContract`
- `BaseFrameworkObject`
- `BaseCollection`
- `BaseRepository`
- `BaseService`
- `UnitOfWork`

**本仓继承链（产品段）**：

- `MessageStore` → `BaseFrameworkObject`（代码：`bms_msg/broker/log.py`）
- `DelayStore` → `BaseFrameworkObject`（代码：`bms_msg/broker/delay.py`）
- `GroupStore` → `BaseFrameworkObject`（代码：`bms_msg/broker/group.py`）
- `OffsetStore` → `BaseFrameworkObject`（代码：`bms_msg/broker/offset.py`）
- `DeadLetterQueue` → `BaseFrameworkObject`（代码：`bms_msg/broker/deadletter.py`）

## 8. 维护 <a id="maintain"></a>

新增可继承类：先在[清单](../../后端基类清单.md) §2 登记，再在本文件 §7 补一条链，最后写代码；调整端口语义视为契约变更，须同步装配与详细设计。
