## 1. 文档目的 <a id="purpose"></a>

概要设计回答「平台拆成哪些模块、模块之间怎么调用、对外暴露哪些接口」。它是**架构设计与详细设计之间的中间层**：

| 文档 | 回答 |
| --- | --- |
| 架构设计 | 平台由哪几面构成、关键决策是什么 |
| **概要设计** | **拆成哪些模块、接口有哪些、数据怎么流** |
| 详细设计 | 每个模块怎么实现、字段与参数是什么 |
| 数据库设计 | 表与字段 |

## 2. 模块划分 <a id="modules"></a>

```text
backend/services/msg/src/bms_msg/
├── main.py / asgi.py / __main__.py     # 装配与入口
├── broker/                             # 数据面
│   ├── transport.py                    # HTTP/2 连接与流
│   ├── protocol.py                     # 帧编解码 / 版本 / 错误码
│   ├── router.py                       # topic / partition / group 路由
│   ├── log.py                          # 追加日志 / 索引 / 分段
│   ├── recovery.py                     # CRC / 截断 / 位点对齐
│   ├── delay.py                        # 延迟区端口 / 发布服务 / 只读投影
│   ├── scheduler.py                    # 分层分桶时间轮 + 推进器（启停 / 限速 / 转投）
│   ├── offset.py                       # 消费位点
│   └── replication.py                  # ISR / 选举（8B_05）
├── rpc/                                # RPC
│   ├── dispatch.py                     # 方法分发 / deadline 传播
│   └── client.py                       # BaseServiceClient 适配
├── console/                            # 控制面（管理）
│   ├── api.py                          # 只读视图 + 写操作
│   └── replay.py                       # 重放任务
├── admin/                              # 控制面（运维）
│   ├── metrics.py                      # 指标
│   └── health.py                       # 探针
├── models/ · repositories/ · schemas/  # 元数据持久化
└── config.py · errors.py
```

| 模块 | 职责 | 依赖 | 被依赖 |
| --- | --- | --- | --- |
| `transport` | 连接、stream、TLS | 无 | `protocol` |
| `protocol` | 帧编解码、版本、错误码 | `transport` | `router`、`rpc.dispatch` |
| `router` | 分区选择、组路由 | `log`、`offset` | `protocol`、`console` |
| `log` | 追加、索引、分段、读取 | 无 | `router`、`recovery`、`delay`、`console` |
| `delay` | 延迟区暂存、延迟发布、只读待投投影 | `log`、`router` | `protocol`、`console`、`scheduler` |
| `scheduler` | 分层分桶时间轮、到期推进、转投（启停 / 限速 / 时钟） | `delay`、`log` | 无（由 `api/data` 惰性启动） |
| `recovery` | 启动扫描、截断、索引重建 | `log` | 启动流程 |
| `offset` | 位点读写 | 无 | `router`、`console` |
| `replication` | ISR 同步、选举（后置） | `log` | `router` |
| `rpc.dispatch` | 方法分发、deadline | `protocol` | 无 |
| `console.api` | 管理接口 | `router`、`log`、`offset` | 无 |
| `console.replay` | 重放任务 | `log`、`router` | 无 |
| `admin.metrics` | 指标采集 | 各模块 | 无 |

**分层规则**：

1. `console` / `admin` **只能读**数据面状态，写操作必须经 `router`。
2. `log` **不依赖**任何上层模块（可单测）。
3. `protocol` **不感知**存储细节（只做编解码与路由调用）。

## 3. 接口清单 <a id="interfaces"></a>

> 参数与响应结构以 `deploy/contracts/msg.json`（契约快照）为唯一事实源；本节只列接口与语义。

### 3.1 数据面

| 接口 | 方法 | 语义 | 主要参数 |
| --- | --- | --- | --- |
| `/msg/publish` | POST | 发布一条消息（带 `delay_level` 即延迟发布） | topic、key、payload、headers、trace_id、delay_level |
| `/msg/subscribe` | GET | 订阅 / 长轮询 | group、topic、offset、maxWait、maxMessages |
| `/msg/ack` | POST | 确认消费 | group、topic、partition、offset |
| `/msg/nack` | POST | 显式拒绝 | 同上 + reason |

### 3.2 远程调用
| 接口 | 方法 | 语义 | 主要参数 |
| --- | --- | --- | --- |
| `/rpc/{service}/{method}` | POST | 一元调用 | 请求体、deadline、trace_id |
| `/rpc/{service}/{method}/stream` | POST | 服务端流 | 同上 |

### 3.4 运维

| 接口 | 方法 | 语义 |
| --- | --- | --- |
| `/health` | GET | 存活探针 |
| `/ready` | GET | 就绪探针（元数据可达、日志可写） |
| `/metrics` | GET | Prometheus 指标 |

### 3.5 租户上下文

| 入口 | 租户来源 |
| --- | --- |
| 管理面 / 远程调用（ASGI） | 基座中间件注入的租户上下文（子域名 → `X-Tenant-ID` → token 租户位） |
| 数据面（HTTP/2 `h2` 直连） | 帧入口复用基座解析函数，不依赖中间件 |
| `/tenant-usage` | 由调用方（bms 租户管理页）传入目标租户，服务端校验调用方权限 |

所有入口都必须校验租户状态（停用拒绝），并按 `tenant_id` 隔离数据。

## 4. 数据流 <a id="flow"></a>

### 4.1 发布

```text
Producer → transport → protocol（解帧）→ 鉴权 / 配额 → router（选分区）
→ log.append（分配 offset）→ offset.update(LEO) → 返回 {offset, partition}
```

### 4.2 消费

```text
Consumer → transport → protocol → router（定位分区与位点）
→ log.read(batch) → 推送 → Consumer 处理 → /msg/ack → offset.commit
```

### 4.3 重放

```text
Admin → console.api → console.replay（建任务）→ 按条件读 log → 限速投递
→ 更新任务进度 → 完成 / 失败
```

### 4.4 远程调用
```text
Client → transport → protocol → rpc.dispatch（方法路由 + deadline）
→ handler → 返回结果 / 错误（retryable）
```

### 4.5 延迟投递

```text
Producer → transport → protocol → 鉴权 / 配额 → router（按 key 锁定分区）
→ delay.enqueue（写 .delay，deliver_at = now + 档位）→ 返回 {message_id, log_id, deliver_at}
…… 时间轮到点 ……
delay.tick → delay.due（取到期记录）→ log.append（此刻才分配 offset）
→ 清 .delay → 进入正常投递链（停等 / 死信 / 保留 / 重放全部复用）
```

**为什么到期才 `append`**：未到期就占 offset 会让停等把整分区堵在队头、并让积压把「还在等」的消息算成「待消费」；
延迟区把它移出 offset 空间，位点与顺序的不变量原样成立（架构 04 §2.4）。

## 5. 模块间关键约束 <a id="constraints"></a>

| 约束 | 说明 |
| --- | --- |
| offset 只能由 `log.append` 分配 | 其他模块不得自行编号 |
| 索引与日志同源 | 索引条目必须与 append 同步生成 |
| 位点只经 `offset` 模块 | 禁止直接写位点文件 |
| 管理写操作经 `router` | 禁止 `console` 直接写 `log` |
| 重放必须限速 | 由 `console.replay` 统一控制 |
| 延迟消息不占 offset | 到期 `append` 前不进入 offset 空间，位点 / 停等 / 积压统计不感知它 |
| 延迟区只经 `delay` 模块 | 禁止 `log` / `console` 直接写 `.delay`；`delay` 依赖 `log` 而不反向 |
| 到期转投先写后清 | 先 `append` 并刷盘、再清 `.delay`：崩溃不丢；恢复期扫日志尾部按 `log_id` 比对（每条记录唯一、重放换新），已入日志的直接清（不重） |
| 指标采集无副作用 | `admin.metrics` 只读 |
